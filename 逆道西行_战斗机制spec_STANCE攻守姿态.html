0. 决策摘要（TL;DR）

1 个每回合唯一决策：姿态布尔 ATTACK / GUARD
0 个新增资源条（复用 momentum + jingLi）
~6 处最小改动点（4 气势 + 1 经力 + 1 心魔）
P0 绑定心魔接战斗内双向口才算完成
结论：不采用提案 A（临时卡选 1，会降密度、抽离构筑）。提案 B 的精神采纳并升级为 STANCE 姿态层：它不造资源，而是调制combat.js 已有的 momentum 与 battle_resource.js 已有的 jingLi，并让心魔 (xinmo) 在战斗内可双向调节——一举补上"决策密度、攻守可见取舍、心魔负 sink"三件事。

1. 设计意图（Fun Hypothesis 钩子）

本作卖点是"在黑暗西游的逆天叙事下，用六道劫印×经文×装备法宝的永久构筑，在单局 81 难走出不同的道"。战斗是构筑的表达口，不是卡牌游戏本身。因此：

  • 任何机制都不能抽离 build（否定临时卡）——决策必须作用于"你的招式/资源"。
  • 攻 / 守的取舍要有真实重量，否则是装饰条。
  • 重量应落在本作已存在的元叙事轴上：逆天（攻）↔ 渡世（守）正是六道·战/渡两极，而心魔已驱动 daoxinTier 三档世界态与 心魔缠身 curse。
关键洞察：心魔 (xinmo) 在代码里已并入道心、已有 tier 系统与扣血 curse，但战斗中无双向调节口——玩家在战斗里既推不动它、也压不了它。STANCE 把"攻推心魔 / 守安心魔"补上，心魔立刻从装饰变有重量的叙事筹码，恰好实现用户"在经与攻间做取舍"。

3. 机制定义 · STANCE

STANCE 是每回合一个布尔选择，不消耗资源、不进面板，仅作为本回合结算的调制开关：

姿态主题对 momentum对 jingLi对 xinmo战术含义
ATTACK 攻逆天 / 战道获取 ×1.5获取 ×0.7+K_ATK / 回合攒势更快、爆发更频，但道心偏逆、心魔上涨
GUARD 守渡世 / 禅意获取 ×0.7获取 ×1.5−K_DEF / 回合蓄经更快、金刚经/化雨更频，道心偏渡、心魔回落

3.1 与现有系统的耦合

  • 攻轴末端：momentum 仍走 applyMomentumBurst 爆发——ATTACK 让它攒得更快，但代价是心魔。
  • 守轴末端：jingLi 仍走金刚经/化雨/绝招——GUARD 让它蓄得更快，且化雨回血直接对抗心魔缠身扣血。
  • 心魔轴末端：xinmo 写入 s.xinmo，实时改变 daoxinTier → 改变劫印 SEAL_MOD(combat.js:137)、触发/加重 心魔缠身 curse、并作为结局权重（见 §8 红线 B）。
为何不是"单条滑块池二选一分配"：本作两资源是独立获取（气势靠命中、经力靠蓄力/道途），强改单池会重写整条管线。STANCE 做"同回合速率调制"，保留双资源语义，改动局限于获取点的乘法系数——风险最低。

4. 输入 / 输出 / 边界

项目定义
输入玩家每回合在"行动点/操作点"前选择 stance ∈ {ATTACK, GUARD}（UI 单按钮切换，默认承上回合）。
处理本回合所有 momentum / jingLi 获取事件乘对应系数；回合结算尾段对 s.xinmo 施加 ±K。
输出① 资源获取速率差（肉眼可见的条增长差）；② 心魔漂移 → daoxinTier 实时变化（UI 道心角标变色）；③ 长期：影响结局分支与 Boss 形态。
边界·必守
  • 系数只作用于获取，不作用于消耗（绝招/爆发结算不变），避免数值崩坏。
  • 心魔 ±K 有上下限：不超过 daoxinTier 单局合理区间，且单局净漂移幅度设 XINMO_CAP 上限。
  • 默认姿态 = 上回合姿态（减少无意义点击），但每回合可改。
  • UI 必须提供"敌 telegraph 大招"情境提示（复用 combat.js 意图预告），降低读盘成本——不新增"临时卡"。
不做的不引入牌库/抽牌/临时行动卡；不新增资源条；不重写 computeStats；不改变三键 CD 框架。

XINMO_K_DEF−2 / 回合−1 ~ −4守姿态心魔减量（安抚）。

调参纪律：任一旋钮改动后，必须重跑 §8 三个失败信号。单旋钮改动不超过 ±0.1 / ±1 步，避免耦合震荡。

6. 伪代码骨架

// === 新增：回合级姿态 (game_core / combat.js 状态对象上挂) ===
const STANCE = { ATTACK: 'attack', GUARD: 'guard' };
// 调参集中处（建议放 data_config.js 或 battle_resource 常量区）
const STANCE_CFG = {
  MOM_GAIN_ATK: 1.5, MOM_GAIN_DEF: 0.7,
  JINGLI_GAIN_DEF: 1.5, JINGLI_GAIN_ATK: 0.7,
  XINMO_K_ATK: 2, XINMO_K_DEF: -2, XINMO_CAP: 25,
};
// 玩家本回合选择（UI 按钮写入，默认继承上回合）
let currentStance = STANCE.ATTACK;

// === A. 气势获取点（combat.js 共 4 处）统一乘系数 ===
// 原： if (deal > 0) momentum = Math.min(MAX_MOMENTUM, momentum + 1);
// 改：
function gainMomentum(base){
  const mul = currentStance === STANCE.ATTACK
    ? STANCE_CFG.MOM_GAIN_ATK : STANCE_CFG.MOM_GAIN_DEF;
  return Math.min(MAX_MOMENTUM, momentum + Math.round(base * mul));
}
// 命中+1 → gainMomentum(1)；回复+2 → gainMomentum(2)；
// 克制+1 / 识破+2 同理经 gainMomentum 入口。

// === B. 经力获取点（battle_resource.js gainJingLi）乘系数 ===
function gainJingLi(state){
  // ...既有 ready / overflow 逻辑不变...
  const mul = currentStance === STANCE.GUARD
    ? STANCE_CFG.JINGLI_GAIN_DEF : STANCE_CFG.JINGLI_GAIN_ATK;
  const gain = Math.max(1, Math.round((state.jingLiGain||1) * 10 * mul) / 10);
  // ...既有 Math.min(max, old+gain) 不变...
}

// === C. 心魔双向口（每回合结算尾段，接入现有 s.xinmo）===
function applyStanceXinmo(state){
  const d = currentStance === STANCE.ATTACK
    ? STANCE_CFG.XINMO_K_ATK : STANCE_CFG.XINMO_K_DEF;
  const before = state.xinmo || 0;
  // 单局净漂移硬上限
  const net = (before - (state._xinmoStart||0));
  let next = before + d;
  if (net + d >  STANCE_CFG.XINMO_CAP) next = before; // 触顶不增
  if (net + d < -STANCE_CFG.XINMO_CAP) next = before; // 触底不减
  state.xinmo = next;
  // 实时重算 tier → 驱动 SEAL_MOD / curse / 结局权重
  state.daoxinTier = NDX.daoxinTier(state);
}

// === D. UI（每回合操作点前渲染单按钮 + 道心角标）===
// 复用 combat.js:911 已透传的 momentum / momentumTier；
// 新增透传 currentStance 与 state.daoxinTier 给 ui_panel。

9. 排期与依赖

  • P0 绑定心魔接负 sink：本 spec 第 6 项（applyStanceXinmo）就是心魔 P0 的战斗内落点；同时须先收敛"结局 4 套并存"（审计 §区域/结局），否则 B 信号无法验证。
  • 顺序先做 1–6（逻辑，可 headless 验证）→ 再做 7（UI）→ 跑 8 三信号。逻辑改动可在无 UI 下用战斗模拟回归。
  • 可独立提交全部为 surgical patch，不碰 canvas-bridge 与未提交改动，符合用户"手术补丁式提交"纪律。

附：为何否掉提案 A（"每回合从 3 张临时行动卡选 1"）

  • 降密度：现每回合可放 3 键（受 CD 约束），已比"选 1"密；改选 1 反而更空，与目标相反。
  • 抽离构筑：临时卡来自随机池，≠ 你的劫印/经文/法宝，直接撞 Fun Hypothesis（构筑是主角）。月圆之夜/杀戮尖塔成立，正因为你打的牌就是你 build。
  • 类比错位：暗黑地牢/为了吾王的"选 1"成立，因其本就低动作密度、每人每轮动一次；本作再降密度是逆操作。
  • 若坚持卡牌化，必须"从你的构筑抽牌且每回合多张"= 重做 DBG，成本巨大且稀释"构筑型 Roguelike"身份。不值得。
