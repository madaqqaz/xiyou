## 一、结论先行

开工前宠物系统**没有真源**。它不是「数据散三处」的整理问题，而是**四条死路叠加**：

| # | 死路 | 现象 | 状态 |
|---|---|---|---|
| 1 | `NDX.PET_LIB` 孤儿表 | 登记 6 只宠物，**无一存在于装备池** ⇒ `petById()` 对真实可获得的宠物 **67/67 全部返回 null** | ✅ 已修 |
| 2 | UI 读槽位常量 | `NDX.petSlotCap = 2` 与真源 `petSlotCapFor()` 并存，三处 UI 读常量 ⇒ 开到 4/6 格的玩家仍显示 2 格 | ✅ 已修 |
| 3 | `cfxPetSynergy` 前置门 | `if (!s \|\| !s.pet) return 0;`，但宠物是**装备**、存档从无 `s.pet` ⇒ 宠物协同真伤**恒为 0** | ✅ 已修 |
| 4 | 宠物成长线无写入点 | `st.petLv` / `s.pet.lv` 全仓无写入 ⇒ `PET_LV_SCALE` 恒取 Lv1 系数 **1.00**，Lv1→Lv10 的 2.35 倍**完全不生效** | ⏳ **待设计** |

⇒ 表象是「宠物数值弱」，实则是**宠物系统从未真正接通**。

## 二、真源地图（收口前 / 收口后）

| 职责 | 收口前 | 收口后 |
|---|---|---|
| 宠物本体 | ❌ 手抄表 `PET_LIB`（孤儿） | ✅ `EQUIP_POOL` + `CRAFT_POOL`（**惰性索引** `NDX._buildPetIndex`） |
| 槽位 | ⚠ 常量 `petSlotCap=2` + 真源 `petSlotCapFor` 并存 | ✅ 唯一真源 `petSlotCapFor` / 适配 `petSlotCapOf` |
| 羁绊 `PET_FETTERS` | `equipment_part3.js` | 保留（可达性已验证 7/7） |
| 进化 `PET_EVOLUTIONS` | `equipment_part3.js` | 保留（可达性已验证 12/12） |
| 协同真伤 | `combat_part2.js` + `data_pet.js` 双入口 | ✅ 唯一 `petSynergyTrueDmg` |

⚠ **加载顺序约束**：`data_pet.js`（index.html:278）早于 `equipment_part1.js`（:286），
模块求值期拿不到装备池 ⇒ 宠物索引必须**惰性构建**，不可在文件顶层建。

```js
NDX._buildPetIndex = function () {
  if (NDX._petIndex) return NDX._petIndex;
  const idx = Object.create(null);
  // 基础形态在 EQUIP_POOL，**进化形态在 CRAFT_POOL**（equipment_part1.js:485 起）
  [].concat(NDX.EQUIP_POOL || [], NDX.CRAFT_POOL || []).forEach(function (e) {
    if (e && e.slot === 'pet') idx[e.id] = e;
  });
  return (NDX._petIndex = idx);
};
```

> 🔑 **判据修正**：进化形态（如 `taigu_shanling` 太古山灵 / `taiyin_xinghu` 太阴星狐）落在
> `CRAFT_POOL` 而非 `EQUIP_POOL`。**只看 `EQUIP_POOL` 会误判「进化目标不可达」** —— 门禁首跑
> 就因此误报过一次，已把判据改为两池并集（宠物合计 67 只）。

## 三、数值体检（走 `game-numeric-design` 五特性模型）

### 3.1 生成：宠物从哪来

- 真实载体 = 装备体系。**67 只**（`EQUIP_POOL` 基础形态 + `CRAFT_POOL` 进化形态）。
- 分支 `branch` 分布：fox 5 / rock 4 / marten 3 / firefly 2 / deer 2 / wolf 2 / listen 2 / dragon / ape 2 / crane 3 / ni 27。
- ⚠ `ni: 27` —— 逆线宠物占近半数，普通线宠物类型偏少。

### 3.2 成长：等级系数

`PET_LV_SCALE(lv) = 1 + (L-1) * 0.15` ⇒ Lv1 ×1.00 / Lv5 ×1.60 / Lv10 ×2.35。

| 判定 | 结论 |
|---|---|
| 公式选型 | 属 skill 公式库的**线性变化**（适用「每点力量 +1 攻击」类），但对「等级→效果」更常用**幂函数（i<1 先易后难）** |
| 现值 | 线性 |
| 风险 | ⏳ **无写入点 ⇒ 恒 1.00**。数值表再漂亮，没有升级入口就是空转 |

### 3.3 变化：齐击边际递减 `PET_SWARM`

| n | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| 系数 | 1.00 | 1.70 | 2.20 | 2.50 | 2.75 | 2.90 |
| 边际 | — | +0.70 | +0.50 | +0.30 | +0.25 | +0.15 |
| 边际递减量 | — | −0.30 | −0.20 | −0.20 | **−0.05** | −0.10 |

- ✅ 满足「单调不减 + 边际递减」双条件（门禁 F2/F3 锁死）。
- ⚠ **递减量不规则**（−0.30 → −0.20 → −0.20 → −0.05 → −0.10），不是平滑等比/等差曲线，观为手填。
- 🔑 但该曲线是 **2026-09-24 用户拍板的设计要旨④**（「6 格收益落在组合多样性而非数值碾压」），
  **故不在本轮擅自调整** —— 是否改平滑，待用户拍板。

### 3.4 联系：协同真伤占比

`petSynergyTrueDmg = base × PET_SYN_PCT(0.12) × PET_LV_SCALE × petSwarmMult(n)`

| 上阵 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|
| Lv10 占比 | 28.2% | 47.9% | 62.0% | 70.5% | 77.5% | **81.8%** |

- ⚠ 满配下宠物协同真伤接近**本体伤害的 82%**，宠物事实上成了「半个输出源」。
- 但 `baseDmg` 口径需与连击/暴击路径对齐后方能定论 —— **待用户拍板是否设上限**（例如封顶 60%）。

### 3.5 消亡：进化与淘汰

- 进化劫难 `PET_EVOLUTIONS` 12 条，base 12/12 可达、target 全部可达 ✅。
- 二段进化（太古山灵 / 太阴星狐）走 `CRAFT_POOL`，**可达性已验证** ✅。

## 四、门禁 `scripts/_verify_pet.js`（22 断言 · 全绿）

| 组 | 断言 | 作用 |
|---|---|---|
| A | R0/A1/A2 | 真源：池可取到；`petById` 必须能解析池内**每一只**宠物（死真源防线） |
| B | B1/B2 | 羁绊 7/7 的 a/b 必须在池内（可达性，防羁绊永不激活） |
| C | C1~C3 | 进化 12 条的 base/target 可达性 |
| D | D1 | **源码级**：生产代码（含 `js/ui/`）不得再读槽位常量 `NDX.petSlotCap` |
| E | E1~E6 | 槽位函数：召唤流=6、无流派=2、不抛异常（常量当函数回归锁） |
| F | F1~F7 | 齐击单调/边际递减/越界安全；**F6/F7 锁死协同真伤不得被 `s.pet` 门吞掉** |

🩸 **反「假门禁」**：R0 取不到池即判失败，绝不用 `|| 空表 ⇒ 跳过` 空过
（历史教训：可达性断言依赖不存在的全局会静默跳过，把死数据养到线上）。
