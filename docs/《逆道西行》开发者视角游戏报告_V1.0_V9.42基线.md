## 二、技术架构解构

### 2.1 三端架构与适配层

```
                     ┌───────────────────────────────┐
                     │  核心代码库（三端共享，同一份）      │
                     │  demo/index.html               │
                     │  demo/js/*.js (165)            │
                     │  demo/css/style.css            │
                     └──────────────┬────────────────┘
                                    │  只调用 NDX.Platform
                     ┌──────────────▼────────────────┐
                     │  平台适配层 demo/platform/      │
                     │  index.js / browser.js          │
                     │  wechat.js / taptap.js          │
                     └──────────────┬────────────────┘
              ┌─────────────────────┼─────────────────────┐
              ▼                     ▼                     ▼
       浏览器 H5            微信小游戏               TapTap 买断版
     localStorage        wx.setStorageSync        本地存储 + 买断验证
```

**`NDX.Platform` 实测暴露接口**（7 个键，与 AGENTS.md §七·五 一致）：

```
name | version | storage | buyout | achievements | share | purchase
```

| 能力 | browser | wechat | taptap |
|---|---|---|---|
| 存档 | `localStorage` | `wx.setStorageSync` | 本地存储 |
| 支付 | 测试支付 | `wx.requestPayment` | **买断验证**（`verifyAndBoot` + `BUYOUT_KEY`） |
| 分享 | 复制链接 | `wx.shareAppMessage` | 系统分享 |
| 成就 | 本地记录 | 游戏圈 | TapTap SDK |
| 广告 | 测试广告 | 激励视频 | **无**（买断制硬约束） |

> **架构评价**：适配层抽象**方向正确**（核心只依赖 `NDX.Platform`），文件也齐（4 个，共 23 KB）。但**契约未被门禁强制**——`platform_test.js` 在 AGENTS.md §十一 标注为「已找到，未运行」，且当前环境中 `www/`、`android/`、`minigame/` 三个产物目录**均不存在**，说明三端发包链路已长时间未跑通。

### 2.2 加载链与性能（核心风险）

| 项 | 实测 | 判断 |
|---|---|---|
| `<script src>` 标签数 | **164** | 每标签一次 HTTP 往返（HTTP/1.1 下 6 并发 → 至少 28 轮） |
| 打包 | **无** | 无 webpack/rollup/esbuild，无 bundle |
| 构建步骤 | **无** | 双击 `index.html` 即玩（设计约束，见 AGENTS.md §一） |
| CSS | `style.css` **778 KB** 未压缩（另有 `style.min.css` 557 KB） | 单文件 CSS 解析成本高 |
| 字体 | 4 个 woff2，**2.4 MB** | 中文字体子集化，但仍是首屏大件 |
| Service Worker | `sw.js` 已实现预缓存 + 策略分级 | **工程正确**，可显著改善二次访问 |
| PWA | `manifest.json`（`display:fullscreen` / `landscape`）齐备 | 可安装、可离线 |

**三重叠加效应**：

1. **164 次请求**（移动端 RTT 高，弱网下串行等待明显）；
2. **778 KB CSS** 阻塞首次渲染；
3. **2.4 MB 字体** + `img/` 首屏图（`bg/` 单图 687 KB 目录）。

> **开发者结论**：这是**当前最大的上线阻塞项**。微信小游戏首包上限 4 MB、TapTap H5 首屏预算同样苛刻，而现状是「164 请求 + 778 KB CSS + 2.4 MB 字体」的组合，**首屏必超**。SW 只能救二次访问，救不了首访。
>
> **建议方向（不改架构、只加一步构建）**：保留「源码仍是零依赖原生 JS」这一约束，但**新增一个可选的发布前置步骤**——把 164 个 JS 按依赖序 concat + terser 成 1 个 `bundle.js`（微信发布指引里其实已有 `bundle.js` 概念，早期包体 1.4–1.78 MB），CSS 走 `style.min.css`，字体按需子集。这与 AGENTS.md §一「不引入构建工具」存在张力，**需要用户拍板是否开一个例外的「发布构建」口子**。

### 3.2 六道体系（核心抉择轴）

六道既是**叙事分支**，也是**成长轴**，也是**掉落偏置**——三合一。

| 道 | 主属性（唯一真源） | 产出签名 | 代表英雄本命 |
|---|---|---|---|
| **渡** | 气血上限（maxHp） | 赐（经文、赐珠、赐冠） | 唐僧 |
| **战** | 攻击（atk） | 料（装备） | 沙僧 |
| **缘** | 防御（dr + mdef） | 伴（随从、羁绊、宠物） | 八戒 |
| **隐** | 闪避（eva） | 路（闪避装、绕行、避劫） | 白龙马 |
| **夺** | 吸血（lifesteal） | 物（法宝、剥材） | 悟空 |
| **逆** | 最终伤害（finalDamage） | 反（逆道经文、逆道随从） | — |

> **设计亮点**：六属性落在**血/攻/双防/闪避/吸血/终伤**六个互不重叠维度（V9.27 修正了「夺/逆同取反伤」的重叠）。「走哪条道＝堆哪条属性＝拿哪类产出」三线合一，认知负担低。
>
> **待落地**：§2.1 标注 `SEAL_DAOTU` 中夺/逆的 `stat` 仍是 `reflect`，需重映射为 `lifesteal` / `finalDamage`，并新增 `finalDamage` 结算管线。**这是内容与代码尚未完全对齐的一处**。

## 四、系统深挖（引擎机制真值）

> 本节的每一项都是**代码事实**，由门禁断言锁死。它们是本项目技术含金量最高的部分。

### 4.1 战斗内核与编队引擎

- **伤害流水线**：`combat_part1.js` 的 `playerAttack()`；三键变种/状态只在**手动三键 + `applyActiveIntervention`** 路径生效，但 V9.33 起**自动路径也消费经位 `mod`**。
- **编队引擎** `combat_squad.js`：`calcCombatSquad` 接管多怪战；**Boss 不编队**。
- **阶段结构**：阶段一（主怪 + 溅射）→ 主怪死亡 → **阶段二（点杀）**。**阶段二不施加 on-hit**。
- **行动序 = 编队序**（V9.38）：主怪先行 → 从怪按 `squad` 下标升序**逐一出手**，每只独立判定；产出 `roundsDetail[].squadActs=[{ord,idx,name,kind,dmg,cum,st,tag}]`。
- **⚠ 收口铁律（V9.37/9.38）**：`res.squad.length > 1` 时 `_resyncFight` / `applyDamageReduction` **必须透传或跳过顶层反推**——编队战顶层 `playerHpLeft` / `win` **唯一由 `calcCombatSquad` 收口**，且必须跟随末回合 `pHpAfter`（`NDX._syncSquadTop`）。
  - **原因**：主怪亡后有「阶段二点杀」回合，按主怪死亡点切片会截掉点杀回合，末回合反推会把玩家误判阵亡并覆写 `win`。
- **aoe 语义**：`aoe` = 「附加怪物最大生命 8% 真伤」；**真群伤**由编队引擎提供（`veil-mantra` 经位 `aoe 0.6` 溅射 + 群伤 60%/顺手 12%）。

### 4.2 状态与层数系统（V9.39 → V9.42 三轮迭代）

| 版本 | 语义 | 存储 |
|---|---|---|
| V9.39 | 层数 = **浓度**（N 层 = N 倍 DoT，共享一个剩余回合计数） | `sec.st[k]` 单值 + `sec.stk[k]` 层数 |
| **V9.41** | 层数 = **条数**（每层各持剩余回合，独立到期） | `sec.st[k] = [{t, born}]` |
| V9.42 | 稳态层数 = `min(cap, poolRounds)` | `rounds`（主怪）与 `poolRounds`（从怪池）解耦 |

- `SEC_STATUS` **7 种**：poison/burn/sunder/slow/weaken/stun/silence；`cap`：poison/burn 5、sunder/slow/weaken 3、stun/silence 1。
- **逐层独立计时规则**：层记 `{t, born}`，存活条件 `(round - born) < t` → **施加当回合不计时**。
  - **为什么必须这样**：若沿用「回合末无条件递减」，`rounds=2` 的层在施加当回合就被减掉 → 稳态恒 1 层，**叠层功能直接被抹掉**。
- **回合内顺序**（V9.41 重排）：**剪除到期层 → on-hit 施加 → DoT → 溅射 → 从怪行动**，使「可见层数 ≡ 生效回合数」。
- **⚠ 可观测性铁律**：阶段二不施加 on-hit → 战斗末态 `squad[].stk` **恒空**。层数**只能看逐回合快照** `roundsDetail[].squadActs[].st`。

### 4.3 伤害记账：逐乘区 + 最大余数法（V9.39）

- **段列表** `_segList`（`hit` = 物理非暴击 + 法伤；`crit` = 物理暴击增益）+ `_scaleSegs(mulF)`。
- **9 处乘区**统一缩放全部段：`bossMul / tianting / engine.multi / oldWound / paradox / chaos / rend / berserk / GLOBAL_DMG_MUL`。
- 真伤 / 连击段经 `_pushSeg` 追加，**不缩放**。
- **段值以最大余数法对齐 `_finalDeal`** → **段和 ≡ `deal`（恒等，非近似）**；`segs` < 2 段时为 `null`（退回旧单段路径）。
- **累计血量传播（V9.34）**：`roundsDetail[].pHpAfter/mHpAfter` 是逐回合**累计**值，顶层取末回合。**一切 post-hoc 单点修正必须经 `NDX._bumpHp(res, list, fromIdx, key, delta)` 向后传播**，否则对最终胜负无效。

> **开发者评价**：最大余数法做伤害分段对账，**是银行级的分账做法**。它保证了「总伤害」与「分段飘字之和」严格相等——这类不变量在游戏里极少被认真对待，但它是**演出可信度的地基**（玩家会加总飘字）。

### 4.6 门禁运行器（V9.40 重建）

**背景**：沙箱内**一切子进程创建均 `EBUSY`**（node / git / cmd 实测全废）→ 旧版靠 `spawnSync` 把 42 项**全判 FAIL**（`exit=null`）。

**现在**：`spawnUsable()` 探测 → 失败则 **in-process vm 回退**（每门禁独立 vm 上下文 + 上下文内 CommonJS 加载器）。

**过程中挖出的两个真坑**（已写进门禁与文档）：

1. **vm 全局词法 TDZ 遮蔽**——门禁顶层 `const NDX = global.NDX` 会在**全局词法环境**建绑定，且整段求值期处于 TDZ → 被加载模块裸读 `NDX` 抛 `ReferenceError`。演进证据：host require **19/42** → 上下文加载器 **27/42** → 门禁自身也经模块包装 **39/42** → 42/42。
2. **shebang**——3 个门禁首行 `#!/usr/bin/env node`，手写包装不剥 → `SyntaxError`；`prep()` 剥 BOM + shebang 后 **42/42**。

> **结论**：**比 TapTap 更远**。`minigame/` 目录消失意味着打包链路已断。若要走微信路线，**需重建 Canvas 引擎承载 + adapter + 分包策略**——这是一笔独立工作量。

### 6.3 PWA / 浏览器（最接近就绪）

| 项 | 现状 |

| `sw.js` | 预缓存 + 4 类缓存策略（image/font/script/audio）资源分级 |
| 离线 | 支持 |
| 双击即玩 | 支持（`index.html`） |

> **结论**：**浏览器 H5 / PWA 是当前唯一可立即交付的形态**。建议先在自有域名上线 PWA 做小规模内测，把首屏体积与手感问题在真实设备上打掉，再谈 TapTap 提审。
