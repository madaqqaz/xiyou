> **性质**：A1 设计（路线图批次 A 第 1 步）· ✅ **已落地并升为真源**（2026-09-25 拍板「按你的设计全部执行」；§九 = A1 落地回执 · **§十 = P3 收口：十流派全量 + 驱动源改配装**；文件名不改，内文 **v1.2**）
> **上游**：系统整合路线图 v1.0（批次 A1）· 四系统复核骨架 v1.0 §3.3 · 职业与隐藏职深度补齐 v1.0（N1-1~N1-4）
> **实读基线**：V9.51 · `data_trials.js`（HIDDEN_JOBS 45 / JOB_STYLE 45）· `data_skill_variant.js`（ULT_STYLE_MOD 10）· `combat_active.js`（三键 512 行全读）
> **一句话结论**：**不是缺设计，是缺接线 + 缺套路层。** 10 个流派大招里 **4 个的机制字段是死字段**（写了没人读），这是「深度不够」的第一根因；L3 套路层是第二根因。

## 〇、目标框定（game-design-goal-framing）

**Goal statement（目标陈述）**
> 通过给 45 个隐藏职补上 **L3 套路层（职业改变"我怎么打"）** 并修复 4 条流派大招的断线，使「隐藏职业」从**称号+数值**升级为**玩法路线**——玩家转职后三键操作、资源循环、装备/经文取舍都发生可感知变化；以「同一英雄不同隐藏职，通关录像看得出操作差异」为验收信号。

**Purpose（为什么）**
1. 用户判定「深度不够」——但根因不是内容少，是**职业不改变玩法**
2. 45 条隐藏职是内容量最大的系统之一，却**无法支撑多周目差异**
3. 与「路线配装 BD」主玩法**脱节**——BD 只由装备/经文决定，职业没参与

**Fit（怎么接）**
- 职业成为 BD 的**第三根支柱**：路线（六道）× 装备·经文 × **职业**
- 三键是唯一出口：L3 只改 `act` 原语，**不改战斗架构**（`calcCombat` 一次性预结算不变）
- 复用现有 10 流派标签，**不扩标签、不新增美术、不新增职业**

**Success criteria（成功标准）**
| 侧 | 信号 |
|---|---|
| 玩家侧 | ① 能一句话说清"我这个职业该怎么打" ② 同英雄不同隐藏职的操作序列可区分 ③ 出现"XX 流怎么配"的讨论 |
| KPI 侧 | ① 单周目转职率 ② 多周目**换流派**重玩比例 ③ 转职后三键使用分布变化（可埋点） |

**Constraints（约束）**
- 不改战斗架构（逐回合决策不可行）
- 不新增美术、职业、流派标签
- MVP 只做 3 个流派
- 外围 `skill_*.js` 只读总表，不得持有倍率常量

## 一、诊断：为什么"深度不够"（实读，非推测）

### 1.1 三层现状

| 层 | 内容 | 现状 | 玩家感知 |
|---|---|---|---|
| **L1 数值层** | `effect.bonus`（hp/atk/dr/matk/eva/spd/cri…） | ✅ 45 条全有 | 「变强了一点」 |
| **L2 机制层** | `effect.passive`（`buddha_def`/`reverseScale`/`empty`/`glutton`/`restored`/`mReflect`/`sunder`/`chaos`…）+ 大招变体 | ✅ 有 | 「多了个被动」 |
| **L3 套路层** | 职业改变**三键形态 / 资源规则 / 适配取舍** | ❌ **完全没有** | — |

### 1.2 🔴 第一根因（本轮新挖，比 L3 缺失更硬）：4 条流派大招是**死字段**

`ULT_STYLE_MOD` 10 条 → `applyUltVariant` 写入 `act`，但 `applyActiveIntervention`（唯一消费端）**不读**其中 5 个字段：

| 流派 | 写入字段 | 战斗侧消费？ | 后果 |
|---|---|---|---|
| **reflect** 反伤 | `reflect: 0.35` | ❌ **零消费** | **反伤流派大招是空转的** |
| **summon** 召唤 | `summon: true` | ❌ **`act.summon` 全仓零命中** | 万兽朝元**从未真正召唤** |
| **evade** 闪避 | `evaUp: 0.20` | ❌ **零消费** | 影遁三袭的闪避提升无效 |
| **purify** 净化 | `cleanse: true` | ❌ 只有**宠物被动** `_pp('cleanse')`，非 `act.cleanse` | 大慈大悲净化无效 |
| drain 汲取 | `lifesteal: 0.25` | ⚠ 写了不读（战斗侧 lifesteal 走 `engine.lifesteal` 另一条线）；但同条 `heal: 0.55` 生效 | 吸血半边生效 |

**有效**的：`crit`（critHit）· `ward`（shield/dr）· `combo`（hits/spread/armorBreak/trueDmg）· `burn`（dot）· `reverse`（dmgMul/heal）

→ **10 个流派里 5 个有机制缺陷。** 这解释了为什么"转了职像没转"。

**修法**：`reflect` 改走**已生效**的 `guardCounter` + `counterPct` + `counterLifesteal`（`NDX.applyGuardCounter` 已存在，`data_skill_variant.js:163/199` 的业报/护法反击就是这么写的）；`summon` / `evaUp` / `cleanse` 需在 `applyActiveIntervention` 补消费分支。

### 1.3 第二根因：L3 缺失 —— 10 流派只有 1 个改了玩法

50 万条职（45）挂到 10 流派，但**只有 `summon` 有实打实的玩法改造**（大招召唤灵兽助战），其余 9 个**只改数值和被动**。

### 1.4 第三个观察：两名职的 `effect` 是空的

`驯兽师·百兽归心` / `逆兽师·百逆归心` 的 `effect: {}` —— 效果全部由御兽套共鸣 `applySetResonance` 承载。**这正好说明"套路层"才是它们的本体**，与 L3 设计方向一致。

## 二、三层模型（核心设计）

```
L3 套路层（新增）→ jobspec：三键形态 / 核心资源 / 适配 / 禁忌
L2 机制层（已有）→ passive + 大招变体（★ 先修 5 条断线）
L1 数值层（已有）→ bonus
```

**L3 套路层四要素**（每个流派一张卡）：

| 要素 | 说明 | 为什么必要 |
|---|---|---|
| ① **核心资源** | 这个流派"攒什么、花什么" | 让职业有**独立资源循环**，不再只是数值 |
| ② **三键改造** | 攻 / 诵 / 绝 各自变成什么 | 玩家操作层的可感知变化（**唯一出口**） |
| ③ **适配** | 推荐经文 / 装备 / 套装 | 把职业接进 BD，与装备·经文层耦合 |
| ④ **禁忌/弱点** | 明确的反面 | 有取舍，BD 才成立（避免"纯加法"） |

## 三、jobspec 数据形状（新增）

**落点**：新建 `js/data_jobspec.js`（单一真源），消费于 `combat_active.js` 三键分支。

```js
NDX.JOBSPEC = {
  summon: {
    style: 'summon', name: '召唤',
    res:   { key: 'pets', name: '灵兽', desc: '上阵灵兽数 × 等级（每只提供协同真伤）' },
    atk:   { petSynergy: true, trueDmgPct: 0.12 },        // 攻：灵宠协同追加真伤
    chant: { callPets: true, extraHits: 1, healPct: 0.15 },// 诵：唤伴——灵宠立即行动
    ult:   { style: 'summon' },                            // 绝：万兽朝元（已通，需补消费）
    fit:   { sutra: ['bond-mantra'], set: '御兽' },
    taboo: { name: '清场腰斩', desc: '灵宠全灭（n=0）则三键改造全部失效' },
  },
  // combo / reflect / crit / ward / drain / evade / purify / burn / reverse 同构
};
```

**统一消费入口**（新增）：`NDX.applyJobStyle(act, key, s, heroId)`
- 只改 `act` 上**已被 `applyActiveIntervention` 消费**的原语字段，不改 `dblBase`、不改 `act.kind/name`
- 未转职 / 未识别流派 → **零操作**（返回原 act，行为完全不变）

**三键插入位置（精确）**：

| 键 | 现有链路 | L3 插入点 |
|---|---|---|
| **atk** | `dblBase` → `_sa.atk` → `daoAtk` 攻式 → `applyHeroKeyFeel` → `_sutraVariant` → `applyJingSlotMods` → `finalizeActiveAct` | **`applyHeroKeyFeel` 之后、`_sutraVariant` 之前**（英雄身份 → 职业形态 → 经文数值） |
| **chant** | 构造 act → `_DAO_ADV` 道途进阶 → 金刚经 → 经力化雨 → `applyJingSlotMods` → `finalizeActiveAct` | **`applyJingSlotMods` 之前** |
| **ult** | `u.kind` → `_sa.ult` → 战意 → 道途加成 → `_sutraVariant('ult')` → `finalizeActiveAct`(→`applyUltVariant`) | **已通**，仅需修 §1.2 的 5 条断线 |

**优先级（冲突时）**：形态 > 数值 > 触发 —— 与《三键技能·经文变体综合设计》§一 一致。

## 五、MVP 三流派详细设计（可直接施工）

### 5.1 summon 召唤（3 职：驯兽师·百兽归心 / 逆兽师·百逆归心 / 女儿国·双随从）

| 键 | 改造 | 落点 | 复用 |
|---|---|---|---|
| 攻 | 灵宠协同追加真伤：`act.trueDmg += petSynergyTrueDmg(s, act.dmg)` | `combat_active.js` atk 分支 | ✅ `NDX.petSynergyTrueDmg` 现成（原仅连招时触发） |
| 诵 | **唤伴**：`act.hits = 1 + min(n,3)`、`act.spread = true`、`act.heal += dmg × 0.15` | chant 分支 | act 原语现成 |
| 绝 | 万兽朝元 | — | ⚠ **需补 `act.summon` 消费**（当前零消费） |

- **资源**：`n = NDX.petDeployCount(s)`（已单源，`data_pet.js`）
- **数值锚**：协同沿用 `PET_SYN_PCT 0.12 × PET_LV_SCALE(lv) × PET_SWARM(n)`（≤×2.90），**不新增倍率常量**
- **禁忌自然成立**：`n=0` 时三键改造全部失效

### 5.2 combo 连击（3 职：斗战明王 / 悟空的棒 / 持棒证道）

| 键 | 改造 | 说明 |
|---|---|---|
| 攻 | **叠层**：基础 `hits=2`；层数 ≥3 时 `hits=3` | 出手后 `stack+1`（上限 5） |
| 诵 | **保层**：`act.sBuff = { comboKeep: 2 }` + `act.heal += dmg × 0.12` | 不清层，并回血 |
| 绝 | **清算**：`act.dmg ×= (1 + 0.15 × stack)` | 出手后 `stack = 0` |

- **资源通道**：复用既有 `S.pending.*Overflow` 模式（`zhanYiOverflow` / `jingLiOverflow` 已在用，≤3 层）→ 新增 `S.pending.comboStack`
- **大招已通**：`ULT_STYLE_MOD.combo` = 千棍破阵（hits 5 / spread 0.18 / armorBreak / trueDmg 0.15）✅

### 5.3 reflect 反伤（4 职：卷帘镇妖 / 天蓬·负岳 / 八戒·护禅 / 卷帘·守舍利）

| 键 | 改造 | 落点 |
|---|---|---|
| 攻 | **蓄势**：`act.dr = 0.20`（本回合减伤）+ `act.trueDmg += dmg × 0.15` | act 原语 `dr` 已被 `applyDamageReduction` 消费 ✅ |
| 诵 | **反震强化**：`act.guardCounter = true` + `act.counterPct = 0.6` + `act.counterLifesteal = 0.30` + `act.sBuff = { ward: 3 }` | ✅ `NDX.applyGuardCounter` 现成 |
| 绝 | **万劫反噬（需修）**：把 `reflect: 0.35` → `guardCounter: true, counterPct: 0.9, counterLifesteal: 0.4, shield: 0.40` | `ULT_STYLE_MOD.reflect` 改写 |

> 关键：`counterPct` / `counterLifesteal` 是**已验证有效**的字段（`data_skill_variant.js:163` 业报、`:199` 护法反击均用此），而 `reflect` 是死字段。**修的是接线，不是设计。**
