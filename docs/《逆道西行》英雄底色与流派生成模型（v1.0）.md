## 〇、用户拍板原文（模型根定义，勿再误解）

> 「英雄设计是这样的，即**唐僧走法伤是最佳路线**，但法伤与其他的叠加就是**玩家自己的选择**，或者说是根据**掉落的装备与劫印**的综合选择，比如可以走盾，走加血，走法吸；**龙马也是如此，他只是闪避**，也可以走闪避堆爆伤，走吸血，走加血靠 debuff 磨。
> **英雄的特性只是底色，上面的建筑是装备与劫印与经文共同的叠加。**
> 可能是第一章掉落的装备让你决定做什么路线，也可能是掉落的经文让你有了倾向性，更或者是你坚持走某条路线而选择的相关装备等等。」

**三句话提炼**：

| # | 原则 | 含义 |
|---|---|---|
| 1 | **英雄 = 底色** | 只提供**基础数值倾向**（唐僧法伤基线高、龙马闪避基线高），不锁定玩法 |
| 2 | **路线 = 上层建筑** | 由**装备 + 劫印 + 经文**三者共同叠加决定，是玩家的选择 |
| 3 | **驱动发生在局内** | 第一章的掉落就可能定下路线；经文掉落给倾向；也可以硬坚持某路线去凑装备 |

## 一、诊断：现状与模型的三处冲突

### 冲突 1｜流派当前由「隐藏职」决定，即由**英雄气质**决定

`NDX.JOB_STYLE`（`data_skill_variant.js:215`）把 45 隐藏职硬贴 10 个流派标签，而标签是**按英雄气质**派的：

```js
purify: 弃经金蝉 / 弃经者 / 判官金蝉 / 金蝉了缘 / 定风金蝉 / 车迟·谕道 / 金蝉·谕经 / 罗刹·铁扇   // 8 个
evade:  白衣渡客 / 白龙·御水 / 白龙·渡河 / 逆鳞白龙 / 龙太子归 / 白龙·吐水                      // 6 个
```

后果（已在 `45隐藏职·英雄归属与流派总表 v1.0` 量化）：

| 英雄 | 职数 | 流派集中度 |
|---|---|---|
| 唐僧 | 8 | **purify 7** |
| 小白龙 | 6 | **evade 5** |

→ **同英雄的不同隐藏职，玩法完全相同**。而按用户模型，它们代表**不同的选择**（弃经 / 了缘 / 判官 / 车迟…），本应是**不同的玩法**。

### 冲突 2｜「定风金蝉」的语义被浪费

`定风金蝉` 的注册文案是「**风不能迷其眼**」（`data_trials.js:176`）—— 语义天然指向**命中/闪避**，却派给了 `purify`。这类「职名语义 ≠ 所派流派」的错配是系统性现象。

### 冲突 3｜流派只驱动大招，而大招是「英雄专属大招的下挂件」

现有链路：`隐藏职 → JOB_STYLE → 流派 → ① ULT_STYLE_MOD（大招，45/45）② applyJobStyle（三键，仅 10/45）`。

- 大招本身是「英雄大招」的变体，**同一英雄的 10 个隐藏职实际只有 1~3 种大招**；
- L3 三键改造只覆盖 3/10 流派 ⇒ **35 职（78%）转了跟没转一样**。

## 二、新模型（三层解耦）

```
┌─ L0 英雄底色（英雄固有，不可变）──────────────────┐
│  基础数值倾向 + 起手路线倾向（软偏置，不封死）        │
│  唐僧 → 法伤基线高；龙马 → 闪避基线高                │
└──────────────────────────────────────────────┘
                    ↓ 作为「权重先验」注入
┌─ L1 上层建筑（局内可变，玩家选择）────────────────┐
│  装备 + 劫印 + 经文 三者共同投票                     │
│  → 决定当前「玩法路线」                              │
└──────────────────────────────────────────────┘
                    ↓
┌─ L2 路线显影（结算）──────────────────────────────┐
│  10 条玩法路线 → 三键改造 + 大招变体 + 面板显影      │
└──────────────────────────────────────────────┘
```

**关键语义变更**：

| 概念 | 旧语义 | 新语义 |
|---|---|---|
| 10 流派 | **英雄/职业的标签** | **人人可走的玩法路线** |
| 隐藏职 `JOB_STYLE` | **决定**流派 | 给某路线**倾向加成**（收敛引导） |
| 英雄 | 决定你能玩什么 | 决定你**起步偏向**什么 |
| 流派来源 | 静态身份 | **动态加权投票**（随配装变化） |

> 这一改，**「唐僧 7/8 purify」不再是问题** —— 因为流派不再从隐藏职来。唐僧照样可以走盾/加血/法吸。

## 三、流派生成算法（与六道同构）

六道已有成熟的先例（`dao_system.js` 的 `daoWeightVector()` + `getMainDao()`）：**锚点 + 动态覆盖 + 软饱和 + 领先阈值**。流派直接复用同一套骨架：

```
styleWeight(style, s) =
      底色权重(hero, style)                    // L0 先验（小值）
    + Σ 装备权重(eq.style === style)           // L1 主来源（大值）
    + Σ 劫印权重(seal → 道 → 流派映射)          // L1
    + Σ 经文权重(sutra.styleTags)              // L1
    + 隐藏职倾向(jobStyleHint, 软饱和)          // L1（收敛机制，不封死）
```

**判定规则（三条硬约束）**：

| 规则 | 值 | 理由 |
|---|---|---|
| **起手锚点** | 前 1~2 区无装备倾向时，回落英雄底色 | 「底色」必须有可见效果 |
| **领先阈值** | 新路线权重需领先当前 **≥2** 才切换 | 防抖动（沿用 `getMainDao` 的领先≥2） |
| **软饱和** | `w = 1 + MAX·k/(k+HALF)` | 防止单件神装一票定音（沿用 `daoWeightVector`） |

**频控**：权重向量在「装备/劫印/经文变化时」重算并缓存，不每回合算。

## 九、落地回执（v1.1）

### 9.1 权重模型（`js/data_jobspec.js` 第九/十章）

```
w[style] = HERO_STYLE_BASE[hero][style]        × 1.0   // L0 底色（小权重先验）
         + Σ 劫印(SEAL_STYLE_MAP[seal.dao])    × 1.2   // L1（首项满分 / 次项 ×0.6）
         + 技能经(持诵位 SUTRA_KIND_STYLE[k])   × 1.5   // L1-BD 主动支点（见 §9.2·分流）
         + 被动经(持有位,合并后软饱和)          < 1.0   // L1 永远只微调
         + 隐藏职倾向(JOB_STYLE[jobConfirm])    × 2.0   // L1 收敛机制（不封死）
```

### 9.2 经文分流：技能经 / 被动经（V9.53 · 用户拍板）

> 用户原话：「经文分技能经与被动经」。
> 上一轮「经文一律 0.8、只微调」**作废** —— 那时技能经与被动经同权，等于把这条分流抹平了。

| | 技能经 | 被动经 |
|---|---|---|
| **位置** | 持诵位 `s.chantSutra`（**同时刻唯一**） | 其余已合成全本（`s.sutras` / `s.niSutras`） |
| **作用** | 替换 chant 形态本体（念什么经、使什么法） | **只叠属性，不换形态** |
| **路线权重** | 1.5（BD 主动支点） | 基数 0.5/部、**软饱和封顶 1.0** |
| **玩家感知** | 换一部 = 换一套诵经套路 | 家底越厚越钝，压不倒底色 |

- **判定口 `NDX.sutraConsumeKind(S, id)`**：**位置判定优先** —— `id === S.chantSutra` ⇒ `'chant'`，否则 `'passive'`。
  数据字段 `full.sutraKind`（缺省 `' chant'`）仅作新增经文的显式声明，用于将来补纯被动经（标 `'passive'` 即自动走被动分支，不改算法）。
- **软饱和** `w = CAP·n/(n+HALF)`（`CAP 1.0` / `HALF 4`）：n=1→0.20、n=4→0.50、n=8→0.67… 恒 < 底色 1.0，
  **任何时候都压不倒英雄底色，也压不倒一枚劫印（1.2）** —— 这是对「经文只能微调」的可执行保证。
- **去重**：被动经按路线去重（同向经不重复计权重）；持诵位那部**不重复计入**被动经。
- **待投背包**（`sutraBackpack`）尚未生效，不计入路线（与 `attr_calc` 生效口径一致）。

**判定（`NDX.currentStyle(s)`）**：纯确定性 argmax；**必须有非底色信号**（`sig[best] ≥ 0.5`）才成立，否则返回 `null`。

> 🔑 **「有信号才显影」是零副作用的关键**：存量玩家（未转职、无劫印、无持诵经）行为**逐字节不变**；
> 一旦有配装信号，路线立刻显影。

### 9.4 P3：十流派三键落地（原 3/10 → 10/10）

7 条新分支全部只写 `applyActiveIntervention` **已消费**的原语（零新常量、零架构改动）：

| 流派 | 攻 | 诵 | 绝（由 `ULT_STYLE_MOD` 承担） |
|---|---|---|---|
| **crit** | 蓄暴：dmg×1.12 + 暴击穿透真伤 | 必暴窗口：`sBuff{might}` + critHit | `critDmg` 折算为实际倍率（原只打标→无效） |
| **ward** | 凝盾：dmg×0.85 换 30% 盾 | 续盾：+55% 盾 + `sBuff{ward}` | 不坏金身（已生效） |
| **evade** | 游走：`evaUp 0.15` | 预兆闪避：`evaUp 0.30`×2 回合 | 影遁三袭（已生效） |
| **drain** | 噬血：heal +22% | 偷势：`armorBreak` + heal + `sBuff{might}` | 吞噬天地（已生效） |
| **purify** | 驱散：`armorBreak` + 真伤 | 净化：`cleanse` + heal | 大慈大悲（已生效） |
| **burn** | 挂火：`dot` 3 回合 | 爆燃：dmg×1.30 + `dot` | 业火焚天（已生效） |
| **reverse** | 逆血：dmg ×(1+0.5×残血比) | 以痛换力：真伤 + `ignoreDef` | 逆鳞血祭（已生效） |

> **关键约束**：`act.critHit` 在预结算架构下**只打标不改伤**（伤害已在 `act` 生成时算定）——
> 故暴击流必须**直接改写 `act.dmg`**，`critDmg` 亦然。
