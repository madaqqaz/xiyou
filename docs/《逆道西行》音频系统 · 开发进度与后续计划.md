## 0. 硬约束（设计边界，不可破）

* 单源 NDX + `file://` 双击 `index.html` 运行，零构建零依赖。

* 三端同步：浏览器 H5 / 微信小游戏 web-view / TapTap 买断（离线包）。

* 移动端 H5 为确认形态；俯视视角；三按键战斗挂钩「渡/逆」。

* `file://` 下浏览器禁止 `fetch` 外部音频 → 运行时**不能**远程拉流/stream 第三方曲库；授权曲只能打包进单源。

* 手术补丁纪律：新增/修改只收敛在 `js/audio/` 三文件 + `index.html` 三行，不污染并行会话；未改动 `NDX.sound / game.js / ui.js / combat.js`。

## 1. 音频架构总览（两层并存）

| 层               | 代码真源                                                                           | 形态                                                                            | 状态            |
| --------------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------------------------- | ------------- |
| 原层 `NDX.sound`  | `js/sound.js` + `assets/sound/*.mp3`                                           | v353 8 条自制 MP3（5 BGM：title/map/fight/boss/home + 3 SFX：click/levelup/worship） | **保留，未改**     |
| 增强层 `NDX.audio` | `js/audio/ndx_audio_engine.js` + `ndx_audio_config.js` + `ndx_audio_bridge.js` | 纯程序化 Web Audio 合成，零外部文件                                                       | **M1–M14 落地** |

**总开关** **`ADAPTIVE_AUDIO`（默认 true）**

* `true`：自适应引擎接管**动态音乐**（战斗强度 / 六道明暗 / Boss 动机变体 / 区域旋律身份），并 `setMusicEnabled(false)` 静默原 MP3 床音，避免双 BGM 同时响。

* `false`：完全回退原 `NDX.sound` 的 MP3 床音（一键回退，零风险）。

**设计原则**：动态交给程序化，成品感留给授权曲/后期英雄时刻；中间件纪律（事件驱动 / 参数驱动 / 总线树 / 语音预算+steal）保留，未来事件表与参数集可直接平移 Wwise JS。

## 2. 当前开发内容（M1–M14 已实现）

### M1–M6 基础引擎

* **M1** 总线树（Master/Music/SFX/UI/Ambience/VO）+ 手势解锁 + **Master 限制器**（移动端防破音爆音）。

* **M2** 合成器库：drone / 钟磬 `bell` / 噪声 `noiseHit` / 脉冲 `tone` / 拨奏 / **环境层**。本次 M14 又扩出 21+ 同名 SFX 基元（见 §2.7）。

* **M3** 量化节拍自适应音乐（96 BPM，CombatIntensity 分层 + 渡/逆调式）。

* **M4** 俯视 `PannerNode(HRTF)` + 遮挡 + **共享混响链**（metal/stone/cave 等）。

* **M5** 语音预算 + steal（移动 24/64 硬上限，桌面 64/256；UI/VO 高优先级豁免、溢出丢弃）。

* **M6** 过渡量化 + Boss 动机（渡=大三明亮 / 逆=小三阴郁）。

### M7–M10 工程加固与内容

* **M7** 数据驱动事件注册表（`playEvent` 查表，可 `registerEvent`）。

* **M8** 区域音景配置（`ZONE_TYPES` + `registerZone` + `setZone`：环境层 / 调式根音 / 混响交叉淡入）。

* **M9** 移动端健壮性（限制器 / 后台挂起恢复 / 设置持久化 / `ThreatLevel`+`RunDepth` 接入可听）。

* **M10** 诊断与真机自检（`getDiagnostics` / `selfTest`）。

### M11 内容层

* `audio_config.js`：17 区域 × 81 试炼的 Zone/Trial 纯数据配置，自动注册；六道（战/渡/缘/夺/隐/逆）节奏铺开。自检页可逐区域 / 逐试炼走查。

### M12 Boss 真实状态边沿 + 特殊试炼音景

* **Boss 不再依赖** **`music('boss')`** **路由**：桥接层每帧读真实 `s.pending.monster.boss`（或 `_boss`），入场边沿触发 `Boss_Roar`+`Boss_Enter`+金属混响；`NDX.bossNameForAct(act)` 记录真实关隘 Boss 名（17 关隘自动联动）。

* **特殊试炼音景**：config 加 `SPECIAL_TRIALS` 表 + `registerSpecialTrial` 运行时 hook（示例 act10 真假猴王→`mirror` 音景 + `event:/Trial/Mirror/Enter`）；引擎补 `Mirror`/`Secret` 事件；桥接命中临时切音景、离开恢复。

### M13 17 关隘 Boss 动机变体

* 引擎加 `BOSS_MOTIF_TABLE`（17 组 `off`+`flavor`，全部唯一）与 `BOSS_FLAVORS`（open/maj/min/sus/phryg 五种音程性格）。

### M15 长曲式 + 和声进行 + 多声部（本次新增，根治「单调」）
- **根因**：原 `_scheduleMotif` 只取 7 音固定序列（≈3.5 小节原样重复）、`_schedulePad` 每小节铺静止三音、探索态仅 `drone+pad+单旋律`，无曲式发展 → 听感单调（用户反馈「太单调」）。
- **长曲式（A→B→A'→C）**：`_formSection(bar)` 把音乐组织成 8 小节循环 **主歌 A → 副歌 B（更宽更亮变体 `ZONE_MOTIF_B` + 对位）→ 主歌变体 A2（加琶音）→ 桥段 C（琶音流动）**，约 20 秒一轮，替代 7 音短循环。
- **和声进行**：`CHORD_PROG` 每区域类型 4 个和弦，pad 按小节在 `root×PENTA_RATIO[deg]` 上走动（不再静止）——「复杂」的核心来源。
- **多声部织体**：新增 `_scheduleBass`（低音线律动）、`_scheduleCounter`（副歌五度对位）、`_scheduleArp`（A2/C 段分解和弦）；探索态由「drone+pad+单旋律」升级为「走动和弦 pad + bass + melody + 可选 counter/arp」。
- **开关与诊断**：`setMusicRich(true/false)` 一键回退原版单循环（便于对比/出问题回退）；诊断新增 `formSection` / `chordIndex` / `musicRich`。
- **验证**：WorkBuddy 工作区 `validate_audio.js` 新增 6 用例（曲式循环 A/B/A2/C、和弦 0..3 推进、新声部独立调用、预算不破、退化开关），全绿；node 桩 `voices=35/64`、`budgetOk=true`。

## 4. 设计决策与铁律

* **不用 FMOD/Wwise 运行时**：`file://` 下 `fetch` 外部 bank 直接崩。

* **程序化合成为主**：零外部文件、体积零、无限变体、三端一致、`file://` 安全。

* **手术补丁纪律**：不动 `NDX.sound / game.js / ui.js / combat.js`；全部收敛在 `js/audio/` 三文件 + `index.html` 三行；`ADAPTIVE_AUDIO=true/false` 一键回退。

* **移动端语音预算**：硬上限 + 优先级 steal + 溢出丢弃；UI/VO 高优先级豁免。

* **修桩不改正代码**：node 校验桩的缺陷只在桩里修，游戏代码本身保持零改动（此前所有校验失败均为桩缺陷，非引擎 bug）。
