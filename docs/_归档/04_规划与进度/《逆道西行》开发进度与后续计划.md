### 1.11 V8.6x 模块一·转职联动攻式（余弦显影）+ 组合门禁加固

**问题**：模块一核心「英雄攻式 + 主键显影」只随英雄走，不反映玩家当前**六道转职**；玩家转职到破军/贪狼等只拿到数值（`bonus.tier`），三键手法读不出自己的沙场派系。

**合同判据（关键取舍）**：转职的数值（破甲 / 吸血 / 多段 / 旧伤 / 闪避…）已全量经 `Z.tierBonus`→`computeStats` 的 `bonus.tier` 线性生效。若给每转职另设攻式**数值变体**，会与既有转职收益**双计**（例：破军 `sunder 0.3` 已生效，攻式再撕甲即两份）。故采用推荐主线——**转职联动攻式 = 余弦显影**：转职不改任何攻键数值，只把「当前最高转职阶的道之 `cls`」追加到攻键 `note`（`·破军/·贪狼/·玄武/·影遁/·逆命`），与英雄攻式（`·撕甲/·慈悲…`）、道途风格（`·连击(战)`）走同一条手感印迹，玩家从三键播报读到专场派系。备选（真数值变体）因双计被否。

**改动**：
- `combat.js` `applyHeroKeyFeel`：atk 分支末尾，若 `s.flags` 存在且 `NDX.ZHUANJIE` 可用，取 `currentTier(s, dao)` 最高的那一道（平手按遍历先到），`tier≥1` 时 `act.note += '·' + CLS[dao].cls`；无转职 / 经键不触。
- `scripts/_smoke_hero_keyfeel.js` 扩至 §7（**33/0**）。

**验收**：`_smoke_hero_keyfeel.js` **33/0**（新增§7：无转职不贴标签 / 战转职显影『破军』且数值不变 / 三标签共存互不覆盖 / 高阶道压过低阶 / 玄武三转 / 转职标签不污染经键）；`regression.js` **149/0**；`platform_test.js` **41/0**；`node --check` 全绿。版本戳 `combat.js?v=385`。
