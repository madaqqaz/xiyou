# 一、游戏全新介绍（产品定义）

## 1.1 一句话定位

> 《逆道西行》是一款**黑暗西游题材的单局 Roguelike 构筑游戏**：你不是去取经的，你是去**拆经的**——取经是献祭，真经是锁，灵山是笼。

```

   ↓

   ↓

   → 更强起点 → 再入单局  （上行螺旋）
```

## 1.5 差异化卖点（相对竞品的护城河）

1. **叙事解构的深度**：81 难全部重写暗面，且「渡/逆」双经文线真正改变结局——这在肉鸽品类里是**罕见的叙事权重**。
2. **六道作为构筑主轴**：战/渡/缘/夺/隐/逆 六道既是数值轴（`SEAL_DAO_BREAKPOINTS` 3/6/9/12 层阶段加成）又是叙事轴（音频共振、地区配额），**机制与叙事同源**。
3. **零依赖 file:// 直跑**：三端一致性极高，无构建即无构建失败——这在长期维护上是**真实优势**。
4. **自适应音频引擎自研**：17 区域音景 + 25 Boss 动机变体 + 四轴 RTPC，零外部音频资产（避开 `file://` fetch 墙），**在同类小游戏里几乎没有对手**。

### ⚠️ 根因：威胁侧校准「死区」（2026-09-09 重大修正）

开战前按玩家 Build 反推怪物属性，**两侧独立**：

```
血量侧：m.hp = _targetRounds × _baseDpr × _growthMul     （怪血 = 目标回合 × 你的输出 × 成长系数）
威胁侧：scale = clamp(承伤预算 × pressure / rounds / threatCur, 0.5, 1.5)；m.atk *= scale
```

#### ❌ 真正的残留缺陷：威胁侧钳位「死区」（方案 B 实现与意图不符）

### 修复方案 B+：γ 幂律部分补偿（2026-09-09 新增，推荐）

把硬钳位换成幂律软化，消除死区：

```js
// 现状（有死区）
scale = Math.min(1.5, Math.max(0.5, target / threatCur));

// B+（推荐）
const GAMMA = 0.45;
scale = Math.min(1.5, Math.max(0.5, Math.pow(target / threatCur, GAMMA)));
```

**数学性质**：净承伤 `= threatCur^(1-γ) × target^γ`。
γ=1 → 完全补偿（现状，死区内收益 0）；γ=0 → 不校准（难度崩坏）；**γ=0.45 → 平滑可感**。

**γ 取值实测对照**：

| dr | γ=0.60 | **γ=0.45 ★** | γ=0.30 |
|---|---|---|---|
| 0.10 | 2.9% | **4.0%** | 5.1% |
| 0.20 | 6.0% | **8.1%** | 10.2% |
| 0.30 | 9.2% | **12.4%** | 15.6% |
| 0.40 | 12.6% | **16.9%** | 21.0% |
| 0.60 | 16.9% | **26.5%** | 32.5% |

**推荐 γ=0.45**：每档减伤都有可见收益（死区消失），高段仍达 26.5%，难度仍受 `pressure` 总闸门控制。

## 4.5 竞品分析的三条硬结论

### 结论 1：**单局 8–12 小时 vs 赛道 3–5 分钟，这是战略级错配**
小游戏用户的典型场景是**通勤、摸鱼、碎片时间**（《无限轮回》严格控制在 3–5 分钟一局）。本作 81 难 × 5–8 分钟 = 8–12 小时，**不是"长"，是"跨数量级"**。

> 这不一定是死罪——TapTap 买断端可以接受长单局。但**三端必须分策略**：
> - **微信小游戏端**：必须提供「短局模式」（如 17 地区任选 3 个地区为一局，20–30 分钟），或**强化断点续玩**（当前已有存档，需验证跨天续玩体验）。
> - **TapTap 买断端**：保留 81 难完整长局，这是买断用户愿意付钱的价值。

### 结论 2：**题材踩中风口，但"微恐"的分寸要对标《无限轮回》**
《无限轮回》证明「中式民俗微恐」在小游戏端成立，且**明确摒弃血腥暴力与跳脸杀**，改用「异化日常空间 + 民俗符号暗示」。
本作「取经是献祭，真经是锁，灵山是笼」的黑暗解构，**在调性上高度契合**——但需确保：① 不过度血腥影响过审 ② 用**音效与文本**而非画面制造压迫（本作自适应音频引擎正好是强项）。

### 结论 3：**「构筑可感知度」是本作唯一真正落后于全竞品的硬指标**
所有竞品（尖塔遗物、剑冢神剑、暖雪流派、小丑牌叠乘）都在做同一件事：**让玩家看见自己的构筑在爆炸式成长**。

> **2026-09-09 修正**：本作**攻击向**成长已不落后（V8.58 方案 A 生效，atk×10 → 回合 2.65→1.38，缩短 48%）。
> 真正残留的差距在**防御向**：威胁侧钳位存在「死区」，dr 0→0.20 收益**精确为 0%**（详见 §3.1 实测表）。
> 玩家堆前 20 点减伤毫无反馈，而竞品的每一件防具都能立刻被感知。

**这一条的优先级仍高于任何内容补齐**——因为它决定的是"游戏好不好玩"，而非"内容够不够多"。
**当前最小解**：威胁侧引入 γ 幂律（γ=0.45），一行级改动即可消除死区。

### 4.7.1 H6 / H7 执行记录（2026-09-09 落地，含两条前提证伪）

> **方法论教训**：提案写完后必须先**验证前提**，否则会对着空气开工。本轮两条提案的前提均被证伪，实录如下。

#### ⚠️ 证伪 1：H6 一开始做错了方向

- **错误做法**：给 `NDX.BattleFX.damageNumber` 加分层逻辑。
- **发现**：该函数在 `ui_battle_fx.js` 之外**零调用**——又是一个孤儿函数。战斗飘字根本不走它。
- **真实路径**：`main_battle.js:_emitBattleFx` → emit `dmg-fly`（带 `kind`）→ `ui_misc_3.js:_fxSpawnDamage` → `class="damage-number damage-{kind}"` → 样式由 `css/style.css` 的 `.damage-*` 控制。
- **本作其实已有分级**（V9.x）：`hit / heavy / crit / shipo / burst / break`。

#### ✅ H6 实际落地：补高段，填视觉空白

真实缺口不是「没有分层」，而是 **`heavy` 阈值只有 18%，18%→100% 是一整片视觉空白**——打掉 19% 和打掉 50% 的怪血，飘字长得一模一样。

改动（`js/main_battle.js`）：
```js
var _mhp = (p.monster ? p.monster.hp : 0) || 0;
if (_mhp > 0 && _pt.deal >= _mhp * 0.55) _kind = 'devastate';   // 毁灭：一击过半
else if (_mhp > 0 && _pt.deal >= _mhp * 0.35) _kind = 'crush';  // 重创：三成以上
else if (_pt.deal >= Math.max(20, _mhp * 0.18)) _kind = 'heavy';
```
并同步把新档位接入打击反馈（否则会退化成普攻手感）：
- `devastate` / `crush` → 震屏 `break` 级、顿帧 `crit` / `break` 级、追加 `climax` 文案

样式新增（`css/style.css`）：`.damage-crush`（赤橙 38px + 抖动 + 描边）、`.damage-devastate`（52px 白热核心 + 双色光晕 + `devastatePop` 弹跳），并补 `fast-mode` 时长收敛。

**五档实测分布**（怪血 1000）：

| 伤害 | 占血 | 档位 | 视觉 |
|---|---|---|---|
| 150 | 15% | hit | 基础 |
| 190 / 340 | 19% / 34% | heavy | 橙 32px |
| 360 / 540 | 36% / 54% | **crush** | 赤橙 38px + 抖 |
| 560 / 900 | 56% / 90% | **devastate** | 52px 白热 + 爆开 |

> 回滚说明：我对孤儿函数 `damageNumber` 的增强**已完整回滚**，只保留一条注释说明真实路径，避免留下无用代码。

#### ⚠️ 证伪 2：H7 前提完全不成立

- **假设**：`ORDER_BLESSINGS`/`CHAOS_BLESSINGS` 是月圆之夜式「局内三选一祝福」，缺 UI。
- **实际**：这是**元进度赐福**（用资源升级等级，非局内三选一），且 `ui_misc_2.js:161–178` **已有完整面板**：名称 / 描述 / 实得% / 稀释提示 / 代价提示 / 升级按钮。**UI 不缺。**

#### ✅ H7 实际落地：修正一个会误导玩家的文案口径 BUG

在检查现有 UI 时发现真实缺陷：

```js
const total = bs.per * fv.orderLv * b.orderMult * 100;   // 「当前总加成」
...实得 ${total}%/级...                                   // 却标为「/级」← BUG
```
**Lv.3 的佛臂·力（每级 2%）会显示「实得 6.0%/级」**——玩家会以为每级 +6%，**高估 3 倍**；且面板完全看不到当前等级。这正属于根因 C。

修正（`js/ui/ui_misc_2.js`）：拆为「Lv.N」+「当前共 +X%」两个量，等级显式化；混沌侧补「现累计 -X% 防御」。

| | 修正前 | 修正后 |
|---|---|---|
| 秩序 | 攻击 +2%/级（实得 6.0%/级·稀释100%） | 攻击 +2%/级　**【Lv.3】当前共 +6.0%** |
| 混沌 | 攻击 +3%/级（实得 6.0%/级）／代价：-1%防御/级 | 攻击 +3%/级　**【Lv.2】当前共 +6.0%**／代价：-1%防御/级，**现累计 -2%** |

**校验**：`node --check` 全过；`validate_audio` 13/0、`validate_balance` 11/0 均未回归。
**未改结构**：不新增 DOM 节点、不新增 CSS 类，沿用既有 `bl-row/bl-name/bl-desc/bl-cost/bl-up`。

#### 本轮方法论沉淀

> **提案落地前必须先跑「前提三查」**：
> ① 目标函数**有没有人调用**（防对着孤儿函数造轮子）；
> ② 该功能**是不是已经存在**（防重复实现）；
> ③ 数据结构语义**是否与提案假设一致**（防张冠李戴）。
>
> 本轮两条提案若不查，就是两处无效功 + 一处文案 BUG 继续误导玩家。

# 五、不足分析（根因分类，非罗列）

> 按**根因**归类，而非按系统罗列。因为很多表面问题共享同一个根因，逐个修是浪费。

## 5.1 根因 A：**威胁侧校准「死区」**（影响 4 个系统）🔄 2026-09-09 降级重述

> **本条已从「成长全维度抹平」降级为「防御向死区」**。
> 攻击向已由 V8.58 方案 A 修复（实测单调可感）；血量向（maxHp）实测亦有效（占血比 11.91%→2.27%）。

**表现**：玩家前期堆减伤 / 闪避**毫无反馈**（dr 0→0.20 收益精确 0.0%），撞上 scale 上界 1.5 后才线性生效。
**根因**：`scale = clamp(target/threatCur, 0.5, 1.5)` 在开区间内使 `净承伤 = threatCur × scale = target` 恒定，与 `dr`/`eva` 无关——**实现与「保留 50% 收益」的注释意图不符**。
**影响面**：战斗、装备（防具词条）、劫印（减伤词条）、六道（隐/逆防御向）—— **占全部可玩系统约 1/4**。
**条件性**：死区只在 `raw` 起点 <1.5 时出现，即**前中期**。后期 `raw` 天然 >1.5，收益满额——所以这是**新手留存杀手**，而非全局问题。
**修复**：方案 B+（γ=0.45 幂律部分补偿），**一行级改动，零签名变更**。完整规格见数值手册 §2。
**性价比**：极高——改动最小、影响面最大、且修的是新手最敏感的区间。

## 5.2 根因 B：**单向经济无回收**（影响 3 个系统）

**表现**：商店节点 0.2%、黄金堆积、商店形同虚设。
**根因**：Faucet 多路持续投放，Sink 几乎为零。
**影响面**：经济、商店、宝库。
**修复**：提高商店节点占比（建议 **6–8%**，即每地区 1 个），并新增 2–3 个 sink（如：劫印重铸消耗、装备升阶消耗、寿命续命消耗）。

## 5.3 根因 C：**「感知层」缺失**（影响 5 个系统）

这是本次分析**新提炼**的根因——很多系统"做了"但"没被感知"：

| 系统 | 做了什么 | 为什么没被感知 |
|---|---|---|
| 六道 | 3/6/9/12 层阶段加成 | 无"境界/段位"标识，玩家不知道自己在哪一层 |
| 元进度 | 死亡解锁 1/2/4/8 + 劫灰坊 | 纵向恒 0，无"我比上局强 X%"的量化展示 |
| 地区 | 17 地区 + 地图皮肤 + 开场叙事 | 91% 通用事件 → 地区辨识度被稀释 |
| 转职 | ZHUANJIE 64 / 隐藏职 6 | 转职时刻无专门播报闭点，只留攻式标签 |
| 经文 | 203 片 / 22 全本 | 待投/已投/主道 ×1.5 的加成无统一来源追踪面板 |

**共同解**：补一个**「属性来源追踪 + 成长刻度」面板**（竞品里《万世剑冢》的灵根/功法面板就是干这个的）。**一份投入，同时解决 5 个系统的感知问题。**

#### 方案 A（血量侧）—— ✅ **V8.58 已落地，实测生效，本项结案**

const _growthMul = Math.pow(_atkGrowth, -0.35);   // ★ 已存在

实测（`scripts/_audit_rubberband.js`，探针已修至 V8.58 口径）：

#### 方案 B+（威胁侧）—— ✅ **已于 2026-09-09 落地（γ=0.45）** 🎉

**状态：已完成。** 落点 `js/data_config.js`（原 279 行），门禁 `scripts/validate_balance.js` **11/0 全绿**。

原问题：硬钳位 `clamp(raw, 0.5, 1.5)` 在开区间内产生死区（dr 0→0.20 收益恒 0%）。

```js
// 现（js/data_config.js:279，有死区）
scale = Math.min(1.5, Math.max(0.5, scale));

// 改为（γ 幂律部分补偿）
const GAMMA = (NDX.BALANCE && NDX.BALANCE.threatGamma != null)
  ? Number(NDX.BALANCE.threatGamma) : 0.45;
scale = Math.min(1.5, Math.max(0.5, Math.pow(Math.max(0.0001, scale), GAMMA)));
```

**落地后实测**（真实 `buildMatchFight`，diffLv=40）：

| dr | 修复前 | **修复后** |
|---|---|---|
| 0.05 | 0.0% | **2.2%** |
