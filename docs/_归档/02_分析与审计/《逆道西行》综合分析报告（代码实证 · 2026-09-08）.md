## 二、P0 — 阻断级（必须当轮收掉）

### P0-1 ★ 气势爆发结算产生 NaN（新发现，可复现）
`applyMomentumBurst` 在难度 ≥30、气势 tier=3 时把 `monsterHpLeft` 算成 `NaN`，且污染整个回合切片。

- **复现**（`scripts/_audit_nan.js`，regression 已验证可用的玩家形状）：
  ```
  diff=30 tier=3 _playerAtk=300 _playerMatk=160 before=0    after=NaN   <<< 回合切片含 NaN
  diff=50 tier=3 before=2149 after=NaN   <<< 回合切片含 NaN
  diff=81 tier=3 before=7855 after=NaN   <<< 回合切片含 NaN
  合计 6 场，NaN 3 场
  ```
- **根因**（已定位到唯一差异点）：`js/combat.js:1427`
  ```js
  const cur = r2.mTurn ? r2.mTurn.hpBefore : (r2.mHpAfter || 0);   // ← 缺回退
  ```
  当 `mTurn` 存在但 `hpBefore` 为 `undefined` 时，`undefined - burstDmg → NaN`，`Math.max(0, NaN) = NaN`。
- **对比佐证**：同文件其余 **5 处**同类结算全部有回退保护，唯独此处没有——
  - `:1205` `:1234` `:1320` `:1376` 均为 `mTurn ? (mTurn.hpBefore || 0) : ...`
  - `:2037` `:2045` 为 `mTurn && mTurn.hpBefore != null ? ... : ...`
  - 且 regression.js:79–93 已为同类"干预延续回合"专门加过回归断言，**本函数漏接**。
- **影响**：爆发后胜负判定 `win=false` 恒定、血条显示 NaN，属玩家可见的战斗结算损坏。

### P0-2 双向动态校准：目标回合对玩家构筑不敏感
开战前按玩家 Build 反推怪物属性，两侧独立：

- **血量侧** `js/game/game_combat_1.js:93-122`
  `_targetRounds = clamp(基础目标回合 / _buildPower)`，`_buildPower` 仅覆盖**暴击/反震/吸血**（`Math.min(2.5, …)`）。
  V8.58 已落地"方案A"：`_adjustedDpr = _baseDpr * _growthMul`，给 atk 成长留净收益 —— **改进已生效，方向正确**。
- **威胁侧** `buildMatchFight`（data_config.js）：`scale` 有钳位，实测在 **难度 ≥30 时全部触底 0.5**。

实测（`_audit_fight.js` PROBE2，type=mob / normal）：

| 难度 | 构筑 | scale | 怪物 atk | 目标回合 | 净承伤 |
|---|---|---|---|---|---|
| 10 | base | 0.649 | 60 | **4** | 91 |
| 10 | dr 0→0.8 | 1.400 | 129 | **4** | 92 ← 减伤被完全抵消 |
| 10 | atk×10 | 0.617 | 57 | **4** | 87 |
| 30 | base | 0.500 | 121 | **6** | 189 |
| 30 | dr 0→0.8 | 0.500 | 121 | **6** | **93** ← 触底后减伤反而生效 |
| 30 | atk×10 | 0.500 | 121 | **6** | 189 |
| 81 | base | 0.500 | 436 | **6** | 683 |
| 81 | dr 0→0.8 | 0.500 | 436 | **6** | **334** |
| 81 | hp×8 | 0.528 | 460 | **6** | 720 |

**结论（比旧结论更精确）**：
1. **目标回合恒定**：同难度下无论 atk×10 / 暴击 1.0 / 减伤 0.8，目标回合一律 4（d10）或 6（d≥30）——战斗节奏只由难度决定，不由构筑决定。
2. **减伤/闪避并非"全程被抵消"**：d=10 被 scale 完全抵消；**d≥30 因 scale 触底 0.5，减伤反而真实生效（净承伤减半）**。旧报告"恒定 ≈358"的结论需按难度分层修正。
3. **atk 与暴击投资不推高怪物强度**（scale 几乎不变），V8.58 方案A 已让 atk 成长换到净收益 —— 但**威胁侧钳位导致"变强"仍难被玩家感知**。

### P0-3 孤儿死系统：Exploration / LoopEnhance
`NDX.Exploration`（js/data_exploration.js）与 `NDX.LoopEnhance`（js/data_loop_enhance.js）定义完整，但**全仓外部引用 = 0**，UI 与主循环零消费。设计文档承诺的"探索未知""多层循环强化"未落地。

### P0-4 渡道 alt 路径 'chant' 永不可达
`js/data_quota.js:35` 定义 `渡:{main:{ferry:2}, alt:{chant:3}}`，但全仓 `addQuota(...'chant')` 命中 = 0 → "诵经 3 次"这条替代达标线永远无法累加。

### P0-5 资源体积 / 无构建流程 → 三端无法上线
img **207M**（icons 134M）、js **121 文件 / 3.9M** 串行加载、css **650KB 单文件**（17015 行）、无 package.json / 无打包。微信小游戏主包限 **4MB**，当前**不具备上线条件**。
