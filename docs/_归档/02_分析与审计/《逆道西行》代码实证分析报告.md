## 一、P0-1 双向动态校准：玩家成长完全失效

### 1.1 机制

战斗难度不是静态表值，而是在**开战前按玩家当前 Build 即时反推**的，两侧独立：

**血量侧**（`js/game/game_combat_1.js:80–160`，mob/elite/boss 三处同构）

```js
m.hp = Math.max(1, Math.round(_targetRounds * _baseDpr));
// _baseDpr = 玩家单回合基础伤害（含怪物减伤后）
```

怪物血量 = 目标回合数 × 玩家输出。

**威胁侧**（`js/data_config.js:248 buildMatchFight`）

```js
const tank = Math.max(1, inHp + hpRegen * (rounds - 1));
const threatPerRoundTarget = (tank * pressure) / rounds;
let scale = threatCur <= 0.0001 ? 1 : threatPerRoundTarget / threatCur;
m.atk *= scale;   // 怪物体/愿攻击同步缩放
```

怪物攻击 = 玩家承伤预算 × 压力系数 ÷ 目标回合。

### 1.2 对照实验（`scripts/_audit_rubberband.js`，难度档 40）

| 投资维度 | 变化区间 | 系统响应 | **实际战斗结果** |
|---|---|---|---|
| 攻击力 atk | 300 → 3000（10×） | 怪血 2000 → 12800 | 实际回合 **恒定 4.65** |
| 减伤 dr | 0 → 0.80 | scale 1.279 → 2.797 | 每回合净承伤 **恒定 ≈358** |
| 闪避 eva | 0 → 0.50 | scale 1.432 → 2.106 | 每回合净承伤 **恒定 ≈358** |
| 血量 maxHp | 2000 → 16000（8×） | 怪攻同步放大 | 承伤占血比 **恒定 11.9%** |
| 暴击 cri | 0 → 1.00 | buildPower 1.00 → 1.50 | 回合 5.00 → 2.00（**唯一有效**） |

### 1.3 为什么减伤/闪避会 100% 失效

`threatCur` 已把玩家防御算进去，再被 `scale` 除回去：

```
physCur = m.atk × (1 - dr) × (1 - eva)
scale   = target / physCur
新 m.atk = m.atk × scale
净承伤   = 新 m.atk × (1 - dr) × (1 - eva) = target   ← 与 dr/eva 无关
```

数学上 `dr`、`eva`、`mdef` 被完全约掉。

### 1.4 影响

- 装备（301 件）、劫印（47 词条）、经文（22 渡 / 12 逆）、修炼的数值选择**不影响战斗结果**
- 肉鸽核心循环「构筑成型 → 割草爽感」在数值层不成立
- 玩家感知：打到第 60 难和第 10 难的手感一致，成长感缺失

### 1.5 设计意图与取舍（公平说明）

代码注释显示这是**有意为之**：

> 「使任何 Build 在所选难度档下都『扛得住而不必死、但威胁足够』」
> 「与旧版固定 3-5 回合的区别：玩家能明显感受到『我变强了，打怪更快了』」

设计者指望 `_buildPower`（暴击/反震/吸血）提供变强感。但实测显示：
- `_buildPower` **只覆盖次级词条**，主属性 atk 完全不在其中
- 上限钳在 2.5，且 `Math.round()` 阶梯化 —— 暴击率 0.15（常见值）仅换来 5 → 4.65 回合，**几乎无感**

**结论：意图（保节奏、防必死）合理，但代价（主成长维度全部归零）过大。**

### 1.6 建议（按激进程度）

| 方案 | 做法 | 代价 |
|---|---|---|
| A 保守（推荐先做） | 血量侧改用 `_enhancedDpr`（含暴击）且**给 atk 成长留 30–40% 净收益**：`m.hp = _targetRounds * _baseDpr * (1 + 0.35 * log(atk/baseAtk))` | 节奏轻微浮动 |
| B 折中 | 威胁侧 `scale` 上限降到 1.5、下限提到 0.5，让 dr/eva 投资保留部分收益 | 极端 Build 风险回升 |
| C 激进 | 恢复静态怪物表值，改用难度档 + 词条控制节奏 | 需重做数值曲线 |

## 五、P1-2 地区辨识度低

`NDX.pickEvent(act, s)` 的过滤口径是 `ev.region = [minAct, maxAct]`（**地区区间**，非难号），无 `region` 字段的事件为通用池。

| 指标 | 实测 |
|---|---|
| 事件总数 | 152 |
| 限定地区 | 94 |
| **通用（无 region）** | **58（38%）** |
| 单地区可出现事件 | 62–67 |
| 单地区**独占**事件 | 4–9 |

**推论**：玩家在车迟国（地区7）和狮驼岭（地区13）遇到的事件池，约 **92% 是同一批通用事件**。17 个地区的差异只由 4–9 条独占事件体现。

这解释了为什么内容量充足（81 难全覆盖、密度均值 13.84）但"地区特色感"仍弱。
