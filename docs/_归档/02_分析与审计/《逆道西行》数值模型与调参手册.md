## 1. 战斗数值主干

### 1.1 两条校准链路（务必分清）

```
【血量侧 · 方案A】 game_combat_1.js → Game.prototype.fight（mob 分支）
    决定：怪有多少血 → 战斗打几回合
    输入：玩家 buildPower、区域难度
    输出：m.hp

【威胁侧 · 方案B】 data_config.js:248 NDX.buildMatchFight
    决定：怪每回合打你多少 → 你会不会死
    输入：玩家 maxHp / hpRegen / dr / eva / mdef
    输出：m.atk、m.matk（就地写回怪物对象）
```

两者**同口径不同侧**：血量侧控制「长度」，威胁侧控制「压强」。

### 1.2 血量侧（方案 A，已落地）

```js
// js/game/game_combat_1.js
const _baseDpr = Math.max(1, /* 玩家基础每回合输出 */);
const _enh     = /* 加成后每回合输出 */;
const _bp      = _buildPower(st);              // 构筑强度（暴击/反震等）
const _atkGrowth = /* 玩家 atk / 区域基准 atk */;
const _growthMul = Math.pow(_atkGrowth, -0.35); // ★ V8.58 核心
const _baseR   = /* 怪基础血量 */;
const _tr      = Math.min(8, Math.max(2, Math.round(_baseR / _bp * _growthMul)));
m.hp = Math.max(1, Math.round(_tr * _baseDpr));
```

**`_growthMul = atkGrowth^(-0.35)` 的语义**：
- 玩家 atk 涨到 10 倍 → `_growthMul = 10^(-0.35) = 0.447`
- 目标回合压到约 44.7%，**但不会压到 0**
- 这是「部分补偿」而非「完全抵消」：保留约 `1/(1+0.35·log10)` 的成长感

**可调参数**：

| 参数 | 当前 | 作用 | 调大后果 | 调小后果 |
|---|---|---|---|---|
| 指数 `-0.35` | 0.35 | 成长转化强度 | 成长感更强、后期过易 | 成长感更弱、节奏拖沓 |
| `_tr` 上界 | 8 | 最长回合 | 战斗更长更肉 | 战斗更短促 |
| `_tr` 下界 | 2 | 最短回合 | — | 秒杀感强、无博弈 |

> 建议：若反馈「后期太脆皮秒过」，把 `-0.35` 调到 `-0.28`；若反馈「后期还是拖」，调到 `-0.42`。**单次调整不超过 0.07**。

### 1.3 威胁侧（方案 B，已落地但有缺陷 —— 见 §2）

```js
// js/data_config.js:248
const p0       = cfg.pressureFactor ?? 0.56;          // 难度基准压强
const slide    = Math.max(0, diffLv - 1) * 0.004;     // 高层滑升
const baseP    = clamp(p0 + slide, 0.30, 0.88);
const pressure = clamp(baseP + wobble, 0.25, 0.90);   // wobble = (rng()-0.5)*0.10

// 目标回合窗口
rounds = mob   ? clamp(round(3 + (diffLv-1)*0.15), 3, 6)
       : elite ? clamp(round(6 + (diffLv-1)*0.25), 6, 10)
       :         clamp(8 + round((diffLv-1)*0.30), 8, 20);

const tank = max(1, maxHp + hpRegen * (rounds - 1));
const threatPerRoundTarget = (tank * pressure) / rounds;

const physCur  = m.atk  * (1 - min(0.9, dr))  * (1 - min(0.9, eva));
const magicCur = m.matk * (1 - min(0.9, mdef));
const threatCur = physCur + magicCur;

let scale = threatCur <= 0.0001 ? 1 : threatPerRoundTarget / threatCur;
scale = Math.min(1.5, Math.max(0.5, scale));        // ★ V8.58 方案B
m.atk  = max(1, round(m.atk  * scale));
m.matk = max(1, round(m.matk * scale));
```

**`pressure` 的语义**：整场战斗你期望承伤 = `tank × pressure`。
`pressure = 0.56` 表示「预期打掉你 56% 血池」。这是**难度总闸门**。

| 参数 | 当前 | 含义 | 调参建议 |
|---|---|---|---|
| `pressureFactor` | 0.56 | 期望承伤占血池比 | 0.45=轻松 / 0.56=标准 / 0.70=硬核 / 0.85=劝退 |
| `slide` 系数 | 0.004 | 每关压强递增 | 81 难累计 +0.32（第 81 关约 0.88，撞上界） |
| `baseP` 钳位 | [0.30, 0.88] | 难度上下限 | 0.88 是「有解」保证，勿动 |
| `wobble` 幅度 | ±0.05 | 单局波动 | 调大会出现「运气局」 |
| `scale` 钳位 | [0.5, 1.5] | 威胁补偿强度 | **见 §2，建议改为 γ 幂律** |
| 回合窗口 | mob 3–6 / elite 6–10 / boss 8–20 | 战斗长度 | 与短局模式联动（见短局文档） |

## 2. ⚠️ 方案 B 的实质缺陷：钳位「死区」

### 2.1 问题陈述

方案 B 的**意图**（代码注释原文）：
> 玩家 dr/eva 翻倍时，怪物攻击最多只增加 50%，玩家保留约 50% 的防御力成长净收益。

方案 B 的**实际行为**：只要 `scale` 落在开区间 `(0.5, 1.5)` 内，
```
缩放后净威胁 = threatCur × scale = threatCur × (target / threatCur) = target
```
**恒等于 target，与 dr/eva 无关 → 玩家防御收益精确为 0%。**

「保留 50% 收益」只在 `scale` 撞上界 1.5 之后才成立。撞界之前是**死区**。

### 2.2 实测证据（真实参数：baseAtk=200.2 / baseMatk=79.7 / target=358.0）

脚本：`scripts/_audit_scaleB2.js`

|---|---|---|---|---|
| 0.00 | 1.279 | 1.279 | 358 | **0.0%** |
| 0.05 | 1.326 | 1.326 | 358 | **0.0%** |
| 0.10 | 1.378 | 1.378 | 358 | **0.0%** |
| 0.15 | 1.433 | 1.433 | 358 | **0.0%** |
| 0.20 | 1.493 | 1.493 | 358 | **0.0%** |

**玩家前 20 点减伤投资，收益精确为零。** 这解释了「堆防御没感觉」的体感来源。

> 死区是**条件性**的：当 `raw` 起点已 >1.5（后期怪强/玩家血厚），全程撞界、收益满额。
> 所以「防御无效」的反馈集中在**前中期**，后期反而正常 —— 这正是最伤新手留存的区间。

### 2.3 修正方案 B+：γ 幂律部分补偿

把**硬钳位**换成**幂律软化**：

```js
// 现状
scale = Math.min(1.5, Math.max(0.5, target / threatCur));

// B+ 建议
const raw = threatCur <= 0.0001 ? 1 : threatPerRoundTarget / threatCur;
const GAMMA = 0.45;                                  // ★ 新建可调常量
scale = Math.min(1.5, Math.max(0.5, Math.pow(raw, GAMMA)));
```

**数学性质**：
```
净承伤 = threatCur × raw^γ = threatCur^(1-γ) × target^γ
```
- γ=1：完全补偿（现状，死区内收益 0）
- γ=0：完全不补偿（无校准，难度崩坏）
- γ=0.45：承伤 ∝ threatCur^0.55 → 平滑可感

**γ 取值对照实测**：

| dr | γ=0.60 | γ=0.45 ★ | γ=0.30 |
|---|---|---|---|
| 0.05 | 1.4% | 2.0% | 2.5% |
| 0.10 | 2.9% | 4.0% | 5.1% |
| 0.20 | 6.0% | **8.1%** | 10.2% |
| 0.30 | 9.2% | **12.4%** | 15.6% |
| 0.40 | 12.6% | **16.9%** | 21.0% |
| 0.60 | 16.9% | **26.5%** | 32.5% |

**推荐 γ=0.45**：
- 每一档减伤都有可见收益（dr 0.2 → 8.1%），死区消失；
- 高段收益仍达 26.5%，防御流构筑成立；
- 难度仍受 `pressure` 总闸门控制，不会崩坏。

## 6. 调参工作流（强制执行）

1. **先跑探针**：`node scripts/_audit_rubberband.js` 看当前基线曲线；
2. **单点修改**：一次只动一个参数（多参数同动无法归因）；
3. **复跑探针**：对照修改前后表格；
4. **跑门禁**：`node scripts/validate_audio.js`（现有）＋建议新建 `validate_balance.js`；
5. **真机手感**：至少 3 局（前 / 中 / 后期各一）再定；
6. **记录**：写入 `docs/版本更新记录.md`（当前版本记录滞后 20 个戳，需补）。

> 铁律：**探针过时 ⇒ 先修探针**（如本次 `_audit_rubberband.js` 缺 `_growthMul` 的教训），
> 绝不因探针输出而修改正确的游戏代码。
