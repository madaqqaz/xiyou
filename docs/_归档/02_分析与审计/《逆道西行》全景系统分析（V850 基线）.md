# 《逆道西行》全景系统分析（V850 基线）

> 基于代码全量审读 + 多维度深度分析，涵盖架构、玩法、UI、数值、内容、市场六大基础维度，
> 以及从从业者、玩家、市场、竞品四个视角新增的十二个专业维度。
> 标记约定：🔴 P0 阻塞/高风险 · 🟡 P1 重要优化 · 🟢 P2 改善建议 · ⚪ P3 远期规划

## 第一部分：基础六维（V840 基线回顾与深化）

> 以下为 V840 整改意见书已覆盖的六个维度，此处做深化补充而非重复。

### 一、架构

**V840 已识别**：game.js 单文件膨胀、NDX 命名空间污染、存档脆弱性、模块拆分未完成。

**深化补充**：

#### 1.5 🟡 依赖链缺乏形式化验证

**现状**：`index.html` 中 56 个 JS 文件按序加载，依赖关系隐含在加载顺序中，无依赖图文档。

**风险**：任何文件顺序调整都可能引入运行时 `NDX.xxx is not defined` 错误，且难以排查。

**整改方案**：
- 生成依赖图：扫描所有 `NDX.` 引用，建立「谁依赖谁」的矩阵
- 在 `demo/scripts/` 新增 `dep_check.js`：启动时验证所有 NDX key 是否已定义，缺失则 console.error 列出
- CI 门禁：每次提交后运行 `dep_check.js`，依赖断裂则阻断

#### 1.6 🟢 错误边界缺失

**现状**：`game.js` / `combat.js` 中大量 `try-catch` 为空或仅 `console.log`，无用户侧错误反馈。

**整改方案**：
- 全局错误边界：`window.onerror` → 显示友好错误提示（黑暗西游风格文案：「天机崩坏，请重启此劫」）+ 一键重置当前节点
- 关键路径（战斗/存档/转职）的 catch 块必须包含用户可见的恢复操作

### 二、玩法

**V840 已识别**：新手认知过载、战斗节奏偏慢、死亡缺乏驱动力、81难差异化。

**深化补充**：

#### 2.5 🟡 英雄差异化体验不足

**现状**：5 英雄（唐僧/悟空/八戒/小白龙/沙僧）主道途不同，但核心战斗循环完全相同（普攻→技能→法宝），英雄个性仅在数值偏向上体现。

**整改方案**：
- 每英雄增加 1 个专属战斗操作（非被动）：
  - 悟空：「分身」— 本回合攻击两次，但下回合防御减半
  - 唐僧：「诵经」— 跳过攻击，下 2 回合法伤 ×1.5
  - 八戒：「吞噬」— 消耗 10% 当前血量，造成等额真实伤害
  - 小白龙：「化形」— 本回合闪避 100%，闪避后反击
  - 沙僧：「镇守」— 本回合减伤 +30%，反弹 15% 伤害
- 专属操作与英雄被动钩子联动，形成独特操作节奏

#### 2.6 🟢 地图路径策略性偏弱

**现状**：蛇形分支地图参考杀戮尖塔，但节点类型分布较均匀，缺乏「高风险高回报」的明确路径选择。

**整改方案**：
- 增加「禁地」节点：高难度但掉落金劫印/稀有装备
- 增加「因果」标记：选择某条路径后，后续 2-3 层节点类型受影响（如选妖道路径→后续精英概率 +30%）
- 地图预览：显示下一层 2-3 个节点的类型图标（不显示具体内容），增加策略规划感

### 三、UI/界面

**V840 已识别**：横屏适配、战斗视觉层次、地图动画、信息密度、五行可视化。

**深化补充**：

#### 3.6 🟡 首屏加载体验

**现状**：56 个 JS 文件（2.02MB）+ CSS（573KB）+ 图片（93MB）+ 音频（28MB），首屏加载无进度指示。

**整改方案**：
- 分层加载：核心 JS（data/combat/game/ui/main ≈ 800KB）优先加载，其余延迟
- 加载画面：水墨风格进度条 + 世界观文案轮播（「灵山终 · 万劫不复」等）
- 图片懒加载已部分实现（地图节点），扩展到立绘和背景

### 四、数值

**V840 已识别**：五行克制幅度、套装乘区叠加、六道平衡、怪物曲线。

**深化补充**：

#### 4.5 🟡 经济系统缺乏闭环验证

**现状**：金币获取（战斗/商店/宝窟）与消耗（商店购买/劫灰坊）的收支曲线未经模拟验证。

**风险**：
- 前期金币不足→商店形同虚设
- 后期金币溢出→无消耗出口
- 劫灰坊定价与坐化收益不匹配

**整改方案**：
- 编写经济模拟脚本：模拟 1000 局金币收支曲线
- 关键验证点：每章末金币余额 / 商店购买率 / 劫灰坊使用率
- 调整策略：引入金币消耗出口（装备强化/劫印重铸/佛经捐赠）

### 五、内容

**V840 已识别**：title 编码、注释损坏、国际化预留、补丁文件缺失。

**深化补充**：

#### 5.5 🟡 81难叙事深度验证

**现状**：`trials81.js`（102.6KB）包含 81 难数据，但需验证：
- 每难的 `dark`（黑暗独白）是否真正传达了「黑暗西游」的世界观？
- 抉择选项是否真正让玩家感到道德困境（而非简单的 A/B 奖励选择）？
- 前后难之间是否有叙事呼应（而非独立事件）？

**整改方案**：
- 叙事审查清单：每难至少 1 个「两难抉择」（无正确答案）
- 前后呼应：标注每难的 `narrativeLinks` 字段，指向前后关联的难号
- 玩家测试：收集 10+ 玩家的抉择数据，验证选择分布是否接近 50/50（偏斜 > 70/30 说明选项不平衡）

### 六、市场与运营

**V840 已识别**：社交传播、中期目标锚点、平台适配。

**深化补充**：

#### 6.4 🟡 缺乏数据驱动的运营基建

**现状**：无埋点、无漏斗分析、无 A/B 测试框架，所有决策依赖设计直觉。

**整改方案**：
- 轻量埋点方案（纯前端，localStorage 聚合 + 导出）：
  - 关键事件：首次战斗/首次坐化/首次转职/每章通关/流失节点
  - 漏斗：开始→第一章通关→第二章通关→...→通关
  - 流失定义：连续 7 天未打开游戏
- 数据导出：JSON 文件 → 玩家手动上传/分享（适配无后端架构）
- 基于数据的决策框架：流失率 > 40% 的章节 → 优先优化

## 第二部分：从业者视角（开发效率与工程品质）

### 七、音频体系

#### 7.1 🟡 音效覆盖严重不足

**现状**：`sound.js` 仅定义 5 条 BGM + 3 条音效（click/zhuanjie/worship），游戏中有 89 处 `NDX.sound.play()` 调用，但大部分音效 key 未在 `sound.js` 中注册。

**问题**：
- 战斗受击/暴击/破韧/克制等核心反馈无音效
- 法宝祭出/转职觉醒等高光时刻音效缺失
- 环境音（篝火/商店/宝窟）全无
- 音效与视觉动画不同步，削弱沉浸感

**整改方案**：
- 音效优先级矩阵：

| 优先级 | 场景 | 音效 | 预估数量 |
|--------|------|------|----------|
| P0 | 战斗核心 | 受击/暴击/闪避/破韧/克制/死亡/胜利 | 7 |
| P0 | UI 反馈 | 按钮点击/面板开关/选择确认/错误提示 | 4 |
| P1 | 系统高光 | 转职觉醒/法宝祭出/劫印获取/套装共鸣 | 4 |
| P1 | 环境 | 篝火/商店/宝窟/劫难/Boss 入场 | 5 |
| P2 | 地图 | 节点选择/路径确认/章节过渡 | 3 |

- 音效资源策略：AI 音频工具自制（与现有 BGM 同源），避免版权风险
- 音效触发与视觉动画同步：`sound.play()` 调用移入 `ui.js` 渲染层，与 CSS animation 同帧触发

#### 7.2 🟢 BGM 场景切换生硬

**现状**：5 条 BGM（title/map/fight/boss/home）切换时无淡入淡出，硬切导致听觉断裂。

**整改方案**：
- BGM 切换增加 500ms 交叉淡入淡出（Web Audio API `gain.linearRampToValueAtTime`）
- 战斗 BGM 在 Boss 战时增加鼓点/弦乐层（叠加而非替换）

### 八、性能与包体管理

#### 8.1 🟡 总包体偏大，首屏加载慢

**现状**：
- JS：56 文件 / 2.02MB
- CSS：1 文件 / 573KB
- 图片：812 文件 / 93MB
- 音频：16 文件 / 28MB
- **总计约 124MB**（未压缩）

**风险**：
- 微信小游戏首包限制 4MB，当前远超
- 移动端 H5 首屏加载 > 10s（4G 网络）
- TapTap 买断版包体过大影响下载转化率

**整改方案**：
- **短期（P1）**：
  - 图片压缩：WebP 格式 + 质量压缩（当前 PNG 可压缩 40-60%）
  - CSS 精简：573KB 单文件过大，按模块拆分 + PurgeCSS 去除未使用样式
  - JS 合并压缩：56 个文件合并为 5-8 个模块包（无需构建工具，手动 concat + minify）
- **中期（P2）**：
  - 按章节懒加载：第 N 章资源仅在进入第 N 章时加载
  - 音频流式加载：BGM 用 `<audio>` streaming，音效用 AudioSprite
- **微信小游戏适配**：
  - 首包仅含第 1 章资源（< 4MB）
  - 其余资源走 CDN 分包加载

#### 8.2 🟢 运行时性能未监控

**现状**：无 FPS 监控、无内存监控、无卡顿检测。

**整改方案**：
- 开发模式增加 FPS 计数器（`requestAnimationFrame` 时间差计算）
- 关键路径（战斗渲染/地图生成）增加耗时打点
- 内存监控：每 30s 检查 `performance.memory`（Chrome），超阈值告警

### 九、可测试性与 QA 体系

#### 9.1 🟡 自动化测试覆盖不足

**现状**：
- `demo/scripts/` 有 `smoke_hidden_jobs.js`、`cdp_test2.js`、`regression.js`、`platform_test.js`
- 覆盖：隐藏职条件 / 战斗数值 / 存档 / 平台兼容（共约 65 项断言）
- **未覆盖**：装备合成 / 劫印生成 / 81难抉择 / 命痕机制 / 佛经系统 / 成就解锁 / 经济系统

**整改方案**：
- 按系统补充测试模块：

| 系统 | 关键断言 | 优先级 |
|------|----------|--------|
| 装备合成 | 合成配方正确性 / 套装共鸣计算 / 材料消耗 | P1 |
| 劫印生成 | 品质上限 / 唯一条款 / 道途偏好 / 逆道封锁 | P1 |
| 81难抉择 | 命运倾向累加 / 隐藏职触发 / 佛经碎片掉落 | P1 |
| 命痕机制 | 上限 5 枚 / 渠道隔离 / 机制改写生效 | P2 |
| 佛经系统 | 碎片合成 / 拓印解锁 / 三结局判定 | P2 |
| 成就解锁 | 条件求值 / 跨周目持久化 / 命数门槛 | P2 |
| 经济系统 | 金币收支 / 商店购买 / 劫灰坊定价 | P2 |

- 回归测试门禁：每次提交自动运行 `node demo/scripts/regression.js`

#### 9.2 🟢 缺乏端到端自动化验证

**现状**：CDP 测试存在但未集成到日常流程，手动验收仍是主要方式。

**整改方案**：
- 将 `cdp_test2.js` 集成到 pre-commit hook
- 关键路径截图对比：战斗界面/地图/商店/劫印面板的截图基线，自动检测视觉回归

### 十、代码规范与可维护性

#### 10.1 🟡 编码损坏问题扩散

**现状**：V840 已识别 `zhuanjie.js` 注释编码损坏，`sound.js` 头部注释同样损坏（`闊虫晥妯″潃锛堥樁娈典竷`）。

**风险**：编码损坏可能从注释蔓延到字符串数据（如 `trials81.js` 的 `dark` 文案）。

**整改方案**：
- 全量扫描：`node -e "require('fs').readFileSync(f,'utf8')"` 逐文件检测非法 UTF-8 序列
- 优先修复 `sound.js` / `zhuanjie.js` 头部注释
- 长期：所有 JS 文件统一 UTF-8 无 BOM 编码

#### 10.2 🟢 JSDoc 覆盖率低

**现状**：核心函数（`fight()`/`computeStats()`/`offerSeals()`）缺乏 JSDoc，参数类型和返回值需读源码才能理解。

**整改方案**：
- 核心模块（data/combat/game）的公开 API 补充 JSDoc
- 优先级：`computeStats` > `fight` > `offerSeals` > `evalHiddenCond` > `renderBattle`

## 第三部分：玩家视角（体验与心理）

### 十一、新手引导与学习曲线

#### 11.1 🔴 新手引导碎片化，缺乏系统性

**现状**：
- `data_compound.js` 定义了「新手指引·前三难」复合节点，分授六道/油灯/战斗+劫印
- 教学以文字 banner 形式呈现（`teach-banner`），信息密度高但交互性低
- 15+ 系统在第一章同时暴露（V840 已识别），渐进解锁机制尚未实现

**问题**：
- 玩家首局平均停留时间可能 < 10 分钟（15 个系统同时呈现的认知负荷）
- 教学文字 banner 容易被忽略/跳过，无强制交互验证
- 缺乏「做中学」环节——玩家读完文字后未必理解系统

**整改方案**——**交互式教学系统**：

| 教学阶段 | 触发条件 | 教学内容 | 交互验证 |
|----------|----------|----------|----------|
| 第1难 | 首局自动 | 六道抉择 | 必须选择一道才能继续 |
| 第2难 | 首局自动 | 油灯（寿命） | 必须确认理解寿命消耗 |
| 第3难 | 首局自动 | 战斗+劫印 | 必须完成战斗并选择1枚劫印 |
| 第5难 | 首次获得装备 | 装备穿戴 | 必须穿戴1件装备 |
| 第8难 | 首次遇精英 | 精英战提示 | 弹窗说明精英与普通的区别 |
| 第15难 | 首次遇劫难 | 劫难抉择说明 | 必须阅读抉择后果预览 |
| 章末 | 首次通关章节 | 章节总结 | 显示本章收获 + 下一章预告 |

- 教学完成标记：`state.tutorial.done` 数组，已完成的教学不再触发
- 二周目跳过：`state.cycle >= 2` 时可一键跳过所有教学

#### 11.2 🟡 系统说明缺乏「一句话解释」

**现状**：每个系统的说明都是多段文字，玩家需要阅读 50-100 字才能理解一个系统。

**整改方案**：
- 每个系统增加 `oneLiner` 字段（一句话解释）：
  - 六道：「选一条路，走到底」
  - 劫印：「打赢选一个加成」
  - 命痕：「改规则，不只加数值」
  - 法宝：「关键时刻祭出来，扭转战局」
  - 五行：「克它，就多打四成」
  - 寿命：「油灯烧完，此局结束」
- 在首次遇到系统时，先显示 oneLiner，点击「详述」才展开完整说明

### 十二、无障碍与色觉友好

#### 12.1 🟡 色觉障碍支持不足

**现状**：
- 五行克制仅靠颜色区分（火红/水蓝/木绿/金白/土黄）
- 劫印品质仅靠颜色区分（白/蓝/金）
- 战斗飘字仅靠颜色区分（crit 金/hurt 橙/miss 灰/dodge 蓝/dot 紫/reflect 红/heal 绿/shield 黄）
- CSS 已有 `prefers-reduced-motion` 支持（4 处），但无 ARIA 标签

**整改方案**：
- 五行克制：增加方向箭头（↑克制/↓被克/—无关），V840 已提及但未实现
- 劫印品质：增加边框样式区分（白=细实线/蓝=粗实线/金=双线+星标）
- 战斗飘字：增加前缀图标（暴击=★/闪避=◆/治疗=+/护盾=■）
- ARIA 标签：关键交互元素增加 `aria-label` 和 `role`
- 色觉模拟验证：使用 Chrome DevTools 的色觉模拟模式测试

#### 12.2 🟢 键盘导航缺失

**现状**：所有交互依赖鼠标/触摸点击，无键盘快捷键。

**整改方案**：
- 战斗快捷键：1/2/3 选择劫印，空格确认，Esc 关闭面板
- 地图导航：方向键选择节点，Enter 确认
- 设置：Tab 切换选项

### 十三、玩家心理与留存设计

#### 13.1 🔴 「首次胜利」体验延迟

**现状**：首局通关需完成 81 难（9 章 × 9 难/章），预估 2-4 小时。肉鸽游戏的首胜体验是留存关键，2 小时无胜点会导致大量流失。

**整改方案**——**微胜利体系**：

| 微胜利 | 触发条件 | 奖励 | 预期时间 |
|--------|----------|------|----------|
| 首战告捷 | 首次战斗胜利 | 劫印 + 成就 | 2 分钟 |
| 初窥门径 | 通关第 1 章 | 英雄碎片 + 解锁 | 15-20 分钟 |
| 小有所成 | 首次精英战胜利 | 蓝劫印 + 成就 | 25-30 分钟 |
| 初悟道途 | 首次集齐 2 件套装 | 套装共鸣激活 | 30-40 分钟 |
| 破茧重生 | 首次坐化 | 劫灰 + 解锁劫灰坊 | 40-60 分钟 |
| 大道初成 | 通关第 3 章 | 解锁五行克制提示 | 60-90 分钟 |

- 每个微胜利都有：视觉庆祝动画 + 文案 + 成就记录

## 第四部分：市场视角（商业化与增长）

### 十四、商业化模型

#### 14.1 🟡 三端商业化模型未明确

**现状**：
- 浏览器 H5：免费，无广告无内购
- 微信小游戏：未明确（微信生态需广告/内购/分享激励）
- TapTap 买断版：买断制，无广告无内购（AGENTS.md 已明确）

**问题**：
- 三端商业模式不同，但核心代码共享，如何避免商业模式影响核心玩法？
- 微信小游戏的广告/内购如何与肉鸽体验兼容？
- 买断版定价策略未确定

**整改方案**——**三端分层商业化**：

| 维度 | 浏览器 H5 | 微信小游戏 | TapTap 买断版 |
|------|-----------|-----------|--------------|
| 核心体验 | 免费完整 | 免费完整 | 买断完整 |
| 变现方式 | 分享引流 | 激励视频广告 + 分享 | 买断定价 |
| 广告场景 | 无 | 死亡复活/劫灰翻倍/额外劫印 | 无 |
| 内购 | 无 | 无（避免 P2W） | 无 |
| 分享激励 | 无 | 分享获劫灰/解锁英雄 | 无 |
| 定价 | 免费 | 免费 | ¥18-25（参考同类） |

- **铁律**：广告仅影响「速度」不影响「结果」——看广告获得的劫灰/复活不改变核心数值平衡
- 微信小游戏广告位设计：
  - 死亡后「观广告续命」（1 次/局，仅限非 Boss 战）
  - 劫灰坊「观广告翻倍」（1 次/局）
  - 商店「观广告刷新商品」（1 次/局）
- 买断版定价参考：杀戮尖塔移动端 ¥25、怪物火车 ¥18、暗黑地牢 ¥30

#### 14.2 🟢 缺乏付费转化漏斗设计

**现状**：TapTap 买断版无试玩→付费的转化漏斗。

**整改方案**：
- 浏览器 H5 版 = 完整试玩版（前 2 章免费，后续章节需购买）
- TapTap 页面：嵌入 H5 试玩链接，降低决策门槛
- 买断解锁：一次性购买解锁全部 9 章 + 5 英雄 + 隐藏内容

### 十五、本地化与出海潜力

#### 15.1 🟡 零本地化基建

**现状**：
- 所有用户可见文案硬编码在 14 个 JS 文件中
- 无 i18n 框架、无 locale 目录、无字符串表
- 81 难的 `dark`/`intro`/`options.text` 虽然数据驱动，但无英文版本

**问题**：
- 出海需重写全部文案，工作量巨大
- 西游题材在海外有文化壁垒（需本地化叙事而非直译）

**整改方案**：
- **短期（P1）**：建立 `locale/zh-CN.js` 字符串表，各模块通过 `NDX.t('key')` 引用（V840 已提及）
- **中期（P2）**：优先英文本地化：
  - 81 难叙事：需「文化翻译」而非直译（如「六道轮回」→「Six Paths of Reincarnation」+ 术语表）
  - UI 文案：约 500 条，可分批翻译
  - 战斗数值：无需翻译
- **长期（P3）**：日文/韩文本地化（西游题材在日韩有认知基础）

#### 15.2 🟢 西游 IP 的文化壁垒与机遇

**分析**：
- **壁垒**：五行/六道/佛经/劫印等概念对非华语玩家有理解门槛
- **机遇**：暗黑西游的「反传统」叙事在海外独立游戏市场有差异化吸引力（类似《黑神话：悟空》的海外热度）
- **策略**：
  - 英文版增加「术语百科」系统（游戏内可查）
  - 营销重点放在「Dark Fantasy Roguelike」而非「Journey to the West」
  - 参考杀戮尖塔的出海路径：先 Steam EA → 社区反馈 → 正式版

### 十六、数据驱动与运营工具

#### 16.1 🟡 零数据埋点

**现状**：无任何用户行为数据收集，无法量化以下关键指标：
- 留存率（次日/7日/30日）
- 章节流失点
- 英雄/道途选择分布
- 平均单局时长
- 付费转化率（TapTap 版）

**整改方案**：
- 轻量级纯前端埋点（无需后端）：

```javascript
// 埋点事件定义
const TRACK_EVENTS = {
  game_start: { hero: '', cycle: 0 },           // 开局
  chapter_end: { act: 0, layer: 0, result: '' }, // 章节结束
  death: { act: 0, layer: 0, cause: '' },        // 死亡
  job_awaken: { hero: '', job: '' },              // 转职
  game_win: { ending: '', time: 0 },              // 通关
  session_end: { duration: 0, events: 0 }        // 会话结束
};
```

- 数据存储：`localStorage` 聚合，每 10 局自动导出 JSON
- 数据利用：玩家可在设置页查看自己的「行迹统计」（复用现有 `STAT_TOTAL` 基建）

#### 17.2 🟡 差异化优势与风险

**差异化优势**：
1. **叙事深度**：81 难抉择 + 善恶系统 + 三结局，远超同类肉鸽的叙事量
2. **构筑广度**：6 大系统交叉联动，构筑自由度高于杀戮尖塔的卡组系统
3. **西游暗黑改编**：独特 IP，在华语市场有天然认知度
4. **多周目长线**：佛经收集 + 隐藏职 + 三结局，多周目动力充足
5. **H5 零门槛**：浏览器即玩，无安装门槛

**差异化风险**：
1. **系统复杂度**：6 大系统对新手的认知负荷远超杀戮尖塔（3 系统），可能导致首日流失
2. **平衡难度**：6 系统交叉联动使数值平衡难度指数级增长
3. **内容消耗**：81 难虽多，但若差异化不足，玩家 3-5 局后可能感觉「换皮」
4. **视觉表现**：纯文字 + 立绘的演出力度远低于杀戮尖塔的卡牌动画
5. **社交缺失**：无排行榜/分享/对战，长线留存依赖单机内容
