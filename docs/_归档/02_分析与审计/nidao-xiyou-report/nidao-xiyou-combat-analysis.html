逆道西行 · 战斗系统专项分析

Rev.5 · 战斗深度诊断（回合时长 / 回合数 / 动画可读性 / 技能结构）· 竞品活检 + 改善提案 · 2026-09-06
结论先行（一句话）：战斗骨架已经成型且设计意图正确——气势系统是对《黑神话·棍势》的优秀回合制抽象、连招窗口与预输入缓冲都到位； 但存在三处 pacing 与一处可读性硬伤：① 早期强制手动 + 1x 锁定的节奏低谷；② FIGHT_TICK 注释/真值漂移（2000≠1300）； ③ 普攻砍半 + 装备滚雪球导致普通战斗回合数方差过大（4～12 轮）；④ 2x/3x 下位移与掉血时序靠两处硬编码同步，存在错位回归风险且无 hit-stop 兜底。 竞品学习的核心不是加系统，而是把"每个回合的决策分量"做厚、把"速度感"与"可读性"解耦。

二、回合时长分析

本作是玩家定速的回合制：每回合 = 玩家决策（不限时）+ 1300ms 演出。因此"回合时长"的瓶颈不是播放，而是早期无法加速带来的节奏低谷。

2.1 真实单回合耗时模型

场景单回合播放决策时间体感
普通战 @1x（前3地区强制）~1.3s玩家思考，无上限偏慢：6 回合≈7.8s 纯演出 + 思考
普通战 @2x（第5地区后）~0.65s同上舒适
Boss @1x（锁定）~1.3s含临阵祭宝操作点合理（需看清韧性条）

2.2 竞品节拍对照

游戏战斗形态单决策耗时对本品的启示
杀戮尖塔 StS回合制卡牌~瞬发（玩家定速）等待≈0，慢只因玩家犹豫 → 本品已接近
黑神话悟空实时动作连续无间歇不可比，但棍势节拍已被本品吸收
怪物火车 MT回合制网格~瞬发回合内反馈极快，靠布局决策
陷阵之志 ITB回合制 telegraph~瞬发敌人意图预告让"等待"变"规划"
哈迪斯 Hades实时 roguelite连续用 hit-stop / 屏震制造打击感
诊断：本品在"可加速期"（第5地区后）节奏健康；洼地是第1–4地区：强制手动 + 只能 1x。 玩家前 20 难被迫用最慢速度做最基础的操作，学习曲线与速度曲线反向——越新手越慢。竞品 StS/ITB 恰恰相反：前期轻、后期重。
提案 C1（低风险）：把 2x 解锁提前到第 3 地区（而非第5）， 或在强制手动期允许"演出中长按快进"（播放期间再点一次 = 跳过本回合演出）。不改变数值，只解耦"看懂"与"等待"。 rationale 前期玩家已学会三键，无需用慢速惩罚；加速降低弃游率。

核心问题：回合数方差由"装备滚雪球"决定，而非设计。 无装备时普通战 12 轮（偏长、拖沓），带装备时 6 轮（偏短、决策密度不足）。 StS 一局战斗约 10–15 回合且高度稳定——本品的方差才是体验问题，不是均值。

四、动画与可读性分析

本作有一条工程铁律（见项目记忆）：位移演出禁 CSS @keyframes，必须 JS 时间驱动 + !important 内联 transform， 因为 doRender() 每回合重建 .fb-arena，@keyframes 会被重建打断重播。这条约束本身正确（架构使然），但带来两个隐患。

4.1 两处硬编码时序同步风险

常量定义点风险
CHARGE_DUR=500main.js:1546位移(冲撞)与掉血(HP条)时序靠两处各自算，一旦一处改、另一处忘改 → 冲撞与掉血错位（项目记忆已记录此坑）
STRIKE_GAP_MS=1000main.js:1489
提案 C3（维护性）：把 CHARGE_DUR / STRIKE_GAP_MS / FIGHT_TICK 收敛到单一真源 （如 NDX.TIMING，与 FIGHT_TICK 同处），main.js 与 ui_misc_3.js 只读不写。 消除"改一处漏一处"的回归雷。不改任何视觉，纯重构。

4.2 2x/3x 下的可读性塌方

倍速通过 FIGHT_TICK/sp 同比压缩。@3x 时单回合 ~433ms，其中冲撞仅 ~167ms。 项目记忆明载"2x/3x 与下一回合重叠"风险——位移还没归位，下一拍已起。 且当前无任何 hit-stop（顿帧）/ 屏震来锚定打击瞬间（而哈迪斯/Hades 恰恰靠这个）。

提案 C4（高收益、低风险，且合规）：在暴击 / 气势三势爆发 / Boss 重击时插入JS 时间冻结 hit-stop。 项目铁律允许 steps()/闪白/抖动，hit-stop 本质是"暂停若干 ms 后继续"，属 JS 时间驱动范畴，不触碰 @keyframes 红线。 rationale 即使 @3x，关键一击也"卡一下"，可读性不塌；同时提供打击爽感（当前缺失的 juice）。

五、技能系统深度分析

5.1 连招：深但"隐身"

combat.js 的连招系统不浅：每3击必暴、streak 三档、有序 [combo,burst,pierce] ×1.25。 但自动模式 AI 只代点 atk/chant，绝招/法宝/爆发须手动（项目记忆确认）。后果：

  • 手动玩家能玩出 chain 深度 → 高上限；
  • 自动玩家永远体验不到这套深度 → 两套体验割裂。
提案 C5（体验统一）：给自动模式一个极简连招策略（如"每第3次 atk 切 burst 风格"）， 让挂机玩家也能偶发 chain，弥合体验割裂。手动玩家不受任何影响（仍可覆盖）。rationale 深度不该被"是否手动"剥夺。

5.2 诵经（chant）的填充感

chant 是三键之一，但作为"经文向 buff/防御"，与 atk 的取舍不尖锐——多数情况下"这回合该攻击还是该诵经"不是真决策， 而是"血量安全就攻击"的默认路径。它缺少一个明确的代价或独特收益。

提案 C6（机制活检）：参考 ITB 的"格挡/闪避二选一"与 Hades 的"冲刺=放弃攻击"， 把 chant 重定义为姿态切换：诵经 = 本回合进入"守势"（减伤 + 攒势加快，但跳过攻击）。 让三键变成"攻 / 守 / 绝"的真三角，每轮都是真实权衡。注意 此改涉及 resolveManualActive('chant') 与战斗结算， 需先确认 chant 当前全部下游效果再动手，属 P1 级改造。

5.3 气势爆发的"可感知蓄力"

气势系统是亮点，但攒势过程缺少 juice。黑神话里棍势条随连击肉眼可见地涨、到三势时角色发光。 本品 combat.js:883 已传出气势层级给 UI，但"层级跃迁"的反馈强度未确认（是否顿帧/音效/特效）。

提案 C7（低风险）：气势每跨一层级（1→3→5）触发一次轻量顿帧 + 金光 callout（复用现有 skill-name 金色 callout 通道）。 成本极低，却把"蓄力→爆发"的爽点从"数值"变成"感知"。
