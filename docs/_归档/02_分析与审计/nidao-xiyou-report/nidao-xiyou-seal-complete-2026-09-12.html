劫印系统完善 —— 三处内容落空与并行真源的收口

《逆道西行》· 落地报告 · 2026-09-12 · 承接「劫印来源真源收口」（同日），本轮以只读体检为入口，收掉劫印系统剩余的三处「有数据、无通路」缺陷

一句话结论：劫印系统主体（词条 47 条 / 六道阶段碑 / 结算链路 / 图标资产）健康无缺，但有三处「数据齐备却拿不到」：
① 篝火仪典 4 项中 3 项点击完全无响应（阻断级·玩家可见）；
② 红劫档位 47/47 数值齐备、有 label/配色/弃印定价，却无任何来源产出（沿「金3合1」合成链被砍后的断链）；
③ 白档会产出 val=undefined 的零收益废印，另有 attr_calc.js 里一份按不存在字段名实现的并行假真源。
本轮全部收口，并新增 2 道门禁（含一条反证断言证明守卫非永真）。

四、白档废印与并行假真源

4.1 白档产出 val=undefined 的零收益废印

「逐杀 / 焚天 / 流沙 / 金蝉 / 万象 / 逆鳞」为蓝金专属词条（无 white 档）。offerSeals 有品阶数值过滤，但 offerSealsAligned（战斗掉落实际走这条）没有——白档抽中即得一枚 val=undefined 的印，战斗里被 v = sl.val || 0 兜成 0 收益。

反证实测（用 git HEAD 版本覆盖运行时函数后同条件复跑）：

版本白档废印命中具体词条
修复前（git HEAD）326 次 / 去重 5 种逐杀、焚天、金蝉、万象、逆鳞（均 val=undefined）
修复后（当前工作树）0 次—

修法是双路口径统一：offerSealsAligned 补上品阶数值过滤（含空池回退链），与 offerSeals 同口径。该反证断言已固化进新门禁，证明守卫非永真。

4.2 calcSealBonus：形似真源、实为陷阱的并行实现

attr_calc.js 的 calcSealBonus 直接按 sl['maxHp' / 'cri' / 'lifeSteal' / 'atk' ...] 取字段，而真实 seal 对象只有 stat（加成目标）+ val（数值），直挂的附随字段名为 maxhp / crit / lifesteal → 零命中，对劫印本体恒返回 {}，仅道途阶段碑生效。任何后来者读这段代码都会误判「劫印不提供属性」。

处置：按真源口径重写为 stat → 目标字段映射（atk→atkPct、maxhp→hpPct、dr/mdef/eva 直通、crit/maxhp/lifesteal 附随），并加注释明确 战斗数值真源唯一在 combat.js computeStats，本函数只服务 AttrCalc 的调试/追踪接口，不得与真源分叉。战斗中实际结算链路本轮未改动（仍走 combat.js 真源，已验证 seal.stat 7 个分支 + mechanism → fateFlags 均在）。
