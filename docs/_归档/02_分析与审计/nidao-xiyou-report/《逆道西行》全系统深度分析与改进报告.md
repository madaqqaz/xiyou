# §1 核心循环（地区/难度/轮回）

## 实现事实
- `data_region_config.js` 唯一真源：17 地区、`TOTAL_TRIALS=81`、`MAX_COL=4`、每层 3-4 节点。
- 四档难度（data_config.js V8.40）+ `scaleRunMods` 逆道/渡道即时调压 0.55~1.6。
- 死亡 → `buildDeathReview` 归因复盘；轮回 = 劫印传承（引渡匣，法宝不传承）+ 轮回赐福（每点进度攻+1/血+2/减伤1%）。
- 地图为杀戮尖塔式网状分叉：`_genBranchCols` 每层 3-4 节点、1-2 条出边、列差≤1、孤岛修复；末层 Boss 单列汇聚。

## 设计分析
- 优点：真源单一、调压有 clamp、死亡有归因、轮回传承有明确"什么带得走"的边界（V8.60 起法宝不传承，防止滚雪球）。
- 结构性短板：地图拓扑过窄——每层最多 4 节点 4 列，**商店全局限主线 2 处**（data_map.js L222 注释），rest 每区仅 0.5-1 个。尖塔的 SL 策略空间建立在"路线规划有真实取舍"上，本作分叉少+关键节点稀缺，路线选择的策略价值有限，多数局走同构路线。

## 改进措施
- 节点池扩大商品/休整密度（mob 40% → 35%，shop/rest +5%），或把商店改造成"可重刷的坊市节点"（花劫灰重置货架一次），给金币第二条消费出口。
- 末段地区（15-17）允许 5 列分叉，制造"绕路拿资源 vs 直奔 Boss"的尖塔式决策。

# §2 战斗系统（combat.js 1685 行，owner）

## 实现事实（含公式）
- **聚合顺序**（combat.js:74-234）：`playerBaseAt(diff)` → 装备平铺（hit 封顶 1）→ 佛经 → 随从 → 劫印（按当前值乘算 + 道心 `sealDaoMod`/本命道 `HOME_DAO_MULT` 双乘）→ 转职乘算 → 套装共鸣乘区 → 封顶：hp≤baseHp×4、dr≤0.85、mdef≤0.85、eva≤0.6。
- **战力公式**：`atk + matk×0.8 + maxHp×0.12 + dr×1500 + mdef×1500 + eva×800 + cri×700 + criMult×120 + 命痕数×60`。
- **伤害**：普攻 `atk×(1+atkB)×克制×(1-effMDr)`，怪物 dr 默认 0.20；**终乘 `GLOBAL_DMG_MUL=0.5`**（combat.js:15）；暴击默认 ×1.6（cri 0.10 起步）。
- **气势**：命中+1 封顶 5；层级阈值 [0,1,3,5]，爆发倍率 [0, 0.6, 1.0, 1.5]×双攻和，克制命中再 ×1.5；受击 >15%maxHp 掉 1 势。
- **识破**：仅 telegraph 回合可触发；格挡+反制双攻×0.8（克制 ×1.5）+奖 2 势。telegraph 规则 = `round%heavyEvery==0` 或残血 30%+偶数回合（594-596）。
- **QTE 窗口**：小怪 2000ms / Boss 2500ms / 破韧 2000ms，超时自动按兵不动。
- **Combo**：每 3 次必暴，手动 2000ms 窗口；3/6/9 连击升档 ×1.5/1.8/2.2；搓招奥义 `[atk,atk,chant]` ×2.5。
- **多阶段 Boss**：`calcMultiStage` 逐阶段调 simulateSingle，跨阶段血量折算延续，破韧窗口手动祭法宝领奖。
- **数值曲线示例**（悟空 baseAtk180/baseHp880）：diff1→atk180；diff5→268；diff10→398；diff20→600。**hp 全程不随 diff 成长，全靠装备且封顶 baseHp×4=3520**。
- **自动战斗**：gate 地区起解锁、Boss 禁用、强制 1 倍速、不祭法宝、固定 lowestHp 目标。

## 疑似阻断 bug（需复现验证，验证前不得宣称"战斗系统完成"）
1. **识破崩溃**：`applyShiPo` 引用未定义变量 `_shiPoMult/_shiPoTier/_timing/_shiPoGain`（combat.js:1022、1043）——玩家点识破即抛 ReferenceError 的形态。
2. **命痕分支崩溃**：`lowHpReflectMult` 分支引用不存在的 `deal`（414 行，疑为 `dealt`）；`immuneDeath` 分支（667-673）在 `maxHp` 声明（675 行 const TDZ）之前使用——触发即崩。
3. **多阶段恒胜**：`calcMultiStage` 硬编码 `win:true, lose:false`（789 行）——即使子阶段玩家已死也判胜，破韧 QTE 无失败张力。
4. 若 1/2 复现成立，则识破与两条命痕词条从未被真实跑通过——这直接推翻"战斗系统完成度最高"的既往结论，必须先用 `node scripts/regression.js` + 手动构造战斗复现。

## 设计分析
- **架构性矛盾：演出预演制**。整场战斗先由 `simulateSingle` 预演出 `roundsDetail`，玩家操作（气势爆发/识破/法宝介入）只是对已定局就地"剪片修正"（856 行注释自述"确定性就地修正"）。后果：(a) 操作不改变胜负走向，只改变演出细节——"打击感"的天花板被架构锁死；(b) 多阶段跨 stage 的 momentum 快照不重算，数值泄漏。
- **全局稀释**：`GLOBAL_DMG_MUL=0.5` 且玩家伤害与反击各乘一次，普攻有效倍率仅 ~0.25×，与暴击 ×1.6 的爽感目标矛盾——这是用全局乘法偷懒补多回合节奏，正确的做法是调敌方血量曲线。
- **识破可背板**：telegraph 规则完全确定性，玩家 100% 白嫖 +2 势，QTE 退化为定时点击。黑神话的识破之所以成立，是因为敌招有起手式差异与假动作。
- **优点同样明确**：聚合公式有封顶、克制/识破/爆发的×1.5 一致克制奖励、Boss 免控、自动战斗的多重限制（Boss 禁用/1 倍速/不祭法宝）都说明设计意图清晰。

## 竞品对比
- 黑神话的棍势/识破是**实时反应**系统（起手式阅读 + 帧窗口），本作是**确定性预测**系统——学到了表面常量（+1/封顶 5/×1.5）没学到随机性。暖雪的打击感来自实机帧反馈+音效+受击停顿；本作对应的替代物（演出文本+血条补间+20+ 特效函数）中**音效钩子几乎缺席**（见§7）。
- 尖塔无操作但操作感问题不存在；本作选择"回合+操作点"是差异化正确的路，但必须让操作**有权改变结果**，否则不如纯自动战斗+倍速。

## 改进措施（P0 优先）
1. **先修 4 个疑似 bug**：复现 → 修 `applyShiPo` 未定义变量、`deal`/TDZ 两处、`calcMultiStage` 恒胜改为真实判负+失败惩罚（丢一档破韧奖励）；各补一条 regression 断言。
2. **让操作有权重**：破韧/识破结果参与胜负判定路径（如识破失败吃到本应格挡的伤害），哪怕幅度小——从"剪片"走向"影响剪辑顺序"。
3. **重校数值**：移除双重 0.5 稀释，改为敌方 hp 曲线二次项上调（diff≥10）；识破 telegraph 加 20% 假动作概率（telegraph 声明但下一回合不发动），破坏背板。
4. **补音效钩子**：命中/识破/爆发/受击四类最小集接入 combat 演出点（§7 详述）。

# §3 构筑系统（装备/劫印/经文/道心/转职/英雄/宠物）

## 实现事实
- **装备**：四阶（基座/成品/凌云/天庭），池约 505 个 id；SET_DAO **25 套**按六道分布（战:破军/悟空/黑风…），共鸣如破军 tier3 = atkPct+30%/cri+10%、玄武 tier3 = drPlus+14%+drMult1.12。
- **六道专职门控**：6 套 comp3 配方需专属遗物（如 pw_comp3 需"摧锋残片"），遗物**主线 Boss 必掉 + 坊市固定出售**双途径。
- **劫印**：六道属性印 + 44 词条（白/蓝/金/红四档，红=金×1.55），机制词条约 18 个覆盖 10 种机制（reviveOnce/regenShieldEachTurn/killRefreshTreasure 等）；保底 SEAL_STARVE_THRESHOLD=3（主道途 3 次未得白提蓝）；上限白≤3/蓝≤2/金≤1，生效格 2+章/2+转职阶，上限 14。注意：**作者注释自认"随机 pity 是死代码未实现"**。
- **经文**：渡经 16 部（133 片）+ 逆经 9 部（58 片，锁二周目），集齐自动合成，三选一掉落。
- **道心**：score=evil+xinmo×0.3 三档；sealmod = abyss 恶印×1.15 善印×0.9（calm 反之）——善恶阵营全局调制。
- **转职**：6 道×3 阶=18 级；隐藏职按英雄分（如悟空 trial45「逆+紧箍」→齐天大圣）；三转 comp1→comp2→comp3(+专属遗物)；互斥闸 MUTEX_AT=16（战↔渡、夺↔缘）。
- **英雄**：5 英雄被动差异化明确（悟空破甲 0.10 / 取经人法伤 mercy 0.10 / 八戒盾反 / 龙马闪避转暴击 criOnDodge 50%×3 / 沙僧法防反震 0.20）；`applyHeroKeyFeel` 把被动显影到攻键（悟空+12% 真伤撕甲、龙马两段连刺等）。
- **宠物**：10 条进化（ch2-7），谛听需六道均衡（任意两道差≤6）、通臂石猿需 ch7 事件。

## 核心问题：流派不互斥，终局趋同（证据链）
1. **词条跨道白拿**：隐道「致命」= eva+12% **+暴击**、战道「连斩」=atk+5% **+吸血**、缘道「磐石」=dr+10% **+maxhp**——任何主道 build 都白拿全属性，闪避流与暴击流不互斥。
2. **终局套自认万能**：封神 tier3 攻18/血18/减伤6/暴8、轮回闪避18+暴18+暴伤25，叠加逆命套/逆天录/经文宏愿全是全属性——"贪一切"是占优策略，其余 20+ 套共鸣沦为过渡消耗品。
3. **元素流缺位**：火/冰/毒 build 根本不存在——DOT 仅沙僧杖势一处 + 宠物毒（guchong）一处，PDB_DOT 表（burn/curse/poison/frost）有数值无流派支撑。
4. **互斥闸形同虚设**：MUTEX_AT=16 < daoGate 18，闸门永远先于收益触发（作者注释自认）；本命道仅 ×1.25 放大而非锁死。
5. **词条选择退化**：白/蓝档纯数值词占比过半，三选一退化为"取最大百分比"；跨轮对非主道无 pity。

## 竞品对比
- 暖雪：圣物槽位互斥（掉落替换+融合分支）+ 神兵绑定，14 流派中 7 个独特——其互斥来自"槽位稀缺+词条带方向代价"，本作词条是"白拿添头"设计，方向相反。
- 尖塔：卡组 30 张上限强制取舍，遗物有 curse 类负面对冲。本作生效格上限 14 有了"稀缺"但没有"代价"，缺最后一步。
- 小骨：换头=换流派，入口认知极清晰。本作 5 层系统（装备×劫印×经文×道心×转职）叠加但无"一页看懂我玩什么流"的表达。

## 改进措施
1. **词条互斥化**（P1，改动集中在 SEAL_WORDS 单一真源）：把"添头属性"改为"条件绑定"——「致命」暴击仅对闪避触发后 3 秒内攻击生效类；每条金/红档词条附一条轻代价（如「连斩」吸血对 Boss 减半）。
2. **终局套去万能**：封神/轮回 tier3 拆成二选一分支（攻向 vs 生存向），或加"共鸣轴"机制——同轴共鸣只能激活一条。
3. **元素流补位**（P2）：以现有 PDB_DOT 表为基础给 2-3 个"dot 联动"词条（burn 传染/poison 叠层引爆/frost 冻结增伤），不必新系统，激活已有死数据。
4. **互斥闸调参**：MUTEX_AT=16 提到 20 或直接删除（注释自认形同虚设），用词条代价替代硬闸。
5. **构筑路线一页化**：长安总览"毕业目标"扩展为当前 build 的流派识别卡（主道/核心共鸣/机制词条数），对齐小骨的入口认知优势。

# §4 事件 / 81 难 / 肉鸽随机

## 实现事实
- 事件池约 **138 个**（30 手写 + 108 批量导入）+ 30 个 SUTRA 双线事件；选项分布 2 选项 37 个 / 3 选项 100 个 / 4 选项 15 个（均值 2.93）。
- 六道 fate 标签：渡 267 / 逆 184 / 缘 75 / 战 61 / 隐 72 / 衡 23——**渡+逆占 63%**，两端倾斜。
- 链式事件机制存在（pickEvent 优先 nextId）但 `chainId` 仅 11 处、`nextId` 占比约 1.5%——**机制远大于内容**，只服务红孩儿长链。
- 81 难双库：story 库（难 1-20，每难 ~230 字成段叙事+具名奖励）+ TRIAL_LIB（全 81 难，dark~40 字+intro~25 字）。**难 1 段落 ~2281 字节 vs 难 60 ~1021 字节，前厚后薄 2.2 倍**；难 60 选项退化到「【缘】化解」两字。
- 区域事件 reward 高度模板化（gold:40/exp:60/seal:true），atk 硬编码爬升且**倒挂**：r08「老龟再临」atk+310 > r13 的 262、r14 的 287（events.js L348/385/392）。
- 概率链三层稀释：问号节点 → 50% 固定触发双线事件 → 池内均匀随机（17 件池单件 1.9%）；V8.53 已加加权补丁但 `_render_event_prob.html` 注释仍标"未实施"，**文档滞后于代码**。
- 配额制（data_quota）实为**软性通关门槛**而非分布控制——只保证该道有节点可走，不提升该道产出质量；选「夺」道的专属装仍受事件池均匀抽取制约，道途承诺与回报链脱节。
- 活的改进证据：装备 soft-pity（EQUIP_PITY_THRESHOLD=6）+ 小怪散宝 45%+连缺 2 保底，是全项目做得最像"现代肉鸽"的一块。

## 竞品对比
- 尖塔的事件（如"活人祭坛"）每条都有明确代价定价与 build 相关收益；本作 r06「火灵啼哭」4 选项中「夺：fight 得 atk+85/gold/exp/seal」vs「隐：仅 dr+3%+素材」收益差数倍无对冲，是伪抉择。
- SUTRA 双线事件全部是「装备 vs 经文」二选一同构（文件尾部 6 连）——对比哈迪斯/尖塔事件池的"机制惊喜率"，本作后期事件池趋同度高。
- 内容曲线问题与暖雪同病（关节素材复用被差评），但本作是"文案复用"而非美术复用，修复成本更低。

## 改进措施
1. **修数值倒挂**（低成本高收益）：r06-r14 事件 reward 改为按 `diffOfLayer` 查表而非硬编码 atk 值，一处 helper 收口。

# §5 元游戏（轮回 / 长安总览 / 成就 / 结局）

## 实现事实
- **轮回**：劫运骰 `summyRoll` 基 65%/75%（勇/渡线）+ 善恶差每 40 点 ±25% + 劫印 +2%/枚（≤+12%）+ 六道亲和 +5%/级（≤+25%），钳位 5~95%——数学上完整且 clamp 纪律好。
- **劫灰坊 5 项升级固定单价**（不递增，线性消耗曲线）——后期劫灰溢出无消费出口。
- **家当三档**定义清晰：壹·入藏永存（藏品库/拓印/图鉴/难簿/赐福）；贰·承继相袭（衰减 20% 至多 4 次）；叁·随世而散（本命法宝）。这是全项目概念设计最精巧的一块。
- **长安八设施全部实装**：大雁塔/录难阁/藏经阁/藏品库/轮回殿/降妖簿/钟楼/劫灰坊 + 总览章（行迹/时长/CG 画廊）。
- **成就 5 卷 40 条**（逆道 4/隐职 14/因果 7/收藏 4/经藏 11）+ 难簿 33 卷×双线功名。
- **结局**：ENDINGS_CG 共 6 张（3 全局：正果/逆道/大圣 + 3 英雄告别卡）；朝代 17 朝死亡 bump/通关 reset。
- **二周目论道确认未实装**：`zhuanjie.js lundaoOpen`（二周目+niInsights≥3）**全库 grep 无调用方**；"旧账·逆道印"凭证与 REBEL_ZHEN_CYCLE_REQ=2 均为数据占位。

## 设计分析
- 元游戏深度是真实护城河：家当三档的"衰减传承"设计（遗物/经文/劫印每次 -20% 至多 4 次）在同类竞品中没有对应物，比暖雪的"继承碎片"更精细。
- 但**终局承诺悬空**：逆经锁二周目 + 论道三选结局是数据里写好的钩子，玩家解锁"旧账·逆道印"后无任何去处——这是当前最大的单点玩家情绪风险（收集完成后无事可做）。

## 竞品对比
- 小骨的多周目用"头骨图鉴+难度爬升"承接长线；尖塔用 Ascension 20 级。本作的"难簿 33 卷功名 + 81 难度爬升"结构其实更强，缺的只是 81 难之后的最后一环（论道/真结局）。
- 暖雪手机版无图鉴被差评，本作图鉴/收集维度全面占优——营销时应把"图鉴+账簿叙事"作为主打卖点而非构筑深度。

## 改进措施
1. **接线论道**（P2 主线项）：`lundaoOpen` 已有条件定义，补调用点 + 三选结局 UI（复用现有 ending CG 流程与六道劫印表），把 6 张 CG 中预留的"逆道"结局接入。
2. **劫灰消耗曲线**：坊市升级改 1.4^n 递增或加第 6 项"劫灰兑换特殊劫印"，消除后期溢出。
3. **毕业目标可视化**：总览章已有三线毕业目标，补"距下一毕业里程碑"进度条（数据都有，纯 UI 工作）。

# §6 存档 / 三端 / 测试矩阵

## 实现事实
- **存档**：SAVE_VERSION=1，16 个集中键，类型化读写 + exportAll/importAll（仅前缀键）+ 双重 fallback 到内存。regression C 段覆盖 round-trip 基础类型——**但未覆盖 MAIN 主档结构与版本迁移路径**（旧键迁移映射仅 2 条）。
- **三端**（platform/ 共 476 行）：
  - browser.js：全实装（storage/buyout mock/成就/分享）。
  - taptap.js：真 SDK + hasSDK 守卫降级，实装度高。
  - **wechat.js：消息桥接占位级**（wx.postMessage），无真 SDK 调用；bundle 由 `build_minigame.cjs` 拼接 + platform_test D 段 6 条漂移防护。
- **测试矩阵（实际比之前认知强很多）**：regression.js 约 130+ 断言（战斗数值 7/技能干预 3/QTE 3/存档 5/战斗功能 12/气势爆发 5/谈判 8+21/英雄剧情键位 15/隐藏职 33/触发链路 10/持久化 12）；platform_test 35 条；smoke 脚本 10+ 个。**缺口**：vault smoke 不入正门禁；轮回赐福/朝代/长安 UI/结局 CG 点亮/audio/map 生成无断言。
- **?v= 版本号纪律失守（确凿）**：版本从 374 到 430 混杂 28 档，相差 56 个版本；audio 仍 v=1/2、journey=16——改老文件极易忘递增导致"改了没生效"的缓存事故。

## 竞品对比
- 暖雪手游/元气骑士原生包无此问题；H5 形态的缓存版本管理是本作独有工程税，只能靠纪律或工具（见下）。
- 尖塔/小骨的存档有云同步；本作 exportAll/importAll 已具备文本导出能力，微信端接真 storage 后可顺势做"复制码导入"低成本云备份替代。

## 改进措施
1. **工具化 ?v= 纪律**（P0，一次性投入）：写 `scripts/bump_version.js`——按 git diff 检测本次改动文件并自动递增 index.html 对应 `?v=`，纳入提交前检查；audio/journey 等长期不动版本号的老文件统一 bump 一次。
2. **微信真机最小闭环**（P0）：真 wx.setStorageSync（已有容量管理代码）+ 分享 + 存档导入导出跑通前 3 难；买断/广告 SDK 后置。
3. **存档迁移测试**：补一条 MAIN 主档构造 V0→V1 迁移断言（现有 2 条映射太薄，SAVE_VERSION 一直没升过反而是风险——说明迁移路径从未被走过）。
4. **vault smoke 转正**：`_smoke_vault` 纳入 regression 门禁。

# §7 UI / UX / 音频

## 实现事实（含对旧认知的勘误）
- ui/ 实为 16 文件约 8300 行；**style.css @media 仅 22 处**（此前"607 处"系规则数误记）；全项目唯一形态=**手机横屏**（竖版媒体查询已物理删除，css:13633），orientation 由 index.html fit() 伪旋转判定。
- **架构**：唯一事件委托 `main.js onAppClick()`，约 120 case 的巨型 switch（近 1100 行）——全项目最大复杂度点。**无模态栈**：关闭弹窗靠手写枚举 18 个 show 标志逐一置 false（main.js:307-331），新增面板必漏。
- **性能**：每次点击 `doRender()` 全量 innerHTML 重建 `#app`，**零虚拟化零 diff**；81 难簿/降妖簿全量 map；血条需要 DOM 缓存+手动补间（main.js:1466）佐证了动画状态全丢。低端机上每个 toast 都付出整页重建代价。
- **职责漂移**：ui_misc_3 同时装战斗特效引擎（_fxStrike 等 20+ 函数）与降妖簿/灵兽图鉴——自动按行数切分的痕迹。
- **音频（勘误：实装度高于预期）**：三层结构完整（sound.js 合成+MP3 → 1011 行自适应引擎 ndx_audio_engine + 17 区域音景配置 + bridge 轮询），场景切 BGM/按钮音/终局音已接。**缺口在 combat 侧钩子稀少**：仅 guard/treasure 两类，普攻/受击/暴击/识破/爆发无独立音效钩子，走引擎推断。
- **文案**：主体文言佛系腔统一；断裂处：emoji 网文腔 toast（`🔱 六道转职…` main.js:266/1019）与原生 `alert()/confirm()` 与自定义浮层并存（main.js:445/885/518）。
- **新手引导**：前三难引导链很密（长安六步教学/寿命两页/教学战/观音引导/首恶浮层），这块不用补。

## 竞品对比
- 暖雪打击感 = 实机帧反馈 + 受击停顿 + 音效三件套；本作已有特效引擎与血条补间，**独缺音效这第三件**——是"免费的打击感"，投入产出比最高。
- 尖塔的手游版用局部刷新保滚动位置；本作全量重建导致地图滚动要 JS 手动回弹补偿——移动端流畅度是 TapTap 评分的第一杠杆。

## 改进措施
1. **combat 音效钩子**（P0 中的性价比之王）：在 combat.js 演出生成点埋 hit/crit/shipo/burst/hurt 五类钩子（引擎已能播放，只是没调用），预计半天工作量。
2. **ModalManager 收口**：18 标志枚举改为模态栈（push/pop），新增面板不再漏关；不急着重构存量，先立栈式入口让新面板走新路径。
3. **渲染增量**（P2，控制成本）：不全量重写渲染层，先对高频路径（toast、战斗播报、面板开关）做局部 DOM 更新——toast 每次点击触发是最大浪费点。
4. **文案/弹窗统一**：替换 3 处原生 alert/confirm 为现有浮层组件；清理 emoji toast，回归账簿文言腔。
5. **ui_misc_3 拆分**：战斗特效引擎迁至独立 `ui_fx.js`，图鉴类归 ui_trial/misc——下次触达该文件时顺路做，不单独立项。
