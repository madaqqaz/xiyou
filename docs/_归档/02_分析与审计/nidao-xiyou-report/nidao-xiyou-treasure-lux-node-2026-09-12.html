二、秘藏宝窟 · 独立节点设计

2.1 两个独立类型（而非同一节点改档）

节点类型名称品阶档奖励地图表现
treasure 宝窟 low（凡/珍品） 金币 + 2 选 1 法宝（不出红，gold 权重低） 常规图标 + 「法宝」标
treasure_lux 秘藏宝窟 / 妖王宝库 / 龙宫旧藏 high（金/红） 金币 ×1.6 + 2 选 1 法宝，且保底至少一件金/红名器 至宝金色高亮 + 光晕 + 独立提示

2.2 生成规则（只中后段投放，避免新手期法宝过载）

  • 后段岔路池（L>5）纳入 treasure，权重约 1/12；前段与第一章不动（第一章模板本就无宝窟）。
  • 宝窟节点以 NDX.TREASURE_LUX_CHANCE = 0.22 升格为 treasure_lux（[PLACEHOLDER·待10局采样]）。
  • 秘藏金币倍率 NDX.TREASURE_LUX_GOLD_MUL = 1.6（[PLACEHOLDER]）。

2.3 秘藏保底（「特殊奖励」的确定性差异）

在 rollFabao(n, state, act, tier) 内，当 tier==='high' 且候选无金/红名器时，从残余池强制换入一件金/红阶法宝。这使「秘藏」名副其实——是确定性差异，不是运气差异，与普通宝窟形成明确分野。纯抽取代换，不改战斗逻辑。

三、图鉴分母真 bug（顺带修复）

data_codex.js 的 progress() 用 NDX.EQUIPMENTS / NDX.SEALS / NDX.TREASURES.length 求分母——但前两者字段不存在，后者是对象（.length 为 undefined），三者分母全部回退为 0。

分类修复前修复后（真源）
equip0（字段不存在）EQUIP_POOL + CRAFT_POOL 按 id 去重
seal0（字段不存在）Object.keys(SEAL_WORDS).length（键=劫印名，与图鉴记录键一致）
treasure0（对象误取 .length）Object.keys(TREASURES).length
enemy / boss / sutra原本正常统一改用兼容「数组/对象」的 NDX.CODEX._count()

六、明确未做（边界）

  • 群攻体系（不做）：真源多怪为「合体单体」（compositeMonster），无多目标战斗落点。要落 V9.5 §七 的 aoeEff/aoeCap，必须先有「多目标」战斗系统，属结构扩张——单独专项。
  • 数值：升格概率 0.22、金币倍率 1.6、品阶权重全为 [PLACEHOLDER·待10局采样]。
  • 视觉目测：门禁与探针只证逻辑与数据；金色光晕/「至宝」标位置需你在浏览器实机看一眼。
