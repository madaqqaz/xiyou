## 一、定位（五层机制的第 3 层）

```
装备 = 基础数值        （提供属性地板）
劫印 = 多维度增强      （反震 / 护盾 / 吸血 / 反伤）
法宝 = 钩子 + 特殊属性（不提供纯数值）      ← 本文件定义
跟随 / 宠物            （行动补位 / 场域改写）
```

**一句话**：**装备决定你能打多少，法宝决定你能打什么。**

法宝**不是战力系统**，是**解题系统**——它回答的是「妖怪在某难用什么招式、你用什么解」。

## 三、钩子系统（已设定，不动）

**真源**：`法宝钩子系统·通用规则文档.md`（v1.3）
**代码锚点**：`js/enemies_part1.js` → 敌人身上的 `breakWith` / `blessTreasure`

### 3.1 钩子语义

> 钩子 = 敌人身上挂的**解法字段**，不是装备属性。
> `breakWith` = 「拿什么破」／ `blessTreasure` = 「拿什么加持」。
> ⚠ 二者引用的都是 `slot:'treasure'` 的物品 **id**，因此**钩子借用装备库存在**，但**语义不属于装备数值**。

### 3.2 现有钩子全集（实测 7 种，15 处挂载）

| 钩子 id | 含义 | 出处真源 |
|---|---|---|
| `dingfeng` | 定风珠 · 破风系 | 钩子系统 §一.1 |
| `zhaoyao` | 照妖镜 · 破幻化/人形减伤 | §三 |
| `baojiao` | 芭蕉扇 · 破金刚琢 / 清灼烧 | §二.1 |
| `ts_jingping` | 观音玉净瓶 · 清弱 / 救人 | §二.2 |
| `zijin_honghulu` | 紫金红葫芦 · 清致盲 | §二 |
| `zijinhu` | 红葫芦 · 清摄魂 | §二 |
| `ts_bowl` | 阴阳二气瓶 · 装天装地 | §二.2（三才净瓶链） |

🔴 **R2 的硬边界**：这 7 种就是全部。要「破毒」「破雷」等新语义时，**走已有钩子的组合或升级链**，不新增钩子种类。

### 3.3 钩子不是必需（重要）

真源 §八「战斗难度分级」：夺(1) → 逆(2) → **针对性法宝(3)** → 请菩萨(4)。
⇒ **法宝是第四优先的降难手段，不是通关必需品**。法宝系统因此**必须保持轻量**（对应 R5）。

## 四、被动归属（R3 落地）

| 层 | 谁提供 | 例子 |
|---|---|---|
| **装备** | 全部常规被动（数值 / 套装 / 特效） | `matk/mdef/hp`、破军四件套 |
| **法宝** | **不提供**常规被动 | 见下行 |

**结论**：所谓「法宝被动」**不是一种独立机制**，而是**装备被动在法宝槽的呈现方式**。
⇒ 总纲 §2.7 的「主动 1 + 被动按章 1→5」中，**「被动」槽位接纳的是普通装备被动**，
   法宝机制本身**只有钩子（主动）与特殊属性**两类。

🩸 这条直接消解了「法宝要不要做被动树」的争论：**不做**。

## 五、操作点子系统（R4 落地）

- **真源**：`《逆道西行》45隐藏职 · 英雄归属与流派总表（v1.0）》§五
- **构成**：识破 / 破韧 = 同一个系统（Operation Point）的两种表现
  - **识破** = 应对变化/幻化 → 对应钩子 `zhaoyao`
  - **破韧** = 应对护体/减伤 → 对应钩子 `dingfeng` / `baojiao` 等
  - 三者**共用一套「操作点」窗口**（telegraph / enrage / lowhp 三战况驱动）
- **归属判定**：操作点**挂法宝**，因为它就是钩子的**执行端**——没有钩子就没有可破目标，没有操作点就没有破的窗口。
- **A1.5 现状（已落地）**：P1-C 删周期 `routine` 窗口；P1-B 自动战斗不再被操作点/破韧打断（非 Boss 走挂机 `idle`）。
  门禁 `_verify_operation_point.js` **21/0**。
- ⚠ **不可删**：破韧是**法宝克制配装的唯一硬验证点**（`monster.breakWith`，如黄风怪↔定风珠）。
  删掉它，法宝系统就没有「设计文档之外的真实验证点」。

## 六、冲突与待决（🔴 需拍板）

### 冲突 A（🔴 阻断级）：法宝的「纯数值件」到底算不算法宝？

- **总纲 v5.6 §2.7**：`slot:'treasure'` 中「**141 件数值件 / 套装件**一律为被动」⇒ 法宝带大量纯数值。
- **用户拍板 R5**：「法宝**几乎没有纯属性数值**，只加特殊属性」⇒ 141 件**不属法宝**。

**我的判法（供拍板）**：
> 那 141 件是**借用法宝槽展示的装备**。按 R3，其被动根源在装备系统 ⇒
> **归属装备，槽位仍用法宝槽呈现**，但**不计入「法宝」条目数**（R1 的「不轻易加数量」因此不受影响）。
> 后果：`_verify_slots` 等门禁里的「法宝件数」口径要同步改，否则会误判。

### 冲突 B：法宝槽是「固定 2 格」还是「按章 2→6」？

| 来源 | 值 |
|---|---|
| 总纲 v5.6 §2.7 | 主动 1 ＋ 被动按章 1→5，**合计 2→6** |
| `js/equipment_part3.js:161-164` | `active:1, passiveBase:1, passiveStep:99, passiveMax:1` ⇒ **固定 2 格** |

🩸 代码注释自认：`// 改回按章成长：passiveBase=1, passiveStep=2, passiveMax=5（合计 2→6）`
   —— 即**文档记录的是目标，代码还停在占位**；且 §2.7 附近注释写着
   `⚠ 主/被动的「具体作用」待讨论——本轮只落地分槽与占位，不赋额外机制。`
   ⇒ **法宝主/被动的「具体作用」从未被定义过**，这正是 B1 要填的空白。

**判法（供拍板）**：B1 先**不动数值**，只把「被动 = 装备被动」的口径写死（R3），
按章成长留到 B1 后续Decision。**冲突 B 属实现口径问题，建议本轮不裁决。**

## 七、职责红线表（法宝 vs 其他四层）

| 系统 | 法宝**能做** | 法宝**不能做** |
|---|---|---|
| 对装备 | 提供钩子与特殊属性 | 提供纯属性成长、套装效果 |
| 对随从 | — | 不提供行动（随从才出手） |
| 对宠物 | — | 不改场域规则（宠物才改写） |
| 对劫印 | — | 不提供反震/吸血（归劫印层） |
| 对操作点 | **提供破的目标与窗口** | 不自己打断战斗（属操作点子系统） |

⇒ **一句话**：**法宝不给你力量，它给你解法。**
