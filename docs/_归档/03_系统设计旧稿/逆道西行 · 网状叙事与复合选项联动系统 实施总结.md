## 二、核心系统实现

### 2.1 ChoiceFlags选择标记系统
- 存档结构新增 `s.choiceFlags = {}`，旧存档自动迁移为空对象
- 选项通过 `opt.setFlag`（字符串 `'key:value'` 或对象）落印
- 非战选项在applyEffectCore后立即落印；战选项押入`s.flags.choiceFlagPending`，战斗胜利后兑现
- 加载难时通过 `trial.branchKey` 读取choiceFlags，匹配 `trial.branches[flagValue]` 覆盖dark/intro/options/treasure
- 防覆盖：自动落印仅在分支键尚未落印时写入，下游难不会冲掉上游选择

### 2.2 复合选项联动（三种机制）
| 机制 | 字段 | 作用 | 示例 |
|---|---|---|---|
| 解锁联动 | `requireFlag` | 需已有特定印记才可选，支持`key:value`语法 | 难4"逼问真相"需难2选"隐忍待发" |
| 锁定联动 | `requireLock` | 已有特定印记则反锁（已被阻断） | 难51"申冤"在夺佛宝后不可选 |
| 增强联动 | `effect`为函数 | 接收choiceFlags返回动态效果对象 | 难20某选项根据n15_bajie分支决定额外增益 |
| 关系门槛 | `requireRel` | NPC关系值达标才可选 | 难20需观音≥8 |

### 2.3 NPC关系系统
- 5个核心NPC：观音/如来/玉帝/太上老君/妖王
- `effect.rel = {观音: +5, 妖王: -3}` 增减关系值
- `requireRel = {玉帝: 5}` 门禁检查
- 关系值影响至少3个后续选项（难16/20/41等）

### 2.4 动态结局系统（10结局）
| 结局ID | 名称 | 触发条件 |
|---|---|---|
| lingshan | 灵山逆座 | 逆道选择≥5 + 恶>善 + biwen分支 |
| liuer | 六耳同修 | s.flags.liuerUnlocked（难41选"伸手相认"） |
| changan | 长安还俗 | 取经人 + 善>40 + 善向分支 |
| wanbao | 万宝归一 | 夺≥5 或 装备≥10 或 gold≥200 |
| wanfa | 万法皆空 | 渡≥8 + 善>恶×2 + 观音≥10 |
| zhanfo | 战佛临世 | 战≥8（可中途结局触发） |
| yuanding | 缘定三生 | 缘≥6 + 关系和≥20 + 收八戒沙僧 |
| jinchan | 金蝉正果 | 取经人 + 善≥恶（兜底善线） |
| yipo | 一魄转世 | 恶>善 或 逆≥3 |
| nidao | 逆道西行 | 取经人兜底 |

- 判定优先级：lingshan > liuer > changan > wanbao > wanfa > zhanfo > yuanding > jinchan > yipo > nidao
- 非取经人英雄未命中时返回null，回退原computeEnding保留大圣脱局/净坛/卷帘/白龙等结局
- 中途结局：难60"剃尽僧发反制"→zhanfo；难70隐藏选项（需liuerUnlocked）→liuer

### 2.5 命运抉择图谱UI
- 每次落印记录到 `s.choiceHistory`（难号/劫难名/选择/印记/时间）
- 通关时先弹命运图谱（时间线样式：左侧竖线+节点，展示关键选择→印记→终局）
- 点"继续"进入gameover胜局屏

### 2.6 跨周目echo
- 通关时保存 `ndx_echo_last`（上周目英雄/结局/choiceFlags/关键选择）到永久存储
- 二周目开局打"前世回响"日志
- 难4依上周目`n4_choice==='biwen'`浮现"前世记忆"专属选项（requireFlag: '__echo_n4_biwen'）

### 2.7 章节末抉择回顾
- 每章土地庙（enterRegionGate）收集本章choiceHistory
- 叙事面板下方展示"本章抉择回顾"（难号+选择+印记）

### 2.8 选项后果提示UI
- `opt.consequence` 字段（如"此选择将影响：难5-7江州余党路线"）
- 选项按钮内斜体金色显示
- 难4/15/16/19/20/60/70等关键选项共18+处

## 七、剩余风险与建议

1. **浏览器实机未跑**：四阶段均做了纯Node语法+数据门禁，未做`npm run serve`浏览器实机渲染验收。建议发布前手动过一遍：难2选隐忍→难4五选→难5-7分支渲染→难15→16→难19→20→21→难41六耳→难60中途结局→难70分支结局→通关命运图谱。

2. **指定回归脚本缺失**：任务要求的`demo/scripts/regression.js`（157项）、`platform_test.js`（41项）、`_smoke_monster_behavior.js`（29项）在磁盘上不存在（宪法表标注"未运行"，疑为前序会话产物已清理）。以仓库现存25个门禁脚本替代验收，未伪造通过数。

3. **NPC关系累积效应**：第四阶段批量给渡选项加`rel:{观音}`，使万法皆空/缘定三生结局更易触发。符合"结局可达成"调优方向，若后续觉得过易可在endings.js cond微调阈值。

4. **命运图谱渲染形态**：fate-graph走默认#panel侧栏渲染（非全屏浮层），与随后全屏deathScreen衔接略跳；功能正确，后续可提升为overlay模态。

5. **51个历史effect**：剩余59个纯善恶中，8个为难1-3锁定项，51个为历史既有`flag/count`等引擎已消费但统计正则不识别的字段，属历史遗留非本轮回归范围。

6. **并行Agent工作树**：worktree存在大量非本轮M文件（combat/data/dao/sound等），为并行OrganizeAgent五阶段任务产物，未触碰未stage，按git规则留给用户处置。
