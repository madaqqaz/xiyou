# 六道抉择"单选项"症结分析 · 多套路（体法/血反/吸攻/攻防）落地方案

> 触发问题：玩家反馈"目前六道抉择为单一选项，没有选第二种六道的理由，实现不了体法/血反/吸攻/攻防等多重套路"。
> 本文为**现状根因分析 + 解决方案设计**，不含代码改动。落地建议见 §四。

---

## 一、核心结论（一句话）

六道被实现成「**单选定调 → 单一主攻式 + 微弱全量加成**」的**单身份系统**，而非「**多道并行 → 机制叠加**」的**构筑系统**。
玩家选第二条道，只换来一点统计加成、换不来"第二种战斗手感"，因此"选第二条道没有意义"。

---

## 二、现状根因（带 file:line 证据）

### 根因 1 · 战斗只有"单一主攻式"，副道无机制层
- `js/dao_system.js:223` `DAO_ATK_STYLE` 按**单一主道**给出唯一攻击特效：
  - 战=crit(暴击) / 渡=heal(回血) / 隐=evade-crit(闪避后必爆) / 夺=lifesteal(吸血) / 缘=shield(护盾) / 逆=true(真伤)。
- `js/dao_system.js:82` `getMainDao(s)` 返回**一个**道（首难锚点 `s.mainDao` 优先，劫印动态可覆盖，但仍是"一个"）。
- `js/combat.js:368` `const _dKey = (_dA && _dA.style) ? _dA.style.key : null;` —— 玩家攻击只取**一个**主道攻式。
  - （`combat.js:1723` 的 `_mdA` 是**怪物**的道式，与玩家无关，进一步印证"玩家只有一式"。）
- **后果**：无论你累计了多少条 渡/隐/夺，你的"出手方式"永远只是主道那一种。第二道在战斗里**不可见**。

### 根因 2 · 事件奖励"品类塌缩"，fate 只影响善恶与锚点
- 设计稿《六道奖励框架》§2 原本要求**六道奖励品类天然错开**：战→劫印 / 渡→原著法宝+好感 / 缘→机制法宝 / 隐→闪避装 / 夺→掠夺装 / 逆→经文感悟。
- 但实际剧情劫难数据（`js/data_trials_story.js`）已塌缩为**通用属性**：
  - 战/逆选项 → `ti:{atk}` 物攻；隐选项 → `ti:{hp}` 气血；渡选项 → `good:` 善恶 + `ti:{hp}`；夺/隐/渡大量共用 `effect:{ equip: 2 }`（**通用二选一装备，不按道过滤**，`data_equip_core.js:590` 亦为 `equip:2` 通用模板）。
- **后果**：选 渡 还是选 隐，拿到的几乎都是"加血/加攻/通用二选一"，**装备池不分化**。fate 标签只左右善恶账和 `s.mainDao` 锚点，不左右你到手的装备品类。选第二条道**没有差异化的收获**，自然"没意义"。

### 根因 3 · 已有的"多道协同"只是平属性，没给"第二种手感"
- `js/data_audit.js` 的 `CROSS_RESONANCE` **其实已经为多套路预留了框架**：
  - `文武双全`：3渡印+3战印+2渡经+2战经 → 物攻+5% 法伤+5%（**这正是"体法"**）。
  - `灵活多变` / `经武通达`：混搭装备 + 双道印/经 → 全属性/经武加成。
- 但这些都是**平属性加成**；触发后你仍只有单一主道攻式。
- 而且触发门槛极高（双道各 3 印 + 各 2 经 + 混搭装备），非刻意构筑几乎不可能自然出现。
- **后果**：多套路"理论存在、实践不可及"，且即使达成也只是数字微涨。

### 根因 4 · "改道"是"换身份"不是"加身份"
- `js/game_event_2.js:184` 首难 `s.mainDao = opt.fate`；`js/game_region.js:213` 土地庙/长安 `s.mainDao = dao` 为"自愿改道"。
- 这是**把单一主道从 A 换成 B**，不是"同时拥有 A 和 B"。玩家最多"中途换流派"，无法"双流派并行"。

> 小结：四条根因叠加 → 玩家感知到的就是"六道=开局选一个标签，之后一路到底，第二条道只是换个善恶数字"。你设想的**体法/血反/吸攻/攻防**本质是"双道机制叠加"，而当前架构从根上只支持"单道机制"。

## 三、你想要的四条套路，现状对照

| 套路 | 需要的道组合 | 当前能否玩到 | 卡在哪 |
|------|--------------|--------------|--------|
| **体法**（物攻+法伤） | 战(物攻/crit) + 渡(法伤/heal) | 仅"文武双全"平属性 +5%/+5%，**无双式** | 根因1（单攻式） |
| **吸攻**（攻击吸血） | 夺(lifesteal) 或 战+夺 | 仅当你把 夺 设为主道才吸血；**无法"暴击+吸血"并存** | 根因1 |
| **血反**（受击反伤/低血反扑） | 逆(reflect 反伤) + 缘(减伤/护体) | 逆印 `stat:'reflect'` 有微弱受击反伤（`combat.js:153`），但**非构筑性、无低血爆发** | 根因1+3（无触发式机制） |
| **攻防**（进攻+防御） | 战(atk) + 缘/逆(dr/reflect) | 单攻式 + 平属性共振，无"攻防一体"机制 | 根因1 |

**共性**：四者全是"主道 + 副道"组合。只要让**副道也能贡献一个战斗机制**，四套路一次性解锁。

> **两层关系澄清（用户原始设想 ↔ 落地）**
> 用户给出的「渡=经 / 逆=逆经 / 战=装备 / 隐=闪避装 / 夺=特殊装备+法宝 / 缘=特殊装备+法宝」是**资源品类层**——每条道发放**完全不同品类**的资源，选第二条道 = 拿到第二种资源，抉择立刻有意义。
> 而「体法/血反/吸攻/攻防」是**战斗构筑层**——两种资源要真的合成一种**出手方式**。
> **Phase 0 修复资源品类层**："为什么选第二条道"立刻成立（拿不同东西）。
> **Phase 1（副道）修复战斗构筑层**："选了之后怎么合成套路"才成立（双式同结算）。
> 二者互补、不可相互替代；Phase 0 是用户原始设想的本意，应优先还原。

## 四、解决方案（分阶段，由低风险到核心改造）

### ▶ Phase 0 · 纯数据修复（零数值风险，建议先做）
**目标**：让"选第二条道"立即获得**不同装备池**，使抉择有差异化收获，并激活已有的 CROSS_RESONANCE。

1. **还原"六道奖励品类错开"（用户原始设计定稿映射）** —— 每条道发放**完全不同品类**的资源：
   | 道 | 原始设计：发放品类 | 定位 / 来源 |
   |----|-------------------|-------------|
   | 渡 | **经文**（正经） | 抉择/感悟积累，驱动内功·心魔法相（与逆构成"正/逆双经轴"） |
   | 逆 | **逆经文**（逆经） | 逆相感悟，驱动逆相心魔（与渡对称） |
   | 战 | **装备**（凡品/通用） | 打怪掉落，构成"体"基底（物攻/血量） |
   | 隐 | **闪避装备**（专精避击） | 独立闪避池，强化 evasive 定位 |
   | 夺 | **特殊装备 + 法宝**（掠夺） | 抢 Boss 掉落，含吸血/掠夺类专属 |
   | 缘 | **特殊装备 + 法宝**（机缘） | 机缘/事件掉落，含机制型法宝 |
   - 把通用的 `equip:2` 按 fate 改写为对应品类的定向发放（或缩小通用池、按 fate 加权）。
   - 注：夺/缘同为"特殊装备+法宝"，靠**获取来源**区分（夺=boss 掠夺、缘=机缘事件），品类内部可再细分主题。
2. **校验 `CROSS_RESONANCE` 触发条件**与品类发放一致（双道各自 3 印/2 经 + 混搭装备的获取是否可达）。
- **效果**：不碰任何战斗公式，纯数据即可让"第二条道"产出不同构筑件；配合现有共振，多套路从"理论"变"可凑齐"。
- **风险**：极低（仅数据），可与现有门禁快速验证。

### ▶ Phase 1 · 机制核心（引入"副道"，解锁四套路）
**目标**：让玩家拥有**主道 + 副道**两套攻击机制，战斗同时结算。

1. **状态扩展**：`s` 增 `subDao`（副道）。设定入口：
   - 方案①（推荐，契合"自愿改道"）：改道面板改为"主道/副道"双选，首难后仍可在土地庙/长安设定副道；
   - 方案②：自动取"劫印第二多的道"为副道（零操作成本，但玩家无主动感）。
2. **`dao_system.js` 改造**：`daoAtkStyleOf(s)` 返回 `[主道式, 副道式]`；`getDaoBonus` 的双道加成合并。
3. **`combat.js` 改造**（`combat.js:368` 一带）：主道式按原 `pct` 结算；副道式按**降权系数**（如 60%）结算第二特效。
   - 体法 = 战主(crit) + 渡副(heal) → 出手既暴击又回血；
   - 吸攻 = 战主(crit) + 夺副(lifesteal) → 暴击且吸血（或夺主+战副）；
   - 血反 = 逆主/副(reflect) + 缘副/主(dr) → 受击反伤+减伤，并在低血时放大（新增 `lowHpReflectMult`，`combat.js:177` 一带已有 `lowHpReflectMult` 占位钩子）；
   - 攻防 = 战主(atk) + 缘副(dr/shield) → 进攻同时带护盾。
4. **UI**：六道总览卡（`ui_panel_2.js:743` 改道面板）新增"副道"位与副道攻式说明。
- **效果**：四套路机制层一次性解锁，且每条都是"主道×副道"的自由组合，构筑广度指数级提升。
- **风险**：中（动战斗结算 + 需配平副道降权系数），但改动面集中、可灰度。

### ▶ Phase 2 · 深度（可选，长线）
- **双道共振升级为"触发式机制"**：把 `文武双全` 等从平属性升级为"每第 N 击触发双道特效""低血迈入血反态"等可见机制。
- **六道专职"双专职"**：`tierOf(s, dao)` 支持副职阶（`data_audit.js:101`），副道也可转职拿被动。
- **心魔随双道演化**：当前心魔由六道驱动（`data_xinmo.js`），双道下可演"双相心魔"。

---

## 五、落地建议

1. **先做 Phase 0**：纯数据、零风险，且能立刻验证"装备池分化 + 共振触发"是否足以让多套路可玩——若够，Phase 1 可缓做。
2. **Phase 1 是"真正解决用户痛点"的关键**：用户要的是"第二种战斗手感"，只有双道双式能给。副道降权系数建议从 0.6 起配平。
3. **Phase 0 与 Phase 1 可独立提交**，互不阻塞。

## 六、二次诊断：六道抉择"被滥用"（选项过载）与重设计

> 用户 2026-09-11 二次反馈：**多次版本叠加后六道被滥用，导致选项太多**；最初设想是"81 难不是每一难都有六道抉择，应按《西游记》常态选择 + 剧情特殊性混合 3-4 个选项"，并建议"**不展示六道选项，在选项标签中隐藏，玩家选完后再按选项增加六道**"。本节为只读量化诊断 + 重设计方案，未改任何游戏代码。

### 6.1 量化诊断（tools/_analyze_sixdao.js 只读统计）
| 指标 | 实测 | 结论 |
|------|------|------|
| 含选项的难 | 81/81 | 100% 强制抉择 |
| **含六道 fate 的难** | **81/81** | **滥用核心：每难都逼玩家选道** |
| 选项数分布 | 3 选项 ×60 / 4 选项 ×16 / 6 选项 ×1(首难) / 2 选项 ×4 | 单难选项数尚可，问题在"覆盖率 + 场景错配" |
| **战+夺同框的难** | **19 难**（黑松林/平顶山/黑水鼍龙/红孩/三妖赌胜/车迟监/通天河/金兜/火焰借扇/牛魔王/翠云山/祭赛/竹节九狮/金平犀灯/给孤招婚/捣药杵/玉兔等） | 场景错配铁证：无 Boss 可抢的难也给了"夺" |
| 四圣试禅心(15) | fate=[渡,缘,逆] | 已正确（无战/夺），说明"按场景给选项"可行 |
| 高老庄 / 白龙马 | **数据中无此命名难目** | 数据已偏离原著，先要"补原著锚点"再谈选项 |

### 6.2 两条根因
1. **覆盖率滥用**：六道从"关键剧情岔路"退化成"每难必答的元菜单"。原著里大量难目是**纯战斗（妖来犯，你打）**或**固定叙事（无抉择）**，硬塞抉择反而稀释了"选道"的意义。
2. **场景错配**：即便给抉择，选项也不贴合该难剧情。"战+夺同框"就是典型——把"抢 Boss 法宝"塞进一个根本没有 Boss 可抢的难。

### 6.3 用户原始设想（权威口径）
- 不是每难都给六道抉择；**只对"剧情意义上的岔路"给**。
- 给的时候**按《西游记》该场景的真实可能性**混合 3-4 个选项：
  - 四圣试禅心（考心）→ 只给 渡/缘/逆（**不该有战/夺**）；
  - 高老庄（降八戒）→ 战（悟空打）或 渡（观音慈悲降服）；
  - 鹰愁涧/白龙马 → 第一次 战（斗龙），第二次可 渡（观音点化）或 隐（潜踪）；
  - 纯战斗难 → 可能根本不给六道，或只给 战/隐（打 or 避）。
- 进阶提议：**选项标签隐藏六道字眼**，玩家看到的是剧情选择（"拔剑相向""诵经化解""夺过鞭梢"），选完再按选项隐含的 fate 累加道途。

### 6.4 方案评估与推荐
- **方案 A（按场景精选 3-4 选项）**：方向正确，但本质是**逐难重撰作者内容**（需读原著锚定每难"能选什么"），工作量在文案不在代码。
- **方案 B（隐藏六道标签，后果累加）**：**更根治**——直接消除"元菜单滥用感"。玩家做剧情选择，fate 后台累加；道途进度放进独立的"道途"面板展示，不污染每难 UI。
- **推荐 = B × A 混合**：
  1. **先给每难打标 `daoChoice: none | curated`**：仅剧情岔路难给抉择（建议覆盖 ~40-50% 难，其余纯战斗/叙事无抉择）。
  2. **curated 难的选项重写为剧情文案**，不再显示【战】【渡】等前缀；每个选项后台带 `fate`。
  3. **首难(金蝉遭贬)作为唯一教学难**，仍展示全 6 道以教会系统；其余一律 curated。
  4. **道途进度独立面板**（ui_panel_2 已有"六道劫层数"位），让玩家随时看清自己偏哪条道、离双道共振还差什么。

> 与 §四 的关系：本节的"隐藏标签 + 场景精选"解决**抉择过载**；§四 的 Phase 0（六道发不同资源）解决**选了有什么用**；Phase 1（副道双式）解决**多套路手感**。三者正交：先治过载（本节），再治收获（Phase 0），最后治手感（Phase 1）。

### 6.5 重撰样例（模板）
- **四圣试禅心**：`[渡] 叩问禅心，受四圣点化` / `[缘] 以情动人，结善缘` / `[逆] 笑问四圣：你等可曾真悟？`（无战/夺）
- **高老庄（补原著锚点后）**：`[战] 棍棒相加，降伏呆子` / `[渡] 请观音慈悲，点化入僧`
- **鹰愁涧·初遇**：`[战] 与小白龙恶斗` ；**鹰愁涧·再临（同场景二次事件）**：`[渡] 观音座下听点化` / `[隐] 隐去龙身，随行西去`

### 6.6 落地顺序建议（均不改战斗公式）
1. **标记覆盖率**：给 81 难打 `daoChoice` 标（none/curated），把纯战斗/固定叙事难剔出六道菜单。
2. **剔除战+夺同框**等场景错配（19 难重撰）。
3. **隐藏每难六道前缀**，选项改剧情文案；fate 后台累加；道途进度移入独立面板。
4. 补 高老庄/白龙马 等缺失的原著锚点难目（或合并进现有难）。
5. 再叠加 §四 Phase 0（六道发不同资源）、Phase 1（副道双式）。

## 七、设计范式升级：从「选项菜单」到「剧情分支架构」（车迟国范式）

> 用户 2026-09-11 08:52 进一步给出**具体范式**：六道选项应**从《西游记》该难的真实剧情结构长出来**，而非通用菜单。以车迟国为例：三妖本为三场斗法，选项应「按原剧情斗法」+「战直接打怪」并存；打完三场后出现**三妖合体最终一战（一打三，极难，连打四场）**——这"如何通关这段难"才是抉择内容；也可选「隐」直接放弃车迟斗法、由妖怪继续占领车迟国。

### 7.1 为什么这个想法比"每难给几个选项"高一个层次
1. **六道从"身份标签"变成"这段难的玩法分支"**：抉择不再问"你是哪条道"，而问"你如何按原著处理此局"——选项天然从剧情长出，滥用问题**结构上消失**（无剧情岔路的难自然没有选项）。
2. **分支有真实玩法后果**：不同选法 → 不同战斗序列 / 不同区域结局，Roguelike 重开价值由此产生。
3. **仍完美映射到六道**：战=打怪 / 渡=按原著慈悲化解 / 隐=规避放弃 / 夺=掠夺 / 缘=机缘 / 逆=逆反。fate 后台累加机制（§四/§六）完全兼容。

### 7.2 车迟国 = 可复用的"范式模板"（用户细化版 · 2026-09-11 09:00）

用户进一步把分支规则钉死为**逐场独立抉择 + 条件高潮**：

- **三场斗法各自独立**：求雨 / 赌胜 / 灭僧（即现 81 难里的 28/29/30）**本就是三个独立节点**（`NDX.TRIAL_BOSS`：28=虎力大仙、29=车迟三妖、30=车迟狱卒，见 `js/trials81.js:1193`）。每场各自给玩家抉择。
- **每场可选 战 / 渡 / 隐**：
  - **战** → 直接打该场妖（如 28 打虎力、29 打鹿力、30 打羊力）；
  - **渡** → 按原著慈悲化解（观音点化），**跳过本场战斗**（不进 `fight`，仅 fate 累加 + 剧情结算）；
  - **隐** → 放弃该车迟斗法，进入"妖占车迟"分支（`chechiOccupied` 旗标置位）。
- **高潮条件触发**：仅当**三场全部选「战」** → 第 31 节点（现 `车迟三妖·合体`）升级为**三妖同框合体终战（一打三）**。只要有一场选了 渡/隐，则**不出现第四场**，直接按"斗法已了 / 妖占车迟"收尾。
- **疲劳问题被设计本身消解**：连打四场只在"全选战"这条最激进路线发生；选 渡 即自然跳过，玩家用"路径选择"为连战代价买单，无需额外场间补给机制。

> 这一细化正好回答了上一轮提出的三个闸门：疲劳 = 玩家路径自担；隐的后果 = 区域旗标；技术闸门 = 仅"一打三合体"需引擎支持（见 7.3）。

### 7.3 技术闸门实测结论（已逐一核验代码）

| 现状点 | 文件:行 | 结论 |

**关键修正（相比 7.3 上一版）**：所谓"必须先扩展遭遇引擎支持 sequential battles"**不成立**——三斗法本就三个节点，连打由现有节点链天然实现。**唯一真实的引擎缺口是"一打三合体"= `fight()` 不接受多敌实体**。其余（条件高潮、隐旗标、隐藏 fate）都是数据/轻量逻辑，不碰战斗内核。

### 7.4 最小改造方案（纯增量，低风险）

**改造 A · 复合怪物构造器（唯一引擎改动，约 30 行）**
- 新增 `NDX.compositeMonster(list)`：输入 `[m1, m2, m3]`，输出单一合成怪：
  - `hp = Σ 各怪 hp`（或按 `1 + 0.6*(n-1)` 折算，避免血条爆炸）；
  - `atk/matk = max(各怪)`（取其锋）；
  - `boss = true`，`tags` 合并，`behavior` 取最凶（boss 模板）；
  - `name = '车迟三妖·合体'`，`tier='boss'`。
- `fight()` 入口加分支：`if (Array.isArray(monster)) monster = NDX.compositeMonster(monster);` —— 之后管线完全复用，**不改 `calcCombat`**。
- UI 代价：演出层只显示一个敌名（"三妖合体"），可接受为 MVP。

**改造 B · 车迟国数据接线（数据 + ~20 行逻辑，不改内核）**
- 每场选项加 `fate` 与 `noFight`（渡/隐 不进 `fight`）：
  - 28/29/30 各加 `[战]打怪 / [渡]慈悲化解(noFight) / [隐]弃国(noFight)`。
- `s.flags.chechiDuels = [c1, c2, c3]`：每场抉择后记录（战/渡/隐）。
- **终战条件钩子**（挂在 `enterNode`/trial 结算后，判定 `s.pending` 是否为车迟第 31 节点之前）：
  - 若 `chechiDuels === ['战','战','战']` → `this.fight([虎力,鹿力,羊力], '车迟三妖·合体', 'elitereward', ...)`（走改造 A 的复合怪）；
  - 否则 → 正常推进，按"渡了n场 / 隐了"给对应叙事与奖励。
- **隐后果旗标**：任一选 `隐` → `s.flags.chechiOccupied = true`，后续（如祭赛国/玉兔线）可读取此旗标做区域结局分支与善恶/心魔微调。

**改造 C · 隐藏六道标签（沿用 §六 方案 B）**：车迟三场选项文案写为"斗法""直接打怪""隐遁弃国"，fate 后台累加，不显示【战】【渡】前缀。
