# 巨型文件拆分方案（P2 工程还债）

> 优先级：P2（版本迭代）
> 日期：2026-09-14
> 目标：将 5000+ 行的巨型文件拆分为功能单一的模块，降低维护成本、提升加载并行度。

---

| 文件 | 行数 | 大小 | 模块组成 |
|------|------|------|----------|
| **equipment.js** | 2408 行 | 266 KB | EQUIP_POOL + CRAFT_POOL + RECIPES + BOSS_REWARDS + TREASURES + SET_RESONANCE |
| **events.js** | 2408 行 | 256 KB | 157 个事件 + 事件触发逻辑 |

## 二、equipment.js 拆分方案（优先级最高）

### 2.1 拆分目标

将 equipment.js 拆分为 5 个功能单一的模块：

| 新文件 | 行号范围 | 内容 | 预计行数 |
|--------|----------|------|----------|
| `js/equipment/equip_pool.js` | 24-368 | 装备池 EQUIP_POOL（572件装备） | ~345 行 |
| `js/equipment/equip_craft.js` | 369-950 | 合成池 CRAFT_POOL + 配方 RECIPES | ~582 行 |
| `js/equipment/equip_boss.js` | 951-1047 | Boss 掉落 BOSS_REWARDS | ~97 行 |
| `js/equipment/equip_treasure.js` | 1048-1549 | 法宝库 TREASURES（47件法宝） | ~502 行 |
| `js/equipment/equip_resonance.js` | 1550-末尾 | 套装共鸣 SET_RESONANCE | ~859 行 |

### 2.2 加载顺序（index.html 调整）

```html
<!-- 替换原来的 equipment.js?v=504 -->
<script src="js/equipment/equip_pool.js?v=1" charset="utf-8" defer></script>
<script src="js/equipment/equip_craft.js?v=1" charset="utf-8" defer></script>
<script src="js/equipment/equip_boss.js?v=1" charset="utf-8" defer></script>
<script src="js/equipment/equip_treasure.js?v=1" charset="utf-8" defer></script>
<script src="js/equipment/equip_resonance.js?v=1" charset="utf-8" defer></script>
```

### 2.3 拆分原则

1. **每个新文件都是独立 IIFE**，挂载到 `window.NDX` 命名空间
2. **保留原文件头部注释**，说明该模块的职责
3. **不修改任何数据内容**，只做物理拆分
4. **原 equipment.js 保留为索引文件**（仅做 `import` 或保留空壳，方便回滚）

### 2.4 回滚方案

若拆分后出现 bug，直接在 index.html 中注释掉新文件，恢复原来的 `equipment.js?v=504` 即可。

## 三、events.js 拆分方案（第二优先级）

### 3.1 拆分目标

将 events.js 按事件类型拆分为 3 个模块：

| 新文件 | 内容 | 预计行数 |
|--------|------|----------|
| `js/events/event_story.js` | 剧情类事件（叙事+选择） | ~800 行 |
| `js/events/event_battle.js` | 战斗类事件（精英怪/Boss战） | ~800 行 |
| `js/events/event_reward.js` | 奖励类事件（装备/法宝/经文掉落） | ~800 行 |

### 3.2 拆分依据

按事件的 `type` 字段分类：
- `type: 'story'` → event_story.js
- `type: 'fight'` / `type: 'elite'` → event_battle.js
- `type: 'reward'` / `type: 'treasure'` → event_reward.js

## 七、收益

1. **维护性提升**：每个文件职责单一，改装备不用翻 2400 行
2. **加载并行度**：5 个小文件并行下载，比 1 个大文件快（HTTP/1.1 下尤为明显）
3. **协作友好**：多人开发时不会冲突在同一个 2400 行文件
4. **缓存效率**：改了套装共鸣只刷新 equip_resonance.js，不用重下 equipment.js
