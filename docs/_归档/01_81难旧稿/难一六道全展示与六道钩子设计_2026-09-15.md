## §1 难一·六道全展示方案

### §1.1 节点形态：采用「总览面板」，不新增独立事件节点

**结论：采用「难1 战后独立弹窗」形态 —— 以 UI 面板（总览卡）承载六道全展示。该面板代码中已实现，本设计只需「增强」而非「新增」。**

理由：
1. **数据源已存在**：`js/dao_system.js:267` `NDX.sixDaoCards()` 已产出六道总览卡数组（道名 / 描述 / 善恶 / 攻式 / 套装 / 升级石 / 经文），文件头注释即写明「供**难1战后弹窗** / 地图改道面板渲染」。本方案直接消费它，零新造数据源。
2. **不重复节点**：难1（`TRIAL_LIB[1]`）本身已是 `sixdaoSelect:true` 的六选一抉择节点（含 6 个道选项），UI 走 `ui_modals_2.js:70` `_sixdaoSelectModal`。**面板 = 抉择后的总览层**，与抉择点衔接，而非并列的第二个节点。
3. **可控"全展示"**：面板可一次性铺开六道全部要素（含逆道锁定态），保证用户要求的"对六道深刻认知"；事件节点受内容池抽取影响，无法保证六道齐现。

> **面板现状（已实现）**：`js/game/game_event_2.js:637-652` 已在难1 结算后弹「六道 · 道途既定」总览（`kind:'dao-overview'`），消费 `sixDaoCards()` 渲染每道的 名称/描述/善恶/攻式/套装/升级石/经文，并高亮 `current` 道；`js/game/game_region.js:287` 亦调用 `sixDaoCards()`。**本设计新增的只是"增强项"**：① 补「招牌钩子」文案（§3）；② 补「逆道锁定态」呈现（§1.3）；③ 补「六道影响深远」的提醒语（道路/装备/事件概率/隐藏职业，见 §2）。

### §1.3 逆道锁定态呈现

- **呈现方式**：灰显（置灰不可点），卡面保留全部要素（道名/描述/钩子/远期影响照常展示），另加"未启"角标——**先让玩家看到逆道之"异"，再告其"何以不可入"**，契合"对六道深刻认知"。
- **提示文案口径**：**复用** `DAO_TIP_LIB['逆'].guanyinTip`（`data_trial_tip.js:45`）原文：
  > 观音菩萨：逆者，逆天改命，不走寻常。我命由我，普度众人——此道最为凶险，须先炼成一世正果（完美通关）方得入此道，然一旦入道，天地皆为之侧目。

### §4.1 C1（原判"选道时机冲突"）→ **已降级为"陈旧注释勘误"**

### §4.2 C2 · 逆道门槛口径冲突

**三方口径**：
| 来源 | 口径 |
|---|---|
| 代码硬门槛 `canPickDao`（`data_config.js:110-114`） | 逆道需 **`hasPerfectClear()`**，即「完美通关（正果·春朝僧档）」，存档键 `xynj_perfect_clear_v1`，`s.over.ending.perfect===true` |
| 用户裁定（§0.2） | 「逆道提示**一周目后**开发」 |
| 成就系统注释（`achievements.js:202` / `:198`） | `req:'cycle2'` =「逆道成就（**V8.16 起一周目即可解锁**）」 |

**结论**：**确已构成口径冲突**。
- `canPickDao` 要"**完美通关**"（≠ 打完一次），而 `achievements.js:202` 说逆道成就"**一周目即可**解锁"。若玩家一周目走**恶线**（未完美通关）却拿到逆道成就，仍无法选逆道 → 门槛与成就语义不一致。
- 用户"一周目后"与二者**都不等价**（打完一周目 ≠ 完美通关）。

**两种口径取舍**：
- **口径 A（代码现状，推荐保留）**：逆道 = **完美通关（一世正果）后**才开。逆道定位"终极恶道"，是善果之后的反向二次挑战，与 `guanyinTip`「须先炼成一世正果（完美通关）方得入此道」**自洽**，叙事最稳。
- **口径 B（用户字面）**：逆道 = 打完任意一周目即开。更易触及，但削弱"凶险/应许"感，且**与 `guanyinTip` 文案直接冲突**，须同改文案。

**推荐**：**保留口径 A（完美通关）为硬门槛**，并把用户的"一周目后开发"读作"逆道功能**不在首周目体验内**、一周目之后才**开发/开放**该玩法"的设计意图——二者在"首周目不可选"这点上**一致**，分歧仅在"是打完即可，还是须完美通关"。
若用户坚持口径 B，则须**三处同源同改**：`canPickDao`（`data_config.js:110`）、`guanyinTip`（`data_trial_tip.js:45`）、`achievements.js:202` 注释——否则口径继续撕裂。

**待拍板**：采用口径 A（推荐）还是 B？

### §4.3 文案风格对齐说明

新增 6 条「玩家可见提示文案」（§3 矩阵第 3 列）严格对齐 `js/data_trial_tip.js` 既有风格：
- 统一**观音口吻**前缀「观音菩萨：」；
- 句式「**X者，〔四字〕，〔四字〕。**〔行为〕——此道〔褒/威〕，然〔限〕，需〔应对〕。」；
