# 《逆道西行》章节 Boss 三模式法宝钩子 + 九区域压缩设计案（v2 · 锁答复版）

> **v2 修订说明**：基于用户答复（80=阿难迦叶、渡也要打且奖励正常、Boss 用"语义化劫难状态"而非抽象难度系数）重写 §三/§四/§七。核心转向：**三模式 = 困难(无钩) / 正常·渡(持破除钩→公平战) / 加持(请菩萨→敌弱化)**，难度差异来自"劫难 gimmick 状态"而非乘算系数。
> 状态：纸面设计，未落地。黄风/白骨为**用户确认样板**，其余 7 Boss 为**提案待签**。

## 一、Fun Hypothesis & Design Pillars

**一句话**：玩家每推进一章，面对一个有名字、三阶变身、持专属法宝可破的标志性 Boss；"攒到对的法宝"把硬仗打成智取——九座 Boss 是九道阶梯，81 老鼋是隐藏 Heart。

**Design Pillars（不可妥协）**：
1. **每章一个高潮锚点**：9 章末 Boss 全是三阶变身超级 Boss，不是白龙马式过渡节点。
2. **法宝即难度杠杆**：持对应钩子 → 战斗从"劫难满状态"降为"公平战/弱化战"；不持 → 硬打。把"为开门禁硬刷"转为"为下一章 Boss 备钩子"的正向构筑。
3. **红劫印是章节勋章**：每章 Boss 必掉红劫印，9 章 = 9 红劫，可感知的台阶式成长。
4. **压缩而非删减**：九区域靠"复合劫难 + 节点收缩"砍掉 grind 节点，内容量不降、刷怪感归零。

## 四、章末战斗 = 语义化劫难状态机 + 剧情驱动第三变体（核心，取代抽象系数）

**两档通用基底**（所有章末 Boss 通用）：

| 模式 | 触发 | 战斗表现 | 难度来源 |
|---|---|---|---|
| **困难·硬打** | 未持破除钩子 | Boss 三阶全开 + gimmick 满状态（如 80% miss / -80% 伤）；`breakWith` 不匹配 → 破韧窗口提示"未携克制法宝" | 劫难惩罚全生效（基准 diff） |
| **正常·渡** | 持破除钩子（多由前置【渡】事件获得） | 钩子命中 `breakWith` → 破韧窗口激活；`cleanse` 化解 gimmick，公平战 | gimmick 失效（由 debuff 幅度决定，**非硬乘算**） |

**第三变体 = 剧情驱动，不强行请菩萨（v2.1 修订）**：废弃「每章统一做请菩萨第三档」的旧提案。每章末的**签名高潮结构**由《西游记》原剧情决定——观音收服系走「请菩萨·敌弱化」；斗法/降妖系走「多 Boss 同场 / 连战分支」。设计原则：**钩子与高潮形态必须可在原著找到出处**，不发明无原型的机制。

**用户确认样板**（黄风 / 白骨）：
- **黄风大圣**：困难 = 召唤黄风 → 玩家 `blind` 80% miss（数值可调，可改"物理攻击丢失、法术没事"）；正常 = 前置事件得**定风珠** → 三昧神风失效，公平战；加持 = **请菩萨得飞龙宝杖** → 不仅失效，Boss 获 `恐惧` 全伤害-20%。
- **白骨夫人**：困难 = 人形态，唐僧不忍下手 → 玩家 `atkDown` 伤-80%；正常 = 持**照妖镜** → 显出原型，可**跳过人形态战斗，直接进入白骨形态**。

**车迟国·三仙斗法（剧情驱动第三变体·参考实现）**：原著车迟国虎力/鹿力/羊力三大仙与悟空斗法。落地为**章末复合弧的签名高潮**，两种路线：
- **斗法·渡路线**：三仙同场一战（玩家持【渡】支线得的照妖/破法钩 → 三仙被破法削弱，一场收掉）。对应原著"智取斗法"。
- **战路线**：连打四场（虎力→鹿力→羊力→三仙合力真身），无钩硬抗，奖励同正常但红劫/法宝照给。对应原著"硬碰硬降妖"。

> 此例说明：第三变体不是"请菩萨"的同质档，而是**每章按原著长出的独特高潮**。观音收服系（红孩儿/金鱼精/玉兔）= 请菩萨·敌弱化；斗法系（车迟）= 多 Boss 同场 / 连战分支；照妖系（白骨/六耳）= 显形跳形态。钩子与结构皆有原著出处。

**渡的定义修正**（v2 关键）：渡 **也打 Boss**，奖励与正常相同。渡是"通向持有破除钩子的前置路线"（如黄风前置【渡】事件得定风珠），而非"跳过战斗"。三模式是战斗态，渡是叙事路线。

**引擎接线（全部复用现有）**：
- 困难/正常：`breakWith` + `cleanse` 已通（§二）。只需给各 Boss 填 `breakWith` 并确认 debuff 调度。
- 加持：在 Boss 数据加 `blessTreasure`（如 飞龙宝杖），开战判定持有时给 Boss 挂 `fear`(-20% dmg) 或复用 `slow`。
- 白骨 phaseSkip：Boss 数据加 `phaseSkipOn:'zhaoyao'`，战斗脚本检测到持照妖镜则跳 phase1 直入 phase2。
- 渡路线：Boss 前置 trial 的【渡】选项 reward 给对应破除钩子法宝（仿 `trials81.js` 白骨 `夺回舍利超度` 范式）。

## 五、九区域节点压缩（治本：砍刷怪量）

**现状痛点**：原每区域靠若干独立 mob/event 节点凑门禁条件 → 无尽刷怪（用户实测"刷吐了"）。

**方案**：每章收束为 **1 复合劫难弧 + 1 章末 Boss**：
- 扩 `compoundFor(act)`：每章 act 定义 1 复合节点（合并 3–4 子难：教学战 + 事件抉择 + 精英），连续不可退避，通关一次性厚赏。
- 收缩独立节点：散落 mob/event/treasure **并入**复合弧或章末前短链，地图可见节点数降一个量级。
- 子 Boss（黄袍/车迟/蝎子/牛魔王/黄狮/大圣残躯）改为复合弧内"弧中高潮"，非独立地图节点。
- 内容量（81 难叙事）**不删**，从"81 平铺节点"改为"9 复合弧 + 9 章末 Boss + 少量事件"。

### 12.3 关键技术发现：`layers` 不可取 9（隐式线性契约）

首次把 layers 设为 9 → **门禁当场抓出 `act8 缺[67]`**。

根因：`_assignTrialDiffs` 的「层号 → 难号」是**线性映射** `g = actStart(act) + L - 1`。ch8 的 `actStart = 59`，故：

```
难67 的自然层号 = 67 - 59 + 1 = L9
```

而 `layers = 9` 时 L9 就是关隘 Boss 层（`L < LAYER_COUNT` 不参与配额，见 `_capTrialNodes`）→ **全章唯一未入弧的非 Boss 难号无处承载**。改为 `layers = 10` 后 L9 承载难67、L10 为 Boss，承载恢复完整。

**这条隐式契约是融合设计的天花板**：弧必须整体排在「线性映射不重叠区」之前，且 `layers` 必须满足 `actStart + layers - 2` 覆盖到最后一个未入弧的难号的下标。改造其他章时须先验算这一点，不能只按「格数目标」拍层数。

## 十三、PHASE 7 · 第二章劫难融合（紧凑分配）+ 线性映射天花板 + 全章空层普查

### 13.1 先纠正 PHASE 6 末尾的一个乐观结论

PHASE 6 说 ch2「可各并 1 弧 → 压到 7 层」。**照当前架构做不到**——不是内容问题，是算法问题。

`_assignTrialDiffs` 用**线性映射**把「层号 → 难号」钉死：`g = actStart(act) + L - 1`。融合弧一旦吃掉某层的 `g`，该层只能降级为纯填充层，而**后续层的 `g` 不会自动前移**。所以：

| 方案 | layers | 结果 |
|---|---|---|
| 线性法 + 两弧 + layers=9（现状式改法） | 9 | L3/L4 因 `g=16/17` 被弧吃掉而**空转成两个无劫难层**——加弧不省层，反而凭空多出空层 |
| 线性法 + 两弧 + layers=7（硬压） | 7 | **难 20/21 漏承载**（它们的自然层号 = 8/9，超出 `L<7` 的循环范围） |

第二行已用反证脚本实测复现（`_rebut_p7.js`：`compact=false + layers=7` → 漏承载 `20,21`、空层 `L3,L4`）。这是 PHASE 6 记下的「layers 不可取 9」天花板的更一般形态。

### 13.2 解法：`compact` 紧凑分配（难号游标）

`COMPOUND_NODES[act].compact = true` 时，`_assignTrialDiffs` 由「层号线性映射」切换为「**难号游标**」：

- 维护 `cursor`，先跳过所有**入弧难号**与**已转缘难号**（`_advance()`）；
- 每个可承载层按顺序消费一个游标值 → `layers` 得以**真正小于章内难数**，且不留空层；
- 融合弧层不承载单难（`_demoteRow`），该校由弧的 `fusionDiffs` 逐难推进；
- **未声明 `compact` 的章行为完全不变**（仍是线性映射）——爆炸半径收敛到显式声明的章。

同步修 `_ensureHiddenTrials` 的层号定位：compact 章的难号不再满足 `L = g - lo`，改为**先查「哪一层已绑该难号」**（读 `fixedTrial`），命中即交给 `hasTrial` 自然 return；未命中再回退线性映射。
