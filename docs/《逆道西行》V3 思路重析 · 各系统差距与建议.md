# 《逆道西行》V3 思路重析 · 各系统差距与建议

> 整理日期：2026-09-05 ｜ 依据：《逆道西行_系统简化与肉鸽核心回归_融合设计文档_V3.md》
> 方法：以 V3「抉择铁律」三分类（该砍=就地管理 / 该留=决策权 / 该补=运气核心技术）逐系统对照当前代码实装。
> 目的：厘清「当前实装 vs V3 目标」的每一项差距，给出**分级处置建议**，供后续会话按序落地。
> 结论速览：**三个核心差距**——① 劫印仍有「生效格+品质堆叠表」两处就地管理未砍；② 经文「集齐自动合成即生效」恰是 V3 明令取消的"无脑生效"，无"投向道途"决策；③ 死亡增强仍以劫灰坊/轮回赐福做**纵向涨数值**，违反 V3"只拓宽玩法不过线"。

## 一、劫印系统（Jieseals）↔ V3 §一 → 处置：**P0 砍管理**

**落点**：`js/jieseals.js`，辅 `combat.js computeStats`、`ui/ui_bag.js` 等。

### 1.1 已保留（V3 §1.1 ✅ / §1.5 符合部分）
- **三选一道途劫印** ✅：`offerSeals` / `offerSealsAligned` 各返回 3 枚；主道途恒在候选池（`pool=[main]`）。
- **道途加权**（近似§1.5 轻度倾向）：`HERO_MAIN_DAOTU` 主道途加权 + `data_config.HERO_HOME_DAO ×1.25` 本命道放大 + `SEAL_STARVE_THRESHOLD` 善系主道途饥渴提档（white→blue）。
- **脸好拿高档印**（§4.6 正反馈）：Boss 掉金劫、土地庙概率出蓝/金。

### 1.2 未砍的管理（V3 §1.1 ❌ 两项 · 就地管理残留）
> **① 生效格与换装** —— 仍在手动管理，V3 明令"劫印不入装备格、自动累计"。
- `sealSlotCap(s, daoxinTier)`：按章 + 转职AREA扩格 + 道心浮动（深渊−1/明镜+1）+ 硬上限 `SEAL_SLOT_MAX=14`。
- `addSeal` 里 `seal.active` 判定 + `toggleSealActive`（捺存/换上）+ `activeSealsFor`（够上限后自动从其余补齐）。
- `totalTier`「每完成一阶转职 +1 生效格」→ `SEAL_SLOT_BASE + SEAL_SLOT_PER_TIER`。

> **② 品质数值堆叠表** —— 四档（白/蓝/金/红）+ 一整套铸造/互换操作，V3 只需"等级台阶、不需玩家管理"。
- `SEAL_TIER_CHAIN`（白3→蓝、蓝3→金、金3→红）、`SEAL_RED_MULT=1.55`、红色就地补档。
- 高阶管理：`composeSeal`（铸印）、`swapSealStart`（同阶相易·2换1）、`redSwapSeal`（红印易异）、`rerollSealStart`（2换1·三选一）、`sealShopOffer/buyShopSeal`（土地庙购印）。
- 每枚印 `tier` + `val=tiers[tier]` 百分比 → `computeStats` 非线性累加。

### 1.3 阈值机制不同（V3 §1.3 → △）
- **现**：劫印加成 = 每枚独立百分比（`bonus.seals.xxx` 逐枚并入 computeStats）。
- **V3**：每道途 **3/6/9/12 层数阶段碑**（如 渡3=法伤+5%，渡6=法伤+10%回蓝2%…），层数按「该道已得劫印数」计。
- 现状无「道途层数 → 阶段效果」单一真源；`DaoSystem.calcDaoStats` 有道累计，但**未派生 V3 的 3/6/9/12 阶段加成**。

### 1.4 极品劫印语义（V3 §1.4 → △）
- **现**：金印 = `gold` 数值（≈1.67×白），红印 = `×1.55` 金，靠合成获得。
- **V3**：金=2个普通、红=3个普通，**按"计数折算"计入道途层数**（脸好=一次顶两三枚，推层数走）。
- 语义差异导致"金红印对层数快进"的正反馈在现状中不成立。

### 1.5 建议（按 V3 §1，P0，成本可控）
1. **砍生效格**：删除 `active` 手动管理，`activeSealsFor`/`sealSlotCap` 收敛为「全部已得劫印自动累计生效」（只留 `impactful`），UI 删"捺存/换上"。一次级改动，副作用是移除"转职扩格"奖励——改由 V3 §6 协同共鸣承接该奖励位。
2. **砍品质堆叠/铸造**：保留"白/蓝/金/红"作为**稀有度稀有度标签**（脸好正反馈），但**去掉合成链与互换操作**（铸印/相易/易异/2换1/土地庙购印全部下线）；金印落地=2 层、红印=3 层计层数，而非数值×倍。改动大但删代码为主。
   - 折中（最小改动、保脸好）：**保留金/红印的"价值高"呈现，但把其效果显性化为"等值 2/3 枚普通"计入道途层数**，数值堆叠改为层数堆叠——`offerSeals` 每生成金/红印记 `layerVal:2/3`。
3. **补轻度道途倾向**：`offerSeals` 候选道途按 `DaoSystem.calcDaoStats` 已投数加权（投渡多→渡印概率升），保留全局阈值保底；`HERO_MAIN_DAOTU` 作为首项偏好保留。

## 二、经文系统（Sutra）↔ V3 §二 → 处置：**P0 引入投向决策**

**落点**：`js/data_sutra.js`、`js/data_sutra_shard.js`、`data_sutra` 的 computeStats 管线。

### 2.1 现状
- 自动碎片收集 ✅：渡经 16 部按地区池 + 逆经 9 部按未完成池，碎片三选一/自动落。
- **集齐自动合成并直接生效**：`grantSutraShard` 在 `full.frags.every(≥1)` 时 `s.sutras.push(full.id)`；逆侧 `tryCombineNiSutra` 自动合成。全本读 computeStats 提供被动战力。
- 主道途归属：`SUTRA_COUNT_BREAKPOINTS`（数量档全属性）+ `SUTRA_DAO_BONUS`（按 `playerDao()` 推断主道，给该道专属加成 / 渡=法伤 战=物攻…）。
- 长线：六道归类 + 拓印跨周目（§12 承继体系，保留）。

### 2.2 差距（V3 §2.1/2.3/2.4）
1. **✕ 无"经文背包 + 关键节点投向道途"决策**——V3 ❌项"合成后不在掉落瞬间无脑生效"正是当前默认行为。全本合成即生效，玩家**零决策**。
2. **△ 每经不绑道途、无道途经文槽位**——16 部渡经无 `dao` 标签，无法"投向渡槽/战槽"；主道途加倍是 `SUTRA_DAO_BONUS` 全局一次，非"每经对该道加倍"。
3. **△ 主道途加倍缺失**——V3 同一经对当前主道途加权；现状经文本体不区分对哪道加成更大。

### 2.3 建议（按 V3 §2，最小改动版 = §2.5 自动路由 / 完全版 = §2.3 背包投向）
- **完全版（§2.3，决策权更足）**：每经实体加 `dao` 字段（心经→渡、金刚经→战…）；合成后**不自动生效**，入 `s.sutraBackpack`；章末/露营「投向道途」把整本投向某道槽位（每道一槽，可换投）；对当前主道途效果×1.5。**保留决策权即肉鸽手感，但改动横跨 data/合成/UI/结算。**
- **自动路由版（§2.5，改动小、保留养成导向）**：合成后自动并入**当前主道途**生效，同一经对主道途加倍；背包仅作"待投/已投"展示，不新增决策点。适合预算紧。
- **共性小改（必做）**：把"集齐自动合成"改为"集齐入背包 + 一次轻提示"，避免"掉落瞬间无声盖帽"；经文加 `dao` 标签以支撑上述任一版。

## 三、死亡增强 ↔ V3 §三 → 处置：**P0 去纵向、补横向渐进**

**落点**：`js/data_reincarnation.js`（劫灰坊 ASH_SHOP / 轮回赐福 favorBonus / 承继）、`data_heroes_data.js`（英雄解锁）。

### 3.1 现状 → 纵向数值（V3 §3.1 明令拆除）
- **劫灰坊五线永久升级** `ASH_SHOP`：金蝉余韵(+2%全局气血)、逆心初萌(+1.5%全局伤害)、六道亲和(+5%劫运)、法宝共鸣(+1初始充能)、劫印拓印(+1永久槽)。**前两条/三条 = 纵向 +%**。
- **轮回赐福** `favorBonus(progress, cycle)`：每点失败累计 → 攻+1 / 气血+2 / 减伤+0.01 / 法强+1 / 法抗+1。**纯纵向**，二周目起生效。
- 承继（遗物/经文/劫印跨世）属横向"带家当"，与 V3 §12 承继体系一致，**保留**。

### 3.2 现状 → 横向解锁，但**非死亡渐进**
- 英雄：`unlockedHeroes()` 初始仅取经人，**取经人通关一次 → 一次性解锁四英雄**（`unlockNext`），无"每次死亡解锁1个"渐进。
- 转职：隐藏职业 = 六道 fate≥3 / 逆道完美通关（`canPickDao('逆')`）。
- 装备掉落：软 pity 保底（`EQUIP_PITY_THRESHOLD`）。
- **V3 §3.2 想要的"每次死亡解锁1个新英雄/经文/事件/转职/装备（累积上限）"横向链路不存在**；死亡只产出劫灰 → 劫灰又被劫灰坊转成纵向数值。

### 3.3 建议（V3 §3，改造核心）
1. **去纵向**：劫灰坊 `金蝉余韵/逆心初萌` 从"全局+%气血/伤害"改为**横向解锁**（如"解锁一本专属经文进池/解锁一件新掉装进池"）；`六道亲和`(骰率) 与 `劫印拓印`(槽位) 属"工具/解锁型"，可保留。轮回赐福每点+攻/血改为只保留"保底不掉落/商店保底已集残片"式**感受性保障**（§3.3 可选兜底），不做乘法攻血。
2. **补死亡渐进横向解锁**：`unlockedHeroes`/事件池/转职池/掉装池增加"按累计死亡次数解锁下一项"的轻链路（可复用软 pity 结构），每死一局＝有横向正反馈。
3. **保留可重置开关**（§3.4）：若已有纯肉鸽模式，确认入口存在；无则补一个"重置传承"开关。

## 六、全局落地优先级建议
