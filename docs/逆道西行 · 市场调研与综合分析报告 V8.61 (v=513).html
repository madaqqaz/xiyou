一、执行摘要

项目定位：黑暗西游题材、单局 Roguelike 构筑（Slay the Spire-like），纯前端 H5，规划三端（浏览器 / 微信小游戏 / TapTap 买断）。

核心优势：内容厚度已达商业级（81难按原著地理重排、237 敌人、572 装备、26 套装、47 法宝、36 经文、144 成就），六道善恶叙事钩子鲜明，寿数系统提供了同类游戏罕见的"时间压力"维度。

核心风险：① 音频完全缺失（氛围型游戏静音即致命）；② 微信小游戏工程未实际落地（无 project.config.json、100MB 图片 vs 4MB 首包硬上限）；③ 战斗为"自动对轰+三键"，操作深度与竞品（杀戮尖塔的牌组构筑、月圆之夜的职业分化）相比偏弱；④ 系统数量多但交叉验证不足，玩家可能感知到"系统多而不痛"。

建议优先级：P0 = 音频补齐 + 微信工程落地 + 战斗手感强化；P1 = 系统间协同可视化 + 新手 30 分钟留存；P2 = 平衡调优与内容扩充。

三、玩法维度分析

3.1 核心循环

地图走格子（节点类型：战斗/精英/事件/商店/休息/Boss）→ 81 难抉择（六道善恶）→ 回合制战斗 → 装备/法宝/劫印掉落 → 构筑成型 → Boss 关隘 → 下一 Act。这是成熟的 Slay the Spire 骨架，结构无硬伤。

3.2 战斗手感

现状：战斗为自动对轰 + 玩家手动三键（攻=普攻 / 经=诵经回血 / 绝=大招）+ 法宝祭出。伤害公式 GLOBAL_DMG_MUL = 0.5，有灼烧/反伤/护盾/破甲/吸血等状态。

问题：

  • ① 自动对轰占比过高，玩家三键的"决策密度"不足——多数时候只是按节奏点攻击，缺乏杀戮尖塔"手牌选择"式的每回合决策。
  • ② 气势/爆发/识破窗口机制已引入（V8.5x 观音偈语教学），但属于"限时反应"而非"构筑决策"，与肉鸽的核心爽点（提前构筑）关联弱。
  • ③ 敌人 237 个，但敌人行为模式（pattern）若只是数值变化，玩家会感到"换皮打怪"。

建议：将"三键"升级为"每回合从 3 张临时行动卡中选 1"（类似《为了吾王》/《暗黑地牢》的行动点制），把构筑与即时决策挂钩；或引入"怒气/禅意"资源条，强制玩家在"经（防守）"与"攻（进攻）"间做取舍。

3.3 构筑维度交叉

游戏同时存在 6 个构筑轴：装备（26 套）× 法宝（47）× 劫印（8）× 经文（36）× 宠物 × 六道善恶。轴多本身是优点，但玩家在 30 分钟单局内能否感知到协同是关键。代码中已有"跨系统协同网络"，但 UI 上是否让玩家"看见"这条协同线，决定了构筑深度是爽点还是噪声。

6.3 内容风险

  • 宗教合规：此前已识别"谤佛金蝉/碎佛像/假佛"等敏感表述，整改方向是"矛头对准人间怪相而非宗教本身"。需在提审前全文复读 难1/难33/难56 等高风险节点。
  • 寿数系统：27 岁西行、55 岁大限，每节点扣寿——这是差异化亮点，但也可能造成"玩得越快越好"的焦虑感，与肉鸽的"放松构筑"调性有冲突，需通过土地庙回寿、行善不折寿来平衡。

8.2 目标用户画像

  • 核心：25-40 岁、西游文化爱好者、玩过杀戮尖塔/月圆之夜、接受买断制的硬核玩家。
  • 扩散：微信小游戏泛用户——但横屏+买断与微信生态的"竖屏+免费+广告/内购"习惯冲突，TapTap 买断版才是主阵地。

8.3 商业化判断

TapTap 买断制（无广告、无内购、离线可玩）与游戏内容厚度匹配，定价区间建议 ¥12-18（对标月圆之夜 DLC 单职业 ¥6-12，我们内容量更大）。微信小游戏若走"免费+广告激励视频复活"会破坏买断承诺，建议微信端定位为"试玩前 3 难 + 跳转 TapTap 购买"的引流页，而非独立商业化版本。
