## 三、重点系统调优说明

### 1. 分支路径难度 / 结局可达性 / NPC 关系幅度
本批 20 处标记**实际分布**与任务模板预设的「刘洪 5 分支 HP/攻击、10 结局触发条件、NPC 关系 ±5~±15」并不重合——这些属于 `data_favor.js`、`endings.js`、分支事件数据，**本批没有落在它们上面的 `[平衡待调]` 标记**。本轮未触碰前三难原文原选项（硬约束遵守）。分支/结局/好感数值的独立调优需另开一轮审计，见 §五。

### 2. 复合选项增强联动增益幅度（任务要求 10~20%）
唯一相关项是 `combat.js` 的 `TREASURE_SYN`：
- 六道同源 `daoMatch=1.25`（+25%）、经文共鸣 `sutraMatch=1.15`（+15%）、额外 proc `+0.06`、总 proc 封顶 `0.35`。
- **`sutraMatch +15%` 已落在 10~20% 区间**；`daoMatch +25%` 略超上限，但**被门禁逐位锁死不得改**，且 procCap 0.35 + Boss 限时豁免已防滚雪球。结论：设计自洽，保持。

### 3. 全 81 难差异化后 effect 数值一致性（任务要求同类 effect 无数量级差）
对 `data_sutra.js` 经文招式模板做了同类 effect 横向审计：
- 续航/护盾/吸血三类「攻击版」均为 0.22、「绝招版」均为 0.40 —— 完全一致。
- 真伤类：`veil-mantra` atk 0.25（带必中）、`break-mantra` atk 0.20（带破甲）—— 差 0.05 来自附带语义，非数量级差。
- 暴击类 `war-buff` atk 1.18 / ult 1.25 —— 单段乘区，合理。
结论：**无数量级差异**，无需拉平。

### 4. 真正改的 3 个数值为何不破坏平衡
- `HALF 4→5`：只把「一半池加成」的到来点从 fate=4 推到 fate=5，渐近上限仍 1.5，分布类门禁（600 样占比阈值）富余充足。
- `LUX_CHANCE 0.22→0.18`：纯概率下调，奖励强度（必得金/红 + 1.6 金）不变，只降频率；4000 样统计门禁 ±0.05 区间覆盖。
- `_gold 120→150`：单点兜底数值，无任何门禁或公式引用，且 primary 路径（给红劫）不变。
