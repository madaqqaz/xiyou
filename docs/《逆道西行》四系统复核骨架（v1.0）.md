## 二、四系统定位与耦合（骨架核心）

```
        路线（六道：战 渡 缘 夺 隐 逆）—— 统一语言层
                     │
      ┌──────────────┼──────────────┬──────────────┐
      │              │              │              │
    装备            转职           技能           宠物
 （外挂数值）    （身份/流派）   （出手方式）   （第二战力）
      │              │              │              │
      └── 提供槽位 ──┴── 决定变体 ──┴── 消费被动 ──┘
                     │
              战斗结算（体/愿双体系）
```

| 关系 | 定义（本骨架裁定） |
|---|---|
| 装备 → 技能 | 装备只提供**触发条件**（法宝联动 status），不提供技能本体；技能本体只在技能总表 |
| 转职 → 技能 | 转职（含隐藏职）只决定**大招变体 + 流派标签**（`JOB_STYLE`→`ULT_STYLE_MOD`），不改普攻/诵经本体 |
| 宠物 → 装备 | 宠物占一个装备槽，但**不是装备**：有独立战斗行为，需独立数据真源 |
| 技能 → 战斗 | 所有出手统一走 `combat_part1.js` 回合内核；外围 7 个 skill_*.js 只允许读总表，**禁止各自定义倍率** |

## 三、逐系统骨架

### 3.1 技能（重做结构 · P0）

**定义（待拍板）**：技能 = 「一次出手的完整描述」，四类且只有四类：

| 类 | 内容 | 现有来源 | 骨架要求 |
|---|---|---|---|
| A 普攻变种 | ATK_VARIANTS 10 | `ATK_VARIANTS` | 并入职总表，字段统一 |
| B 诵经变种 | CHANT_VARIANTS 10 | `CHANT_VARIANTS` | 同上 |
| C 大招变体 | ULT_STYLE_MOD 10 × JOB_STYLE 45 | 两者交叉 | 骨架裁定：**由转职单向驱动**，不做二维矩阵全展开 |
| D 战斗干预 | 识破 / 气势爆发 | `combat_skills.js` | 独立一类，不并进 A/B/C |

**最小字段（骨架层，新增技能必须填全）**：
`id` · `name` · `类(A/B/C/D)` · `体/愿归属` · `倍率` · `消耗` · `冷却` · `附带status` · `六道标签` · `解锁来源`

**外围 7 文件收口规则**（新增）：`skill_build / skill_upgrade / skill_synergy / skill_combo / skill_timing / skill_feedback / skill_cooldown_ui` —— 只读总表，**不得持有倍率常量**（现有 `combat_part2.js:747 CFX_PET_SYN=12` 属违规，随宠物骨架一并处理）

**待决项**：
- S1：C 类是否真需要 45×10 展开？建议按 `JOB_STYLE` 分组只做「流派→大招」映射（10 条以内）
- S2：D 类（识破/气势）是否算技能？建议算，但单独面板

### 3.4 宠物（先定性 · P0 待拍板）

**这是唯一一个「要不要存在」都没定的系统。**

| 方案 | 定义 | 成本 | 骨架建议 |
|---|---|---|---|
| **P-A 装备化**（推荐） | 宠物 = 装备槽内的被动提供者，不出场、不独立养成 | 低（现状即如此） | 只需补一份 `PET_DATA`（id/被动/羁绊/六道），立绘已有 |
| **P-B 半独立** | 宠物有独立等级/出战槽，战斗追加真伤（已有 `CFX_PET_SYN`） | 中（需养成线+UI） | 需新建 `data_pet.js` + 养成消耗设计 |
| **P-C 完整伙伴** | 独立单位、独立行动回合 | 高（战斗架构需改） | 不建议（当前战斗是「一次性预结算+回放」，逐回合决策不可行） |

**骨架裁定（暂定）**：走 **P-A**，理由是战斗架构限制（`calcCombat` 只调一次，逐回合输入无法回灌 —— 见架构记忆）导致 P-C 不可行；P-B 需新增养成线，与「路线配装 BD」主玩法抢资源。

**必须先解决的命名冲突**：`随从` 一词让给**敌方**（精英/Boss 前置肉盾），玩家侧统一叫 **灵宠**。

## 四、统一语言约束（跨四系统）

1. **六道词汇**只用「战 渡 缘 夺 隐 逆」（`DAO_LIST` 单源），四系统的标签、掉落、被动名一律对齐
2. **单源**：每系统一张总表，外围文件只读不写；新增条目先改总表
3. **代码改动**须递增 `index.html` 的 `?v=NN`
4. **门禁**：改动后跑 `node scripts/_run_all_gates.js`（唯一真源；`_audit_*` 5 个不被自动发现，需手动补跑）
