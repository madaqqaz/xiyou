## 二、本轮落地（✅ 已完成）

### 2.1 装备：获取途径 + 六维标签（**派生函数**，非手写字段）

> 为什么派生：466 件装备手写 `source` 字段 =  一场必然腐化的苦役，且极易沦为**死字段**
> （写入端有、读取端无）。派生则是改数值即自动更新，且天然有消费点。

新增 `NDX.equipSource(e)` 与 `NDX.equipTags(e)`：

```js
NDX.equipSource(e)   // → 事件掉落 | 冒险日记 | 宝窟合成 | 随机掉落
NDX.equipTags(e)     // → { 减伤, 增伤, 暴击, 闪避, 吸血, 反伤, 套装, 隐藏, 可进化, ... }
```

映射规则（全部从既有字段推导，零新增数据）：

| 派生值 | 判据 |
|---|---|
| `冒险日记` | `e.diary === true` 或 id 属 `DIARY_EQUIP_IDS` |
| `事件掉落` | `e.eventOnly === true`（上一轮新增的 20 件 `TRIAL_DROPS` 即此类） |
| `宝窟合成` | `NDX.CRAFT_POOL` 内含 或 有 `craftHint` |
| `随机掉落` | 其余（进 EQUIP_POOL 的常规件） |

六维标签按数值阈值派生 —— 与图鉴「闪避 暴击 格挡 无敌 幸运 增减伤」一一对应：

| 标签 | 判据 |
|---|---|
| `减伤` / `增伤` | `dr >= 0.05` / `dr < 0.05 且 dr > 0`（减伤为正向价值） |
| `暴击` | `crit > 0` |
| `闪避` | `eva > 0` |
| `吸血` | `reflect > 0` |
| `套装` | 有 `set` 且 `setTier >= 1` |
| `隐藏` | `eventOnly` 或 `diary` |
| `可进化` | 有 `evolveTo` / `evoTo` |

**消费点**：装备详情弹窗（`ui_modals_1.js` 装备卡）与背包列表展示标签 chip，
与已有 `reso-chip` 样式同构，不新增美术。

### 2.2 转职：职阶层级（派生）+ 玩法评测（文案）

`NDX.jobTier(job)` 从 `chainId` + 链内序号派生，对应图鉴「战士普转 / 守护骑士二转」层级：

| 派生职阶 | 判据 | 数量 |
|---|---|---|
| `本相` | 链上前 2 步 | 14 |
| `进阶` | 链中 3–4 步 | 6 |
| `终极` | 链尾（最后 1–2 步） | 5 |
| `孤本` | 无链独立职 | 12 |

`NDX.jobReview(job)`：45 职逐条**玩法定位**文案，对应图鉴「评测」列。
示例（取自既有 `note` 与流派，不新增设定）：

| 职 | 评测 |
|---|---|
| 判官金蝉 | 结局向终职，赢的是「判」而不是「打」 |
| 持棒证道 | 悟空线数值终点，全链增益在此收口 |
| 驯兽师·百兽归心 | 宠物格 2→6，养兽流专用 |

**消费点**：总览页「本局转职链」改为带职阶徽章的链（`ui_misc_2.js:712`），
鼠标悬停显示玩法评测。

### 2.3 事件：选项条件门槛 + 可重刷语义

> ⚠ 落地过程中修正了 §1.3 的一处判断：逆道**并非**「option 级没有门槛字段」。
> 网状叙事 P0/P1 早就写了 `requireFlag / requireFlagNot / requireLock / requireRel`，
> 引擎读端在 `game_event_4._optionGate`。真问题是 **三个字段只写不判**（见下表）——
> 玩家能选到作者明确写了「未请神、未用法宝」才该排除的选项。

**实测：3 个门槛字段是死字段（14 处数据，零读取端）**

| 字段 | 数据处数 | 引擎读端（落地前） | 语义（依 `consequence` 文案反推） |
|---|---|---|---|
| `requireNoTreasure` | 9（ch2×2 / ch8×2 / ch9×3） | ❌ 零 | 「未请救兵、未用法宝纯凭实力击败」⇒ 不得持该法宝 |
| `requireFlagNot` | 4（ch2 / ch3×3） | ❌ 零 | 「（悟空主角·未选隐）」⇒ 不得落过该印记 |
| `requireHero` | 1（ch2） | ❌ 零 | 「（悟空主角…）」⇒ 限该英雄主角 |

**本轮处置**

1. `game_event_4._optionGate` 新增规则⑦，把上述三字段接进判定。全锁兜底由既有的
   `_optGateCtx` 提供（`P0-6` 死锁修复），不会造成新死锁。
2. `NDX.optionCondText(opt)` —— 把门槛字段翻成玩家读得懂的一句话
   （`须先 · 第15难「请观音，遣木叉收伏」` / `不得持 · 照妖镜` / `限 · wukong`）。
   ⚠ **只认门槛字段**；`effect.good / alignGood` 是「善+N」的**收益**，不是门槛，切勿反读。
3. `NDX.optionCondMet(opt, s)` —— UI 侧判定，与引擎同源（门禁 ⑥ 逐条比对，288 条零冲突）。
4. `NDX.optionRepeat(opt)` → `once | repeat | end`，另有并列版 `optionRepeatAll`，
   应对「`fight` + `setFlag` 同现」（既战完才出现，又落过不再出）只显示一条的问题。

**消费点**：`ui_modals_2.sceneModal` 的选项按钮挂门槛徽章（不满足时转红标）与重刷徽章。
实测渲染效果：

```
恶  未请神不用宝，纯实力折服   门槛 · 不得持 · 照妖镜   一次性 · 战斗结束
善  请神求助（已被照妖镜锁）   门槛 · 须先 · n15_liusha:du
善  普通选项                                        （无徽章）
```

实测数据：`TRIAL_LIB` 331 个选项中 **109 个带门槛（32.9%）**；后续态分布
`可重复 81 / 一次性 230 / 战斗结束 20`。

## 五、结论

图鉴真正的价值不是「1155 件装备」这个数量，而是**它把散在代码里的东西整理成了玩家能查的说明书**——
属性面板、获取途径、合成公式、玩法评测、事件条件。

逆道西行现在有 `desc` 一句话 + `note` 一句话，玩家想知道「哪件装备吸血」只能翻代码或靠记忆。
本轮补的四个派生函数就是把这份说明书**从数据里抽出来**，且不增加任何维护负担。

数量差（466 vs 1155）**不建议追** —— 逆道的装备是按 81 难逐个设计的叙事件，
堆数量只会稀释「这一件从某难某怪身上拿到」的意义。
