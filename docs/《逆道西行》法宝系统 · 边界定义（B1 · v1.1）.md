## 一、定位（五层机制的第 3 层）

```
装备 = 基础数值        （提供属性地板，含第 5 栏「特殊装备」）
劫印 = 多维度增强      （反震 / 护盾 / 吸血 / 反伤）
法宝 = 钩子 + 特殊属性（不提供纯数值）      ← 本文件定义
跟随 / 宠物            （行动补位 / 场域改写）
```

**一句话**：**装备决定你能打多少，法宝决定你能打什么。**

法宝**不是战力系统**，是**解题系统**——它回答的是「妖怪在某难用什么招式、你用什么解」。

## 三、钩子系统（已设定，不动）

**真源**：`法宝钩子系统·通用规则文档.md`（v1.3）
**代码锚点**：`js/enemies_part1.js` → 敌人身上的 `breakWith` / `blessTreasure`

### 3.1 钩子语义

> 钩子 = 敌人身上挂的**解法字段**，不是装备属性。
> `breakWith` = 「拿什么破」／ `blessTreasure` = 「拿什么加持」。
> ⚠ 二者引用的都是 `slot:'treasure'` 的物品 **id**，因此**钩子借用装备库存在**，但**语义不属于装备数值**。

### 3.2 现有钩子全集（实测 7 种，15 处挂载）

| 钩子 id | 含义 | 出处真源 |
|---|---|---|
| `dingfeng` | 定风珠 · 破风系 | 钩子系统 §一.1 |
| `zhaoyao` | 照妖镜 · 破幻化/人形减伤 | §三 |
| `baojiao` | 芭蕉扇 · 破金刚琢 / 清灼烧 | §二.1 |
| `ts_jingping` | 观音玉净瓶 · 清弱 / 救人 | §二.2 |
| `zijin_honghulu` | 紫金红葫芦 · 清致盲 | §二 |
| `zijinhu` | 红葫芦 · 清摄魂 | §二 |
| `ts_bowl` | 阴阳二气瓶 · 装天装地 | §二.2 |

🔴 **R2 的硬边界**：这 7 种就是全部。要「破毒」「破雷」等新语义时，**走已有钩子的组合或升级链**，不新增钩子种类。

### 3.3 钩子不是必需（重要）

真源 §八「战斗难度分级」：夺(1) → 逆(2) → **针对性法宝(3)** → 请菩萨(4)。
⇒ **法宝是第三/第四优先的降难手段，不是通关必需品**。法宝系统因此**必须保持轻量**（对应 R5）。

## 四、🔴 那「141 件纯法宝」到底是什么（实测）

> 用户原话：「141 件纯法宝是什么东西，你就给个名字我怎么知道。」

**答：它们不是法宝。是 72 件「假法宝」——借用了法宝的名字（珠／盂／瓶／扇／铃／印／袋），本质是装备。**

### 4.1 实测数字（推翻真源）

| 口径 | 真源（总纲 v5.6） | **实测** | 差 |
|---|---|---|---|
| 祭出式（真·法宝） | 24 | **75** | +51 |
| 被动件（假·装备） | 141 | **72** | −69 |
| 合计 `slot:'treasure'` | 165 | **147** | −18 |

**测法**：按 `index.html` 脚本顺序 in-process 加载 → 遍历 `EQUIP_POOL` / `BASIC_EQUIPS` / `SUTRA_EVENT_GEAR` / `BOSS_REWARDS` / `FABAO_POOL`，
取 `slot==='treasure'` 且按 id 去重 ⇒ 147 条。其中**唯一 `treasureId` 值 = 75**（即 `NDX.isActiveTreasure` 判真的条数）。
⇒ **真源的两个数字都不对**，后续一切以 **75 / 72 / 147** 为准。

### 4.2 这 72 件假法宝的两副面孔

| 类 | 条数 | 是什么 | 举例 |
|---|---|---|---|
| **A · 套装第三件** | 46 | 每个套装 3 件里排在「法宝位」的那一件，**名字叫「XX胚」= 合成基座** | 贪狼胚、紫金钵胚、便便肚胚、骷髅串胚、三昧火种、落胎石、蟒珠、蛛丝网、月华影、晒经石、无底船骨、散财钱袋／银囊／金珠… |

## 五、🆕 归属重划（R7 落地 · 冲突 A 裁决）

### 5.1 装备区（穿在身上，给数值）

| 栏 | slot | 条目 |
|---|---|---|
| 兵刃 | `weapon` | 兵刃类 |
| 甲胄 | `armor` | 甲胄类 |
| 头冠 | `head` | 头冠类 |
| 战靴 | `boots` | 战靴类 |
| 🆕 **特殊装备** | `special` | **原 `slot:'treasure'` 中的 72 件被动件**（§4.2 的 A+B） |

### 5.2 法宝区（独立，给解法）

- 载体：**75 件真·祭出式法宝**（§4.3）
- 槽位：**初设 2 格**（R8），成就 `slot_treasure` → +1
- 机制：钩子（R2）＋ 特殊属性（R5），**不给纯数值**

### 5.3 为什么这样切

| 判据 | 说明 |
|---|---|
| 用户原话 | 「如果是装备类的，应该归属到特殊装备一栏，可以在四件装备后面加一栏」 |
| 名字判据 | 「胚」「·残」「·枝」「六部件之一」→ 一看就知道不是法宝 |
| 机制判据 | 这 72 件产出的是 `atk/hp/dr/eva` 等**纯数值**（R5 明令法宝不给） |
| 钩子判据 | 钩子只引用 7 种有名字的法宝 id，**不引用这 72 件**⇒ 它们对钩子系统零贡献 |

⇒ **切了以后法宝条目数从「147」变成「75」，R1「不轻易加数量」从此有真实口径。**

### 5.4 🔴 法宝的角色多重性（2026-09-26 · 用户纠正后补）

> **用户原话**：「本来定风珠就是法宝加钩子加唐僧僧袍升级配件啊」

**这不是「同名重复」，是一件法宝承担多重角色——是设计，不是事故。**

以定风珠（`dingfeng`）为范式，**单件法宝可同时充当**：

| 角色 | 说明 | 定风珠的落地 |
|---|---|---|
| **法宝本体** | 占法宝槽、有充能、可祭出 | `equipment_part1.js:570`（贪狼套·2 充能） |
| **钩子载体** | `breakWith` / `blessTreasure` 的目标 | `enemies_part1.js:733`（破黄风怪三昧神风） |
| **BOSS 克制物** | `counterItem` 指名 | `boss_skills.js:31,138` |
| **养成条件** | 随从点化 / 转职门槛 `held` | `data_follower_fuse.js:280` |
| **协同基元** | 法宝 pair / 劫印协同 / 妖类亲和 | `equipment_part2.js:711,740`、`equipment_part3.js:869` |
| **英雄装备升级配件** | 作为专属装备配方材料 | `equipment_part2.js:52`（唐僧 `ts_armor_ch2` 耗「定风珠碎片」） |

⚠ **但「升级配件」这一角色目前只落在命名上**：配方消耗的是「定风珠**碎片**」，而碎片现存来源仅为 ch1 随机材料掉落（`data_materials.js:14`），**与法宝 `dingfeng` 无产出链**。若要坐实，需补「定风珠 → 定风珠碎片」的产出（如退役/拆解法宝得碎片）。

### 5.5 🔴 新增红线 R9：法宝必须「一身一 id」

> **同一件法宝在实现上只允许一个 id。** 允许该 id 被钩子／克制／点化／协同／配方**多处引用**（角色多重性是设计），但**禁止为同一物另建第二个 id 承载不同玩法面**。

**违规实例（现存 33 件）**：`data_treasure_evo.js` 生成的 `tre_*` 系列**全部不在 `NDX.TREASURES` 字典里**，因此：祭出无效果（`combat_part2.js:65`）、永远无法破韧（`game_combat_3.js:14-18` 的 `if (!T) return false` 直接短路）、不被道途认领（`data_equip_core.js:275` 无 `dao`）。

**后果**：35 处「夺/渡」选项发放 `tre_*`，其中至少 4 处出现**文案承诺 ≠ 实物**（难13 破三昧神风／难49 免疫火伤／难39 主动收敌兵器／难25 三选一）。详见《装备系统·统一审计报告（v1.0）》§七。

## 六、被动归属（R3 落地）

| 层 | 谁提供 | 例子 |
|---|---|---|
| **装备** | 全部常规被动（数值 / 套装 / 特效），**含第 5 栏特殊装备** | `matk/mdef/hp`、破军四件套 |
| **法宝** | **不提供**常规被动；只提供钩子与特殊属性 | 见下行 |

**结论**：所谓「法宝被动」**不是一种独立机制**，而是**装备被动在法宝槽的呈现方式**。
⇒ 「法宝主/被动树」这个争论**直接消解**——**不做**。

## 七、操作点子系统（R4 落地）

- **真源**：`《逆道西行》45隐藏职 · 英雄归属与流派总表（v1.0）》§五
- **构成**：识破 / 破韧 = 同一个系统（Operation Point）的两种表现
  - **识破** = 应对变化/幻化 → 对应钩子 `zhaoyao`
  - **破韧** = 应对护体/减伤 → 对应钩子 `dingfeng` / `baojiao`
  - 三者**共用一套「操作点」窗口**（telegraph / enrage / lowhp 三战况驱动）
- **归属判定**：操作点**挂法宝**，因为它是钩子的**执行端**——没有钩子就没有可破目标，没有操作点就没有破的窗口。
- **A1.5 现状（已落地）**：P1-C 删周期 `routine` 窗口；P1-B 自动战斗不再被操作点/破韧打断。门禁 `_verify_operation_point.js` **21/0**。
- ⚠ **不可删**：破韧是**法宝克制配装的唯一硬验证点**（`monster.breakWith`，黄风怪↔定风珠）。

## 八、职责红线表（法宝 vs 其他四层）

| 系统 | 法宝**能做** | 法宝**不能做** |
|---|---|---|
| 对装备 | 提供钩子与特殊属性 | 提供纯属性成长、套装效果（→ 特殊装备栏） |
| 对随从 | — | 不提供行动（随从才出手） |
| 对宠物 | — | 不改场域规则（宠物才改写） |
| 对劫印 | — | 不提供反震/吸血（归劫印层） |
| 对操作点 | **提供破的目标与窗口** | 不自己打断战斗（属操作点子系统） |

⇒ **一句话**：**法宝不给你力量，它给你解法。**
