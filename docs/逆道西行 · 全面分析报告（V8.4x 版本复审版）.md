## 结论摘要

内容面已从 demo 骨架铺开为全量游戏（五英雄 / 17 地区 / 81 难 / 129+122 事件 / 163 装备），表现层达到零依赖 H5 的上游水准。但**当前 build 存在阻断级缺陷：战斗核心每次调用必抛异常，任何一场战斗都无法结算**；另有状态面板静默失效、双存档层键名冲突两个同级问题。玩法层面"自动战斗 + 稀疏操作点"的参与感短板未解决，V8.40 新加的连招系统在游玩路径上不可达。移动端教学依赖 hover 提示（手机不可见）与约 45MB 字体首载，是发布 TapTap 前的硬门槛。

## 零、阻断问题（P0 · 修复前其他一切无意义）

### 0.1 战斗核心崩溃 —— 每场战斗必然异常

V8.40"技能进阶 / 连招"代码引入了两个未声明变量，`calcCombat → simulateSingle` 两条路径全部命中：

| 位置 | 代码 | 触发条件 | 实测结果 |
|---|---|---|---|
| combat.js:376 | `const seals = (player && player.seals) \|\| (bonus && bonus.seals) \|\| [];` | 玩家无劫印（`player.seals` 为 undefined，短路失效） | `ReferenceError: bonus is not defined` |
| combat.js:390 | `const ultTier = NDX.ultimateTier ? NDX.ultimateTier(s) : 0;` | 玩家带劫印（376 行被短路救过，但 390 行裸 `s` 直接崩） | `ReferenceError: s is not defined` |
| combat.js:400 | `const _ultTrait = (s && s.ultimateTrait) \|\| ...` | 同上，同一裸 `s` | 同类崩溃 |

复现方式：Node 加载 storage/data/events/equipment/enemies/combat 六个模块后分别以"无劫印玩家"与"3 战道劫印玩家"调用 `NDX.calcCombat`，两个用例均崩溃（2026-08-28 实测）。

根因：`bonus` 与 `s` 在 `simulateSingle(player, m)` 作用域内从未声明，全仓库也无顶层 `var s` 全局兜底（main.js:1260 的 `var s = g.state` 是函数内变量）。`bonus` 仅在 `computeStats`（combat.js:69）内作为参数存在；computeStats 只在 `bonus.seals` 非空时才把 seals 拷入返回值，因此无劫印玩家必然走到 376 行的雷。

同批同类隐患（未逐一实机复现，代码审读确认）：

- combat.js:483 —— `deal > 0`，`deal` 未定义（万劫 fate 分支）
- combat.js:711 —— `rd.ultHeal`，`rd` 先引用后赋值（渡系绝招分支）
- combat.js:824 —— 使用 `maxHp`，声明在 830 行（TDZ 暂时性死区，"免疫致死"分支）

旁证：game.js:2371 `resolveManualActive` 绕开坏掉的副本手动重实现了 `skill-advance` 检测——说明写码时已发现异常，但未修根。

**影响**：所有战斗（小怪 / 精英 / boss / 试炼战 / 心魔）在 `NDX.calcCombat` 调用处中断，且调用方无 try/catch 兜底（game.js:1557、game.js:815）。当前版本实机不可通关。

### 0.2 人物状态面板静默失效

- ui.js:1127（`statusHtml`）与 ui.js:2381（`heroDetailModal`）引用未定义的 `g`（应为 `NDX.game`）。
- `statusHtml` 被 `_safe(() => this.statusHtml(s, st, hero), '')`（ui.js:164）包裹，异常被吞 → **气血 / 寿数 / 攻 / 善恶 / 一生账本整块每帧渲染为空字符串**。
- `heroDetailModal` 走 modal 错误兜底提示，用户可见报错。
- 铁证：ui.js:1278 注释——"V8.35 修复：_mapHud 内部此前引用未定义的 g，被 catch 吞掉导致整块 HUD 不渲染"。同一 bug 类已在 `_mapHud` 修过并留档，但 `statusHtml` / `heroDetailModal` 两处未修。

### 0.3 双持久化层键名冲突

storage.js（`NDX.storage`，134 行，自称"单一持久化真源，禁止散落 localStorage"）与 save_system.js（`NDX.SaveSystem`，338 行）各自维护键注册表，且对同一概念注册了**不同的 key**：

| 概念 | storage.js | save_system.js | 后果 |
|---|---|---|---|
| 成就 | `nx_ach_v1` | `xynj_ach` | 读写分裂，成就解锁状态可能丢失或双份 |
| 通关难度 | `ndx_cleared_diffs` | `xynj_cleared_diffs` | 同上 |
| 收集册 / 业藏录 / 朝代 | `xynj_*`（两表一致） | 同左 | 暂无冲突 |

现状：runtime 自动存档走 `NDX.storage`（game.js:1318-1355），成就 / 收集 / 解锁走 `NDX.SaveSystem`（achievements.js、data.js 十余处），另有约 **40 处裸 localStorage 调用**绕过两层。三层并立、键名打架。

## 二、玩法与战斗设计

### 2.1 战斗结构：预演算回放 + 稀疏操作点

- `simulateSingle`（combat.js:279）一次性预演算整场战斗生成 `roundsDetail`（combat.js:857-893），`driveFight`（main.js:1257-1379）仅做播放。代码自注："战斗 AI 底层标注：自动为主、法宝人为干预"（combat.js:718）。
- 操作点触发规则（combat.js:783-793）：telegraph（重击预警回合）/ enrage（狂暴）/ lowhp（血量 ≤25% 首次）/ routine（每 5 回合）。
- **决策密度量化**：普通小怪 `heavyEvery: 0`（enemies.js:700）→ 小怪战 **0~1 个操作点**；boss（heavyEvery 3-5，enemies.js:809/832）约 3~5 个。设计目标"每场 4~7 回合"在数值上成立（满配终局 boss 约 4 回合击破），但"回合多"不等于"决策多"。
- 最优决策设计是 telegraph 回合的格挡 / 闪避 / 硬抗三选一（game.js:2183-2192、combat.js:1212-1257）——真实赌注，但每场最多出现 1~2 次。
- 气势系统（combat.js:403-410）：命中 +1、受重击 -1、封顶 5，三档爆发倍率 0.6/1.0/1.5。设计合理，但积累发生在模拟内部，玩家只消费不经营。

### 2.2 玩家自主权被侵蚀的三处

1. **aiAutoTreasure（game.js:2542-2586）**：血量 ≤30% 时自动祭低阶保命法宝，**手动模式下同样生效**（main.js:1349-1359 未检查 autoFight）——全场最紧张时刻的决策权被 AI 拿走。
2. **破韧窗口固定工具检查**（game.js:2612-2620）：多阶段 boss 强制要求持有特定反制法宝，持有=奖励（gold 120/160 + 灵玉），缺失=闲置兜底（30/40）——用固定钥匙换决策点。
3. **镜像自动跳过**（game.js:1530-1554）：部分状态可被动免战。

### 2.3 死亡机制：V8.40 连招系统不可达

- 连招计数器读取 `pTurn.skillKind`（combat.js:740），**全仓库无任何赋值点**（全仓 grep 验证）。`applyActiveIntervention`（game.js:2394）注入手动诵经 / 绝招时未写入 skillKind。
- 结果：三连击（连击·破）、禅定·悟、三连·绝杀在游玩路径上**永远无法触发**。宣传的连招深度目前是空中楼阁。

### 2.4 识破无技巧分级

`applyShiPo`（combat.js:1156-1204）为二元判定：2.5 秒窗口内按到=免伤 + 0.8× 双攻反击 + 2 气势，没按到=无事发生。设计文档规划过的 perfect/ok/miss 三档时间判定未实现（docs/111/legacy-digest.md:135 仍列为未来 M3 工作）。

### 2.5 经济：一条真轴 + 两条死轴

- **寿数（真轴，设计良好）**：起始 27 / 上限 55 岁，每节点消耗 0.2~0.6，转职 0.3、封印 0.15、影遁重入 3 岁；结局按余寿评级（game.js:509-522）。这是全游戏最好的稀缺性设计。
- **金币（通胀死轴）**：收入随层数增长（法宝节点 80+6·layer），商店价格全游戏固定 30~38 金（events.js:1019-1021），无后期消耗坑。第三章起金币失去决策意义。
- **灵玉（死货币）**：只发放（game.js:1065-1066、2134），全仓库无消耗点。

### 2.6 数值与构筑

- **数值曲线稳健**：玩家基础曲线 `t=(diff-1)/19` 无上限但防御 0.85 封顶；怪物 `f=(diff/20)^1.16` 平衡 V43；终局 boss 约 4 回合击破。无失控，反而玩家偏强（后期每受击约 2-3% 有效血量）。
- **龟缩倾向**：玄武套装减伤 × 缘道劫印为乘法复合（combat.js:57-65 `drSealMult`，代码注释自认"正反馈闭环"），叠加 0.85 减伤帽与激怒惩罚，数学上奖励拖时间的反射 / 护盾流。
- **构筑深度真实存在**：184 装备池、56 法宝、47 劫印字（18 个机制字接入战斗内核）、6 职业 ×3 转职 + 约 29 个隐藏职、6 终极特质。劫印机制词（吸血转化护盾、闪避重置冷却、护盾破碎反射等）与道心全局 ±10-15%、五行克制、法宝反制标签 ×1.5 形成真协同而非纯数值堆叠。
- **但身份被前置决定**：封印三选一池化规则 `[主道, 逆, 随机 1]`（jieseals.js:199-208）+ 英雄→主道固定映射（jieseals.js:191-193），构筑差异约一半在选英雄时已定；47 个劫印字摊到 6 道 ×3 级后，多数三选一是"同名不同字"的同属性变体。
- 心魔镜像 ×1.35 血 / ×1.15 攻（enemies.js:175-197）是好的防滚雪球阀，但纯惩罚性（无掉落）。

### 2.7 肉鸽 Meta（设计最好的一块）

- 跨局保留：成就→永久属性（软上限边际递减，achievements.js:285-300）、业藏录、拓印库→封印槽扩容、朝代 / 轮回 / 排名 / 解锁。
- 死亡继承：衣冠冢埋最多 3 件非法宝装备供下世（game.js:4883-4928），同件不重复获得防刷。
- 胜利继承：引渡匣跨局衰减 ×1→0.8→0.6→0.4，4 次后破损（game.js:108-123）——强势局衰减而非滚雪球，设计诚实。
- 单局修改器限幅 [-45%, +60%]（data.js:222-234），防"逆道死亡螺旋"。

## 三、UI / UX 与表现层

### 3.1 已达标项（相对上次大幅进步）

- Boss 入场分层演出（帷幕 + 小妖滑入 / 精英砸落 / Boss 降下，main.js:1144-1195）；狂暴 / 破韧 / 金箍全屏水墨特写。

- 无障碍选项齐备：字号缩放、高对比、色盲模式、reduced-motion。
- 17 张地区手绘背景 + 49 角色立绘 + 约 147 UI 底板。

### 3.2 核心问题

1. **教学押在 hover 上，目标平台却是手机**。气势说明（ui.js:3254）、节点 tooltip（ui.js:876-906）、事件选项完整文案（截断 12 字，全文靠 title，ui.js:5157-5160）全部依赖 `title` 属性——触摸屏上永远不可见。手机新玩家无法理解识破 / 气势 / 操作点是什么。**这是移动端留存的最大单点风险。**
2. **信息分层未落地**：战斗屏同屏约 20 个信息簇（双资源条 + 韧性条 + 机制 chips + 词缀 + 三戏标签 + 顶底双栏 + 抽屉）；地图 8 个浮窗 + 观音任务卡常驻不可折叠（上次"任务卡折叠"未实施，全仓库仅 2 处无关 details 折叠）。横版下速度按钮 padding 2px 6px / 字号 10px（style.css:8953）、任务卡 9.5-10.5px（1768-1774），低于移动可点性底线。
3. **加载重量**：三套全量 CJK webfont（文远宋体 R/B/H ≈15MB×3、汇迹正楷 14MB、站酷高端黑 3.9MB，style.css:72-106）+ 多张 1-5MB PNG（长安.png 5.3MB）。`font-display: swap` 不阻塞渲染，但移动端首载总量随时超 45MB——TapTap H5 上线前的硬伤。
4. **渲染架构**：`render()` 全量 innerHTML 重建（ui.js:142-159），战斗每 tick 重建一次（1300ms/tick，加速档 2~2.3 次/秒），全部 FX 依赖 rAF 延迟重挂（ui.js:2934-2939 自注此约束）。当前 DOM 规模（≤36 节点 + 全连边，约 150-250 节点）可承受，但每个新表现效果都在与架构搏斗，是表现层最大技术债。
5. **细节毛刺**：21 个音效仅接 7 个（click/open/skill/dodge/equip/seal/heal 等定义未调用，UI 导航全程无声）；怪物死亡无动画（FINISH 重建时直接消失）；双飘字系统（声明式 fb-float + FX dmg-fly）可能对同一击重复显示；`assets/Boss.png` / `精英.png` / `小怪.png` 回退图文件不存在（ui.js:3785，已验证）；viewport 禁用缩放牺牲无障碍（index.html:5）。
6. 更正一条上次审计的误报：index.html 标题与加载骨架**无乱码**（实测字节为正常"逆道西行 · 黑暗西游肉鸽 · Demo"），此前子代理结论有误。

## 四、架构卫生

本轮迭代引入了一批"迁移做一半"的模块，形成系统性隐患：

| 模块 | 判定 | 问题 |
|---|---|---|
| telemetry.js | **死代码** | `NDX.telemetry` 全仓 0 调用（含 getReport 弃坑分析能力，从未接线） |
| attr_calc.js | **死代码** | `NDX.AttrCalc` 全仓 0 调用；平行复刻 computeStats 的装备 / 劫印加成求和，留着即维护陷阱 |
| battle_resource.js | 半迁移 | `if (BR) {模块} else {game.js 内联旧逻辑}` 双轨：game.js:2410-2411 / 2426-2429 与模块内 gainZhanYi / gainJingLi 数学并存且均可达；另将 dao_system 的道 bonus 表降级复刻了一份（battle_resource.js:67-97 vs dao_system.js:116-156） |
| dao_system.js | 半迁移 | "主道判定"现有 **三个 owner**：`Z.dominantDao`（zhuanjie.js:288）、`NDX.playerDao`（data.js:4222-4235，与 DaoSystem.getMainDao 几乎逐行相同）、`DaoSystem.getMainDao`；恶道集合 `['战','夺','逆']` 与 combat.js:128 双份硬编码 |
| save_system.js | 半迁移 | 与 storage.js 键名冲突（见 0.3）；自身宣言与 storage.js 的"单一真源"宣言互相矛盾；两模块调用点均保留裸 localStorage 兜底分支 |

## 五、市场前景

**题材与卖点**：黑暗西游 + 单局肉鸽踩在西游题材热度上，TapTap 单机区有真实受众。差异化资产真实且不易复制：六道命运抉择叙事、寿数稀缺经济、衣冠冢 / 引渡匣世代传承（带衰减防滚雪球）、文言白话混合黑暗叙事、81 难全手写文案量。

**竞争位置**：肉鸽卡牌赛道极度拥挤（月圆之夜、杀戮尖塔手游及大量模仿者）。"自动战斗 + 稀疏 QTE"的战斗形态在同赛道参与感垫底——在这个位置，参与感已不是体验瑕疵，而是与竞品正面碰撞时的生死线。

**发布硬门槛（按当前代码事实）**：

1. 45MB 字体 / 图片首载（P0 级，直接决定买量转化与首日留存）
2. hover 教学在手机失效 → 核心机制不可学（P0 级）

4. 当前战斗崩溃——任何发布尝试前必须清零 0.x 全部阻断项

**变现约束**：零后端零账号体系 → 无内购，路径仅广告或口碑自发传播。这意味着前五分钟体验必须自证——而当前新玩家前五分钟看到的是空白状态面板（0.2）与看不懂的识破按钮（3.2-1）。
