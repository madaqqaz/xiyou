# 《逆道西行》系统完善台账（逐系统 · skill 驱动）

> **这份文档的用途**：把「逐个系统推进」做成可验收的流水线，而不是每次临时想改什么就改什么。
> **一条硬规矩**：每个系统先出**设计 + 数值**，再动代码。反过来的顺序（先改码再补设计）就是「跑偏」。
> 真源关系见 `《逆道西行》系统整合路线图（v1.0）.md`（8 层 23 系统 + 5 批 + 3 条硬依赖）；本台账只负责**进度与 skill 使用**。
> 最近更新：**2026-09-25**（V9.54 收口后）

---

## 〇、标准作业流程（SOP）—— 每个系统都走这 6 步

| 步 | 干什么 | 用哪个 skill | 产出物（必须先有文档再有代码） |
|---|---|---|---|
| **S1 定目标** | 把「深度不够/数值不对」翻译成可验收目标 | `game-design-goal-framing` | 一段目标陈述 + 成功判据 |
| **S2 拆方案** | 出系统骨架与子系统切分 | `game-plan` | 设计文档骨架（章节结构） |
| **S3 审体感** | 减法规 / 动机覆盖 / 野心 / 概率体感 | `game-design-one-thing-to-remove`<br>`game-design-perceived-randomness-audit`<br>`game-design-bartle-archetype-audit`<br>`game-design-molyneux-lens` | 砍项结论 / 概率体感诊断（按需，不必全走） |
| **S4 定数值** | 成长曲线、掉落、联动系数、定价 | `game-numeric-design` + `game-balance-notes-skill` | **数值表**（可直接抄进代码的表） |
| **S5 落地** | 改码 + 配门禁 | `dev-expert` | 代码 + `scripts/_verify_*.js` |
| **S6 回写** | 同步真源文档 + 记忆 | `xiyou-doc-truth-sync` | 文档 + `.workbuddy/memory/` |

**为什么必须 S4 先于 S5**：数值是设计的一部分。先改码再调数 = 每次调参都要在代码堆里找常量，且容易留下「改了但没改全」的残留（V9.54 定价改版就一次抓出 3 个消费点没跟上）。

### 6.3 方法论沉淀（写入门禁，非仅文档）
> 🩸 **「验了形，没验用」= 假门禁。** 验一张表的自洽性（曲线单调、消耗是斐波那契）**不等于**它被使用。
> 新增任何数据表，门禁必须含一条 **「有无消费点」** 断言（源码级 `Q10` 或数值级 `Q11`）。
>
> 🩸 **扩数量必同步扩组合。** 池子从 67→91 是「形」，羁绊仍 7 条是「用」。`Q4 羁绊零孤儿`
> 是唯一能自动发现这类「扩了一半」的断言。
>
> 🩸 **标签/枚举类映射表必须放数据层。** 内联在渲染函数里 = 数据层加键时无人同步（图鉴英文名事故）。
