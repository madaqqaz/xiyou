### 8.2 三个方案对比

| 方案 | 做法 | 数据改动 | 存档兼容 | 风险 |
|---|---|---|---|---|
| **甲 · 改数据** | 106 条字面量 `slot:'treasure'` → `'special'` | 106 处（分散在字面量，无法安全批量替换） | 需写迁移函数 | 🔴 高（盲替换会误伤真法宝） |
| **乙 · 运行时归一化** ⭐ | 新增 `NDX.equipSlotOf(e)`，20+ 处判定改用它 | **0** | **天然兼容** | 🟢 低 |
| 丙 · 加载期改写 | 加载后遍历池与存档，直接改 `e.slot` | 0（运行时改） | 天然兼容 | 🟡 中（改的是共享对象） |

**推荐：方案乙。** 理由：
1. **零数据改动** ⇒ 不碰 106 条字面量，无盲替换风险；
2. **老存档天然兼容** ⇒ 归一化在读取时发生，老档的 `slot:'treasure'` 被动件自动被认作 `special`；
3. 与项目既有纪律一致 —— `isActiveTreasure` 本来就是**机械判定，无需逐件标注**（`equipment_part3.js:383` 注释）；乙只是把它提升为「槽位归一化」的单一入口。

### 8.3 方案乙的实现骨架

```js
// equipment_part3.js · 新增单一入口（放在 isActiveTreasure 之后）
// 归一化槽位：非祭出式的 slot:'treasure' 一律视为 'special'（装备第 5 栏）
NDX.equipSlotOf = function (e) {
  if (!e) return null;
  if (e.slot === 'treasure' && !NDX.isActiveTreasure(e)) return 'special';
  return e.slot;
};
// 分栏过滤统一入口（替换 20+ 处 e.slot === 'treasure' 与 filter(e => e.slot === slot)）
NDX.equipsOfSlot = function (list, slot) {
  return (list || []).filter(e => NDX.equipSlotOf(e) === slot);
};
NDX.EQUIP_SLOT_LABEL = { weapon:'兵刃', armor:'甲胄', head:'头冠', boots:'战靴',
  special:'特殊装备', treasure:'法宝' };
```
