### 1.5 边界与异常

- **零迁移承诺成立**：V9.54 只改成本口径不改 id 结构（`data_sutra.js:127` 注释 + L113-114 说明"三种子补足使 203→210/76→79，部数不变"），实测 kind 求和 = 210/79 与 SPEC 一致 ⇒ **无脏 id**。
- **幂等**：`routePendingSutras` 5 处调用（`data_sutra.js:483/666`、`game_sutra.js:63`、`game_region.js:300`、`game_vault.js:61`），入匣前均先判 `done`（L93/L246/L273）⇒ 重复调用不双投。
- **释经不罚性**：`game_rest.js:137` 明确"放下不减拼篇阶（`_sutraPieces` 只增不减）"⇒ 删卡是纯收益转换。
- **寿元唯一入口**：`doChantSutra` L277-288 走 `NDX.sutraLifeSink`（= `_loseLife`），仅在其缺失时才直写 `s.life`（L287 兜底分支，注释 L278 自警）⇒ 大限判定不被绕过。
- **rng 三源混用（可复现性隐患，实锤）**：同一段代码里 `game_sutra.js:101` 用**裸 `Math.random()`** 判掉不掉，而 L114-115 抽哪一片用播种的 `runWeightedPick`/`runRandom`；`data_sutra.js:467` 与 `:510` 的朝代追加判定也用裸 `Math.random()`（耦合矩阵 §1.1 点名的两个消费点）。⇒ **同局重放可能掉/不掉，但掉的是哪一片可复现**。
- **兜底常量与真值不一致**：`data_sutra.js:230` 与 `:282` 的 `LIFE_DAYS || 18` 兜底 vs 真值 L217 `40`；若 `SUTRA_CHANT` 缺失，定价约束会静默降到 45%（当前无行为影响，属隐患，与 S07 §1.7 同类）。
- **跨周目**：`cycleReq` 过滤三处一致（L366-367、L1012、`data_sutra_shard.js:36`）⇒ 真·逆经锁定二周目，无泄漏。

抽到的片**若已存在（哪怕只有 1 枚）就整条静默丢弃**（无 else、无日志、无回落换片）。而 V9.54 起合成看的是**数量**（`sutraCostOf` 合计 357 片 vs 渡+逆种类仅 289 种），意味着 C5 通道在其 210 种渡片被集齐后**产出恒为 0**。当前因每局很难集齐 210 种，尚未显性爆发；但这是**结构性的通道-口径错配**：三套产量口径（种类 289 / 定价 357 / 拼篇累计另计）并存。

**B. `sutraHalfPick` 仍按"种类"判据 ⇒ 与 V9.54 定价口径不齐**
`data_sutra.js:1013` `f.frags.some(fid => (frags[fid]||0) < 1)` —— 判的是"有没有这一**种**片"，不是"离 `sutraCostOf` 还差几片"。后果：章首念经会挑一部"已集满 5 种、但定价 12 片"的经给半部（看起来进度条不动），而不会优先挑"只有 2 种但定价 6 片、马上能成"的经。对照 L260 `sutraChantPool` 已明确改为 `need`/`gap` 排序 ⇒ **两条同功能选部逻辑口径不同**（C2 用旧口径，C3 用新口径）。

**C. `SUTRA_SPEC` 注释区的总量数字与代码实测冲突（-7）**
`data_sutra.js:109` 声明"总量变成 渡 223 / 逆 127 / 合计 350 片 —— 见 `sutraFragOverview().total`"。实测：
- `sutraCostOf` 全表求值 → 渡 **223**（一致）/ 逆 **134**（注释少 7）/ 合计 **357**（注释少 7）；
- `sutraFragOverview({})` 实跑 → `{fullN:22, total:223, fragN:210}` ⇒ **该函数只统计渡侧**，根本不是"合计"来源。
⇒ 注释既把 ferry-only 函数误引为合计来源，其"逆 127"也与代码不符。SPEC 的部数/种类数（22/12/289）则完全正确。

**D. 朝代追加通道破坏整局可复现（耦合矩阵 §1.1 点名的两行）**
`data_sutra.js:466-473` 与 `:509-513` 各用一次裸 `Math.random()`（L467、L510）。这是本系统唯一两处不进播种流的随机：其余（`game_sutra.js:114`、`game_rest.js:121/175`）都走 `runRandom`/`NDX._rand`。⇒ 依赖 `scripts/_verify_sutra_*.js` 播种重放的回归**看不到这条分支**，属门禁盲区叠加。

**E. `chant` 三重命名冲突（阅读事故源）**
同一字符串在三个不相干语境里：① `SUTRA_CHANT`（土地庙诵经动作，`data_sutra.js:211`）；② `CHANTS` / `chantOf`（战斗真言，`data_chants.js:13/21`，5 英雄）；③ `s.jing.chant` / `kind:'chant'`（经匣槽位与出牌位，`game_sutra.js:17`、`ui_panel_1.js:271/322`、`ui_misc_3.js:752`）。三者的 owner 与数值毫无关系，但 `grep chant` 一次命中全部，跨系统沟通极易串台。

**F. "逆经只能靠 C1/C2/C6，渡经只能靠 C1/C3/C5/C6"的非对称矩阵**
`doChantSutra` L271 只查 `sutraFullById` ⇒ **诵经永不出逆片**；`dropSutraFrag` L102/L117-118 只写 `s.sutraFrags` ⇒ **劫难永不出逆片**。逆侧实质只剩 C1（交替）+ C2（恒逆）+ C6。设计上是有意分轨（L145-146 逆更贵），但**没有任何注释或门禁固化这一非对称**，后续新增通道极易只补渡侧而把逆侧饿死。

**G. 门禁覆盖错位**
`_verify_sutra_pricing.js` 43/0、`_verify_sutra_variant.js` 46/0、`_verify_sutra_resonance.js` 9/0、`_verify_sutra_gain.js`/`_verify_sutra_two_type.js`/`_smoke_sutra_panel.js` 全 ok —— 但**没有一个**断言：C5 在片种集齐后仍有产出（§1.7-A）、C2 选部落在 `gap` 最小者（§1.7-B）、朝代分支 rng 可注入（§1.7-D）。
