## 二、证据可信度分级
1. **L1 代码实证（可写入结论）**：`file:line` 直接引用、`node scripts/_dump_balance_db.js` 快照、`grep -c` 实测计数、既有 `_verify_*`/`_audit_*` 门禁输出。
2. **L2 待核（只能进 §⑥）**：记不准的竞品数值、未复现的运行期行为、旧文档口径。
3. **禁止**：把设计文档口径当作"当前内容"、引用不存在的文件、用"应该是"代替实跑证据。

## 五、"未接入/孤儿"五步判据（不得只凭"未加载"就判断链）
1. **加载状态**：是否在 `index.html` script 链、行号。
2. **符号外引**：其导出符号是否被其他 `js/` 文件引用。
3. **内部闭环**：模块内部是否有自洽的写入端与读取端。
4. **外部触发点**：游戏流程（战斗/事件/结算）是否有调用入口。
5. **运行期/脚本证据**：是否有 `_verify_*`/`_audit_*` 或 dump 输出佐证。
> 五步不足时只出"嫌疑"，不出"结论"，写入 §⑥。

## 六、数值取数口径
- **BalanceDB 覆盖的 11 系统**（hero/equipment/pet/sutra/seal/zhuanjie/ultimate/monster/boss/achievement）：直接引 `data/balance_db.json`，标注快照日期。
- **未覆盖系统**（事件/劫难选项/法宝/地图配额/商店价格/朝代feature/结局条件）：grep owner 表 + 复用 `scripts/_audit_*`。
- **计数类**：`grep -c`/脚本实测，禁引旧报告数字。
- **定标类**：难度结论守"≥40 seeds、`--k` 为额外倍率、玩家骨架复刻 ti/yuan/spd 映射"。
- 同一数值只在 `02_耦合矩阵` 与本系统文档出现一次，其余文档**链接引用**，防漂移。
