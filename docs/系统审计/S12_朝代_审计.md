## ① 当前游戏内容（代码事实）

> 硬规则：每条数值/机制必须带 `file:line` 或 BalanceDB 键；无证据者移入 §⑥。

### 1.1 核心循环
「开局读朝 → 局内吃 feature → 死亡递进 → 通关归夏」，跨周目持久化于单个数字 key：

1. **入口·读朝**：`NDX.getDynastyIdx()`（`data_dynasty.js:55`）经 `NDX.SaveSystem.loadNumber(NDX.DYNASTY_KEY, 0)`（`:58`）读 `ndx_dynasty_idx`，clamp 到 `[0, LAST_IDX=9]`（`:59`）；`:60-67` 有一次性校准（从未通关且 `cycle>1` 且朝代落后于周目 → 追平并回写）。
2. **局内·吃 feature**：三条统一入口 `dynastyHas(key)`（`:132`）/ `dynastyValue(key,def)`（`:141`）/ `dynastyAdjust(value,type)`（`:158`），三者首行均先过 **`hasClearedAny()` 门禁**（`:134/:143/:160`）⇒ **首周目（任何英雄都未通关前）全部 feature 不生效**。
3. **死亡·递进**：`bumpDynasty()`（`:78`）— 非唐朝 `idx+1` 回写（`:86-88`）；已是唐朝则**原地复位唐**（`:81-84`，即十世为终点，不再递进也不降级）。调用点：战斗死亡 `game_combat_2.js:117-118`、寿尽坐化 `game_meta.js:185-186`。
4. **通关·归夏**：`resetDynasty()`（`:92`）写 0；调用点 `game_meta.js:269-270`（`settleReturn` 内）。
5. **轮回重开**：`reincarnateReset()`（`:113`）= 朝代归夏 + `resetCycle()` + 清除 `INHERIT/MONUMENT_GEAR/MONUMENT` 三类承继（`:118-120`），保留成就/藏品/图鉴/赐福；入口 `js/main.js:556`。
6. **可感知层**：朝代年表浮层 `ui/ui_changan.js:171-197`（已历朝代全文展示、未至朝代遮 `？？？` `:177-181`）；顶栏/结算面板显示「X朝 · 第N周目」`ui_misc_1.js:408`、`ui_misc_2.js:810`；排行榜记录朝代名 `game_meta.js:227-229/235`。

### 1.5 边界与异常
- **clamp**：`getDynastyIdx` 对读值做 `isNaN→0` 与 `Math.max(0, Math.min(9, v))` 双向钳位（`:59`）⇒ 手改 localStorage 越界不会崩 UI。
- **门禁三重**：`dynastyHas/dynastyValue/dynastyAdjust` 各自首行独立判 `hasClearedAny()`（`:134/:143/:160`），且 `!NDX.hasClearedAny ||` 短路——**owner 加载顺序颠倒或 data_heroes_data.js 缺失时安全退化为"feature 全不生效"**。
- **幂等/兜底**：三入口均 `try/catch`，`dynastyAdjust` 异常返回**原值**（`:228-230`），`dynastyHas` 异常返回 `false`（`:137`）⇒ 朝代永不成为崩点。
- **历史脏档自愈**：`:60-67` 一次性校准（旧版本战斗死亡漏调 `bumpDynasty` 导致高周目卡夏）→ 追平后立即回写，只跑一次（条件 `v < cycle-1` 不再成立）。
- **rng**：朝代层不产随机数；概率型 feature（`sutra`/`sutraShard`/`eliteDrop`）在消费侧用裸 `Math.random()`（`data_sutra.js:467`、`:510`、`game_loot.js:26`）⇒ **不吃整局 seed**（跨系统债务，与 S17 §1.7-2 同源，本审计登记不修改）。
- **存档侧**：朝代是单个 number（`saveNumber`），非 JSON 对象 ⇒ **不经过 `storage.js` 的 `_migrate()`**（该函数只处理对象型 `data._version`），因此 V8.41 之前的旧 `ndx_dynasty_idx` 值无任何结构迁移；`data_dynasty.js:64` 的校准是唯一自愈路径。

### 1.7 已知债务与死区
> ⚠ 均为实测代码债务，本审计只登记不改码。

1. **【悬空 feature·接线】`eliteBonus: 1` 全仓零消费**：三国 feature 声明「精英怪数量+1」（`data_dynasty.js:37`），但 `eliteBonus` 全仓**仅此一处定义、无任何读取**（同朝 `eliteDrop` 有消费 `game_loot.js:25`）。⇒ 三国实际收益 = `eliteDrop`+`petLevel` 两项，**描述与实装不符**（featureDesc 仍在年表侧作为唯一可见信息源，虽然 UI 也没渲染，见 4）。P1 接线债。
2. **【门禁时序·高价值】`perfectEnding` 与卷九朝代成就被 `resetDynasty` 抹平**：`game_meta.js` `settleReturn` 顺序为 `resetDynasty()`（`:269-270`，写 idx=0）→ `_syncAch()`（`:305`）→ `dynastyHas('perfectEnding')` 判定（`:307`）⇒ **通关瞬间朝代已复位为夏**，`dynastyHas` 永远返回 false（唐专属键），卷九判定（`achievements.js:247-252`）永远只看得到 `_dId==='xia'`。后果：`shang_seng`/`all_dynasty` **通关路径零可达**（唐朝 index 9 无法在判定时存活）；结局视频（V9.67 声称已接通）在"唐世首次完美通关"这一条设计上唯一预期路径里**不触发**，只有历史存档 idx 停在 9 且 `resetDynasty` 抛异常被 `:273` 吞掉时才可能触发。P0 接线/门禁债（跨 S13/S14）。
3. **【死码】`dynastyInterp` + 占位符链整体零消费**：`data_dynasty.js:97-109` 定义 `{{MONARCH_TITLE}}/{{MONARCH}}/{{KING}}/{{DYNASTY}}` 四类插值；全仓 grep `dynastyInterp` 仅命中定义行，`{{MONARCH_TITLE}}`/`{{KING}}`/`{{DYNASTY}}` 在任何文本数据里 0 命中 ⇒ "送行叙事动态代入天子"（表头注释 L17-22 的设计意图）**未落地**，`monarchKing` 字段随之成为孤儿字段。债务登记。
