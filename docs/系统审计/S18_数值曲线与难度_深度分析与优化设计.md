## 〇、执行摘要（TL;DR）

- **系统现状**：难度已从"数值膨胀"升级为**双端动态校准**——血量侧"节奏校准"反推目标回合、威胁侧 `buildMatchFight` 势均采样把怪攻钳进"扛得住但威胁足"窗口。工程上成熟，钳制族甚至**比竞品更完备**。
- **三大真问题（本轮实测/实跑，非旧文档）**：
  1. **承伤/击杀剪刀差**（`_balance_anchor.js` 实测）：三槽「渡」玩家对章末 Boss 的**承伤预算回合** ch1=28 → ch2 起断崖 **3–4**，而**击杀所需回合** ch2=8 → ch9=15。根因：玩家坦度（HP+DR）**近乎零成长**（`playerBaseAt` hp 恒 1000、dr 于 d20 饱和 +0.06，装备血封顶 `baseHp×4≈3640`），而 Boss 每回合承伤 93→1037（**×11**）。
  2. **势均钳制在后期失效**：`buildMatchFight` 的 `scale` 被夹在 `[0.5,1.5]`（`data_config.js:284`）。高章 Boss 手工基础攻已是"承伤预算"的 2.4×，需要的 scale≈0.21 **触底 0.5 抬不起来** → 注释承诺的"必死局占比≈0"（`pressure≤0.90`）在 ch3+ **不成立**。
  3. **玩家成长被主动中和 → power fantasy 缺失**：血量侧 `_growthMul=atkGrowth^-0.35`（atk 翻倍怪血仅 +57%）+ 威胁侧 scale 钳制，**联手把"我变强了"的收益钳掉**。这与"数值成长肉鸽"的核心爽点正面冲突。
- **竞品一句话结论**：三大竞品几乎都站在光谱另一端——StS/Hades = **固定遭遇**（尊重 build 成长），冒险日记 = **玩家驱动雪球**（拥抱成长）；本作站在中间"**动态橡皮筋**"，**两头不占**，且这是唯一"越玩越没成长感"的一档。
- **优化优先级**：P0 = 破剪刀差 + 修钳制触底 + 难度档分哲学（普通=橡皮筋、高难/进阶=固定遭遇）；P1 = 单调进阶表 reward 真耦合（补 Hades-Heat 缺口）+ 一把尺可验证。

## 一、当前系统解剖（代码实况）

> 结构细节链接 [S18 §1.1–1.4](S18_难度定标_审计.md)，此处只给"设计视角"的关键链路 + 本轮实测。

### 1.1 一场战斗的难度是如何"算"出来的（新模型全链路）

```
diffLv(线路,1–81) + difficulty档(easy/normal/hard/hell) + 道带monStr/monWeak + 朝代diff乘子
        │
        ├─①通用预缩放  scale=(1+min(diffLv-1,20)×0.03)×朝代 → 封顶×1.6      game_combat_1.js:46-50
        ├─②血量侧「节奏校准」  按玩家有效DPS反推目标回合 → 定怪血（覆盖①）      game_combat_1.js:138-238
        │     mob 2–8回合 / elite 4–16 / Boss两相劫 8–10 + 8–12(≤20)
        │     成长保留 _growthMul = atkGrowth^-0.35（玩家atk翻倍→怪血仅×1.57）
        ├─③威胁侧「势均采样」buildMatchFight（就地改写怪攻）                    data_config.js:253-298
        │     tank=HP+回复×(回合-1) ; 目标每回合威胁=tank×pressure/回合
        │     pressure∈[0.25,0.90]（±5%抖动）, scale∈[0.5,1.5]
        └─④天道劫地板  base×(1+layer×0.1)²（唯一保留的乘法膨胀，作"后期必死"兜底） data_mirror.js:184
```

- **难度档唯一有效轴** = `pressureFactor` 0.40/0.56/0.68/0.80（`data_config.js:146/160/174/188`）；`monsterHpMult/AtkMult/rewardMult/sealMult/startGold` **全部零消费者**（旧审计 D5 仍成立）。
- **Boss 强度靠手工基础值**：`BOSS_FORMS` 逐 Boss 写 phases（白骨 hp 1165/1457/1748、atk 1358/1662/1965；青牛二相 dr 0.55 无敌须芭蕉扇破，`enemies_part1.js:593-660`）。这些再被 ②/③ 覆写/钳制。

### 1.2 玩家坦度实测：这是所有问题的分母

`playerBaseAt`（`data_heroes.js:13-34`，实读确认）：
- **hp 恒 1000**（`:27` 注释"血量完全由装备提供"，无难度成长）。
- **dr = baseDr + 0.06·t**，`t=min(1,(d-1)/19)` → **d20 即饱和**，全游戏坦度只 +6% 减伤。
- **atk/matk** 是唯一实成长轴：`atk=base+420t+lateAtk(≤400)`、`matk=base+500t+lateMatk(≤450)`。
- 装备血封顶 `baseHp×4`（anchor 打印）、dr 封顶 0.55、mdef 封顶 0.50、`GLOBAL_DMG_MUL=0.5` 仍生效。

⇒ **结论**：玩家在整局里"更能打"（双攻涨）但**几乎没更能扛**（血/盾靠装备且早早封顶）。而 ② 让怪血跟着玩家 DPS 走（你越强怪血越高），③ 又钳不住高章手工 Boss 的攻击 → 坦度分母塌方。

### 1.3 运行时实测：承伤 vs 击杀 剪刀差（本轮 `_balance_anchor.js` 原始输出）

### 1.4 势均钳制在 ch3+ 触底失效（承 §1.3）

`buildMatchFight`：目标每回合威胁 = `tank×pressure/rounds`。以 ch5 渡为例：tank≈3640、pressure≤0.90、rounds≈13 → 目标威胁/回合 ≈ 3640×0.9/13 ≈ **252**；现怪威胁 ≈ **1189** → 需要 `scale=252/1189≈0.21`，但 **`scale` 下限锁 0.5**（`data_config.js:284` V8.58 为保 dr/eva 收益而设）→ 怪攻最多砍半到 ~595，仍是目标的 **2.4×**。⇒ **"必死局≈0"的设计承诺在 ch3 之后被 scale 下限打破**；实机表现为高章 Boss"读不出但一刀重一刀"，玩家体感"橡皮筋也没救回来"。

### 1.5 现有"自选进阶"层（已具备 Hades-Heat 骨架）

`CURSE_TABLE` 5 词条（`data_config.js:202-228`）：每条负面效果换 `mul` 碎金加成，`curseRewardMul=1+Σmul`。这**确实是 Hades 热度/惩罚契约的同构**。缺口只在：①只有 5 条、无"阶数"概念；②`rewardMult/sealMult/startGold` 未接入（奖励侧耦合不完整，见旧审计 D5）。

## 二、设计目标：难度系统"应然"的三条曲线

> 先立靶子，§④ 差距与 §⑤ 优化都对着这三条打。

1. **单局内体验曲线（难度感）**：应随章节**单调上扬**、且**可被玩家选择加剧**（进阶）。当前因橡皮筋钳制，中段体感趋于恒定（每场都被拉回"势均"），缺少 StS/Hades 那种"我变强了 → 同样遭遇碾压得越来越顺"的正反馈。**目标**：普通档可保势均（友好），困难/地狱/进阶档应**解除或放宽钳制**，让遭遇固定、难度真实上扬。
2. **单局内成长曲线（power fantasy）**：构筑/数值成长应转化为**可感的碾压**（更短回合、更低承伤占比）。当前 `atkGrowth^-0.35` + scale 钳制**主动抵消**成长收益。**目标**：成长保留系数改为"部分保留"而非"抵消"（如把 -0.35 放宽至 -0.15~-0.20，或高难档直接不反推怪血、走固定遭遇），让 atk 翻倍时**至少多砍 20–30%**。
3. **长线元进度曲线（数值雪球）**：跨局养成（装备/境界/法杖）应提供**受控的乘数雪球**（冒险日记式），使"多玩 = 更早碾压前期、撬动更高进阶"。当前元进度与单局难度的耦合薄弱。**目标**：区分"局内橡皮筋（保平衡）"与"局外雪球（保追求）"两条线，雪球只作用于局外起点，不回填局内钳制。

## 三、竞品机制深挖（机制对机制，带真实来源）

### 3.1 杀戮尖塔 · 进阶 Ascension（"固定遭遇 + 单调可选进阶"的业界举证标准）
- **结构**：通关解锁更高进阶，**20 阶、每阶一条确定规则、累积生效**（灰机wiki：进阶1=精英出现频率 +60%；进阶2=普通敌人造成更多伤害；进阶3=精英更多伤害……进阶20 最凶）。
- **哲学**：**遭遇数值固定**，玩家 build 越强越能碾压；难度来自** encounter 组成与决策压力**（更多精英、healer 球、沉睡威胁、计时条款），而非"把怪数值拉到贴着你脸"。
- **可验证性**：ascension 表是**公开单调真值**，任何一阶改了什么清清楚楚 → 这是"数值公平可举证"的范本（本作正是缺这条，旧审计 D3）。
- **对 S18 启示**：进阶 = **离散、机械、可举证**，且**不剥夺成长感**。

### 3.2 Hades · 热度 Heat + 惩罚契约 Pact of Punishment（"自选难度↔回报强耦合"）
- **结构**：`Pact of Punishment` 解锁后逐条加"热度"，**每把武器独立热度上限**（Reddit/Fandom：热度可逐条开关、0→32+），**加热度直接抬高稀有资源（宝石/徽章/材料）掉落概率与数量** = **Penalty Buffer**（难度倍率 ↔ 回报倍率绑定）。
- **哲学**：难度**完全玩家自选、透明、可随时调**；高难必高回报，闭环硬耦合。
- **对 S18 启示**：本作 `CURSE_TABLE` 已同构，但**回报侧耦合断了**（rewardMult/sealMult 零消费）→ 把词条/Hades 式"阶"与真实掉落倍率焊死，即补齐最大设计缺口。

### 3.3 冒险日记 · 每层成长 / 击杀成长 / % 道具时机（"玩家驱动的受控雪球"）
- **机制**（TapTap 攻略实测口径）：装备有**"击杀成长"与"每层成长"**两条乘数线；**"百分比道具越晚使用收益最高，因为基数（击杀/每层成长）越高"** → 核心决策是**雪球时机**（何时把 % 乘数拍下去）。
- **哲学**：**拥抱数值膨胀**，把"膨胀节奏 + 时机抉择"本身做成玩法；难度用**层级**表达，成长用**乘数**表达，玩家主动经营雪球。
- **对 S18 启示**：本作 `atkGrowth^-0.35` 反雪球**恰好是它的反面**。可借鉴的不是"照抄膨胀"，而是**把'成长何时兑现'做成抉择**（局内滚雪球 vs 局外雪球分层），以及长线 meta 用**受控乘数**给玩家"越玩越强"的确定追求。

### 3.4 难度哲学光谱定位（本作站哪）

```
固定遭遇(尊重成长)                动态橡皮筋(中和成长)         数值雪球(拥抱成长)
 StS Ascension · Hades base   ←  【逆道西行·当前】         →   冒险日记
 (强build碾压顺, 难度靠编成)      (build越强怪越强, 拉回势均)     (乘数滚雪球, 难度靠层)
```
**核心分歧**：本作几乎**独占**了"橡皮筋"这一档——它保证"永不劝退但也不给碾压"，代价是**削掉 power fantasy**。竞品要么不橡皮筋（StS/Hades 让你真变强），要么把膨胀本身当卖点（冒险日记）。

**五列差距（旧审计 §④ 基础上，据新模型重判）**：
- **广度**：中（轴不缺，缺"每轴有效"）。**深度**：小（钳制族比竞品更完备）。

- **可验证性**：**大**（无对外单调举证；两尺口径互斥；`scale` 触底破坏自身"必死≈0"承诺却无门禁捕获）。

## 五、优化设计（可实施，带目标数值 + 落点 + 门禁 + 风险）

> 本轮**不改码**；每条给出足够实现的信息。优先级 P0>P1>P2。

### O1 ·（P0）拆剪刀差：给坦度一条受控成长线 + 重排章节承伤目标
- **问题**：玩家血/盾零成长封顶 3640，Boss 承伤/回合 ×11 → 承伤预算崩到 3–4（§1.3）。
- **方案**（二选一或组合）：
  - A. **装备血解封顶**：`baseHp×4` 上限改为随章节软上限 `baseHp×(3 + act×0.25)`，让 ch3+ 仍有坦度成长（约 +15%/章）。落点：装备/`computeStats` 血封顶处（`combat_part1.js`），非 `playerBaseAt`。

## 八、v1.1 代码复核校正（2026-09-27 09:40，V9.66 基线）

### 8.1 §1.4「scale 触底 → 怪攻仍是 2.4×」被实跑证伪为**低估**

实跑 `NDX.buildMatchFight`（vm 直载 `data_config.js`，rng 固定 0.5 无抖动），入参取 `_balance_anchor.js` 表②/表③ 的真实章末数值：

| ch2/d20 | 3250 | 0.603 | 14 | **0.5（触底）** | 1898 | 1066 | **6.3×** |
| ch3/d31 | 3640 | 0.708 | 17 | **0.5** | 1928 | 1040 | **6.5×** |
| ch4/d41 | 3640 | 0.705 | 20 | **0.5** | 2223 | 1277 | **6.7×** |
| ch5/d46 | 3640 | 0.741 | 20 | **0.5** | 2386 | 1322 | **8.0×** |
| ch6/d51 | 3640 | 0.803 | 20 | **0.5** | 1936 | 1045 | **9.7×** |

⇒ 触底**提前到 ch2**（本文原写 ch3+），倍数 **6~9×**（原写 2.4×）。按 `buildMatchFight` 自己的注释标准（`pressure ≤ 0.90` ⇒ 「必死局占比≈0」）衡量，ch2+ 的实际威胁是设计目标的 **6~9 倍**，注释承诺与实现早已脱钩。

### 8.2 反推所需 `scale` 只有 0.06~0.08 ⇒ **O2「下限 0.5→0.25」数学上无效**

| ch2 | ch3 | ch4 | ch5 | ch6 | ch7 | ch8 | ch9 |
|---|---|---|---|---|---|---|---|
| 0.074 | 0.079 | 0.078 | 0.057 | 0.063 | 0.073 | 0.080 | 0.078 |

即便下限放到 0.25，仍是需求的 3× 以上 ⇒ 只会把怪攻抬得更高。**根因不在下限，在 `tank`**（见 8.3）。

### 8.3 结构性根因：`tank` 只认 HP 型坦度

`data_config.js:271-274`：`tank = max(1, maxHp + hpRegen×(rounds-1))` ⇒ 堆血 build 的坦度 100% 计入，堆 dr/eva 的坦度 **0%** 计入；玩家 dr 提高 → `threatCur` 降低 → `scale = target/cur` 上升 → 怪攻自动补回 ⇒ **DR 收益被数学抵消**。V8.58 引入的 `scale ≥ 0.5` 想保住 DR 收益，但下限只在 `scale<0.5` 时起作用，而 ch2+ 恰好全程 `<0.5` ⇒ 保护在最需要它的区间必然失效。旁证：V9.66 给逆道补的 `ls=0.035` 完全不在 `tank` 内，却让「打不穿→第 8 次」⇒ 真实续航远大于 `tank` 模型的估计。

### 8.4 对本文 O2 的修正

O2 应改写为：**① 扩 `tank` 承认续航/DR/EVA（推荐），② 下限保持 0.5 只作手感保护**。单改下限无效。整改项 R3。
