## ① 当前游戏内容（代码事实）

> 硬规则：每条数值/机制必须带 `file:line` 或 BalanceDB 键；无证据者移入 §⑥。

### 1.1 核心循环
「进节点 → 合成优先/供货 → 定价 → 购买/刷新 → 结算」，金币 `s.gold`（局内）与劫灰 `ash.credits`（跨周）双货币：

1. **进入坊市节点**：`game_core_2.js` `case 'shop'`（`js/game/game_core_2.js:907`）→ 先算价 `price = NDX.shopPrice(node.priceTier)`（`:908`）→ 朝代折扣 `dynastyAdjust(price,'shop')`（`:910`）。
2. **合成优先**：进坊市先查 `NDX.availableRecipes(s)`（`:912`），有可合成配方则改开 `pending.kind='craft'`（`:919`）而非购物——"材料换装备优先于购买"。
3. **供货**：无合成时 `NDX.rollEquips(2, s)`（`:922`）摆 2 件货架；未获当前主导道专属遗物时固定摆其残片（`_relic` 标记，`:934`，兜底确定性获取）。
4. **定价**：`NDX.shopPrice(tier, act)`（`js/events_part2.js:66`）——`base = 30 + (tier-1)*4`（`:67`），地区乘算 `actMult`（`:69`，⚠ 见 §1.7-1 缺失 act）。
5. **购买**：`NDX.Game.prototype.buyShop(id)`（`js/game/game_shop.js:42`）——金币校验 `s.gold < item.price`（`:46`）→ 扣款 `:47` → `_consumeShown` 出库 `:48` → `_relic` 走 `giveRelic`（`:50`）否则 `grantEquip`（`:51`）→ 移出货架 `:52`。
6. **刷新**：`NDX.Game.prototype.shopReroll()`（`js/game/game_event_4.js:275`）——次数封顶（`:281-282`）→ 扣 `SHOP_REROLL_COST`（`:283-285`）→ `rollEquips(2)` 换货（`:287`）→ 新货按 `shopRerollPrice(tier, next)` 上浮定价（`:289-290`）。
7. **劫灰坊（跨周）**：`buyAshUp(id)`（`js/game/game_shop.js:18`）用劫灰 credits 升 `ASH_SHOP` 五线（`js/data_reincarnation.js:56-61`），永久写 `localStorage`（`saveAsh` `:48`）。

### 1.5 边界与异常
- **幂等供货**：`rollEquips` 排除已拥有 + `shownEquips` 曾展示（见 S03 §1.5）；池空时 `shopReroll` 落空**退款** `s.gold += cost`（`game_event_4.js:288`）。
- **合成优先短路**：有可合成配方时**不进购物货架**直接开 `craft`（`game_core_2.js:913/919`），购物与合成在同一节点互斥。
- **craft-leave 复开**：坊市合成页「暂不炼化」回落到重开货架 `rollEquips(3)`（`main.js:1366-1370`，注意此处 3 件而初架 2 件）。
- **价格快照不可逆**：`item.price` 在生成时固化进 `pending.items`（`game_core_2.js:930`），后续朝代折扣/套装折扣只在生成瞬间作用于 `price`，已上架件不随金币变动重算。
- **遗物兜底分流**：`_relic` 件走 `ZHUANJIE.giveRelic`（材料入库）而非 `grantEquip`（`game_shop.js:50`），防误入装备槽。
- **劫灰封顶**：`buyAshUp` 满级 `lv >= def.max` 拒绝（`game_shop.js:24`）、余额不足拒绝（`:25`），落库 `saveAsh`（`:28`）。

### 1.6 跨系统接口
- **朝代 S12（主链）**：`shopRefresh`（隋，刷新+1）在 `events_part2.js:78`；`shop`/`shopDiscount`（商，价-10%）在 `game_core_2.js:910`→`data_dynasty.js:166-168`；`eliteDrop`（三国，+20%）在 `game_loot.js:25`。→ 见 [耦合矩阵 §1.1](02_耦合矩阵与数值口径登记表.md)。
- **装备 S03（供货）**：货架内容全部来自 `NDX.rollEquips`（真源 `data_equip_core.js:503`），购买落地 `grantEquip`（`game_shop.js:51`）。
- **经济金流**：`s.gold` 扣款在本系统，但发放/收入归经济链（enterNode 巡游生金 `equipEconFlags` 见 [耦合矩阵 §二](02_耦合矩阵与数值口径登记表.md) 与 S03 §1.6）；`SET_RESONANCE` 盘缠套 `shopDiscount` 由装备侧提供（`equipment_part3.js:32`）。
- **转职 S11（遗物兜底）**：`_relic`→`ZHUANJIE.giveRelic`（`game_shop.js:50`），当前主导道专属遗物残片的确定性获取口。
- **轮回 S16（劫灰坊）**：`ASH_SHOP`/`loadAsh`/`saveAsh`/`ashLevel` 归 `data_reincarnation.js`（`:56/43/48/63`），`ash.credits` 来自跨周结算（本系统仅消费/升级）。
- **战斗 S01**：`_ashBattleFlags` chg 线补足法宝充能（`game_shop.js:6-14`），联动 S08 法宝。

### 1.7 已知债务与死区
> ⚠ 以下均为**实测代码债务**，本审计只登记不改码。

1. **【设计落空·数值】`shopPrice`/`shopRerollPrice` 地区增长参数 `act` 在所有外部调用点缺失**：`shopPrice(tier, act)` 形参含地区乘算 `actMult`（`events_part2.js:66-69`，注释「V8.41 金币轴决断：价格随地区增长」），`shopRerollPrice(tier, rerollCount, act)`（`:81-82`）第三形参透传。但**四处外部调用全部漏传 `act`**：① 直接 `shopPrice` 只传 tier — `game_core_2.js:908`、`main.js:1366`；② `shopRerollPrice` 只传 (tier, rerollCount)、第三形参 act=undefined — `game_event_4.js:289`（购买价）、`ui_panel_2.js:1303`（UI 显示价，Phase4 与 S10 交叉核对新增）。结果 `act||1`（`:69`）恒取 1 ⇒ `actMult = 1 + min(0.8, 0.05) = 1.05` 固定，**“价格随地区增长”完全未生效**，后期通胀防线形同虚设。P1 数值债务。
2. **【rng 不一致】** `game_loot.js:26` 三国 eliteDrop 追加倍率判定用裸 `Math.random() < (_eliteMul - 1)`，小怪 45% 掉率亦用 `Math.random()`（`:33`）——均不吃整局播种，破坏 seed 可复现（与 `rollEquips`/`rollAdvDrops` 主链 `runRandom()` 相悖，见 S03 §1.5）。
3. **【供货件数不一致】** 初架与刷新供 2 件（`game_core_2.js:922`、`game_event_4.js:287`），但 craft-leave 回落供 **3 件**（`main.js:1367` `rollEquips(3)`）——同节点不同入口件数不同，疑似遗留差异（无注释解释），影响决策一致性。
4. **【双处定价·折扣路径分叉】** `game_core_2.js:908-910`（含朝代 `dynastyAdjust(...,'shop')`）与 `main.js:1366`（**无朝代折扣**）两处独立生成 `price`；craft-leave 复开货架丢失商朝 -10% 折扣，两条入口价格口径不一致。
5. **【无 BalanceDB 覆盖】** 商店/劫灰坊全部数值（`SHOP_REROLL_*`、`ASH_SHOP` cost/max、`shopPrice` 系数）**不在 `data/balance_db.json`**，无任何快照/门禁；改数无自动回归，仅靠 `file:line` 人工核对。
6. **【`_ashDirty` 悬空标记】** `buyAshUp` 置 `s._ashDirty = true`（`game_shop.js:32`）后仅 `bus.emit('render')`，本审计未在 owner 链中定位到 `_ashDirty` 的消费复位点（可能为陈旧标记，§⑥待核）。

## ③ 竞品对比（机制对机制）
> 框架：结构 / 深度 / 手感。主竞品=**STS 商店 / 刷新**，次=ETG（弹性地牢）经济。竞品精确值无本地来源者标「待核」入 §⑥。

| 机制维度 | 本作（实测值+出处） | 主竞品〈STS〉 | 经典肉鸽参照 |
|---|---|---|---|
| 结构 | 局内金币坊市（`shopPrice`）+ 跨周劫灰坊（`ASH_SHOP` 五线）双货币双店（`game_shop.js`） | STS 每层商店卖卡/遗物/删卡，单货币（金币）；无跨局永久店（精确价目待核） | ETG 以「物品价格随稀有度」建模经济；本作档位制 `30+(tier-1)*4` 更粗粒度 |
| 深度 | 刷新 COST30/上限2/涨价20% 三段（`events_part2.js:74-84`）+ 合成优先互斥 + 朝代刷新+1 | STS 商店无「刷新货架」机制（商品固定，精确待核）；本作刷新层为独有 | 本作「刷新次数封顶 + 逐次涨价」是 STS/ETG 均无的 anti-reroll 防滚雪球层 |
| 手感/反馈 | 落空退款（`game_event_4.js:288`）+ 货郎文案（`:282/292`）+ 新手指引合成（`game_core_2.js:917`） | 购买即时的确定感 | 本作劫灰坊「永久升级跨周累积」提供 meta 层正反馈，强于 STS 单局限 |
