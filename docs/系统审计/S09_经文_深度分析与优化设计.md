## 〇、执行摘要（TL;DR）

1. **深度维度：本作经文比 STS 遗物/卡牌"更厚"。** STS 遗物/卡牌皆为"拿到即全额生效"的扁平条目，无"凑件中间态"；本作经文明确保有 **跨章积累 → 凡/灵/真拼篇阶位叠乘 → 渡=boost / 逆=curse 双轨 → 技能经/被动经分流 → 六藏跨周目拓印** 五层纵深（`data_sutra_shard.js:11-15`、`combat_active.js` chant 三态、`data_sutra.js:709`）。
2. **可达性维度：三处"口径错配"正在给这条纵深远水节流。** ——〔C5〕`dropSutraFrag` 每次只产"新种类各 1"、已持有则**整段丢弃不叠量**（`game_sutra.js:117-118`），与 V9.54「可重复堆叠凑够 cost」的新定价直接冲突，高频战斗掉片通道实为半瘫；〔C2〕`sutraHalfPick` 仍按"该部是否有空缺种类"判据（`data_sutra.js:1013`），与 `sutraChantPool` 的 gap（还差几片）新口径不一致；〔C3-rng〕朝代追加掉落两处走**裸 `Math.random()`**（`data_sutra.js:467 / :510`），不经 `runRandom` 播种流，破坏可复现性与门禁盲区。
3. **对 STS 的最大差距 = "可举证的稀有度单调表"缺位。** STS 每一档稀有度都是**可写死、可回归**的单调数字（卡牌 60/37/3、遗物 50/33/17，L1 wiki）；本作经文的"稀有度"藏在 **六道加权 × 主道偏置 × 被动经软饱和**（`data_sutra.js:107-114`、`data_jobspec.js:383-468`）三重隐函数之后，玩家与门禁都拿不出一张"第 N 章单局可得几片 / 各档期望"的单调表。深度是真深度，透明是假透明。
4. **§⑤ P0 三条**：〔O1〕去 `dropSutraFrag` 种类门槛改数量叠加；〔O2〕`sutraHalfPick` 统一到 gap 新口径；〔O3〕朝代/概率门两处裸随机收编入 `runRandom` 播种流。三条均**只设计不改码**、可被现有 5 个门禁脚本扩测。

### 1.4 边界与死区（本卷核心发现）

- **〔C5 · 掉片半瘫〕** `game_sutra.js:117-118`：
  ```
  if (!s.sutraFrags[fid]) { s.sutraFrags[fid] = 1; ... }   // 已持有该 fid → 整段丢弃，永不 +1
  ```
  V9.54 定价已改为"凑够 cost 枚**任意片**（可重复堆叠）"（`sutraHave :167`、`chooseSutra :50`），但这条高频通道仍停在"每个 fid 至多 1 枚"的旧语义。⇒ 战斗/事件掉片对**已摸过的种类毫无贡献**，边际产出随进度骤降，与"首周目合理可达量"目标（`game_sutra.js:94-96` 注释自陈）背离。
- **〔C2 · 口径分裂〕** `data_sutra.js:1013` `sutraHalfPick`：`f.frags.some(fid => (frags[fid]||0) < 1)` 判"该部是否还有**空种类**"；而诵经池 `sutraChantPool`/合成走的是 gap（还差几片）。两套判据 ⇒ "看起来还能凑"与"实际被推荐/被允许凑"的两张皮。
- **〔C3-rng · 可复现破坏〕** `data_sutra.js:467`（`grantSutraShard` 朝代倍率追加）与 `:510`（`grantSutraAuto` 朝代追加）两处 `Math.random()` **不走 `runRandom`/播种**，而同文件的逆经掉片 `:685/:688` 已实现 `rng ? rng() : Math.random()` 的正解。⇒ 同种子不同结果，门禁回归存在盲区。
- **〔兜底漂移〕** `data_sutra.js:282` `costDays = C.LIFE_DAYS || 18`，真值 `LIFE_DAYS:40`（`:217`）。正常路径取 40 无碍；一旦 `SUTRA_CHANT` 读取失败即回落 18，而 `:214-216` 注释明确指出"18 天 ⇒ 仅 3.9%，寿命几乎不构成约束，诵经成为无脑刷"。兜底值恰是注释判过死刑的值。
- **〔诵经仅渡〕** `doChantSutra:271` 只 `NDX.sutraFullById(fullId)`（渡侧表），逆经永不入诵经补片通道 ⇒ 诵经是"渡藏专属回收"，逆藏只能靠战斗/事件掉片累积。是设计意图但**未在 UI/文案上言明**。
- **〔注释即错〕** `data_sutra.js:109` 注释写"总量变成 渡 223 / 逆 127 / 合计 350 片"，实测 effective 为 **渡223/逆134/合计357**（逆侧与合计各少 7）。注释自陈为"防文档漂移的单一事实来源"，本身却已漂移。
- **〔命名撞车〕** `data_chants.js:13-19` `CHANTS`= 5 英雄**本命战斗真言**（CD2、mult1.5-1.7），与"诵经"(`doChantSutra`/`gateChantSutra`)、`s.chantSutra`（持诵格）三者共享 `chant` 字根。审计/沟通时须每次消歧。

## 二、设计目标：经文系统"应然"的评判标准

1. **多样性优先于堆叠**：经文的存在意义是"改变诵经/技能的**形态**"（`SUTRA_VARIANT_TMPL` 7 kind），而非纯数值。⇒ 评判标尺一：单局能否稳定见到 ≥2–3 种技能形态变化。
2. **可达性曲线可证**：cost 定价应保证"入门经 1–2 章即得、终极经须跨周目"（`SUTRA_CHANT:219-221` 自陈体感目标）。⇒ 标尺二：每章期望得片、单局可成部数应可列表举证，如 STS 之稀有度。
3. **确定性可复现**：零构建 H5 尤须同种子同结果，供门禁与竞速。⇒ 标尺三：任何 `Math.random()` 皆须可收编入播种流。
4. **稀有度可举证**：软加权（六道 × 主道 × 软饱和）是深度，但须有"单调报表"托底，否则玩家无从判断"下次是否该赌"。
5. **双轨代价对等**：渡=boost、逆=curse(`data_sutra_shard.js:17-21`)，逆强须有实付代价。⇒ 标尺五：逆侧增益与其 curse 代价在数值上须可对齐审计。

## 三、竞品机制深挖（含一手来源）

### 3.1 杀戮尖塔 STS · 遗物（主竞品，L1 — slaythespire.wiki.gg / Relics）
- **稀有度分层**：Common **50%** / Uncommon **33%** / Rare **17%**——一张写死的单调表。
- **宝箱三档**：Small 75/25/0、Medium 35/50/15、Large 0/75/25（越往后 Rare 权重越高，可举证）。
- **决策密度**：Boss 遗物**三选一**；商店固定陈列约 20 件；遗物总量约 297。⇒ 玩家几乎每层都在"读稀有度 + 读协同"做主动取舍。
- **无中间态**：遗物拿到即全额生效，没有"凑件/合成"环节——协同靠"已持有集合"涌现，而非靠进度条。

### 3.2 杀戮尖塔 STS · 卡牌与升级（L1 — Cards / Rest Sites）
- **稀有度概率**（pre-offset）：普通遭遇 60/37/3、精英 50/40/10、商店 54/37/9。
- **伪随机递增（anti-streak）**：Rare 起点 = 表值 −5%，每 roll 到一张 Common，Rare 概率 +1%，roll 到 Rare 即重置。⇒ **既保底又限欧，可完全推导**。
- **升级路径**：一张牌**只能升级一次**（Searing Blow 例外可多次）；升级靠**休息处 Smith**，与回血(Rest 30% maxHP)、删牌(Peace Pipe)互斥争夺同一"休息"资源。
- **节律保障**：每章 Boss 前必为休息处 ⇒ 决策点位置固定可预期。

### 3.3 万世剑冢 · Eternal Sword Tomb（扩展竞品，L2 — Steam/3DM/TapTap，无一手数值）
- **借法 / 传承机制**：角色陨落化"剑魂"留存，后世掌门向先祖借法继承力量——**跨周目元进度**结构，对应本作六藏拓印收集线。
- **本命神剑拼装**：部件拼装成型，对应本作"残片凑 cost 合成全本 + 凡灵真拼篇阶"。
- **流派 × 终极特质**：v1.4.3 新增 7 流派 / 14 终极特质——**形态分流**思路对应本作 7 kind 技能经模板 + 技能经/被动经分流。
- **五行克制**构筑维度对应本作六道加权。
- ⚠ 数值无一手来源，仅作**结构对照**（L2），不入量化表。

### 3.4 稀有度哲学三档定位
- STS：**固定表 + 伪随机递增**（透明、可推导、可回归）。
- 万世剑冢：**传承解锁 + 拼装**（元进度驱动、局内确定性中等）。
- 本作：**六道软加权 + 主道偏置 + 被动经软饱和**（深度最高、透明度最低）。

| **删/换通道** | Peace Pipe 删牌 / 商店 | 释经换金（`game_rest.js:138` dropSutraShard：渡 8/逆 12、全本 16/24） | 已具备 | ✓ 对等 |
