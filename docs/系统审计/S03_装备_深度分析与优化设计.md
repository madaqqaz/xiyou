## 〇、执行摘要（TL;DR）

- **系统现状**：装备是全作最重的养成系统，**注册表 698 / 本体 674 件**，五池（EQUIP_POOL 489 / CRAFT_POOL 197 / BOSS_REWARDS 12 / ADVENTURE_GEAR 18 / TREASURES 93 属 S08）+ 214 条配方 + 26 套共鸣 + 六道成长六轴 + 传承衰减 + 派生式图鉴，**全部落地且有真实消费点**。工程完成度在同类独立游戏里属上乘；数据一致性（26 套名 ↔ 26 共鸣键零孤儿、图标 314 全覆盖）也早已达标。
- **四大真问题（全部本轮实跑，非旧文档）**：
  1. **词条键名分裂 ⇒ 69 件装备的卖点词条为零效**。`crit` 53 件 + `criMult` 3 件 + `lifesteal` 13 件在 `computeStats` 无读取点；而图鉴 `equipTags` 按 `crit` 出「暴击」标（实测 53 件出标）⇒ **面板/图鉴承诺、战斗不兑现**。装备侧真正能拿到生效暴击 `cri` 的只有 7 件（6 宠 + 1 法宝），武器/护甲事实上**没有暴击词条来源**，暴击全靠劫印（`sl.crit`×`sealMult`）与套装共鸣（`cri` 17 处）供养。
  2. **后半程装备供给在 ch4 断崖，并直接反噬 S18 的难度曲线**。`_advChapterPool(ch)` 实测可掉落：ch1 **79** → ch4 **15** → **ch5 8 / ch6 5 / ch7 4 / ch8 4 / ch9 19**，且 **ch5–ch9 的 weapon / armor / head 件数恒为 0**（只掉 1 双靴 + 若干 treasure 位散件）。英雄专属链封顶 ch4。实跑 `computeStats`：悟空 ch4 满配 **atk 3015 / power 5430**，ch9 满配 **atk 1579 / power 4461**（四件全是盘缠商店散件）⇒ **终章面板只有四章峰值的 52%**；血量自 ch3 起撞 `baseHp×4` 顶恒 3640。这与 [S18 §1.3](S18_数值曲线与难度_深度分析与优化设计.md) 的「承伤预算 ch2 起崩到 3–4 回合」互为因果，是"ch9 通关率≈0"的**装备侧根因**。
  3. **"稀有度"有四套互不感知的口径，玩家看到的颜色是假的**。① `quality`（668/698 无值，注释倍率失实）② `setTier`（实际主轴）③ `dropTier`（18 件写 low/elite/boss，而 `game_core_2.js:670` 又把 `green/blue/red/gold` 写进**同名字段** `node.dropTier`）④ 显示档 `EQUIP_TIERS` 白绿蓝红金（`equipTierOf` 只看 setTier/quality/chapter，**完全不看属性**）。后果实测：**装备本体金装 0 件**（gold 需 `setTier≥4`＝0 件 或 `quality≥3`＝仅 8 只宠物）；`adv_a_jiuzhuan`（hp680 / dr20% / 护盾13%）这种顶级散宝显示为**白装**。
  4. **V9.9「章末 Boss 必掉阶梯核心物」的成就感台阶在实装上完全空转**。`bossDropTierFloor`（[combat_part2.js:497](../../js/combat_part2.js)）给 Boss 盖 blue/red/gold 下限，`game_combat_3.js:110` 用 `_tierOk` 在节点自有掉落里筛达标件——但 **BOSS_REWARDS 12 件（`bf_*`，全章共用）实测五档全为 white**，`_tierOk` 恒 false，`:114/115` 的 `if (length)` 保护静默回退原列表。⇒ 机制在，判据永假。
- **竞品一句话结论**：主竞品**冒险日记**用四条成长轴（击杀成长 / 每层成长付资源 / %道具使用时机 / 链式跨类合成）把"装备"变成了**决策载体**；扩展竞品**杀戮尖塔 193 件遗物**几乎**每件都改规则而不加数值**。本作装备本体 **674 件里 0 件带"触发条件+效果"的机制动词**（机制动词只存在于 26 套共鸣的 4/20 个字段里），且**同 id 全局唯一**（`game_equip.js:14`）⇒ 不存在"刷第二件同款"，也就不存在冒险日记式的"重复件喂成长"闭环。
- **优化优先级**：**P0 = 修死词条（O1）+ 重建 ch5–ch9 供给（O2）+ 稀有度轴归一（O3）+ 让 Boss tier 地板真落地（O4）**；P1 = 机制动词词条（O5）/ 成长决策化（O6）/ 跨类链式合成（O7）/ 淬炼扩维（O8）；P2 = 死码与重复块清理（O9/O10）、rng 收敛（O11）、图鉴一致性（O12）。

## 三、竞品机制深挖

> **取证说明**：主竞品**冒险日记**以本地精读报告 [逆道西行_vs_冒险日记_转职系统对比分析报告.md](../逆道西行_vs_冒险日记_转职系统对比分析报告.md) + 本轮联网检索到的一手玩家长文《冒险日记新版本部分装备介绍、点评》（7723 手游网，2026-09-18 转载）交叉印证；文中引号内容均为原文直引（**L2：机制描述可信、精确数值未经官方表格逐条复核**）。扩展竞品 15.71 图鉴取本地报告 + 联网；杀戮尖塔遗物池取 wiki.gg / Fandom（**L2**，页面计数为**抓取时点**值）。

### 3.1 冒险日记（主竞品）：装备的四条成长轴

冒险日记的装备之所以"值得每件看一眼"，是因为它把装备做成了**一个有独立时间轴的投资品**。拆成四条彼此正交的成长轴：

**轴 A · 击杀成长（无成本、自动、慢）**
> 「民兵套，新版属性没变，效果**命中怪物 15% 加 1 血上限**，聊胜于无，最垃圾的成长装备。」

触发器挂在**战斗事件**上（命中），无需玩家操作，概率 + 小步长。它的意义不是强度，而是"每一件装备都有自己的成长速率"，于是"穿哪件" = "想练哪条轴"。玩家自己给这条轴排了 T 级（"最垃圾的成长装备"），说明**成长速率本身成了可评价的决策维度**。

**轴 B · 每层成长（有成本、手动、可评估 ROI）**
> 「黑暗经书……**每层耗 20 点杀戮值 + 3 魔力**，5 血上限。」
> 「佣兵 3 件……**每层耗 300 块加 3 点力量**，300 块等于一层打 15 个怪，没有 15 个怪就相当于花钱买力量属性。」
> 「魔晶法帽改版，**每层耗 15 魔晶加 3 魔力**。」
> 「自然 3 件……**每层三维上限 +1**……单件前期过渡装备，看上去很美好而已，**100 层也就加 100 上限**。」

这是本作最缺的一环：**"要不要在本层付这个资源"是一层一层的重复博弈**，且玩家会自己做单位换算（300 块 ≈ 15 只怪 ≈ 3 点力量 ⇒ 折算成"打钱效率"）。它把楼层进度、货币、属性、装备四者焊死在一个决策里。

**轴 C · 百分比道具的"使用时机"博弈（延迟满足）**
> 「（百分比道具）**越晚使用收益最高，因为装备有击杀成长和每层成长**。」
> 「绿鞋很难出……出了之后，**200 层以后再用**，要不力量魔力属性基数会不够。」

本作有 `%` 词条（`atkPct/hpPct/matkPct` 等 20+ 处共鸣字段），但**没有"何时结算"的概念**——`computeStats` 每帧重算，`%` 与定值在同一个瞬间加完（`combat_part1.js:111+` 之后）。因此**"存着晚点用"在本作里既不可能、也不被理解**。轴 C 是三条轴里唯一一条**纯粹由"结算时序"创造深度**的机制，成本最低、收益最高（详见 §⑤ O6）。

**轴 D · 链式跨类合成（装备 → 装备 → 更高类别）**
> 「白银剑 + 净化剑（**暗黑剑强化 2 次**）= 圣剑」
> 「白银 3 件，头盔鞋子衣服合成白银套 + **强化石** = 圣光战甲」
> 「圣剑 + 圣光战甲 = **神光剑圣**」（战士专属，"特效物理加成 100%，攻击命中回复 5% 生命，命中减 10% 物抗"）
> 「**元素使徒 = 法师自带宠物元素精灵 + 三色龙牙**」
> 「3 件套 + **自然符文**」「4 件套 + **战神符文**」

这条链的关键是三件事：**(a) 输入跨类别**（装备 + 装备 + 强化石 + 符文 + 宠物），**(b) 中间态需要"强化 N 次"作为前置**（把轴 B/C 的资源决策接进合成图），**(c) 终点改名改性**（神光剑圣不再是"剑"或"甲"，是一件新的规则件）。
本作 `RECIPES` 214 条的形态是 **`base + materials → out`（同类、单跳、一次性）**，`base` 与 `materials` 全是装备/材料字符串，**没有一条配方跨到宠物/符文/技能**（元素使徒那种"宠物 + 装备"合成在本作无处安放，因为 `slot:'pet'` 与 `RECIPES` 无交集）——这是 §④ 的最大结构差距。

### 3.2 冒险日记：词条是"动词"，不是"数字"

> 「白银侍从……**被打 80% 减伤，70% 概率出手。每次被打或者出手消耗 5 + 层数/3 的金币**。不能用来挂机，打 boss 用的。」
> 「（野蛮系）特效都是**每掉 10% 血加 20% 物理加成**。」
> 「（潜行 3 件）效果 **20% 2 倍暴击变 3 倍**……合成之后 **25% 10 倍暴击**，基本 300 层是完全没问题了。」
> 「（战神 4 件套）100% 物理加成，40% 格挡，300 血，50 力。」
> 「（神光剑圣）**命中回 5% 血、命中减 10% 物抗**。」

每一条都是 **`触发条件 → 动作 → 代价`** 三元组，并且**带资源后果**（白银侍从"打完高层 Boss 发现没钱了"）。这就是"机制动词词条"。对照本作：装备本体的词条全部是 `+=`（§1.3 白名单 21 键全部是加法），**唯一的"动词"在 `SET_RESONANCE` 的 4 个字段**（`drSealMult` 对劫印减伤做乘区、`evaOnDodge` 闪避后再判闪、`petRes`、`xinmoSuppress`）——即**本作的机制密度 = 26 套共鸣的 4/20 字段，装备件本身 0/674**。

### 3.3 冒险日记：稀缺格子与"具名 farm"——两个让玩家自己排优先级的压力源

> 「魔晶法帽……前期挂一挂可以，**后期没格子**，黑暗经书比这玩意强太多。」
> 「肯定还有些我不清楚的，比如尸鬼之怒，打了好久都没出过，听说是**食尸鬼杀了村长**出的。」
> 「史莱姆液，**杀史莱姆给**」「野蛮之锤，**打哥布林概率爆**」「玷污之刃，**杀堕落天使掉**」

- **格子稀缺**：装备栏位是硬预算，玩家被迫在"两件都好"之间取舍。本作 `activeEquipsFor` 的四槽 + special 1 + pet 2~6 + treasure 2 看似也有预算，但因为 **`_pickActiveN` 自动择优（`equipment_part3.js:1193-1201`）+ 同 id 唯一收集制**，玩家**不需要真的取舍**——系统替他选了，且"曾展示 / 已拥有"去重让候选池单调收敛。
- **怪物 → 具名装备**：掉落表绑定在**具体怪**上，于是"想变强就去刷那件"成为可行计划（farm 动机）。本作的掉落入口 `_advChapterPool(ch)` 是**按章的均匀池**（`equipment_part3.js:906-918`），且 ch5–ch9 无武器护甲件（§1.5a）⇒ 玩家**无法通过"多打某类怪"来定向获取**，farm 动机为零。
- **装备可卖钱**：重复/过渡件有出口，形成"捡→卖→买核心件"的经济环。本作重复件走 `_grantDuplicateReward`（`game_equip.js:14-17`）折成资源，**有等价机制**，此项不属差距（诚实标注）。

|---|---|---|

## 五、可实施优化设计（只设计，不改码）

> 每条统一格式：**问题 → 目标值/公式 → 落点（owner 文件）→ 验收门禁 → 风险 → 优先级**。所有跨系统难度/曲线口径一律引用 [S18 深度文档](S18_数值曲线与难度_深度分析与优化设计.md) 与 [02_耦合矩阵](02_耦合矩阵与数值口径登记表.md)，本文不另立数字。

### O1 ·（P0）词条键名归一：消灭 69 件死词条

- **问题**：`crit` 53 件 + `criMult` 3 件 + `lifesteal` 13 件在 `computeStats` 无读取点；图鉴仍按 `crit` 出标（D1）。这是"面板承诺、战斗不兑现"的诚信问题，且集中在红装合成链基座胚件（镇妖/封神/轮回剑胚等）上。
- **方案（三选一，推荐 a）**：
  - **(a) 数据侧改键**（最小风险）：把 53 件 `crit:` → `cri:`、3 件 `criMult` → **保持不接线但删字段**、13 件 `lifesteal` 按下方公式并入现有 `sealFlags.lifesteal` 管道（它是真实存在的出口 `combat_part1.js:359`）。
  - **(b) 内核侧别名**：`computeStats` 循环内 `cri += (e.cri || e.crit || 0)`。⚠ 不推荐：会永久保留双名，下次审计又要对表。
  - **(c) 废掉装备侧暴击**：删 53 件 `crit` 字段并将对应数值改入 `atk`（保持总 power 不变）。⚠ 会改变已上线图鉴文案。
- **目标值**（按 (a)，power 守恒，公式取 `combat_part1.js:342-350` 的权重）：
  ```
  Δatk_equiv = crit × 700        // 暴击在 power 式里权重 700
  例：五佛冠·真 crit 0.08 → 等效 56 power；若改为 cri:0.08 则直接生效，无需换算
  平衡护栏：全装备生效 cri 总量从 7 件 → ≤60 件，面板 cri 总额封顶仍受 :324 同族钳制约束（建议新增 CRI_CAP = 0.45）
  ```
- **落点**：`js/equipment_part1.js`（EQUIP_POOL/CRAFT_POOL 字面量）、`js/equipment_part3.js:673-695`（ADVENTURE_GEAR）、`js/combat_part1.js:100-110`（**只改注释与钳制，不改读取名单**）；图鉴侧 `data_equip_core.js` 的 `equipTags` 自动跟随。
- **验收门禁**（新增 `scripts/_verify_equip_field_truth.js`，可挂在现有 `_verify_equip_truth.js:217` 旁）：
  1. 遍历注册表 698 件，断言「存在至少一个不在 21 键白名单内的数值字段的件数 == 0」（白名单从 `combat_part1.js:100-110` 正则抽取，**不手写**）；
  2. 实跑 `computeStats('wukong', [全 53 件 former-crit 装备], …)` 与基线对比，断言 `cri` 按预期上升；
  3. 图鉴一致性：`equipTags` 出「暴击」标的件数 == 实跑 `cri > 0.10` 的件数。
- **风险**：⚠ **中等偏高**。53 件真生效后，玩家暴击从基线 0.10 上跳，会直接推高 DPS → 喂给 S18 的 `buildMatchFight`（其 `tank` 只认 HP 型坦度，见 [S18 §8.3](S18_数值曲线与难度_深度分析与优化设计.md)），**难度会隐性下降**。⇒ 必与 O1 的 `CRI_CAP` 护栏同批落地，并重跑 `_balance_sweep.js --baseline` 与 `_balance_run_model.js --seeds=40` 对比道带胜率（基线：渡3/战5/夺10/逆5）。
- **优先级**：**P0**（它是其他一切优化的前置：不然新加机制词条也会被同一类键名分裂吃干）。

### O6 ·（P1）成长从"免费点满"变"逐层投资"（熔铸收费 + 载体扩容）
