## 〇、执行摘要（TL;DR）

- **系统现状**：结局面是"动态 10（`endings.js` cond 链）+ 静态 7（`game_meta.computeEnding` 英雄×善恶 if 链）+ 告别卡 5（`NDX.ENDINGS` 图鉴层）= 22 条"的三层判定，配 8 张 CG、3 支实机视频、朝代/成就/寿数/排行榜多轴耦合。**广度确实超 Hades**，判定轴也丰富。
- **三大真问题（本轮实跑/实读，非旧文档）**：
  1. **完美结局视频 + 朝代成就同根死锁（P0）**：`settleReturn` 在播视频/落成就**之前**就 `resetDynasty()` 把朝代打回夏（`game_meta.js:269` → `:305/:307`），复位后 `dynastyHas('perfectEnding')` 恒 false、`getDynastyIdx()` 恒 0 ⇒ 3 支 mp4 **一次都不播**、`all_dynasty` **一次都不亮**（探针 L1 坐实）。这是投入最重的演出资产被一行时序静默吞掉。
  2. **动态结局贪婪遮蔽静态英雄结局（P1·幻影）**：`wanbao` 门槛过松（金币≥200/装备≥10 是终局常态）且排在 `ORDER` 第 4，把 zhanfo/yuanding/jinchan 及全部"英雄专属静态结局"压在身后 → 常态通关**几乎只得「万宝归一」一个结局**，多结局广度是**纸面数字**。
  3. **多结局"收集可验证感"整条未闭环（P1）**：22 条索引的 `threshold/source/desc` 无任何 UI 消费（`endingsBySource`/`endingCgOf` 零调用），CG 画廊各画各的（只按英雄通关/六藏拓印点亮，不读结局表）；告别卡 5 条零接线 ⇒ 玩家看不到"还缺哪几个结局"，索引表立项动机落空。
- **竞品一句话结论**：Hades 的护城河不是"结局数量"，而是**"死亡即推进 + 结局与叙事解锁经济硬绑定"**——每一局（哪怕暴毙）都产出新对白/新剧情，真结局锁在"重复击败终Boss × 好感度 gift 经济 × 支线任务链"之后，**结局本身是 meta 进度条**。本作结局广度反超，但**结局不产出任何跨局可累积的叙事增量**（通关后除逆道门/排行榜外几乎无长期收集反馈），且这唯一的视频奖励还被时序死锁吞了。
- **优化优先级**：**P0 = 修复位时序死锁（O1，接线即兑现既有 3 视频 + all_dynasty）**；P1 = 收紧/重排 `wanbao` 解除结局遮蔽（O2）+ 建结局图鉴让消费者真读 `NDX.ENDINGS`（O3）+ 统一静态/动态结局对象带 id/cg（O4）；P2 = 视频预检/`st_jinchan` 字面清理、论道改写结局纳入索引、rng/门禁补强。

## 一、当前系统解剖（代码实况）

> 结构细节链接 [S14 审计 §1.1–1.7](S14_结局_审计.md)，此处只给"设计视角"关键链路 + 本轮探针实测。

### 1.1 一个结局是如何"算"出来的（全链路）

```
终局触发（第81难凌云渡返程）→ settleReturn(game_meta.js:194 起)
  ├─① buildReturnScene(data.js:310) 按到西天余寿 left 定档：
  │     left<SHRINE_R(9)→grade'shrine'留舍利(:325)  否则 grade'return'，perfect = left≥PERFECT_R(14)(:326)
  │     回长安余寿 = left − RETURN_COST(9)(:327)                     （常量真源 data_life.js:31/33/34）
  ├─② NDX.Ending.determineEnding(s)(:209)  ← endings.js:125 按 ORDER(:119) 10 键首命中，null=全不中
  │     命中→包装层(data_endings_index.js:113)补 id+cg；不中→computeEnding() 静态 7 分支(:453-501)
  ├─③ grade'return'→ending.perfect/rankName 落定(:217-218)、savePerfectClear() 永久解锁逆道门(:221)
  ├─④ 排行榜双榜 submitRank(:224-243，读复位前当朝 → 朝代名正确)
  ├─⑤ s.over = {win,reason,ending}(:244)、扣 RETURN_COST 落 s.life(:251-256)
  ├─⑥ bumpCycleOnce()(:266) → resetDynasty()(:269-273)  ← ⚠ 朝代在此被打回夏(idx=0)
  ├─⑦ _syncAch()(:305)  ← 朝代类成就在此读 getDynastyIdx()，但 idx 已=0（探针坐实）→ all_dynasty 恒不亮
  └─⑧ 视频：dynastyHas('perfectEnding')(:307) → play(_eid)(:312)  ← ⚠ idx 已复位→夏无该 feature→恒 false→恒不播
```

- **判定链双互备**：动态链异常/不中 → `computeEnding` 静态兜底**必返**（无 null 出口）→ 任何通关必有结局，无空终局态（`game_meta.js:209-210`、`endings.js:128-131` 单条 cond try/catch）。这是系统最扎实的一面。
- **但"必有结局"≠"结局分布合理"**：见 §1.3——判定顺序使绝大多数通关落进同一条（万宝归一）。

### 1.5 边界与异常
- **CG 画廊有点亮逻辑但走错数据源**：`ui_misc_2.js:472-478` `_cgCardOn(c)=c.hero? clearedHeroes.includes(c.hero) : sixDaosComplete()` —— 5 张告别 CG（有 hero）按"该英雄通关"点亮、3 张主线 CG（无 hero）按"六藏全拓印"点亮。这是**按 CG 卡独立判定**，与 `NDX.ENDINGS` 的 22 条结局无任何关联（画廊从不 `endingById`）。
- **论道可越界改写结局**：二周目论道三选了断（`game_lundao.js:144-160`）用 `NDX.LUNDAO.choices[key]` **整体覆盖** `s.over.ending`，新对象仅 `{title,text[,cg]}`，脱离 22 索引命名空间；且视频在 `settleReturn` 内已基于**覆盖前**结局判定，论道换的结局不再触发任何视频/成就复核。

### 1.6 未接入项与幻影（本文核心，均 L1）

- **① 完美结局视频链复位时序死锁（P0，探针坐实）**：`settleReturn` 在 `game_meta.js:269` 调 `NDX.resetDynasty()`（`data_dynasty.js:92-96` 把 `DYNASTY_KEY` 写回 0=夏），**之后** `:307` 才 `dynastyHas('perfectEnding')`。`dynastyHas`（`data_dynasty.js:132-138`）按**当前** idx 取 feature，复位后 idx=0=夏，夏 feature（`:26-27` `{ashBonus,startEquip}`）**无 perfectEnding**（仅唐 `:44-45` 有）⇒ 恒 false ⇒ `EndingVideo.play`（`:312`）每次通关**恒不被调用**。探针：复位前 `dynastyHas=true`、复位后 `dynastyHas=false`。
- **② `farewell` 5 条 + 查询接口零消费者（P1）**：`source:'farewell'`（`data_endings_index.js:83-94`）、`endingsBySource`（`:98`）、`endingCgOf`（`:101`）全库 Grep **仅命中自身定义**，无任何 UI/结算调用。5 条告别卡的 `threshold`/`desc` 文案在运行期无人读取（对比：动态/静态结局至少有 `determineEnding→s.over.ending` 消费链）。
- **③ 静态结局对象缺 id/cg（P2，探针坐实）**：`computeEnding` 返回 `{title,text}`（探针键集 = `['title','text']`），无 id/cg；`video` 分支 `s.over.ending.id==='st_jinchan'`（`game_meta.js:308`）**恒 false**（动态 id=`jinchan`、静态无 id），仅 `title.indexOf('金蝉')` 兜住 zhengguo。`净坛圆觉/卷帘归真/白龙渡海` 本也无对应视频（仅 3 支），故 cg 缺失对视频无影响，但对任何"按 id 取 CG"的图鉴/回放是隐患。
- **④ 朝代成就同锁（P0，与①同根）**：`_syncAch`（`game_meta.js:305`）在复位后跑，`achievements.js:245-253` 读 `getDynastyIdx()` 恒 0 ⇒ 每次通关点亮 `xia_seng`，`all_dynasty`（需 idx≥LAST_IDX=9）**永不可达**。

## 二、设计目标：结局系统"应然"的三条判据

> §④ 差距与 §⑤ 优化都对着这三条打。

1. **结局即 meta 推进的可验证承诺**：既然本作结构是"结局即通关收束 + 朝代轮回"，则每个结局应产出**跨局可累积、可在图鉴检视**的增量（收集进度/解锁/叙事回响）。当前 22 条广度只有 3 类真消费（`s.over.ending` 文本、排行榜、3 成就 title），**图鉴收集闭环与告别卡点亮皆缺**，"多结局"沦为一次性文本分支。
2. **可达性诚实（无幻影）**：索引表陈列的每条结局，要么有真实可达路径，要么显式灰标"未开放"。当前 `st_nidao` 做了灰标（`unreachable`），但 `wanbao` 遮蔽造成的**批量幻影**、farewell **零接线**都未登记 → 玩家面对 22 条目录却实际只能稳定收到极少数几种。
3. **投入资产必兑现**：3 支实机制结局视频 + `all_dynasty` 成就是高成本内容，应保证在满足条件时**确实播放/确实点亮**。当前被一行时序（resetDynasty 早于判定）静默吞掉，属"做了等于没做"的最坏债。

## 三、竞品机制深挖（机制对机制，带真实来源）

### 3.1 Hades · 死亡即推进 + 结局与叙事解锁经济硬绑定（主竞品）
- **结构**（Supergiant 官方口径 / Fandom·Reddit 社区，精确计数标 L2）：Hades 有**单一"真结局"**，但抵达它需要**反复击败终 Boss**（每一世把冥殿主线推进一段），并且结局/尾声（Epilogue）的触发**锁在人物关系链后**——通过赠送 **Nectar（好感货币）→ 首次送礼换 Keepsake → 更高阶 Ambrosia 抬好感 → 解锁专属对白/支线任务/至宝进阶**（Steam 社区 heart/favor 指南、rogueranker Hades2 送礼指南：Hades II 有 33 个 Keepsakes，多由"首次赠 Nectar""完成支线后赠 Ambrosia"解锁）。
- **哲学**：**"失败也是一种进展"**——即便战死回冥殿，也会因"本局用了什么武器/见了哪个 Boss/推进到哪"触发**新的反应式对白**，叙事进度条**只增不减**；结局不是靠"这一局打得好"，而是靠**跨局累积的关系经济与剧情 flag**。
- **对 S14 裁决**：这正是本作**最缺的一维**。本作结局**不产出任何跨局叙事增量**——通关后除"逆道门永久解锁"（`game_meta.js:221` `savePerfectClear`）与排行榜外，**没有"看了这个结局 → 图鉴进一格 / 下世开新对白"的累积反馈**。可借鉴的是**把结局接进 meta 解锁经济**（O3 结局图鉴 = Hades 冥殿剧情回放的对应物），而非照抄"单真结局"（本作多结局是差异化资产，勿削）。

### 3.2 多结局可达性表设计（扩展对比对象，业界通行范式）
- **范式**（视觉小说/CRPG 通用）：成熟多结局系统对外提供**可达性矩阵**——每个结局标注「触发条件 + 当前是否可达成 + 已收集与否」，并把"条件互斥/优先级"做成**可举证的确定规则**（如优先级链中靠后的结局，其前置必须与靠前结局**互斥**，否则靠前项**吞噬**靠后项）。
- **对本作**：`ORDER` 首命中即返（`endings.js:126-132`）是**优先级吞噬**的教科书场景——`wanbao` 门槛与其它项**不互斥且过松**，直接把靠后所有结局吞掉（§1.3）。Hades 式做法会把每条结局写成**离散互斥条件**（"战≥8 且 非(金币≥200 的万宝态)"）。裁决：**本作需要的是可达性门禁 + 条件互斥化，不是加更多结局**（广度已过剩）。

### 3.3 Rogue Legacy · 传承型终局（对照"结局非收集对象"一档）
- **机制**：单一终局（击败父王），收集在"传承变异/职业/装备"维度而非结局本身；结局是 NG+ 循环的开关。
- **对本作**：本作的"NG+ 传承"由**朝代/轮回/引渡匣**承担（`game_meta.js:261-273`，见 [S12_朝代_审计.md](S12_朝代_审计.md)），结局系统与之**职责重叠又互不通气**——朝代复位本该由结局系统感知（当前反而把它冲掉，§1.6-①）。

### 3.4 结构光谱定位（本作站哪）

```
结局=叙事增量落点(每结局必产跨局反馈)     结局=一次性文本分支(打完即止)     结局=单真结局开关
   Hades(关系经济+剧情flag)        ←   【逆道西行·当前】(22条但无收集闭环)  →   Rogue Legacy
   (死亡即推进,结局锁好感/支线)      (广度第一,兑现与可验证度垫底)          (传承承担 meta)
```
**核心分歧**：本作**独占**了"动态 cond 链 × 英雄×善恶×命数×余寿档×朝代 多轴 + 22 条 + 8 CG + 3 视频"的**广度与耦合复杂度**，竞品无一在"判定轴数量"上接近；但**结局的兑现（视频恒不播）、可达性（wanbao 遮蔽幻影）、可收集性（图鉴零消费）三项竞品标配全部缺失**——广度换来了深度错觉，实收却是最薄的。
