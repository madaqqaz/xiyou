## ① 当前游戏内容（代码事实）

> 硬规则：每条数值/机制必须带 `file:line` 或 BalanceDB 键；无证据者移入 §⑥。

### 1.1 核心循环
「业务侧写存档 → 门面双 API（`NDX.storage.save` 注入 `_version/_savedAt` 后 JSON 序列化 | `NDX.SaveSystem.save/load` 带类型化 loadNumber/saveNumber）→ `_store()` 解析后端：`NDX.Platform.storage` →裸 localStorage（`__PLATFORM_FALLBACK__` 白名单）→内存 Map（L124-132）→ 宿主 `setItem`」；读路径对称：`getItem→JSON.parse→失败返 null/默认值`；断点循环：

1. **自动断点**：`autoSave`（`js/game/game_meta.js:317-333`）深拷贝 `s`、剔除 `pending` 浮层（`:322`）、写 `meta{hero,layer,ts,version:NDX.storage.VERSION}`（`:323-330`）→ `NDX.storage.save(KEYS.RUN)`（`:331`）；触发点：战斗后 `game_combat_2.js:246`、节点后 `game_core_2.js:970`、结算 `game_meta.js:332` 一带。
2. **还原**：`restoreRun`（`js/game/game_rest.js:2-26`）：结构校验（`:5`）→ **旧版断点拒绝**：`_runInvalid || meta.version < VERSION` 即 `remove` 并开新局（`:7-10`）→ 逐字段纯还原 + 旧档补 `choiceFlags/npcRel`（`:20-22`）→ **读后即删防双读**（`:23`）。
3. **跨局落盘枢纽**：`recordRunEnd(s, killed)`（`js/data_save.js:79`）一局终结集中写：lastRun 摘要 + favor 赐福 + track 善恶 + collection 藏品 + rubbing 拓印 + monument 碑塔（留存 `slice(0,200)` `:163`）+ ash 劫灰 + stats 统计。
4. **寄存匣（万世剑冢）**：`registerVault`（`js/data_vault.js:61`）LRU 存入 `xynj_vault_v1`（`:10`），上限 `VAULT_MAX=3`（`:11`）、衰减 `VAULT_DECAY=[1,0.7,0.4]`（`:12`）、出库经 `_stripVaultReward` 剥离链式/成就钩子（`:91`）。
5. **键名迁移**：`SaveSystem.load` 读空时遍历 `KEY_MIGRATION_MAP`（`js/save_system.js:132-141`）：`xynj_ach→nx_ach_v1`、`xynj_cleared_diffs→ndx_cleared_diffs`（`:89-92`），搬家后删旧键。
6. **结构迁移**：storage 层 `MIGRATIONS[1]`：v1 断点（`meta`+数值 `layer`）标 `_runInvalid`（`js/storage.js:47-56`）→ 由 restoreRun 消费清理；`load` 对对象自动 `_migrate`（`:158-161`）、`save` 自动注入版本（`:168-172`）。

### 1.5 边界与异常
- **读损坏**：JSON.parse 失败 → storage 返 `null`（`storage.js:163`）/ SaveSystem 返 `defaultValue`（`save_system.js:147/153-156` console.warn），**不炸主流程**。
- **写失败**：配额满/隐私模式静默吞（`storage.js:174` 注释自证；`browser.js:23` 同）；SaveSystem `save` 返 boolean（`:163-164` JSDoc）。
- **启动窗口兜底**：Platform 未装配时 storage 直落裸 localStorage，`__PLATFORM_FALLBACK__` 行尾标记由门禁白名单管理（`storage.js:118/123`；`_verify_storage_platform_bridge.js` 存在）。
- **无迭代能力降级**：Platform 后端缺 `length/key` 时 `_storeKeys()` 返空数组不抛（`storage.js:135-147`）——但连带使 `clearAll` 前缀扫描在该后端下**静默清 0 个**（仅注册表 33 键被删，§⑥ 关联 1.7-3）。
- **数组不迁移**：`load` 只对非数组对象自动 `_migrate`（`storage.js:159`）——成就数组 `nx_ach_v1` 天然不走结构迁移（其兼容由并集语义保证，S13 §1.5）。
- **无校验和/防作弊**：全链路仅 JSON 往返，明文可改（纯前端单机的设计选择，非缺陷；登记事实）。

### 1.7 已知债务与死区
> ⚠ 以下均为**实测代码债务**，本审计只登记不改码。

1. **【休眠 API·前缀漏扫】** `getAllKeys/clearAll/getSize/exportAll/importAll`（`save_system.js:306-393`）只扫 `KEY_PREFIX='xynj_'`（`:119`）——**漏 `ndx_/nx_/xy_` 三族 14 键**（成就/朝代索引/断点全在漏区）；且实测**五函数全库零消费者**。"备份/导出"能力当前是纸面 API，一旦接线即静默丢一半存档。
2. **【死链·迁移门禁不可达】** `SAVE_KEYS` 16 键表外部仅 `MAIN` 命中 1 次（`save_system.js:149`，且 MAIN 自身零外部写方）⇒ `migrateSave`（`:104-114`）+ `MIGRATIONS{}` 空骨架（`:101-103`）整条"值域结构迁移"链**无真实数据可达**；V9.26 注释宣称"未来登记即生效"（`:98-99`）在接线前不成立。同文件 `DYNASTY:'xynj_dynasty'`（`:66`）全库唯一出现处即定义行=死键（真实朝代键 `ndx_dynasty_idx` 走 storage 层）。
3. **【clearAll 漏键】** `storage.clearAll` 注册表遍历（`storage.js:203`）+ 前缀扫描（`:204-211`）；但 `xynj_save/xynj_stupa/xynj_vault_v1` **不在 STORE** 且 `_storeKeys()` 在 Platform 后端缺 `key/length` 时返空（`:135-147`）⇒ 该后端下重置只删 33 注册键、遗留键全存活（跨 1.5 边界）。
4. **【键名双表分叉】** `save_system.js:48` 注释自称"V8.41 与 storage.js 的 STORE 键名一致"，实测不符：`SETTINGS` `xynj_settings`（`:82`）vs `ndx_settings`（`storage.js:85`）、`DIFFICULTY` `xynj_difficulty` vs `ndx_difficulty`（`:82-83`）——双真源各写各前缀（两侧实际消费点均稀少，暂无数据分裂事故，但属 01 宪法"同量双真源"违规）；另 `KEYS.DYNASTY_IDX` 被 `data_dynasty.js:53` 引用却未注册（undefined || 兜底掩盖）。
5. **【冗余门面】** `NDX.storage` 与 `NDX.SaveSystem` 包同一 `_store()` 语义的两套 API（storage 有迁移注入/注册表；SaveSystem 有默认值/类型化原语，实测引用各上百处并存）+ `migrateAll`（`storage.js:185`）零消费者 + 双 `SAVE_VERSION` 常量（2/2 靠人肉同步）——门面合并/职责划界未落地（V9.63 设计稿只回拢了 Platform 层，见 §②）。
6. **【无云端/跨设备同步】** taptap 宿主存储仍落本地 `localStorage`（`platform/taptap.js:35`），SDK 云档接口未消费——"平台适配"实为**同一本地介质的两副面孔**；元进度跨设备一致性为零（设计边界，§③ 竞品差距的根因）。
