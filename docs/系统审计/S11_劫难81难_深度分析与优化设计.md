## 〇、执行摘要（TL;DR）

- **系统现状**：81 难是**三套坐标系叠在一根轴上**——9 章 `ACT_RANGES`（`js/data_region_config.js:39-49`，末难 14/20/31/41/46/51/64/75/81，层数合计 62）／难簿 4 卷 `VOLUME_BOUNDS=[20,40,60,81]`（`js/data_volume.js:9`）／**42 个"复合弧"难号**（`js/data_compound.js`，九章 `compact` 全开）。内容量：`TRIAL_LIB` 81 难 / **331 选项**（均 4.09/难）/ 60 处 `portrait` / 57 处 `branchKey` / 23 处 `treasure`。工程侧密度不低：`_optionGate` 七规则（`js/game/game_event_4.js:121-211`）、`normalizeTrial`、`echoPayoff`、劫印六源 `SEAL_SOURCE_TIER`（`js/jieseals.js:214-229`）、即时难度六轴，全都在。
- **四大真问题（本轮实测，非旧文档）**：
  1. **复合弧是一条"叙事降级通道"**。42/81（52%）难走 `_compoundTrial`（`js/game/game_event_1.js:272-335`），它构造的 `s.pending` 与 `case 'trial'`（`js/game/game_core_2.js:327-516`）相比**缺四件事**：不透传 `branchKey`、不合并 `branches`、不做 `echoPayoff`、无 `fightOpt` 兜底。后果被量化：全库 53 个"只能靠自动落印"的选项中 **48 个落在弧内（demo 内 26 个）**——即网状叙事 P0 的"关键难自动落印"机制 **91% 被弧路径吞掉**；21 个带 `branches` 的难里 **16 个的专属文案永久不可见**。
  2. **通天河终局矩阵三重死 + 一处反向误伤**。`tongtianAllNi` 需三子难全「逆」，而难 36/37/38 的 `opt.fate` 值域里**根本没有「逆」**（`js/trials_ch4.js:114-116,133-134,152-155`）⇒ `tongtianFury` 及其 5 个下游全灭；`tongtianAllDu` 数学可达，但消费点被钉在 `case 'elite'/'boss'` 且要求 `node.diff===36`，而章末 Boss 节点 `diff` 恒为 `actEnd(4)=41`（`js/data_map.js:259`）⇒ 唯一可能命中它的是 **act4 局部层 L5 的随机精英节点**（`diffOfLayer` ⇒ 31+5=36），届时会把一场普通精英战误记为"金鱼精·通天河决战（鱼篮收伏）"并吞掉其绿劫印+经文碎片。**不是无害死代码，是"一旦生效就错"**。
  3. **印记词汇表没有契约**。5 个 requireFlag 键**全仓零写入点**（`n17_sisheng_du/_yuan`、`n30_honghaier_rescued`、`wukong_absent`×6 引用）⇒ 9 条引用不可满足；难 18 用中文 `opt.key` 落印、难 19 用拼音 `n18_wuzhuang:du` 读印 ⇒ 键域/值域交集为空；再加难 18/19 双双在弧内（连自动落印都不发生）⇒ **三重死**。而且这类失败**不会卡死**，因为 `_optGateCtx` 整组放行兜底——它治的是 V9.50 P0-6 难 24→难 25 真死锁事故（注释自陈 `js/game/game_event_4.js:79-85`），代价是把所有"前置失败"变成静默。
  4. **隐藏职与簿册的结算 API 已失配**。`jobProgressFor`（`js/data_trials_story.js:384-407`）读 `cfg.jobs`，但 `NDX.HIDDEN_JOBS[hero]` 是**数组**（探针：5/11/3/4/3/19=45 岗位，`.jobs` 全不存在）⇒ **六英雄一律返回 `null`**，消费方 `js/game/game_combat_2.js:509` 的"转职解锁进度"永久空白；`js/game/game_rest.js:216-217` 双死（`(NDX.TRIALS||[]).length` —— `NDX.TRIALS` 是 22 键**对象** ⇒ 恒 0；`s.metTrials` **全仓零写入点**）⇒ 弃档面板"历经劫难 0/0"。
- **竞品一句话结论**：《斗战神》（官方活动页标题即「**不一样的西游**」）把八十一难**去编号化**为 16 个具名副本 + 原画收集，"收集场景即进度"；Hades 用 **Pact of Punishment（热度上限 40，门槛 8/16/32 分层解锁）+ 每武器 21 组悬赏（0–20 普通档 & 5–25 地狱档）+ Mirror of Night（6,165 / 含 Boon 14,365 Darkness）+ 主线需 10 次成功逃离**，把"重复挑战"折成"叙事增量 + 永久解锁"三种货币；FTL 用 **8 星区 + beacon 类型配额池**做到"每类事件按固定次数抽取、用完即空"。本作在**配额池**这一项已工程对齐（`_capTrialNodes` + `usedTrialDiffs` + `taken` 排除集），但**81 难是一次性消耗品**（难号被 `usedTrialDiffs` 吃掉、无跨周目复用），既没有斗战神的"收集册"资产化，也没有 Hades 的"自缚换回报"旋钮。
- **优化优先级**：**P0 = 补齐弧路径叙事（O1）+ 拆除/重铸通天河死矩阵（O2）+ 印记闭环门禁（O3）+ 修 `jobProgressFor`/`metTrials`（O4）** —— 四条都是"承诺已存在、代码为空或错接"的静默缺陷，零新设计即兑现既有文案。P1 = 难 18→19 因果重铸（O5）、车迟 `s.diff=31` 跨章身份窃取（O6）、`_compoundBoss` 死函数与黄风大圣硬编码（O7）、注释坐标系统一（O8）。P2 = `RETURN_TRIALS` 接线或退役（O9）、劫难"自缚契约 + 簿册收集"经济（O10）。

### 3.1 主竞品解构：《斗战神》「不一样的西游」

- **定位对齐度极高**：官方活动页标题即「不一样的西游」（`http://dzs.qq.com/act/a20130607byyxy/index.htm`），以今何在《悟空传》为蓝本、"成人视角重读西游"——与本作的"黑暗西游 + 逆道"是同一解构母题。

- **对本作的镜鉴（可量化）**：本作把"编号"当进度主轴（81 编号 + 4 卷 + 9 章），但真正有差异化的资产在**抉择层**：331 选项 / 60 `portrait` / 21 `branches` / 42 `echo` / 253 `consequence`。当前状态是"**编号轴过度宣传、叙事资产静默丢失**"（A1/A2/A3）——与斗战神方向恰好相反。可行的最小对齐动作不是加副本，而是**把已写好的 16 难 `branches` 文案变成可收集、可回放的簿册条目**（见 O10）。

### 3.2 Hades：把"重复挑战"折成三种货币的双阶段经济

| Fated Ordeals（命中注定的试炼） | 该武器热度 **≥8** 才解锁 | "试炼"作为**可自选进入**的独立高回报节点 |
| 主线叙事 | 需 **10 次成功逃离** 才看完结局 | 通关≠结束；重复=剧情增量 |

**关键洞察**：Hades 的"试炼/劫难"不是进度条，而是**三种可兑换物**（热度=自缚权限、赏金=武器特定目标、黑暗=元进度），并且**每次 run 都会推进某一种**。本作三者皆无：热度轴不存在（`bossDiff` 字段填写 0，见 §1.2）、赏金表不存在（`RETURN_TRIALS` 30 条零消费）、历难产出只在局内（`trialsPassed` 不入 `NDX.vault` 永久维度，与 [S15_存档_深度分析与优化设计.md](S15_存档_深度分析与优化设计.md) 对账）。

### 3.3 FTL：beacon 类型配额池 + flavor 复用

8 星区、每星区尾 Boss；节点按 **beacon 类型**从"每种事件按固定出现次数"的配额池抽取（精确事件总数未获权威源，见 §⑦ L2）。对本作最有用的两点：

1. **配额池的"稀缺性由类型决定而非由编号决定"** —— 本作 `_capTrialNodes` 配额（act2/act6 普通劫难点 = 1）已经实现了"每层唯一劫难位"，但难号一旦被 `usedTrialDiffs` 消费就永久出局（一局内），且弧把 42 个难号打包成 14 次产出（§1.4）⇒ **稀缺性被弧压缩，多样性和获取次数此消彼长却没人对账**。
2. **flavor 每次重读** —— FTL 的事件文本会重复出现仍有效；本作 81 难是"一次性剧本"，重玩价值全靠隐藏职/结局/簿册（[S14_结局_深度分析与优化设计.md](S14_结局_深度分析与优化设计.md)），而这几个下游目前各有一处断链（A4）。
