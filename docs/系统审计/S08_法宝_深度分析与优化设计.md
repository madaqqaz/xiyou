## 〇、执行摘要（TL;DR）

- **系统现状**：法宝是"主动祭出 / on-hit 常驻 / 夺宝进化"三条并行子循环，容器同为 `s.equips`。工程门禁**密**（`_verify_treasure_synergy` 39/0、`_verify_treasure_onhit` 27/0、`_verify_treasure_lux`），主动祭宝链（含共鸣临时放大、软克制、COMBO 连段 ×3）**成熟且独有**。
- **三大真问题（本轮实测，非旧文档）**：
  1. **法宝→技能状态链整条断链**：19 条 `TREASURE_STATUS` 是设计给"夺道至宝（进化体）在手动三键里挂眩晕/毒/灼烧/沉默/虚弱/迟缓/破甲"用的，但因扫错存档字段，运行期**一条都不触发**。夺道至宝只剩扁平 atk/hp/dr 数值，**承诺的机制效果静默蒸发**。
  2. **紧箍 on-hit 悬挂调用**：`NDX.applyJinguProc` 无定义却仍被 `fight()` 调用，`jingu`（如意精箍棒）是**全章可获取 + 悟空本命法宝**（`FABAO_POOL` / `HERO_BENMING_FABAO`）→ 极可能装备即崩，或"每回合额外重击"永久失效。
  3. **构筑耦合薄弱 + 数值无锁**：法宝主力是"扁平数值 + 一次性充能爆发 + 概率 proc"，真正把它焊进 build 的三条线（同源共鸣、软克制、双持共鸣）**要么只作用于主动祭出、要么依赖断链的状态注入**；6 件名器 proc 值无门禁兜底。
- **竞品一句话结论**：STS 遗物 = **规则改造器**（一次拾取全程改写打法，无充无祭）；Hades 双性 Boon = **构筑前置解锁**（集齐两神特定 boon 才以 12% 掉出更强组合）；冒险日记 饰品 = **图鉴收集 + 条件合成 + % 时机**。本作法宝**多出"充能稀缺 + 主动祭出参与感 + 顺/逆命进化"三重竞品都没有的结构**，但在"机制改造密度"与"构筑前置解锁"两项上明显落后 STS/Hades。
- **优化优先级**：**P0 = 接回状态断链（O1）+ 修/删紧箍悬挂（O2）**（两者都是"承诺存在、代码为空"的静默缺陷，零设计成本即兑现既有文案）；P1 = proc 逐值锁门禁（O3）+ 法宝 relic 化"机制改造"扩轴（O4）+ 共鸣改 Hades 式前置解锁（O5）；P2 = rng 播种（O6）+ `phase`/`counter` 枚举与真源统一（O7）。

### 1.5 边界与异常
- **先收集后一次性结算**：`applyTreasureOnHit` 避免同击/窗口重复叠乘；多源减伤取最小乘数（最强），仅减伤类保留 `SHRINK_FLOOR0.30` 地板，控制类（stun 归零/silence 减半）可破地板（`combat_part2.js:551-628`）。
- **Boss 控制弱化**：`stun/silence` 对 Boss `_bossDur=min(2,n)`（`:548/590`）。
- **进化幂等**：一宝只进化一条支线（命中即 `break` `:280`），`lootById` 取不到 `continue`（`:272`），原位 `splice`（`:273`）。

- **rng 不一致**：on-hit 触发（`combat_part2.js:567`）与状态注入（`data_skill_variant.js:105`）均裸 `Math.random()`，不吃整局播种（旧审计 §1.7-3 仍成立）。

## 二、设计目标：法宝系统"应然"的三条判据

> §④ 差距与 §⑤ 优化都对着这三条打。

1. **文案即契约**：装备描述里写到的每一条机制（"每回合概率附带额外重击""至宝圆满挂 XX 状态"）必须**在运行期真实结算**。当前 §1.6-①② 直接违反此条——这是法宝系统最高优先级的"应然底线"，且**修复成本近零**（要么接线、要么删文案）。
2. **构筑改造 > 数值堆叠**：法宝的长期价值应来自"改变打法"（relic 化规则改造、build 前置解锁），而非"再多 40 atk"。当前主力是扁平数值 + 一次性充能爆发，真正焊进 build 的三条线（同源共鸣、软克制、双持共鸣）覆盖面窄或依赖断链。
3. **可验证的数值公平**：所有触发概率/效果强度（6 名器 proc、SYN 四系数、counter dmgX、evo 门槛）应锁进门禁，形成对外可举证表。当前仅 SYN 被锁，proc/dur 裸奔。

## 三、竞品机制深挖（机制对机制，带真实来源）

### 3.1 杀戮尖塔 · 遗物 Relic（"规则改造器"，法宝最该对标却最没学透的一档）
- **结构**（slaythespire.wiki.gg / fandom）：遗物按 **Starter / Common / Uncommon / Rare / Shop / Event / Boss / Ancient / Curse** 分类；**一次拾取、整局常驻、无充能、无主动祭出**；绝大多数遗物是**条件触发的规则改写**，例：「每回合出牌 ≤3 张 → 下回合多抽 3 张」。
- **哲学**：遗物**不堆数值，改的是'怎么打'**——把构筑决策压进"这张遗物让哪种 deck 成立"。玩家为**触发条件**重塑整个 build。
- **对 S08 启示**：本作法宝强在"充能稀缺 + 主动祭出参与感"（STS 完全没有），但**弱在机制改造密度**：6 件 on-hit 名器是"概率施加一个 debuff"，仍属**加法数值**，不改"打法结构"。O4 即补此缺口。

### 3.2 Hades · 双性 Boon Duo/_dual_（"构筑前置解锁 + 稀有度"）
- **结构**（Fandom `Duo_Boons/Hades_II`、IGN、rogueranker）：Hades 2 约 **37 个 Duo Boon、9 位神共享**；掉落**基础概率 12%**（可被护身符/契约提升）；解锁条件是**已持有该组合两神各自的指定前置 Boon**——先集齐 Ares+Zeus 特定升级，才会"长"出对应双性。
- **哲学**：更强效果**锁在构筑路径后**——"你先把流派搭到位，我才给你组合技"，形成**可追求、可规划、稀缺**的正反馈。
- **对 S08 启示**：本作 `TREASURE_SYNERGY`（4 组双持共鸣）是**静态 AND 判定**（`hasSynergy` 只看"两件都在档"），既无 12% 稀缺、也无"前置件先成型"的成长台阶。O5 把共鸣改 Hades 式前置解锁。

### 3.3 冒险日记 · 饰品 / 条件合成 / % 道具时机（主竞品，收集与雪球）
- **机制**（TapTap 攻略口径，L2 精确值无源）：**装备于栏自动合成**（把素材件穿上即合成成品）、**许愿/图鉴收集**、**unique 唯一件互斥**、**"百分比道具越晚用收益越高"**（雪球时机，与 [S18 §3.3](S18_数值曲线与难度_深度分析与优化设计.md) 同源）。
- **对 S08 启示**：本作法宝的"顺/逆命进化"（§1.1④）**在'浇灌道途决定成品分叉'上强于冒险日记**（后者合成线较浅）；但**收集图鉴化 / 单局槽位稀缺经营**上，本作法宝栏 `active:2` 已具雏形，缺的是"unique 唯一件互斥"这种**排他决策**（本作红宝"一局仅一件" `noRecharge`/`hasNi` 已有局部实现，未成体系）。

### 3.4 结构光谱定位（本作站哪）

```
纯被动规则改造(无充无祭)          混合：稀缺充能+主动祭出+常驻被动        纯佩戴数值(收集/合成)
 STS 遗物 · Hades Boon      ←   【逆道西行·法宝】(独有 charges/祭出/进化)  →   冒险日记 饰品
 (改"怎么打",全程生效)          (参与感强,但机制改造密度低+两条链断)          (收集/合成/雪球)
```
**核心分歧**：本作**独占**了"充能稀缺 + 救命替劫（`phase:'dead'`）+ 顺逆命进化"这三重竞品皆无的结构；代价是**机制改造密度**（STS 维度）与**构筑前置解锁**（Hades 维度）两头都欠，且这次实测发现**两条本该提供机制深度的链根本是断的**。
