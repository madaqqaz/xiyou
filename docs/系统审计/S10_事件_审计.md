> 硬规则：每条数值/机制必须带 `file:line` 或 BalanceDB 键；无证据者移入 §⑥。

### 1.1 核心循环

```
地图「缘(?)」节点 → NDX.rollYuan(s)  ──「遭遇战」50% mob / 50% elite → 战斗
                                    └─「奇遇」→ 四层漏斗择一：
                                        ① 送行事件 INIT_GIFT_EVENTS（英雄首个缘）
                                        ② 灵兽进化事件 rollPetEvolution
                                        ③ 双线经文事件池（30%/70% 分池 + 加权 + 3 连保底）
                                        ④ 通用奇遇 pickEvent（均匀抽）
                                     → s.pending{kind:'event'} → 玩家选项
                                     → applyEventOpt → _applyFate/gainMoral/gainXinmo/_gainFate
                                     → thenEvent 递归接下一事件 / 回落 s.pending.then
```

### 1.5 边界与异常

- **池空兜底不卡死**：`_usedEventIds` 用尽后回退全过滤池（`js/events_part1.js:107-108`）；双线池空则回落 `pickEvent`（`js/game/game_core_2.js:844`）。
- **`thenEvent` 指向不存在 id 时静默回落** `s.pending.then`（`js/events_part1.js:46-47` → `js/game/game_event_3.js:198-200`），无异常。
- **门控失败方向正确**：`hero`/`dao` 声明了就必须命中，状态缺失一律排除，杜绝跨英雄泄漏（`js/events_part1.js:86-92`，V9.20 加固注释）。
- **needPet 判据"在队才算"**，非图鉴解锁（`js/events_part1.js:100-104`）——避免兑现不了的事件文案。
- **rng 不可注入**：`rollYuan`/`weightedSutraPick`/`pickEvent` 全走 `Math.random()`（`js/events_part1.js:140`、`js/events_part2.js:1165`），而 `js/data_sutra.js:685` 的同类加权支持 `rng` 参数 → 事件链**不可种子复现**，S18 定标无法把事件方差与战斗方差分离。
- **跨周目/存档**：`_usedEventIds` 是**模块级全局**（`js/data_map.js:9`），仅在第 1 章建图时重置（`js/data_map.js:95`）→ 同一页面内连开第二局若从 `act>1` 起（传承/调试入口）不会清空；`s.eventPity`/`s._sutraEvDone`/`s._gearEventMiss` 随 state 存档（`kind:'event'` pending 不入档，见 [S15](S15_存档_审计.md)）。
- **心魔封顶有旁路**：`gainXinmo` 默认受 `CHAPTER_CAP` 约束（`js/game/game_event_3.js:834`），但 5 处调用显式传 `cap:false`（`js/game/game_event_4.js:34/245`、`js/game/game_meta.js:393/400/426`）→ "章封顶"仅对事件/劫难增量生效。

1. **"三层池 + 稀有度加权"未接线**（主机制缺位）：166/166 条带 `pool` 标注（common/god/hero/dao），但 `pickEvent` 全文不读 `pool`，过滤后均匀 `_pick`（`js/events_part1.js:107-109`）。god 池 27 条与 common 池同概率。
