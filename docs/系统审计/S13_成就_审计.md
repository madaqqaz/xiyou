## ① 当前游戏内容（代码事实）

> 硬规则：每条数值/机制必须带 `file:line` 或 BalanceDB 键；无证据者移入 §⑥。

### 1.1 核心循环
「对局行为 → `checkAch(s)` 全量重算达成集合 → `_syncAch` 与历史并集比对 → 新点亮落 `saveAch`（跨周目持久）→ 平台上报 + toast/log 播报 → 永久加成经 `globalAchBonus`/`achvSlotBonus` 在下一局开局注入」：

1. **触发点**：`NDX.Game.prototype._syncAch`（`js/game/game_event_3.js:430`）调 `NDX.checkAch(s)`（`:433`），全库实测 **13 个调用点**：`game_combat_2.js:122`（失败结算落簿）、`game_core_2.js:253/379`、`game_equip.js:245`、`game_event_2.js:433/490`、`game_event_3.js:428`、`game_meta.js:305`（通关结局类落簿）、`game_region.js:122`、`game_rest.js:234`、`game_sutra.js:70`、`game_vault.js:73`。
2. **落簿**：新增 id `hist.push(id)` + `NDX.saveAch(hist)`（`game_event_3.js:437-453`），并集语义 = 历史不回退（本局未满足不清除已点亮）。
3. **播报**：`【难簿·新功名】` 日志（`:443`）+ 首次解锁教学 toast（`:445-448`）。
4. **平台上报**：`NDX.Platform.achievements.reportUnlocked(newlyUnlocked)`（`game_event_3.js:458-460`），不阻塞主循环（宪法 §七·五）。
5. **反馈环**：`globalAchBonus()`（`achievements.js:398`）在开局 `applyStart` 注入 `s.bonusTi/bonusYuan`（消费 `js/game/game_event_1.js:197-201`）→ 成就直接换全局属性。

### 1.5 边界与异常
- **并集不回退**：`_syncAch` 只做 `hist.push`（`game_event_3.js:438`），成就一经点亮永久；`checkAch` 纯重算不写库。
- **隐藏成就豁免**：非完美通关时 `hidden` 条目被 `got.delete` 摘除（`achievements.js:208`），但 V8.36 注释称"记录为隐性获得"——实际无暂存载体，仅不点亮（`:204-205` 注释与实现半一致）。
- **try/catch 防断链**：`achvSlotBonus` 整体包 try，`loadAch` 无/异常返 0（`equipment_part3.js:174-181`）；`loadAch/saveAch` 优先 `NDX.SaveSystem`、降级 `NDX.storage`、再兜底返 `[]`（`achievements.js:821-843`）。
- **快照 norm 化**：`balance_db.js:123` 只序列化 `ACHIEVEMENTS`，`NANBU` 不入库——难簿 req 门槛无快照回归。
- **周目读取降级**：`getCycle` 双通道（`SaveSystem.loadNumber`→`storage.load`），`NaN` 回落 1（`achievements.js:762-768`）。

### 1.7 已知债务与死区
> ⚠ 以下均为**实测代码债务**，本审计只登记不改码。

1. **【零通道成就·逻辑死锁】`qing_seng`**：判定 `if (_dId === 'qing') got.add('qing_seng')`（`achievements.js:251`）——但十朝表 `DYNASTY.LIST` = 夏商周秦汉三国晋南北朝隋唐（`js/data_dynasty.js:24-48`）**无 'qing'**（"清"仅存在于成就文案 `:111-112` 与 `all_dynasty` desc 的"夏商周秦汉三国晋南北朝隋唐五代宋辽金元明清"19 朝虚指中），该 add 调用**永不触发 ⇒ 69 条中唯一的字面接线零通道成就**。desc 的朝代列表与代码实际 10 朝背离（`:112`）。
2. **【时序死锁】`all_dynasty` 通关即复位**：判定要求 `_dIdx >= LAST_IDX`（`:252`），而 `settleReturn` 在 `_syncAch`（`game_meta.js:305`）**之前**已 `resetDynasty` 写 0（`game_meta.js:269-270`）⇒ 唐朝通关瞬间 `_dIdx=0`，`all_dynasty` 与 `shang_seng`（`_dId==='shang'`）等按"当前朝代"判定的成就在唯一合法触发时刻全部拿到复位后的"夏"。与 S12 §1.7 完美结局死锁同根（见 [S12](S12_朝代_审计.md)）。
3. **【口径背离】`all_17`**：desc「单局走过全部17个地区」（`achievements.js:95`），判定实为 `regionsVisited 键数 >= TOTAL_ACTS(9)`（`:230`；`TOTAL_ACTS=9` `js/data_region_config.js:51`）——**9 章 ≠ 17 地区**，走过 9 章即点亮"十七路皆通"，名实不符（`TOTAL_TRIALS=81` 同文件 `:52` 被 `all_81` 正确使用）。
4. **【重复定义】`equipment_part3.js` 槽位块整段两份**：`SLOT_CAP`（L168 与 L272）、`achvSlotBonus`（L173 与 L277）、`companionSlotCap`（L184 与 L288）、`sealSlotCap`+`dynastySealSlot`（L248-257 与 L350-361，node 比对**文本逐字节相同**）——后定义覆盖前者，运行时结果暂一致，但双维护必然漂移（一份改一份漏）。
5. **【难簿无快照】** `NANBU` 66 条 + `VOLUME_ACH` 4 条不进 BalanceDB（`balance_db.js:121-127` 仅序列化 `ACHIEVEMENTS`+2 meta）——占成就点亮通道一半（`checkAch:199-203` 动态 add）却无门禁回归；`ACH_BONUS_CAP=70` 来源亦不在快照。

| 机制维度 | 本作（实测值+出处） | 主竞品〈Gungeon〉 | 扩展〈Hades〉 |
|---|---|---|---|
| 结构 | 双轨：69 条卷九成就（行为徽章）+ 70 条难簿逐卷功名（meta 货币前身），统一落 `nx_ach_v1`（`achievements.js:820`） | 成就（Challenges）单轨，界面以**解锁百分比**作总进度导向（精确条数待核） | 功绩单轨，且成就即 meta 系统本体 |
