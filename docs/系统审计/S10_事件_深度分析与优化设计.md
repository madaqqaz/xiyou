## 〇、执行摘要（TL;DR）

- **一句话现状**：事件系统是"**三池 + 四层漏斗**"——主池 `EVENTS`（166）、双线池 `SUTRA_EVENTS`（157）、引导池 `INIT_GIFT_EVENTS`（5），由 `game_core_2.js:707-864` 的 `case 'event'` 串成 `rollYuan → 送行 → 灵兽进化 → 双线三级判定 → pickEvent 兜底`。抽取口径是**均匀抽 + 跨章去重**（非加权）。
- **好消息**（不必向竞品补课的部分）：① 问号节点的"事件/战斗"自适应保底已经**与 STS 同构**——`rollYuan` 以 `p=min(1, 0.10+0.10×pity)` 递增（`events_part1.js:137-148`），且 `s.eventPity` **每章归零**（`game_region.js:177`），正对应 STS `UnknownMapPointOdds.ResetToBase()` 的"章节边界清零"；② 20 万次实跑事件份额 **72.74%**、最长连事件 **9**，与 STS "?"节点 ~85% 事件率同量级——**差距不在"出不出事件"，而在"出哪个事件"**。
- **一个 P0 级断线（不是设计问题，是奖励根本没发）**：双线池 157 事件的**全部专属奖励**——51 件事件装备（`gear`）、273 处指定经文残片（`sutra`）、14 处观音好感（`favor`）、193+125 处精确善恶分档（`alignGood/alignEvil`）——**在事件通道一件都不结算**。归一化代码只存在于 `applyTrialOpt`（`game_event_2.js:58-63`），双线事件却走 `applyEventOpt`（`main.js:616-619`）。玩家点"求经——心经一卷"实际只拿到 `_autoGE` 兜底的**善/恶 ±1** 与一次 `dropSutraFrag` 的**随机碎片**（`game_sutra.js:100` 按 fate 掷 15%/70%，与所选经文无关）；点"讨衣——旧衲傍身"**什么装备都拿不到**。更讽刺的是：④ 层那套精心设计的"30% 装备池 / 70% 普通池 / 3 连必出装备"保底（`game_core_2.js:814-828`）**专门服务于这个空转**——保底机制越是认真地把装备事件送到玩家眼前，落空的反差越大。详见 §1.5-M，修法见 §⑤-O0。
- **四大真问题**（除上条断线外，其余三条均为本轮实测，非旧文档）：
  1. **稀有度只是一行注释。** `pool: 'god'` 全仓**零读取**（`events_part1.js:77-108` 只过 `region/hero/dao/needPet`，不看 `pool`），主池亦无 `weight` 字段。实跑池份额：act1 `common 75.6% / god 18.8% / dao 5.6%`，act9 `common 68.9% / god 19.7% / hero 6.5% / dao 4.9%`——**份额完全等于条数占比**，"神佛降世"与"残碑秘闻"在机制上等价。而"神佛"若真与凡俗同价，西游最稀缺的那层想象力就当场贬值。
  2. **因果链在事件层结构上不可能成立。** 引擎侧 `_optionGate` 七条叙事门**齐备且已防死锁**（`game_event_4.js:121-211` + 全锁兜底 `_optGateCtx:86`），数据侧 323 事件 / 819 选项**零使用**；唯一在跑的 `thenEvent` 链路把"已见"记进 `s._usedEventIds`（`game_event_3.js:195`），而抽取时读的是全局 `NDX._usedEventIds`（`events_part1.js:107`），**两容器零交集**（探针 E1-E4 实证）⇒ 链走完的下一步仍可被随机再抽一次；更糟的是整局 state 会被序列化（`game_meta.js:321`）而全局容器不会 ⇒ **读档后主池"见过"清零、链式"见过"仍在**。
  3. **同种子复现得了地图，复现不了奇遇。** 装备/法宝、经文、劫印三池都已走 `runRandom/runWeightedPick` 播种流，而事件的 **6 个**随机点仍走裸 `Math.random`：`events_part1.js:140/:143`（rollYuan）、`events_part2.js:1165`（双线加权抽）、`game_core_2.js:818/:823`（双线触发与分池）、`game_event_3.js:239`（`resolveRoll` 判定）。种子分享功能因此只能复盘"走了哪条路"，复盘不了"路上撞见了什么"——**可传播性最强的那一半丢了**。
- **竞品一句话结论**：STS 把事件当**资源池**经营（三层池 × 三种"记忆粒度" × 资格过滤 × 自适应保底），Hades 更进一步把池**交给玩家操纵**（一局 4 神上限、keepsake 扩池即稀释、Vow of Denial 直接删项），ETG 用**跨层钥匙/状态累积**把"事件"变成"挣来的"而非"抽到的"；本作站在光谱最左端——**列表式抽奖 + 命名即链式**。
- **优化优先级**：**P0 = O0 双线奖励通道合一（修断线）**、**O1 稀有度权重化（接上第五池）**、**O2 去重双容器合一并入档**、**O3 事件随机接播种入口**；P1 = O4 风险窗（roll）补量、O5 事件金币抉择通道、O6 叙事门数据化（复用劫难已验证的契约）+ 链语义裁决、O7 坊市价格 act 轴移交 S17；P2 = O8 双线池前期补量与 `neutral` 定性、O9 回血文案与结算一致、O10 双线池与主池的六道口径同构。

### 1.5 边界与死区（A–L，本轮新增/升级）

- **A. `pool` 全链路空转**：166 处写入、0 处读取。god 池实得 18.8-19.7%，纯由条数决定。
- **B. 链式状态机永不启动**：`chainId/chainStep/nextStepId` 数据 **0 条** ⇒ `events_part1.js:61-76`（优先返回链下一步）与 `:112-122`（记录进度）两段代码是**结构性死路**；而 god 池 27 条里有 **11 条以 `chain_` 命名**（40.7%），与单发事件混在一起均匀抽——**名字承诺了机制，机制没有兑现名字**。
- **C. 叙事门契约：劫难已接入、事件零接入**：`_optionGate` 七规则（`ge/geVal`、`requireFlag`、`requireLock`、`requireRel`、`requireNoTreasure`、`requireFlagNot`、`requireHero`）+ 逆道 `canPickDao` 齐备，`trials_ch1~9.js` 已实际写入 **222 处 `setFlag` / 110 处 `require*`**（并由 `_verify_opt_gate_escape.js` 做防死锁回归）；而两池共 819 选项**零使用**（`Q3=Q4={}`）。⇒ 事件层**没有"写入叙事状态"的通道**不是引擎缺位，而是**事件数据从未采用这套已在姊妹系统验证过的契约**——这使 O5 的成本从"造机制"降为"抄格式"。
- **D. 去重双容器 + 存档不对称**（最锋利的一条）：

## 二、本系统的设计目标（先立靶，再打分）

事件系统在肉鸽里的本职不是"讲故事"，而是**在不确定的路线上，稳定供给"有意义的抉择"**。据此立四条目标，每条给可测口径（目标 0 是底线：吹出去的牛必须兑现）：

- **目标 0 · 言出必行（奖励与文案一致）**
  凡选项文案宣称"得经 / 得宝 / 得装备 / 善+10"者，**结算必须当场兑现且可被脚本断言**。
  度量：从 `SUTRA_EVENTS` 逐条构造 pending → 走真实 `applyEventOpt` → 断言 `s.equipments` / `s.sutraFrags` / `s.favors` / `s.good` 增量与声明值一致（当前：**全部不符**，见 §1.5-M）。
  *为什么排在第一*：稀有度、前置链、保底都是"活得更好"；奖励不落袋是"活得不对"。前者可慢办，后者不可拖。

- **目标 A · 稀缺性可感（稀有度契约）**
  凡命名/文案宣称"罕见"者（神佛、英雄、道途），其**实测出现频率必须显著低于凡俗**，且长草局要有 no-fail 保底。
  度量：播种 20 万次抽取 → 各 `pool` 份额与档位声明一致（目标 `god 6-9%`）；`god` 池在单局内 0 命中的概率 ≤ 5%。
  *为什么值得*：黑暗西游的题材势能全在"神佛极少露面"。现在每 5 个奇遇就有 1 个是神佛，**通胀把神话贬成了 NPC**。
- **目标 B · 因果可追（叙事记忆）**
  一次抉择必须能在后续事件里被记住；同一条事件在一局内**不无理由地重复**。
  度量：`setFlag/requireFlag` 使用数 > 0（可直接抄 `trials_ch5.js` 现有格式）；链式记账与抽取去重**同一容器**；读档后去重语义等价（探针 diff=0）；同局事件重复率 ≤ 5%。
- **目标 C · 可复盘、可证（决定可被质疑）**
  同一种子 → 同一事件序列（路线一样时）；每章至少有量化下限的"风险选项"与"非战斗金币选项"。
  度量：`initRunRng(seed)` 双跑逐位相等；每章含 `roll/rollFail` 的事件 ≥ 3 条（折算全池选项占比 ≥8%，见 O4）；`effect.gold` 非零选项 ≥20 条。
  *为什么值得*：本作已有"种子分享"这一传播抓手，而事件是**玩家口述里最戏剧化的部分**（"我那次撞上了……"）。这一半不可复盘，种子就只分享了一半乐趣。

> 四目标与 S18 的"成长可感"是同一件事的两面：S18 证明玩家"数值上越玩越强"这条线被钳制住了；S10 若把言出必行、稀有度与因果做出来，"境遇越玩越不一般"就能补上那半边体验。

## 三、竞品机制深挖（机制对机制，带真实来源）

> 本轮真查（非凭记忆）。凡社区/第三方来源一律标 **L2**，本仓库自有实读实跑标 **L1**。

### 3.1 杀戮尖塔 STS —— 把事件当"资源池"经营（主竞品）

STS 的事件只在 Unknown（`?`）地板出现，且**第 4 章没有 Unknown 地板 ⇒ 整章无事件**（wiki.gg，L2）。其内部结构有三层，**不同层用不同的"记忆粒度"**：

| 内部类型 | 出现频率 | 限章？ | 可否重复 | 社区合称 |
|---|---|---|---|---|
| **Act Event** | Common | 是（绑死某一章） | **不可**（本局该章见过即永别；没遇到就是错过了） | — |
| **Shrine** | **Rare** | 否（任意章可出） | **每章一次**（进下一章全部重置、可再遇） | Shrine Event |
| **One-Time Event** | **Rare** | 视条目（多数不限章） | **一局一次**（跨章也不重置） | Shrine Event |

（表源：`slaythespire.wiki.gg/wiki/Events`，本会话抓取全文，L2）

五条最值得学的机制设计：

1. **稀有度不是标签，是抽样路径。** 当局判定"该出稀有事件"时，游戏**把 Shrine 池与 One-Time 池合并成一个池再随机取一**（原文："the game will combine the eligible Shrine and One-Time Event pools and then pick a random event from that combined pool"，L2）。也就是说：**"罕见"由抽取流程保证，而不是靠文案自称**。⇒ 对照本作 §1.5-A：`pool:'god'` 全仓零读取，god 份额 18.8% 恰好等于条数占比。
2. **先过滤资格，再抽样。** 每个事件带一组 `criteria`，**全部满足才进池**，wiki 举的实例（L2）：`Golden Idol` 限 Act 1；`Mushrooms` 需 Act 1 且 **floor ≥ 7**；**`The Cleric` 需持有 ≥ 35 金币**（本会话二次检索三源同口径复核，含 namu wiki 原文 "It only appears when you have 35 or more gold"）；`Knowing Skull` 需 HP ≥ 13、`The Moai Head` 需 HP ≤ 50%；`N'loth` 需 ≥ 2 件遗物；`The Divine Fountain` 需卡组里有一张诅咒。⇒ **门槛本身就是抉择的一部分**："这一枚 `?` 会不会给我一部《心经》"取决于我此刻的血、钱、牌——事件的戏剧性来自"我配不配"。本作四道过滤（`region/hero/dao/needPet`）里**没有任何一条读玩家当局的资源状态**。
3. **自适应保底与逐章清零（no-fail）。** 进 `?` 时按类型各掷一次：Monster 基础 **10%**（每未命中一次 +10%）、Shop **3%**（+3%）、Treasure **2%**（+2%），**Event = 余量**；且 `UnknownMapPointOdds.ResetToBase()` **在每章边界把计数全部归零**；首局的前两个 `?` 强制为事件（spire-codex 源码整理，L2）。⇒ **没有任何一局会"整章碰不到事件"**，同时"连续撞商店"这种路线也不会发生。
   - **本作已同构**：`rollYuan` 的 `p = min(1, 0.10 + 0.10×s.eventPity)`（`events_part1.js:139`）+ `s.eventPity` 每章归零（`game_region.js:177`），20 万次实跑事件份额 **72.74%**、最长连 9（L1）。**这一格不必补课。**
4. **难度轴直接改写事件表。** **Ascension 15 起，部分事件"好结果变少、坏结果变重"**（掉更多血、给更少金、涨价更高、更容易被塞诅咒）（wiki.gg 原文首屏即述，L2）。⇒ 难度不只作用于战斗数值，也作用于**境遇的恶意**。这正是 [S18](S18_数值曲线与难度_深度分析与优化设计.md) §④ 想要的"难度可感"的第二根柱子，本作完全没有。
5. **反面教材（与本文 §1.5-D 惊人同构）**：wiki 明记一个 **Bug** —— Shrine 本该每章一次，但**"Shrine 池不入存档"**，中途存退即视为"一个都没见过"，于是**同一章可反复刷 Shrine**（原文："unlike the Act Events and One-Time Events, the Shrine pool is not saved"，L2）。⇒ 我们 `NDX._usedEventIds`（不入档）与 `s._usedEventIds`（入档）的双容器错位，在 STS 里是以 bug 形态被社区记录下来的；**它是同一条坑，只是被写成了意外而非结构**。这个对照的价值是：修它不需要发明什么，照 STS 的意图做即可。

### 3.2 Enter the Gungeon —— 前置链是"挣来的"，不是"抽到的"

ETG 的 Chamber 结构本身是**层级 + 秘密分支**的组合（wiki.gg《The Gungeon》，本会话抓取，L2）：常规层之外存在**只有在当局满足特定条件才会出现**的隐藏区，最典型的是 **Abbey of the True Gun**（社区口径：把 `Old Crest` 放到某处祭坛才开启入口）、以及需专门钥匙方能进入的隐藏层（如 3.5 层的 Jugal 相关通路）。这些条目的**精确解锁条件多为社区整理，标 L2**，但其机制骨架清楚：

- 事件的"前置"不写在事件表里，而写成**一个可携带、可展示、可查验的当局状态**（钥匙 / 徽记 / 物品）；
- 玩家**看得见自己在推进链**（拿着 Old Crest 就知道还差一座祭坛）；
- 跨层不重置：链的记忆粒度天然是"一局"。

⇒ 对照本作：`chain_*` 13 条只是命名，`chainId/nextStepId` 状态机 0 数据，`thenEvent` 一条 4 步链还记错了容器（§1.5-D）。**ETG 证明"前置链"最好的载体是"一件物品 / 一个旗标"，而不是"一个计数器"** —— 本作 `s.flags` 已经在劫难侧被验证（222 处 `setFlag`，L1），复用即可。

### 3.3 Hades —— 把池子交给玩家操纵

Hades 以"恩赐（Boon）"为单位组织遭遇，其**池管理**是三者最激进的（leereamsnyder 的 Hades 指南，本会话抓取全文；条目细节属社区整理，L2）：

- **每局可请的神是有限随机子集**（社区常记为"一局 4 神"），玩家**先手看见是谁**再决定要不要进这扇门；
- **Keepsake 等道具的作用是"扩容 / 稀释"** —— 它不提升品质，而是**改变池的组成**，让玩家能把想要的东西"洗"进候选；
- **誓约 / 惩罚类模式直接从池里删项**（用难度换掉某类可能）；
- **提供"重掷当夜 / 改种子"性质的机制**，让"这次没出好货"可以有限度地重来。

⇒ 光谱上 Hades 在最右：**玩家参与定义池本身**。本作连池的组成都不暴露给玩家（`?` 内容在踏入前完全不可知，除 `DAO_NODE_BIAS` 悄悄改了节点类型投放，`data_map.js:60-67`）。这对西游题材未必是坏事（天机不可泄露），但**至少可以学到"让玩家看得见池"**：图鉴里"本局已见过的奇遇 / 未见的奇遇"是可做的、零随机改动的一步。

### 3.4 稀有度经营光谱（本作定位）

```
  ← 列表式均匀抽奖                    分层 + 过滤 + 保底             玩家可操纵池 →
  ─────────┬──────────────────┬──────────────────┬───────────────────┬─────────────
       【本作 S10】        ETG（钥匙前置）      STS（三层池+A15）       Hades（选神/稀释/删池）
      pool 零读取·均匀抽       链 = 当局物品       rare = 合并池+资格过滤    池 = 玩家构筑的一部分
```

**本作独占的位置**：连"稀有度"这个字段都不参与抽取。STS 至少把"罕见"实现成了**路径**；ETG 把"罕见"实现成了**门槛**；本作把"罕见"实现成了**注释**。

## 五、可实施优化设计（只设计，不改码）
