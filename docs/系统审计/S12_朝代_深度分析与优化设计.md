## 〇、执行摘要（TL;DR）

- **系统现状**：朝代是"**死亡递进（`bumpDynasty`）+ 通关归夏（`resetDynasty`）**"的 **10 朝线性元进度时钟**，对外只持久化**一个 number**（localStorage `ndx_dynasty_idx`）。每朝挂一组 `feature`（共 **23 个 feature 键**），经三入口 `dynastyHas/dynastyValue/dynastyAdjust` 消费，**首行都过 `hasClearedAny()` 门禁 ⇒ 首周目全部 feature 不生效**。feature 点火**成熟**（除 owner 外约 22 处 distinct 消费点），不是空壳。
- **三大真问题（本轮实测，非旧文档）**：
  1. **跨系统时序死锁（P0）**：唐朝"完美结局 / 千秋万代 / 结局动画"三条承诺，全部被 `settleReturn` 内"`resetDynasty` 早于判定"抹平 → 通关瞬间已回到夏，唐专属判定永不成立。这是**最典型的"看起来接了、运行期永远为假"的静默缺陷**。
  2. **悬空/死码字段成群**：`eliteBonus`（三国"精英怪+1"）**全仓零消费**；`dynastyInterp` + `{{MONARCH}}` 占位符插值链整体零调用；`featureDesc`（注释自称"UI展示用"）**从不上屏** → 玩家能看到朝代名/天子/一句 `desc`，却**永远看不到这一朝到底改了哪条数值**。
  3. **"乘子当概率"与 rng 口径不统一**：`drop/sutra/sutraShard/eliteDrop` 等"百分比"feature 在消费点被写成 `Math.random() < (mul-1)` 的**概率追加**（`game_combat_2.js:214`），语义与"×1.15 掉落乘区"名实不符，且用**裸 `Math.random`**、不吃 seed，破坏复现。
- **竞品一句话结论**：Hades 的"循环/纪元"= **死亡即叙事增量 + 永久进展**（Mirror of Night 用黑暗果实离散解锁、God Mode 随死亡 20%→+2%→cap 80%）；Rogue Legacy 世代制 = **死亡换人 + 庄园升级树（每买一项其余 +10 金、世代不清档）**。本作朝代**同属"死亡推进 meta 时钟"这一族**，且已把"递进"接进了战斗死亡/寿尽，**结构骨架对**；但它把"变强的钱"和"讲故事的壳"**焊反了**——Hades/RL 用死亡**累积**永久资源，本作却在通关时**归零**（resetDynasty 写 0），且 10 朝 feature 多为"通关后才生效的数值微调"，**既没兑现成叙事，也没兑现成可感知的构筑差异**。
- **优化优先级**：**P0 = 修时序死锁（O1）+ 接线或删除 `eliteBonus`（O2）**（两者都是"承诺存在、代码为空/永假"）；P1 = `featureDesc` 上屏（O3）+ 朝代进 BalanceDB 并补 `_verify_dynasty_gate`（O4）+ 概率/乘子语义与 rng 统一（O5）；P2 = 复活 `dynastyInterp` 送行代入（O6）+ 删重复块/收编 `DYNASTY_IDX` 键漂移（O7）。

## 一、当前系统解剖（代码实况）

> 结构细节链接 [S12 审计 §1.1–1.7](S12_朝代_审计.md)，此处只给"设计视角"关键链路 + 本轮实测。

### 1.1 朝代时钟的五步循环（+ 单一 number 持久化）

1. **入口·读朝**：`getDynastyIdx()`（`data_dynasty.js:55`）经 `SaveSystem.loadNumber(DYNASTY_KEY,0)`（`:58`）读 `ndx_dynasty_idx`，clamp 到 `[0,LAST_IDX=9]`（`:59`）；`:60-67` 一次性校准（从未通关且 `cycle>1` 且朝代落后周目 → 追平回写）。
2. **局内·吃 feature**：三入口 `dynastyHas:132` / `dynastyValue:141` / `dynastyAdjust:158`，**首行各判一次 `hasClearedAny()`**（`:134/:143/:160`）⇒ 首周目（任何英雄都未通关前）全部 feature 不生效。
3. **死亡·递进**：`bumpDynasty:78` — 非唐朝 `idx+1`（`:86-88`）；已是唐朝**原地复位唐**（`:81-84`，十世为终点）。调用点：战斗死亡 `game_combat_2.js:117`、寿尽坐化 `game_meta.js:185`。
4. **通关·归夏**：`resetDynasty:92` 写 0；调用点 `game_meta.js:269-270`（`settleReturn` 内，**⚠ 早于同函数下游判定，见 §1.6-①**）。
5. **轮回重开**：`reincarnateReset:113` = 归夏 + `resetCycle()` + 清 `INHERIT/MONUMENT_GEAR/MONUMENT`（`:118-120`），保留成就/藏品/图鉴/赐福。

**载体本质**：整个系统的"世界状态"就是**一个 0–9 的整数**；feature 表是它对外的**唯一变量集**。持久化面极小 ⇒ 好处是简单，坏处是"朝代差异"必须靠下游各系统主动 `dynastyAdjust` 才能被感知，而下游一旦漏接/时序错位，玩家完全无从察觉。

### 1.5 边界与异常

- **门禁一刀切**：`hasClearedAny()` 未通关 = 全 feature 失效 ⇒ **玩家首周目完全玩不到任何朝代特色**，而"递进"却在首周目死亡时照常发生 → 前 10 世是"**换了个名字、数值纹丝不动**"的空转。
- **唐朝复位语义**：`bumpDynasty` 到唐原地复位（`:81-84`），配合通关 `resetDynasty` 归夏 ⇒ "通关"与"唐朝继续死"是两条不同出口，正是 §1.6-① 死锁的成因。
- **键名三处漂移**：`DYNASTY_KEY` 取 `storage.KEYS.DYNASTY_IDX || 'ndx_dynasty_idx'`（`:53`），但 `storage.js:59-92` 的 `STORE` **未注册 `DYNASTY_IDX`**（探针 `KEYS.DYNASTY_IDX===undefined`），全靠回退值；而 `save_system.js:66` 另立 `DYNASTY:'xynj_dynasty'` **从未被引用** → 三套命名，实跑只认 `ndx_dynasty_idx`。
- **零门禁 / 零快照**：`data/balance_db.json` 的 `meta.counts` **无 `dynasty` 键**，朝代 feature 全手工取证；`scripts/` 下**无任何 `_verify_dynasty*` 门禁**。

### 1.6 未接入项与死区（本文核心新增，均 L1）

1. **①（P0）通关时序死锁**：`game_meta.js` 的 `settleReturn` 内 `:270 resetDynasty()`（idx→0）**早于** `:305 _syncAch()` 与 `:307 dynastyHas('perfectEnding')`。唐朝通关瞬间判定读到的已是夏 ⇒ **`perfectEnding` 结局动画、卷九 `all_dynasty/shang_seng` 经"通关"路径全部不可达**（探针 `checkAch` 模拟 idx=0，只落 `xia_seng`）。
2. **②`eliteBonus` 零消费 + `qing_seng` 死成就**：`eliteBonus:1`（`data_dynasty.js:37`）全仓仅此一处定义、无消费点（Grep 单命中）；`achievements.js:251` 判 `_dId==='qing'` 而 LIST 无"清" → `qing_seng` 永不可解锁；`all_dynasty` 文案（`:112`）罗列 17 朝也远超实装 10 朝。
3. **③`dynastyInterp` 整体死码**：`data_dynasty.js:100` 的 `{{MONARCH_TITLE}}/{{MONARCH}}/{{KING}}/{{DYNASTY}}` 占位符插值链**无任何调用方**，连带 `monarchKing` 字段失去唯一读者 → "转世到他朝、送行天子更替"的**代入设计从未落地**。
4. **④`equipment_part3.js:247-257` 与 `:351-361` 重复块**：`dynastySealSlot`+`sealSlotCap` 逐字节两份（探针 `dupBlock=true`），后者覆盖前者，坏合并残留；同时虚增了审计"消费点数"。
5. **⑤`featureDesc` 从不上屏**：年表 `ui_changan.js:171-197` 只渲染 `full/name/monarchTitle/desc`，**不含 `featureDesc`** ⇒ 玩家知道"今值唐朝、唐太宗在位"，却**不知道"这一朝到底给了我什么"**，meta 层的"选择意义"被抽空。
6. **⑥"乘子当概率"**：`game_combat_2.js:214` 取 `_dropMul=dynastyAdjust(1,'drop')` 后写 `Math.random() < (_dropMul-1)`（秦 15%/唐 10% 概率**追加一次**掉落），`sutraShard/eliteDrop/craft` 同类 —— 名为"+15%"实为"15% 触发"，语义漂移，且**裸 `Math.random`** 不吃 seed，与 `rollEquips` 走 `runRandom()` 的复现口径相悖。

## 二、设计目标：朝代 meta 层"应然"的三条判据

朝代既不是战斗系统也不是数值系统，它是**"把重复游玩转成长线意义"的元层**。以竞品的 meta 层为尺，本系统"应然"须同时满足：

- **判据 A｜可感知增量**：每一次"换代"都必须带来玩家**能看见、能说出**的差异（新机制/新叙事/新构筑口子），而非只换个国号。→ 现由 `feature` 承载，但 `featureDesc` 不上屏（§1.6-⑤）+ 首周目全失效（§1.5）→ **A 严重不达标**。
- **判据 B｜永久累积而非归零**：meta 时钟应让"玩得越久、留下的越多"（Hades 黑暗果实、RL 庄园升级）。本作却在**通关即 `resetDynasty` 写 0**，把唯一的进展载体清空 → **B 方向相反**。
- **判据 C｜承诺必兑现（无静默死链）**：写进 `feature` 的每条都必须在运行期真生效。`eliteBonus`/`perfectEnding`/`qing_seng`/`dynastyInterp` 四条"写了没接"→ **C 破口最多**。

## 三、竞品机制深挖（机制对机制，带真实来源）

### 3.1 Hades · "死亡即推进 + 叙事增量"（主竞品）

- **循环壳**：每次死亡回到冥殿，**剧情/对白按死亡次数与阶段推进**（Nyxi/Chaos 支线、家猫、冥殿 NPC 对话轮换）——重复游玩被**转成叙事进度**，而非重置。
- **永久进展 Mirror of Night（镜夜）**：用**黑暗（Darkness，随游玩累积的永久货币）**离散解锁天赋（如 `Rare Pet`、`Max Health+`），**死亡不清档、跨局保留**。
- **God Mode（可及性斜坡）**：开启后**受伤 -20% 起、每死一次 +2%、封顶 -80%**（来源：Hades Fandom Wiki / TheGamer）——**用死亡次数把难度单调拉低**，正对应"死得多=变强"。
- **Pact of Punishment（热度 Heat）**：通关后解锁"自选难度↔自选回报"契约，把"再来一世"变成**玩家驱动的加码**，而非系统强制归零。
- **对本作的镜鉴**：Hades 把"循环"同时喂给**叙事(A)+永久资源(B)+难度斜坡(可及性)** 三条管道；本作朝代**只接了"数值微调"这一条最弱的管道，且默认首周目还不开**。

### 3.2 Rogue Legacy · 世代制（死亡换人 + 庄园升级树）

- **死亡换继承人**：死亡后选**下一位后代**（随机天赋/职业），金币（永久货币）**不清零**带入。
- **庄园升级树**：以金币买 HP/魔抗/属性等永久升级；**每购买/升一级，其余所有升级价格 +10 金**（来源：Rogue Legacy Wiki / Steam 讨论）——一条内置的**通胀斜坡**，让"世代数"与"能买到的强度"挂钩。
- **对本作的镜鉴**：RL 的"世代"= `resetDynasty` 的理想反面——它**累积、不抹平**。本作的"十世金蝉子"叙事其实是天然的世代壳，却被 `resetDynasty(0)` 自废。

### 3.3 结构光谱定位（本作"朝代"站哪）

```
纯数值时钟(死亡+1)         叙事+永久资源+难度斜坡          世代累积升级树
  【逆道西行·朝代】     ←   Hades 循环 / RL 庄园   →   （更重的养成）
 (只换国号，多数feature
  首周目还不开、通关还归零)      (死亡即喂三条管道)
```
**核心分歧**：本作**独占**了"金蝉子十世 + 每朝专属国运 feature"这一**极具西游味的叙事壳**（竞品没有的文化资产），却只把它实现成了**一个会被通关归零的 number + 一堆首周目不生效的数值微调**——**壳是顶级的，管道是堵塞的**。

## 四、差距量化 + "适合/不适合 + 为什么"裁决

> 左=竞品真实机制，中=本作实况，右=是否采纳 + 理由。

| # | 机制 | 竞品做法 | 本作现状 | 裁决 | 理由 |
|---|---|---|---|---|---|
| G1 | 无静默死链 | Hades/RL：承诺必结算 | `eliteBonus`/`perfectEnding`/`qing_seng`/`dynastyInterp` 写了没接 | **适合·P0** | 零设计成本兑现既有文案；不修则"朝代有四条假承诺" |
| G2 | 死亡累积永久资源 | RL 庄园/Hades 黑暗 | ⚠ 反向：通关 `resetDynasty` 归 0 | **部分适合·P1** | 可加"历世纪念物/国运点"累积轴；但**不能删归夏**（金蝉子转世是核心叙事），要"归零 + 旁路累积"并存 |
| G3 | 难度随死亡单调调节 | Hades God Mode 20%→+2%→cap80% | 朝代 `diffBonus` 仅秦 +10% 且通关才生效 | **适合·P2** | 可把"第 N 世"做成温和斜坡；但不照抄 -80% 上限（本作 Roguelike 硬核定位不同） |
| G4 | 换代=可见的机制差异 | RL 每代新职业/天赋 | feature 多样但 `featureDesc` 不上屏、首周目不生效 | **适合·P1** | 低成本高感知：把 `featureDesc` 渲染出来（§1.6-⑤）即可兑现"可感知增量" |
| G5 | 死亡推进叙事 | Hades 对白轮换/剧情门控 | `dynastyInterp` 占位符链整体死码 | **适合·P2** | 复活送行插值即可把"换了天子"演出感拉起来（§1.6-③），是最贴西游味的差异化 |
| G6 | 数值可举证 | 竞品数值公开可查 | 无 BalanceDB 覆盖、无 `_verify_dynasty` | **适合·P1** | 23 feature 键全裸奔，正是"代码即真源"最该被自动化守住处 |
| G7 | rng 可复现 | —（单机弱需求） | `drop/sutraShard` 裸 `Math.random`、概率当乘子 | **适合·P2** | 与 `rollEquips` 走 `runRandom()` 相悖，须播种 + 语义归一 |

**五列差距（据实测重判）**：
- **广度**：中偏大（10 朝 × 23 feature，覆盖面广，但 eliteBonus 等虚位）。
- **深度**：中（多数 feature 是"单系统 ×1.x"的浅修正，少有几个改变打法；`allBonus` 全局乘区偏数值不偏机制）。
- **可达性**：**小**（首周目全锁 + 通关时序死锁把最强唐承诺抹掉 → 兑现通道断）。
- **决策密度**：小（玩家不能选朝代、不能为朝代做取舍；递进纯被动 → 无构筑决策，正是与 RL"买哪棵升级树"决策的最大落差）。
- **可验证性**：**大**（无门禁、无快照、4 条死链零拦截 → 全程裸奔）。

### O1 ·（P0）修通"唐朝通关"时序死锁：让 `perfectEnding`/`all_dynasty`/结局动画真可达

- **最大回归风险**：判定顺序改动会影响"归夏 vs 结算"既有日志/存档时序；须回归 [S14 结局] 与成就落簿，勿把 `resetDynasty` 挪到函数最尾而遗漏 `runRec/echo` 对 idx 的读取。链回 [S18 §六](S18_数值曲线与难度_深度分析与优化设计.md) 一把尺。
