## 〇、执行摘要（TL;DR）

- **系统现状**：宠物已完成 v1.4「兽印化」收口——从"独立子系统"降格为"装备（兽印）的一种分支"，**8 机制轴 × 3 阶（本相/显形/证道）= 24 活跃宠**（探针实测 `counts.pet=24`、`reserve=91`），星阶数值轴主动撤销（`PET_STAR_MUL` 全 1、`PET_STAR_SCALE_FIELDS=[]`），三重叠乘爆炸被"阶不引乘子、档数加性"两条铁律钳住。数据轴设计成熟，护栏注释自证（`data_pet.js:571`）。
- **头号真问题（本轮实跑，非旧文档）**：**宠物机制被动"配了却不生效"**。8 轴里 **6 轴的机制身份**（连击/免控/裂伤/回春/血噬/狂战）因 `_playerObj` 白名单断链，在真实战斗流程中**从未触发**；玩家戴一只「小石猴(comboUp)」期望的"加连击率"，实机拿不到——`petCombo` 死在中转层。唯 crit/ward 两轴因把收益**静态折进 `ti.cri`/`ti.dr`** 而蒙混过关。这与"收集灵兽→变强"的设计承诺正面冲突。
- **可达性真相**：本相 8/8（`rollEquips` 只掉 `setTier<2`）、显形 8/8（**走 `PET_EVOLUTIONS` 章节点化事件**，非旧审计所说的合成配方）、证道 **仅 1/8**（`ni_huxianfeng`）。`petEvolve` 19 条配方里 **16 条 `out` 已归档**，是 UI"显示可合成、点击静默失败"的坑（旧 §1.7-C 仍成立）。
- **竞品一句话结论**：冒险日记把复杂度压在**单一成长轴的雪球时机**（击杀/每层成长 × % 道具时机），Hades 神犬 Cerberus 把伙伴做成**短路径必达的亲密轴**，Pokémon 把进化做成**核心收集循环**。本作反其道——**多轴叠乘但轴未真正通电**，等于"广度没换来深度、深度又断在最后一步接线"。
- **优化优先级**：**P0 = 修 `_playerObj` 白名单断链（让宠物被动真生效）+ 证道接可达通道 + 摘死配方**；P1 = 复活跨轴协同（补组合广度）+ 等级轴接游戏内入口 + 摘除恒等空转段；P2 = 亲密/情感轴（对标 Cerberus）、局外雪球（借鉴冒险日记，只作用局外）。

### 1.5 边界与死区

- **加法式聚合**：档数 `tierW+starExtra` 加性、各机制按 count 线性累加再套 cap（`combat_part1.js:285-296` comboUp cap0.30/critHit cap0.25/magicUp cap0.25）——防叠乘爆炸。
- **无裸随机**：宠物侧 rng 走 `data_equip_core.js:503-560`（`NDX._rand` 播种）；探针为消噪临时改 `Math.random` 属取证手段，非产品码。
- **归档不删数据**：`equipment_part1.js:905` 仅 `delete evolveTo/From`，条目留 `PET_RESERVE`；但 `craftById` 只查 `CRAFT_POOL`（L948 已 filter）⇒ 归档宠配方返 `undefined`。
- **两套 summon 扩容实现**：`petSlotCapOf`（`data_pet.js:44-46` 直给 6，**绕过**封顶逻辑）与 `petSlotCapFor`（`equipment_part3.js:526-529` `min(6)`）值同径异。

### 1.7 ★未接入项 / 头号真问题：机制型宠物被动实机不生效（L1）

**断链定位**（三向闭合，探针消噪实测复证）：

1. **产出**：`computeStats` 把机制聚合与连击率放在返回对象**顶层**——`combat_part1.js:379 petPassive:m8pp`、`:383 petCombo`、`:424 petGold`（与 `ti`/`yuan` **平级**，**不在** `ti` 内）。
2. **中转丢失**：`game_combat_1.js:14 const st=this.stats()` 拿到含上述三字段的 `st`，但 `:353-394` 逐字段手工组装 `_playerObj` 时**只拷 `ti/yuan/reflect/...`，唯独漏 `petPassive/petCombo/petGold`**（grep `js/game/` 全目录：无这三字段的赋值/透传）。`_playerObj` 随即喂给 `calcCombat`/`calcCombatSquad`（`:401-403`）。
3. **消费端等死**：`simulateSingle` 回合内核 `combat_part1.js:461 const _m8=player.petPassive||{}`、`:462-463 _pp/_ppN`、`:916 _comboRate=...+player.petCombo`——因 `player` 即白名单 `_playerObj`，`_pp('regen'/'whisk'/'rend'/'berserk'/'bloodLoss'/...)` **恒 false**、`_comboRate` 的宠物项 **恒 0**。

|---|---|---|---|---|---|
| xiaoshihou(combo→petCombo) | petCombo=0.06 | 2037 | 3196 | **5/5** | 透传才生效 ⇒ 白名单下连击死 |
| renshanguozi(purify→regen) | {regen:1} | 2790 | 3163 | **3/5** | 回春机制透传才咬合 |
| xiaoheilong(reverse→berserk) | {berserk:1} | 2681 | 3090 | **5/5** | 残血狂暴透传才生效 |
| qingyuehu(evade→whisk) | {whisk:1} | 2698 | 2698 | 0/5 | 该场无 Boss debuff，whisk 无从体现 |

## 二、设计目标：宠物系统"应然"的四条承诺

> 先立靶子，§④ 差距与 §⑤ 优化都对着这四条打。

1. **接线承诺（最底线）**："戴某宠 ⇒ 该宠机制在战斗里真兑现"。comboUp 该加连击、regen 该回血、berserk 该残血增伤——当前 6/8 轴违背此承诺（§1.7）。**目标**：被动经中转层不丢失，`player.petPassive/petCombo` 在实机有值且被消费。
2. **可达承诺**："图鉴画了三阶，玩家三阶都追得到"。本相/显形已 8/8，证道仅 1/8。**目标**：证道 8/8 至少 1 条实测走通的发放口。
3. **辅助供给锚点**：宠物是"辅助供给，不与装备等量"（`scripts/_tmp_pet_anchor.js:2` 自述口径：双宠主攻 ≥ 裸号 10%、血 ≥ 裸号 18%）。**目标**：接线后重跑锚点，量级不破 S18 难度定标（防"宠物被动一活→平衡矩阵崩"）。
4. **组合广度**：既然选了"多轴"而非"单轴雪球"，就该让**轴与轴的配对**产生决策（共鸣/羁绊/跨轴协同）。当前 `petEchoEffects` 两格恒命中 1 条（弱广度），`CROSS_SYNERGY` 整簇死（强广度缺位）。**目标**：把"同队选哪两只不同轴"变成有意义决策。

## 三、竞品机制深挖（机制对机制，带真实来源）

### 3.1 冒险日记（Day R / Road to Vostok 类）· 单成长轴 + 雪球时机
- **机制**（TapTap 攻略实测口径，L2）：装备/随从有**"击杀成长"与"每层成长"**两条乘数线；**"百分比道具越晚使用收益最高，因为基数（击杀/每层成长）越高"** ⇒ 核心决策是**雪球时机**（何时把 % 乘数拍下去）。成长轴**少而深**，机制表达靠技能/装备外挂。
- **哲学**：**拥抱膨胀**，把"膨胀节奏 + 时机抉择"做成玩法；难度用层级表达、成长用乘数表达，玩家主动经营。
- **对 S06 启示**：本作走的是它的**反面**——多轴但轴间不叠乘、且多数轴机制不通电。可借鉴的不是"照抄雪球"，而是**让每条轴"配了就有可感反馈"**（先解决 §1.7，再谈轴数），以及**把"何时兑现成长"做成抉择**（局内滚雪球 vs 局外分层）。

### 3.2 Pokémon · 进化链 = 核心收集循环
- **机制**（Bulbapedia/pokemondb，L2）：种族值 + 个体值(IV) + 努力值(EV) + 性格，**四轴在局外**；**亲密度进化**（Gen II 起，happiness 随同行/战斗/升级累积，特定精灵亲密度达标进化）。进化是**确定、可达、情感驱动**的收集主线。
- **对 S06 启示**：本作**显形进化事件**（`PET_EVOLUTIONS` 35% + 保底，`equipment_part3.js:1132-1148`）与 Pokémon"陪伴→进化"同构，方向正确；但**证道 7/8 无进化出口**（只到阶2），把"进化链"截断在三分之二处，削弱收集闭环的终局追求。

### 3.3 Hades · 神犬 Cerberus · 短路径必达的亲密轴
- **机制**（Fandom/Polygon/Kotaku，L2）：Cerberus 无等级轴，靠**送礼/抚摸累积亲密**（7 格），亲密达标即给**确定 keepake 奖励**（如 `+25~50 最大生命`）；路径**短、必达、透明**。
- **对 S06 启示**：本作**等级轴**（`petRaiseLevel` × 2.30 真伤成长，探针实测）本该提供同款"养了就确定变强"的正反馈，却因**游戏内零入口**而形同虚设（§1.7）。Cerberus 证明：伙伴系统"简单但必达"胜"复杂但断裂"。

### 3.4 宠物/伙伴设计光谱定位（本作站哪）

```
单轴雪球(拥抱成长)         短路径必达(确定反馈)        多轴叠乘(组合广度)      进化收集(情感主线)
 冒险日记            ←        Hades Cerberus     →    【逆道西行·当前】  ↔   Pokémon
 (%道具时机, 轴少而深)     (亲密→keepake, 无等级轴)    (轴多但6/8机制不通电)   (亲密度进化, 三阶应全可达)
```
**核心分歧**：本作**占尽了光谱右端的"设计野心"**（多轴 + 进化 + 星阶 + 共鸣 + 羁绊），却**没兑现左端竞品共同的底线**——"配了即生效、追了即可达、养了即变强"。这是一台**功能齐全但多数线路没通电**的机器。

**五列差距（据探针重判）**：
- **广度**：**小**（24 宠/8 轴，条目量不缺）。
- **深度**：**中偏大**（名义 4 轴，实生效**不足 1 轴半**：仅 crit/ward 静态折属性 + 羁绊真伤活；6 轴机制死、星阶数值死、契轴死）。

- **决策密度**：**中偏大**（选轴 + 选配对 + 培养本应强决策，但被动不通电把决策价值清零）。
- **可验证性**：**大**（`_verify_pet.js` 134/0 全绿却**没验到 `_playerObj` 是否透传 petPassive** ⇒ 典型"验形没验用"，`combat_part1.js:908-913` 注释自承踩过同坑）。

### O1 ·（P0）修 `_playerObj` 白名单断链——让宠物机制被动真生效 ★最高优先级
- **问题**：`computeStats` 产出的 `petPassive/petCombo`（顶层）在 `game_combat_1.js:353-394` 组装 `_playerObj` 时被漏拷 ⇒ 6/8 轴机制实机恒不触发（§1.7）。
