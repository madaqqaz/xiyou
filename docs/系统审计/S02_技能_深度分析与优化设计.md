## 〇、执行摘要（TL;DR）

- **系统现状**：三键（攻 / 诵经 / 大招）的变体层已在 **V9.55 三层收口**——数据全归 `data_skill_index.js`（层二数值真源）、`resolveSkillAct` 按 `SKILL_ORDER` 8 层顺序**幂等**落地（层三顺序真源）、`combat_active.js` 三处唯一接线；执行器 `data_skill_variant.js` 降级为纯解释器。**工程成熟度高**：单源、顺序显式、单层异常隔离、rng 可注入、回归门禁 `_verify_skill_variant.js`（实跑通过，exit 0）。
- **三大真问题（本轮实测/实跑）**：
  1. **缺"单技能纵向成长轴"**：每个技能（变种）只有"形态"没有"等级"。变种 = 流派表现层（`JOB_STYLE_VARIANT`，随 `currentStyle` 权重向量定），一旦流派确定该键形态即锁死；**没有一条让"你最顺手的招随使用/投入变强"的纵向轴**。第 5 成长轴"技能精研"是全仓零实现（探针 `grep 精研/PRECIS/Mastery` 命中 = 0）。
  2. **获取通道纯被动、构筑主动性弱**：玩家不逐招挑选。攻/诵两键的变种由流派自动映射，10 流派塌缩到**仅 7 种不同攻键变种、8 种不同诵经变种**（探针 `atk_variant_distinct_used=7 / chant=8`）—— ward/burn 同为 `sunder`、crit/reverse 同为 `crit`、summon/evade 同为 `multi`，**存在形态撞车**。竞品（STS 每战选升级、ETG 选/合成主动道具）把"构筑选择"做成核心决策回路，本作这里近乎空白。
  3. **执行器有死分支、D 类半外置**：`dmgPct` case 无人引用（净冗余）；`SKILL_CLASSES.D`（识破/气势爆发）源在 `combat_skills.js`，**不进 `SKILL_LAYERS`**、不参与三键收口，`skillIndex()` 对其仅固定 push 两项（非动态采集）——"顺序真源"对战斗干预这一族名存实亡。
- **竞品一句话结论**：三大竞品分别占据"技能成长"的三条正交轴——STS = **单卡纵向升级 + 移除（构筑提纯）**、ETG = **主动道具配额槽（1 格）+ 合成（2→1 生成新行为）**、万世剑冢 = **招式获取（轮回借取）+ 流派特质合成解锁终极神通**；本作的技能"广度"（形态/原语/联动）已达竞品量级，独缺**"获取抉择 + 纵向升级"这条玩家主动经营的轴**。
- **优化优先级**：P0 = 打通"精研"纵向轴（接草案，构造性零回归）；P1 = 消解变种撞车 + 开放"每战三选一"轻量获取；P2 = 死分支清理 + D 类纳入顺序真源。

## 一、当前系统解剖（代码实况）

> 结构细节链接 [S02 审计 §1.1–1.7](S02_技能_审计.md)，此处只给"设计视角"的关键链路 + 本轮实跑。

### 1.1 一次三键出手是如何被"加工"出来的（收口全链路）

```
玩家在 combat_active.js 触发 atk / chant / ult 任一键
   → activeSkill() 先算「伤害基值」dblBase/magicBase（物理/法术双轨）
   → NDX.resolveSkillAct(act, kind, ctx)  按 SKILL_ORDER 逐层幂等加工
   → game_core_3.js:resolveManualActive 再叠「套路层」（连击/奥义/连招/cfx 协同）
   → NDX.applyActiveIntervention(res, atRound, act) 就地改写 roundsDetail 落地回合结算
```

- **顺序真源（8 层）** `SKILL_ORDER = [hero, dao, job, ult, sutra, variant, jing, treasure]`（`data_skill_index.js:302`）。每层 `kinds` 限定作用于哪些键（`data_skill_index.js:304-381`）：
  - `hero`/`dao`/`job` 仅 `atk`（本命攻式 / 六道攻式 / 隐藏职流派）；
  - `ult` 仅 `ult`（大招变体 + 经文绝招包 + summon 协同预算）；
  - `sutra`/`variant`/`jing` 仅 `atk,chant`（经文变体 / 流派变种 / 经位修饰）；
  - `treasure` 覆盖 `atk,chant,ult`（法宝状态）。
- **顺序即数值正确性**：`variant` 必须排在 `sutra` **之后**——"舍攻为盾"抹 `dmg`，若经文 `dmgMul` 先加再归零会白吞整层收益（`data_skill_index.js:298-300`）。
- **幂等回归防线**：`resolveSkillAct` 用 `act._skillDone[layer]` 逐层登记，同层同 act 永不跑两次（直接针对 V9.54"同一变体应用两次"缺陷）。探针实跑：对同一 act 连调两次 `resolveSkillAct`，`dmg`/`note` **逐字节相等**（`idempotent_dmg_equal=true / idempotent_note_equal=true`），`done_layers` 对 atk 键 = `[hero,dao,job,sutra,variant,jing,treasure]`（7 层，`ult` 因 `kinds` 不含 atk 正确跳过）。

### 1.2 每层对一次攻键出手的真实改写（探针逐层裁剪 trace）

以「斗战明王（combo 流派）+ 悟空 + 装第一部渡经 + rng 恒 0（概率必触发）」跑一次攻键，基值 `dmg=100`：

| 层 | 对 act 的净写入 | 说明 |
|---|---|---|
| hero | — | `applyHeroKeyFeel` 悟空挂 `trueDmg+·撕甲`，但此处 rng 前置态未触发字段差（探针显示 delta 空） |
| dao | — | 无 `daoAtk` 风格输入 |
| **job** | `hits: 2` | `_jobCombo`（`data_jobspec.js:225-231`）按 comboStack 定段数 |
| ult | — | 攻键不进 ult 层 |
| sutra | — | 经文变体经 `applySutraVariant` 可叠 dmgMul/heal 等，本态无净差 |
| variant | — | 流派攻键变种 `combo→连环`（hits 覆盖） |
| **jing** | `dmg: 100→130`, `hits: 2→3` | `applyJingSlotMods`（`data_sutra.js:1294-1319`）经连击 + 追伤 |
| treasure | — | 无 `TREASURE_STATUS` 命中态 |

⇒ 终态 `note="挥兵狠击·连击×2（层0）·连环·经连击"`, `dmg=130`, `hits=3`。**关键观察**：真正的"成长"发生在 **jing（经位）+ sutra（经文）+ job（流派资源 comboStack）** 三处，而非技能本体——**技能自身永远是 Lv 基态**。

## 二、设计目标：技能系统"应然"的四条轴

> 先立靶子，§④ 差距、§⑤ 优化对着打。技能系统应承担"玩家可主动经营的构筑回路"，至少四轴正交：

1. **形态轴（横向广度）——已具备**：三键 × 变种 × 大招变体 × 经文改写，25 原语正交组合。当前广度**够用**（探针实测与竞品量级齐平），问题是**撞车**（10 流派塌 7 攻形态）。
2. **成长轴（纵向深度）——缺失**：单个技能应有 Lv/精研式的纵向数值成长（STS 每卡可升级一次是最小可用范式）。当前技能本体永远是 Lv0，成长全外包给经位/流派资源。
3. **获取轴（决策密度）——被动**：玩家应能在局内**主动**决定"要哪个变种 / 升哪张 / 合成哪个"。当前获取全由 build 加权投票反推，构筑主动性弱。
4. **协同轴（combo depth）——半具备**：变种与法宝/经位/流派已协同（jing+treasure 层）；缺"技能 A × 技能 B = 新行为"的**合成/连锁**（ETG 合成、万世剑冢特质合成终极神通是此轴的成熟形态）。

## 三、竞品机制深挖（机制对机制，带真实来源）

### 3.1 杀戮尖塔 · 卡牌升级 / 移除 / 协同（"单技能纵向升级"的举证标准）
- **升级**（wiki.gg / Fandom）：**每张卡只能升级一次**，升级"改善效果或降低费用"（加伤害、去掉 Exhaust、加 Innate 等）；升级来源 = 篝火（每 REST 一张）+ 商店 + 部分遗物/事件 → **高频、离散、玩家自选"升哪张"**。
- **移除**：商店可 **Remove 卡**，把卡组"提纯"（deck thinning）——构筑不只是加，更是**减**。
- **协同**：升级改变的是"卡与卡的 combo 上限"（如 Inflame × 多段攻击牌、Double Pain 等），单卡纵向升级直接抬高协同天花板。
- **对 S02 启示**：本作缺的正是"**每技能可升级一次** + **每战选升级的篝火决策**"。技能精研草案（Lv0→5）是同轴更细的刻度。
- **来源**：`https://slaythespire.wiki.gg/wiki/Slay_the_Spire_2:Upgrade`、`https://slay-the-spire.fandom.com/wiki/Upgrade`（升级一次、改进/降费）。**L1（公开）**，逐卡精确值属 L2。

### 3.2 Enter the Gungeon · 主动道具配额槽 + 合成（"配额门禁 + 生成新行为"）
- **配额门禁**（wiki.gg Stats）：**主动道具默认 1 格**（`Additional Item Capacity` 各角色基准 0），仅个别角色/道具（如 Robot / `All Capacity Up!`）扩到 2 格 → **"只能带一个主动技"本身就是强决策约束**，逼玩家在互斥的主动效果里取舍。被动道具则无上限堆叠。
- **合成**：Old Knight's Flask 把两件道具**合成为一件**（最多存 2  charges，跨 floor 携带配方）→ 合成产出**新行为**而非单纯数值。
- **广度**：道具总量 **271**（Fandom：210 本体 + 26 + …）。
- **对 S02 启示**：本作的三键 = 天然"3 格配额"，但**每格内容由流派锁死、玩家不能选带哪个变种**——把"配额门禁"用成了"配额固定"，浪费了它作为决策点的价值。合成轴（变种×变种）本作全无。
- **来源**：`https://enterthegungeon.wiki.gg/wiki/Stats`（capacity 基准 0）、`https://enterthegungeon.fandom.com/wiki/Items`（271 总量）、Old Knight's Flask（合成/2 charges）。**L1（公开）**，具体道具效果属 L2。

### 3.3 万世剑冢 · 招式获取与流派特质合成（主竞品，"轮回借取 + 合成解锁终极神通"）
- **获取通道**（3DM 游戏库/官方描述）：核心"**轮回传承**"——角色陨落不重置存档，化作剑魂留存剑冢，**后代弟子可入冢借取先辈的功法与装备**。招式（功法）获取是**跨周目累积 + 局内借取**，非每局从零掷骰。
- **合成 / 门禁**：**"开放七大修仙流派，支持特质合成解锁终极神通"**；本命神剑 = **剑身 × 剑柄随机组合**（自由装配 → 独一无二）。战斗以**五行相克 +30% 伤害**、灵兽协同增伤。→ "终极神通"需**特质合成**才解锁 = 一种"门禁 + 合成"的招式获取深度。
- **对 S02 启示**：本作已有"转职即换形态"的**表现层**（对标其流派），但缺"**跨周目借取/解锁**"的**获取层**和"**合成解锁终极**"的深度层。本作大招 3 阶（`ultimateTier`）是最接近"终极神通"的骨架，但解锁靠命数阈值、非合成抉择。
- **来源**：`https://dl.3dmgame.com/pc/151135.html`（轮回传承/7 流派/特质合成终极神通/五行+30%/剑身×剑柄）。**招式"配额门禁"的精确携带数无一手来源 → L2（待核）**，机制定性确证为 L1。

### 3.4 构筑哲学光谱（本作站哪）

```
被动表现层(随 build 反推形态)      主动获取+纵向升级            合成/生成新行为
  【逆道西行·当前】       ←→      STS 选升级/Remove        ←→   ETG 合成 · 万世剑冢 特质合成终极神通
 (广度足, 但玩家不逐招挑, 无等级)   (高频决策 + 单卡纵向成长)      (2→1 涌现 / 门禁解锁)
```
**核心分歧**：本作把技能做成了"**build 的结果**"（流派/经文投票 → 形态自显），竞品把技能做成"**build 的手段**"（玩家主动选带哪个、升哪个、合成哪个）。前者爽在"我配的装自然显影成一套打法"，代价是**丧失了逐招决策这一高频乐趣回路**。

## 五、优化设计（可实施，带目标值/公式 + 落点 owner + 验收门禁 + 风险 + 优先级）

> 本轮**不改码**；每条给足实现信息。优先级 P0>P1>P2。**跨系统数值口径链接 S18 与 02 耦合矩阵，不另立数字。**

### O1 ·（P0）接通"技能精研"纵向轴——把 G1 缺失的成长回路补上
- **问题**：技能本体无等级（§1.2 trace 证实成长全外包），长线养成缺一条玩家可主动经营的轴。
- **方案**：按草案 [精研 v0.9](../《逆道西行》技能精研系统设计（阶段③ v0.9草案）.md) 落地"第 5 轴"：
  - 新增单源表 `NDX.SKILL_REFINE = { cap:5, cost(n), gain(lv), branchAt:3 }`；收益曲线 Lv0→5 = `+0/8/16/24/32/40%`（草案 §2.2），消耗 `ceil(30·n^1.5)` 香火 / `ceil(2·n^1.3)` 妖丹（草案 §2.1）。
  - 状态 `s.skillRefine = { skillId: {lv, branch} }`（走 `data_save` 白名单）。
  - **唯一结算点**：`resolveSkillAct` 入口对 act 主数值乘 `1 + gain(lv)`（草案 §三-3）。⚠ **只乘 `dmg/heal/shield`，不乘 `hits`**（草案 `:57`：hits 已被 `act.dmg 总量按 hits 分摊` 语义约束，动它会净增/净削翻转，见 `data_skill_index.js:139-146` multi 纠错史）。
  - 默认 Lv0 ⇒ 乘子 = 1 ⇒ 分支不可达 ⇒ **构造性零回归**（同 S18 O4"接死字段"哲学）。
- **落点 owner**：`data_skill_index.js:386`（入口乘算）+ 新表文件（建议 `js/data_skill_refine.js`，须在 `data_skill_index.js` 之后、`combat_active.js` 之前加载）。
- **验收门禁**：新建 `_verify_skill_refine.js`——① Lv0 全量输出与现网逐字节一致；② Lv5 主数值 = ×1.40、hits 不变；③ 消耗曲线复算；④ 分岔不可回退。掉率标定用 `_dump_balance_db` 口径实测，**超调先调掉率不动曲线**（草案 §2.4）。
- **风险**：① 与经位/流派收益叠乘可能超预算——须并入 S18 全局 DPS 反推链复测（`_balance_anchor.js` 表②），确保击杀回合斜率不因精研二次膨胀；② 精研入口乘算须排在 `resolveSkillAct` **最前**（基值之后、其它层之前），否则与"舍攻为盾归零 dmg"类变种冲突（乘 0 仍 0）。**DPS 验收线：满研后同章标准怪击杀回合缩短 ≤ 20%（草案 §2.4）。**
