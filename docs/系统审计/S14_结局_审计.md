## ① 当前游戏内容（代码事实）

> 硬规则：每条数值/机制必须带 `file:line` 或 BalanceDB 键；无证据者移入 §⑥。

### 1.1 核心循环
「终局触发（第 81 难凌云渡/返程）→ `buildReturnScene` 按余寿定档（shrine/return×perfect）→ `NDX.Ending.determineEnding(s)` 动态 10 条按 ORDER 首命中 → 未命中落 `computeEnding()` 静态 7 分支 → 索引表包装补 `id+cg` → 落 `s.over.ending` → 成就落簿 `_syncAch` → perfectEnding 朝代门 + `perfect` 达标 → `EndingVideo.play` → 排行榜/朝代推进」：

1. **档位判定**：`NDX.buildReturnScene`（`js/data.js:310`）读到西天余寿 `left`（`:313`）：`left < SHRINE_R(9)` → `grade:'shrine'` 返程坐化留舍利（`:325`）；否则 `grade:'return'`，`perfect = left >= PERFECT_R(14)`（`:326`），回长安余寿 = `left − RETURN_COST(9)`（`:327`）。
2. **动态结局**：`NDX.Ending.determineEnding(s)`（`js/endings.js:125-133`）按 `ORDER`（`:119`，10 键优先级序）**首命中即返**，单条 cond 异常 try/catch 跳过（`:130`）；全不命中返 `null`（`:132`）。
3. **兜底静态**：`game_meta.js:209` 调动态、`:210` `if (!ending) ending = this.computeEnding()`；`computeEnding`（`js/game/game_meta.js:453-501`）**7 分支**：唐僧善线→金蝉正果（`:461-466`）、evilPath→一魄转世（`:467-472`，evilPath 定义 `:459`）、悟空→大圣脱局（`:473`）、八戒→净坛圆觉（`:479`）、沙僧→卷帘归真（`:485`）、小白龙→白龙渡海（`:491`）、兜底→逆道西行（`:497-500`）。
4. **索引包装**：`data_endings_index.js:110-126` IIFE 重包 `determineEnding`，返回值补 `id + cg`（经 `endingByTitle` 反查，`:99`），使"结局→CG"关联首次落地（头注 `:14-15`）。
5. **完美旗标**：`grade==='return'` 时 `ending.perfect = !!rt.perfect`（`game_meta.js:217`）、`rankName`（`:218`）；`perfect && savePerfectClear()` 永久解锁逆道抉择（`:220-221`）。
6. **视频演出**：通关后 `_syncAch()`（`:305`）→ `dynastyHas('perfectEnding') && s.over.ending.perfect`（`:307`）→ 标题映射 `_eid`：金蝉→zhengguo / 逆道→nidao / 大圣→dasheng（`:308-310`）→ `window.EndingVideo.play(_eid)`，失败不阻断结算（`:311-313`）。
7. **排行/落档**：`grade==='return'` 双榜提交 `NDX.submitRank`（`:224-231`，含 perfect 旗标与朝代名 `:227-229`）。

### 1.5 边界与异常
- **双链互备**：动态链异常/不命中 → 静态兜底必返（`game_meta.js:209-210`；`computeEnding` 无 null 出口）→ **任何通关必有结局**，无空终局态。
- **单条 cond 异常隔离**：`determineEnding` 对每条 cond try/catch（`endings.js:128-131`），一坏不拖全局。
- **视频降级**：`play()` 包 try/catch、`isPlaying` 防重入（`game_meta.js:311-312`）；视频缺文件时 `ending_video.js` 内部降级（不阻断结算）。
- **包装层防死表**：`_verify_endings_index.js` E9（`:97-101`）反向断言 determineEnding 返回值带 `id+cg`，防索引表再被"清理成没人读的死壳"（头注 `:4-6` 记载历史教训）。
- **不可达显式登记**：`st_nidao.unreachable:true`（`data_endings_index.js:79`）在门禁 E7 获豁免（`_verify_endings_index.js:77-78`）——可见性登记而非数据缺陷，但**它仍是当前英雄集下的零通道条目**（§1.7-3）。
- **三处同步约定**：新增/改结局必须同步索引 + endings.js + ENDINGS_CG，由 E2-E6 校验 id 唯一/标题一致/CG 引用存在（头注 `:17-18`）。

### 1.7 已知债务与死区
> ⚠ 以下均为**实测代码债务**，本审计只登记不改码。

1. **【文档漂移】头注"20 条：10 动态 + 7 静态 + 3 告别卡"**（`data_endings_index.js:12`）与实测 **22 条（10+7+5）** 不符——V9.26 补悟空/取经人告别卡（`:90-94`）时未回头改头注；`ENDINGS_CG` 头侧注释同样残留"CG 6 张"口径（`:9` 注释区）。零运行时影响，但违反 01 宪法"滞后文档复核"条款，属本档主登记项。
2. **【零接线数据】`source:'farewell'` 无运行时消费者**：全库 grep `farewell` 仅命中两份数据文件（`data_endings_index.js:83-94`、`data_endings_cg.js:24-45`），**无任何 UI/结算代码按"该英雄通关"点亮告别卡**（threshold 文案悬空）；`endingsBySource('farewell')` 理论可查但全库无调用。5 张告别卡 CG 的收集/点亮闭环未实现（对比：dynamic/static 均有 `determineEnding→s.over.ending` 消费链）。
3. **【零通道结局（已登记）】`st_nidao`**：`computeEnding` 兜底分支（`game_meta.js:497-500`）要求非唐僧善/非 evilPath 且非悟空八戒沙僧小白龙——现 5 英雄集下**逻辑不可达**（`:461-495` 五分支全覆盖），故 `unreachable:true`（`data_endings_index.js:79`）且门禁豁免。定性=**为未来新英雄预留的合法兜底**而非 bug，但 22 条中它作为"可收集结局"陈列于图鉴口径时玩家永远打不到 → 可达性表须以 ⚠ 标注（§④）。
4. **【时序死锁波及】唐 `perfectEnding` 视频链在通关瞬间难满足**：`settleReturn` 先 `resetDynasty`（`game_meta.js:269-270`）→ 后 `dynastyHas('perfectEnding')`（`:307`），而 `dynastyHas` 按**当前**朝代索引取 feature（`data_dynasty.js:132`）——复位后索引=0（夏），唐朝 feature 表拿不到 ⇒ 完美结局视频与 S13 `qing/all_dynasty` 成就同根死锁（详 [S12 §1.7](S12_朝代_审计.md)）。⚠ 若 `hasClearedAny()` 门禁下夏朝无 perfectEnding 则视频**每次都不播**，V9.67 "已接通"仅接线、未验证时序。
5. **【无快照门禁】** 22 条索引、8 CG、3 视频映射、PERFECT_R 档位均不入 `data/balance_db.json`（`meta.counts` 无 ending 键）；唯一体检=`_verify_endings_index.js` 运行时脚本（须手动/CI 跑，非 dump 比对）。
6. **【endingByTitle 反查脆弱】** 包装层以**标题字符串**反查 id/cg（`data_endings_index.js:99`、`endings.js:129` 只返 `{title,text}`）——动态结局与告别卡存在同名标题（'净坛圆觉'：st_jingtan `:65` vs bajie-farewell `:84`；同理卷帘归真/白龙渡海/金蝉正果），`find` 首命中按表序返回，**同题歧义下 `id` 归属取决于数组顺序**而非语义（当前表序 dynamic 在前，恰好稳定；若调序即漂移），无唯一性门禁。

## ③ 竞品对比（机制对机制）
> 框架：结构 / 深度 / 手感。主竞品=**Hades（多结局+叙事增量）**，扩展=**Rogue Legacy（传承型终局）**。竞品精确值无本地来源者标「待核」入 §⑥。

| 机制维度 | 本作（实测值+出处） | 主竞品〈Hades〉 | 扩展〈Rogue Legacy〉 |
|---|---|---|---|
| 结构 | 三层判定：10 动态 cond 链（优先）+ 7 静态兜底 + 5 告别卡（图鉴层）= 22 条（§1.4）；任一通关必有终局（§1.5） | 通关即推进主叙事线，结局数量少（数个大分支，精确待核）但**每个终局=叙事增量落点**（新对话/真相推进） | 单一终局（击败父王），结局非收集对象；收集在"传承变异"维度 |
| 深度 | 结局由 英雄×善恶×六道命数×朝代 交叉决定（`game_meta.js:459`、`endings.js:39-116`），与完美档/逆道门联动闭环（`:220-221`） | 结局与人物好感/剧情章节强绑定，重开动机=看下一段戏 | 终局后进入 NG+ 继承循环（本作由朝代/轮回承担，非结局系统本体） |
| 手感/反馈 | 结算即播 CG 引用+3 条实机视频（`ending_video.js:16-35`）、双榜留名（`game_meta.js:224-231`）、新功名播报（S13）；但**无"结局图鉴缺哪几个"的可检视收集进度**（索引表已具备数据，UI 消费面未见） | 每结局给"下一次逃跑的新理由"，图鉴式剧情回放在冥殿对话完成 | 结局后的家族树呈现是 Rogue Legacy 独有反馈层 |

**核心对比结论**：本作结局**广度（22 条）超 Hades**，判定链与朝代/成就/寿数耦合深；差距在 Hades 式「结局→叙事增量必落可见反馈」——本作告别卡零接线（§1.7-2）、视频链受时序死锁威胁（§1.7-4），多结局的"收集可验证感"未闭环。
