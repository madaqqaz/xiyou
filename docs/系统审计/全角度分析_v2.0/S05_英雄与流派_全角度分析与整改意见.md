### 1.1 核心循环与玩家动线

- **选角 → 养成 → 战斗**（`L1`）：`s.hero` → `HEROES[hero]`（`data_heroes_data.js:10-95`）→ `playerBaseAt(diff, hero)`（`data_heroes.js:13-34`）→ `computeStats`（`combat_part1.js:100+`）→ 三键 `activeSkill('atk'/'chant'/'ult')`（`combat_active.js:31/58/192`）。
- **流派显影**（`L1`）：`getMainDao(s)`（`dao_system.js:82-104`，锚点 `s.mainDao` + 劫印分布动态覆盖）→ `daoAtkStyleOf`（`dao_system.js:254-257`）→ 消费于 `combat_part1.js:521-524`（自动轨）与 `data_skill_variant.js:172-185`（手动轨）。**六道攻式是真接线**，不是死数据——这是相对旧审计的**纠正**（旧审计 §1.3 未记载消费点）。
- **善恶累积**（`L1`）：逐选项 `effect.alignGood / alignEvil` → `s.good / s.evil`；实测全仓 **alignGood 395 处 / alignEvil 335 处 = 730 处**（`grep -ro 'alignGood"*:' js/` 分文件分布：`events_part2.js` 193、`trials_ch1.js` 58、`trials_ch7.js` 30、`trials_ch8.js` 23、`trials_return.js` 18、`trials_ch9.js` 17、`trials_ch3.js` 14、`trials_ch4.js` 12、`trials_ch2.js` 10、`trials_ch6.js` 9、`trials_ch5.js` 8、`hero_trials_ch1.js` 2、`game_event_2.js` 1）。另有 **1457 个选项**带显式六道标记 `fate: '战|渡|隐|夺|缘|逆'`。
- **前 30 分钟首次体验路径**（`L1`）：`startScreen()`（`ui_misc_1.js:300-341`）渲染 5 张卡 → 默认 `NDX.pendingHero || HERO_ORDER[0] = 'tangseng'`（`ui_misc_1.js:302`、`main.js:495/534/537/545`）→ 开局序章已于 V8.6x 移除（`ui_misc_1.js:337` 注释「已移除」）⇒ **零引导、直落选人屏**。卡面仅含：立绘 + 名 + `sysLabel` + `主键·攻/经` + 攻式名（`ui_misc_1.js:305-326`）。**前 30 分钟玩家实际只可能玩到取经人**（`unlockedHeroesAll()` 冷启动 = `["tangseng"]`，实跑）；另 4 张卡的锁文案**只写 1/3 通道**（`ui_misc_1.js:315`：「通关【取经人】任意一次后解锁」），漏掉死亡渐进（1/2/4/8 次死亡逐解）与劫灰提前解锁两条通道（`data_reincarnation.js:64-92`、`data_heroes_data.js:389-400`）。
- **唯一的英雄对比工具埋在经文弹窗里**（`L1`）：`heroHandFeelHtml()`（`ui_misc_2.js:315-344`，四格＝主打键/攻式/本命诵经/绝招·起手）只在 `rubbingHtml()`（`ui_misc_2.js:502`）内被调用，即「藏经阁」弹窗中部，与 CG、随从册并列；注册于 `ui_modals_1.js:26`。**选人屏与总鉴均无入口**。

### 1.5 边界与异常

- **道带 clamp**（`L1`）：`scaleRunMods` 把渡/逆差距收窄到 `[0.72, 1.28]`，多阶段 Boss `stages[]` 同步缩放防阶段条脱节（`data_heroes.js:44,49`）。
- **零操作兜底**（`L1`）：`currentStyle` 无信号返 `null`（实跑：无劫印时 5 英雄**全部 null**），存量玩家行为逐字节不变（`data_jobspec.js:519-535`）。
- **大招兜底**：`ultimateOf` 取不到定义时静默回落 `dblBase×1.5`（`combat_active.js:277`），**无告警**。
- **攻式分支互斥**（`L1`）：`data_skill_variant.js:173-174`「已进阶走进阶口径，六道攻式不叠加」⇒ `_skillAdvance.atk` 命中时六道攻式被跳过，两条轨**互斥**；同一 `player.daoAtk` 在 `combat_part1.js`（自动）与 `data_skill_variant.js`（手动）**各写一遍六道 switch**，是双轨同结果的**结构性重复**（改一处漏一处的风险点）。
- **`pct` 字段语义重载**（`L1`）：`crit` 分支把 `pct` 当**概率**（`Math.random() < 0.25`），`heal/lifesteal/shield/true` 分支把它当**伤害比例**（`deal × pct`）。同一字段两种单位，见 `data_skill_variant.js:177-184`。
- **跨周目与存档迁移**（`L1`）：解锁态走 `SaveSystem`（`nx_hero_unlock_v1` / `nx_clear_v1`），已通关记录 `clearedHeroes()` / `hasClearedAny()`（`data_heroes_data.js:419-434`）；V8.41 已统一 `SaveSystem`、删除降级逻辑。死亡/劫灰进度各存 `xynj_death_unlock_v1` / 劫灰档位。
- **⚠ 劫灰英雄映射缺口**（`L1`，本文新发现）：`unlockedHeroesAll` 以 `HERO_ORDER` **下标-1** 判定劫灰解锁（`i-1 < ashN`），而 `ashN = min(4, 金蝉档 + 逆心档)`（`data_reincarnation.js:66-68`）是**两线求和**。实跑复刻该判定式：
