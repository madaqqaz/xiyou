### 1.1 核心循环与玩家动线

**局内坊市（节点驱动）**

```
进入节点 type='shop'
  game_core_2.js:907  ── 算价 shopPrice(node.priceTier)            :908  ← act 漏传
                       ── 朝代折扣 dynastyAdjust(price,'shop')     :910  （仅此一条路径）
                       ── 合成优先：availableRecipes 非空 ⇒ 整店换 craft 面板并 break  :912-921

                       ── 遗物残片兜底 _relic 同价 push             :934-943
购买   game_shop.js:42-53  buyShop：gold<price 拒绝(:46) → 扣款(:47) → _consumeShown(:48)
                            → giveRelic(_relic) / grantEquip(:50-51) → 移出货架(:52)
刷新   game_event_4.js:275-293：次数封顶(:281) → 扣 30(:283-285) → rollEquips(2)(:287)
                            → 落空退款(:288) → shopRerollPrice 重定价(:289-290)
```

### 1.5 边界与异常

- **幂等供货**：`rollEquips` 排除 `owned` 与 `shown`；购买时 `_consumeShown` 释放回池（`game_loot.js:47-53`）；刷新落空**退款** `s.gold += cost`（`game_event_4.js:288`）。✅
- **档位钳制**：`tier = clamp(1+floor(d/4)+_rand(0,1), 1, 5)`（`data_equipment.js:167`）⇒ d=16 触顶，此后 65 个难号恒 t5。✅
- **价格快照不可逆**：`item.price` 生成时固化（`:930`），后续朝代/套装折扣只在生成瞬间作用。✅
- **金币不足零反馈**：仅 `pushLog('金币不足')`（`game_shop.js:46`），无差额提示。✅
- **劫灰封顶**：满级拒绝（`game_shop.js:24`）、余额不足拒绝（`:25`）。✅
- **跨周目/迁移**：旧档 `materials` 旧名经 `migrateLegacyMaterials`（`data_materials.js:59-72`，幂等）在 `restoreRun` 时折算；`MAT_LEGACY_MAP` 31 条目标全 ⊆ `MAT_CORE`（门禁 `_verify_materials` B 组）。✅
- **非异常但需登记的边界**：`withSeed` 只包住 `generateMap(1)`（`game_event_1.js:11/14/17`），转章 `game_region.js:214` 在作用域外 ⇒ 坊市档位**跨章不可复现**（审计层 §1.11 结论本轮维持）。

### 1.9 补：R1「act 漏传」的量化价格表（2026-09-27 补录）

> 此前只给了「−26.5%~−28.4%」的百分比，缺具体价位、无法排期与验收。本条补齐绝对值。
> 公式复刻自 `events_part2.js:66-71`：`base = 30 + (tier-1)*4`，`actMult = 1 + min(0.8, (act||1)*0.05)`。

**逐档实收 vs 应然（应然取 act=9，即九章末）**

| 档位 | 实收（act 漏传） | 应然（act=9） | 差额 | 实收/应然 |
|---|---|---|---|---|
| t1 | **32** | 44 | −12 | 72.7% |
| t2 | **36** | 49 | −13 | 73.5% |
| t3 | **40** | 55 | −15 | 72.7% |
| t4 | **44** | 61 | −17 | 72.1% |
| t5 | **48** | 67 | −19 | 71.6% |

**跨章梯度（这是比百分比更严重的一面）**

```
实收（4 处调用一律 act=undefined）:  t1..t5 = 32 / 36 / 40 / 44 / 48   ← 与第一章完全相同
应然（act=9）                     :  t1..t5 = 44 / 49 / 55 / 61 / 67
```

⇒ 由于 4 个调用点**全都不传 `act`**，`actMult` 恒等于 `act=1` 时的值，`shopPrice` 的「价格随地区增长」这一 V8.41 决策**在玩家可见的全部路径上完全不存在**——九章物价与第一章 **逐档完全相同**。这是"后期金币通胀失去决策意义"的**直接机制**，而不是通胀的后果。

**修复后的可验收判据**（供 `_verify_shop_economy.js` 使用）：

1. 全 9 章 × 5 档共 45 组，`price(tier, act=9)` 必须等于上表"应然"列；
2. 同 `tier` 下 `price(act=1) < price(act=5) < price(act=9)` 单调成立；
3. `price(tier, undefined)` 在修复后**不再被任何外部调用点使用**（反证：把 4 处补实参后，`grep -rn "shopPrice(" js/` 的匹配行号中不得再出现 `main.js` / `game_event_4.js` / `ui_panel_2.js`）。

> ⚠ 时长提醒：修复会把 t1~t5 全线提价 **约 28%**，与 `rewardMult`（0.8~1.6）、诅咒乘子同批回归，否则价格与收入两条曲线会各自漂移、归因不清。
