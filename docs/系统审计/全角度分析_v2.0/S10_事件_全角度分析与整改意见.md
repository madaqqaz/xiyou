### 1.1 核心循环与玩家动线

```
长安（无事件弹窗） → 第1难「金蝉遭贬」复合弧（game_compound.js:3 → _compoundNext:61 → _compoundTrial）
     ├─ 教学战（接引使者）→ finishFight 恢复 _tutorialResume（game_event_1.js:321-332）
     └─ 六道抉择（subOptions 二级面板）→ applyTrialOpt（game_event_2.js:55）
地图「缘(?)」节点 → rollYuan(s)（events_part1.js:137）── p=min(1,0.10+0.10·pity) 掷「遭遇战 / 奇遇」
     ├─ 遇战 50% mob / 50% elite
     └─ 奇遇 → 四层漏斗（game_core_2.js:707-864）：送行 INIT_GIFT_EVENTS → 灵兽进化
              → 双线 SUTRA_EVENTS（三级判定 + 加权）→ pickEvent 兜底（events_part1.js:54）
           → s.pending{kind:'event'} → ui_panel_2.js:922 sceneModal 渲染
           → 玩家点选项 → applyEventOpt（game_event_3.js:99）→ applyEffectCore（:500）
           → thenEvent 递归接后续事件（:192）／回落 s.pending.then
```

**前 30 分钟首次体验路径**（实测链路）：开局 `start()`（`game_event_1.js:2`）→ `pending={kind:'curse-pick'|'choices'}`（`:218-220`）→ 第一难复合弧走六道教学 → 胜接引使者教学战 → 难1 抉择 → 六道升级石 → **第一个真正的"问号"出现在第 1 章中后段**（`s.eventPity` 每章归零，`game_region.js:177`）。即：**前 30 分钟玩家一次都没见到 `EVENTS` 主池事件**，主池的 166 条内容在首局前 30 分钟内**零曝光**（属推导，入 §5）。

### 2.6 玩家视角

**前 30 分钟**：第一难复合弧（复合教学战 + 六道抉择）⇒ 玩家**一次都见不到主池 166 条事件**（首局最早期问号出现在第 1 章中后段）。玩家在此阶段学到的唯一规则是"选项决定 fate"，而 fate 后果**不展示**。｜证据：`game_event_1.js:272-335`、`game_region.js:177`｜**中**

**第 2–5 局**：进入主池后，玩家面对 3 选项（72.3% 命中）事件，**81.3% 的事件三选项效果两两全异** ⇒ 决策不是假的。但 **`consequence` 0/482、`tip` 0/482** ⇒ 玩家**无从预知后果**，只能靠读 `effect` 数值盲猜，而 UI 从不渲染数值（唯一的朝代提示只在 8 条商朝 SUTRA 事件上）。玩家实际动作：点第一个"看起来安全"或第一个"听着酷"的选项。｜证据：`node` 枚举 + `ui_modals_2.js:31-40,50-52`｜**P1**

**可预期性 vs 劫难的落差**：同一套 UI（`sceneModal`）渲染劫难选项时，`consequence` 明示率 253/331 = 76.4%，且 `optionCondMet` 门槛徽章对 109 条带门槛选项生效（满足时蓝标、不满足时红标）；渲染事件选项时这两项**同时归零**。玩家会感知到的直接结论："**劫难的选项写得清清楚楚，问号的选项看天亮**"。｜证据：`ui_modals_2.js:50-70` 与两池数据计数对照｜**P1**

**中期构筑（挫败点，最强）**：双线池 157 条本应是"经文/装备定向获取"的主渠道，但**奖励一件都不发**（§1.7-1）——点「求经——心经一卷」拿不到指定残片、点「讨衣——旧衲傍身」**一件装备都拿不到**。玩家在中期会得出"选经文事件没用"的错误结论，并可能因此放弃整条渡/逆线构筑。而更反讽的是：④ 层那套"30% 装备池 / 70% 普通池 / `_miss>=3` 强制装备池"保底（`game_core_2.js:818-828`，`_gearEventMiss` 连续 3 个问号未出装备即 100% 触发）**专门服务于这个空转**——保底越是认真把装备事件送到眼前，落空的反差越大。｜证据：§1.2-B 实测｜**P0**

**后期重复**：`thenEvent` 4 层链仅 1 条（占 166 条的 0.6%）；链上事件去重记账写错容器 ⇒ 重复可感度接近零。而重复感主要来自 230 条 `setFlag` 的劫难抉择，不在事件池。｜证据：`node` 链枚举 + `game_event_3.js:194-195`｜**P2**

**决策密度反证（本轮主动证伪）**：对"事件决策密度充足"做反向检验——若多数选项等价，则密度是假的。实测：166 事件中**效果签名全同 0 条**、仅 2 种 31 条、**三选项两两全异 135 条（81.3%）**；选项数分布 2/3/4 = 31/120/15，无"默认选项 + 两个装饰选项"的结构。⇒ **密度真实，问题在可见性与兑现，不在数量**。此条同时是对 `../S10_事件_审计.md` §④"决策密度=中"的**上调**（证据支持上调为健康）。｜证据：`node` 归一化签名比对｜**健康**
