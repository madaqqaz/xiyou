## 〇、执行摘要（TL;DR）

**现状**：S04 是**双层职业系统**——明线「六道专职」（6 道 × 3 阶，门槛=道途命数 + 行为 + 抉择）+ 暗线「隐藏转职」（45 职，5 条 6~7 步链 + 12 孤本，跨周目以 localStorage 永久继承），再叠一层 L3「流派」（10 流派，全部 `impl:true`）。结构层面相当健康：`nextJob` 悬空引用 **0**、重名职 **0**、`Z.selfCheck().ok = true`、三门禁 **88 项断言全绿**（11 + 26 + 51）。

**三大真问题（均以实跑/实读为据）**：

| # | 问题 | 实测数字 | 后果 |
|---|---|---|---|
| **T1** | 隐藏职 cond 是**正则白名单 DSL**，白名单外的裸词一律当"材料名"去查背包；`未用法宝 / 未请救兵 / 第20难逆 / 来福在队` 等**全仓无发放点**，遂恒判负 | 正传节点级种子 **13 条，其中 6 条恒假**（探针：`{"kind":"plot","msg":"需持有材料「未用法宝」"}`）；旗舰链 `wk_chibang` 7 步断 **5** 步且含链尾 `持棒证道` | 玩家看得见门槛文案（`ui_misc_2.js:690-738` 直读 cond），引擎永远判不通过；**静默死锁**，无任何门禁报警 |
| **T2** | `JOB_BONUS_CAP` 只封 `atk/hp/maxHp/matk` 4 键（[data_trials.js:492](../../js/data_trials.js#L492)） | 全 45 职理论叠加：`dr +1.10`、`eva +0.47`、`cri +0.34`、`mdef +0.45`、`spd +18` **完全不封顶**；明线六系三转 `tierBonus` 更给出 `drPlus 1.014`、`atkPct 2.002` | 与 S18 已确立的"坦度/伤害封顶口径"未打通（见 [S18](./S18_数值曲线与难度_深度分析与优化设计.md) 与 [02_耦合矩阵](./02_耦合矩阵与数值口径登记表.md)），多周目全觉醒后防御侧坍缩为免伤 |
| **T3** | 三处"写了但没接线"，形成文案与判定双真源 | `STYLE_W.EQUIP=2.4`（最高权重）现网恒 0：全仓 `style:` 在 `equipment*.js` **0 命中**；`RETURN_TRIALS` 零消费；注册表 `cond` 字段"零消费仅为文档"（[data_trials.js:777](../../js/data_trials.js#L777)） | L3 流派轴的"装备"这一维形同虚设；324 行难数据 + 7 条转职种子成为死库存 |

**竞品一句话结论**：本作**广度已追平甚至反超**冒险日记（45 隐藏职 + 10 流派 vs 其社区口径的百职但同质化），**决策密度与可达性差距最大**——本作链是 `nextJob` 单值的**线性链**（分支度 = 1），竞品是 3-4 层 × 每层 2-3 岔的**树**，且转职后"属性+技能+种族+外观"全变；而本作最要命的是**树的入口本身没接上**（T1/T2 之外的结构性断链）。Rogue Legacy 2 值得抄的不是职业数，而是**"未解锁项明码标价"**（金币 + 庄园等级 + 建筑组合，L2）。

**优化优先级**：P0 = **O1 cond 可判定性收口 + 死短语门禁**、**O2 断链补齐（齐天·大圣/六耳·残）**、**O3 职业加成封顶口径并入 S18 全局封顶表**；P1 = O4 装备 `style` 落地、O5 行为口径（behGate）真实化、O6 死亡解锁通道开 `zhuanjie` 线；P2 = O7 第四阶/终极觉醒层（补深度差）、O8 返程段接入。

## 二、设计目标（应然）

**G1 「逆道」的主题性**：转职不该是"选一个更强的皮"，而是"你这一路怎么待人"的**结算**。逆/顺、善/恶、用不用法宝——**手段即职业**。⇒ 现网 `alignMin`、`karmaBacklash`、`requireNoTreasure` 都在为它服务，但 cond 死锁把最纯粹的"不借外物"这条线锁死了（T1）。
**G2 「链」的叙事递进性**：一条 6-7 步链应当像一部经——每步一小悟（`note`/`hint`），末步证道（`chainTail`），且**每步都可被玩家主动规划**。⇒ 结构完好（悬空 0/重名 0），但**线性分支度 = 1**，且不可达。
**G3 「多周目」的重玩性**：单局 20 节点短流程 ⇒ 单局至多 1-2 次转职，乐趣必须建立在"跨局攒觉醒 + 继承放大"上。
**目标（可验证）**：
- **每个隐藏职都有一条引擎承认的觉醒路径**，且 cond 文本与判定真源**唯一**；
- **全 45 职任意组合下面板不越 S18 全局封顶**（防御向不出现 >1 的加算减伤）；
- **玩家能在 UI 上看见"此职尚不可得的原因，且该原因可被满足"**（拒绝恒假提示）；
- **流派五维（含装备）每一维权重都能被现网数据实际驱动**。

## 三、竞品机制深挖

> 取证方式：WebSearch 联网核源 + 精读本地 [逆道西行_vs_冒险日记_转职系统对比分析报告](../逆道西行_vs_冒险日记_转职系统对比分析报告.md)（649 行）。凡**精确数值无一手可读者，一律标 L2**（TapTap 原帖遭 WAF 拦截，仅得搜索摘要；EtG/RL2 的 fandom 页不可达，改用 Steam 指南 / TheGamer / IGN 摘要交叉）。

### 3.1 冒险日记（主竞品）——「树 × 变异条件」

**结构**（L2，本地报告 §1.1 + 社区攻略摘要）：初始职业 → 一转 → 二转 →（部分）三转，每层 2-3 岔；转职后**属性 + 技能 + 种族 + 外观全变**；支持**自动转职**与**跨分支进阶**。隐藏职靠「怪异条件」触发，社区攻略所列条件类型（[TapTap 隐藏职业汇总](https://www.taptap.cn/moment/256104057729452790)、[doyo 汇总](https://www.doyo.cn/news/191664.html)，L2）：

| 条件类型 | 实例（社区口径，L2） |
|---|---|
| 层数门槛 | 空我需 300 层；平民「铸剑为犁」**须 30 层以内**才可转 |
| 道德数值 | 空我需 **500 善良**起、终阶需 **3000 善** |
| 装备套装 | 民兵套 → 民兵；骑士腰带 → 空我阶段 |
| **文本口令** | 输入「铸剑为犁」即转平民（伤害仅 20%，受伤后伤害 ×200%） |
| 职业互动 | 与圣骑士 NPC 互动方能取得腰带 |
| 多阶段链 | **空我 5 阶段**（觉悟 → 初生 → … → 3000 善终阶） |

**哲学**：条件本身即内容，「知道条件」就是社交货币（口令/梗）。代价是**必须依赖攻略**——游戏内不做可解析提示。
**对 S04 的启示**：① 本作 cond-DSL 的方向是对的（实测 11 类，比报告旧口径的 5 类更丰富），**但 DSL 一旦有拼写缺口就是死锁**；冒险日记靠「人工攻略验收」绕过了这个问题，本作必须靠**门禁**。② 「转职后外观/种族/技能全变」是玩家可感知度最高的一环，本作仅 `JOB_STYLE_COLOR` + `jobStyleHint`，偏软。

### 3.2 Rogue Legacy 2（扩展）——「未解锁项明码标价」

**结构**（L2，[TheGamer 全职业解锁指南](https://www.thegamer.com/rogue-legacy-2-class-unlock-guide/)、[Fandom Upgrades](https://rogue-legacy-2.fandom.com/wiki/Upgrades)）：约 **15 个并列职业**（非树），解锁条件是**三元素组合的显式报价**——金币价 + 庄园建筑等级 + 指定设施升级；例：Ronin = 旅店 **1,410 金** + `Arsenal / Sauna / Jousting Studies` 各升 1 级 + **庄园 ≥48 级**。另有以稀有货币（灵魂）在商店购得的 Reaper / Pizza Knight。每职业自带独立天赋树，社区共识为「先每格点 1 点把树铺开」（L2，[Steam 讨论](https://steamcommunity.com/app/1253920/discussions/0/3281447372957358550/)）。
**哲学**：**深度不在树形，在「平行选项 + 永久进度」**。玩家永远看得见下一个目标与其成本，于是「没解锁」是**计划问题**，不是**谜题**。
**对 S04 的启示**：本作 `DEATH_UNLOCKS.zhuanjie = []`（D7）等于把这条报价栏整个空置；而 T1 的死锁之所以长期无人察觉，正因为 UI 显示的是**不可满足的伪条件**而非「成本」。

### 3.3 Enter the Gungeon（扩展）——「以 A 通关才能见 B」的互锁链

**结构**（L2，[Steam 全解锁指南](https://steamcommunity.com/sharedfiles/filedetails?id=1928483873)、[IGN Unlockables](https://www.ign.com/wikis/enter-the-gungeon/Unlockables)）：起始 4 名（另 Cultist 限合作），共 8 名；解锁是**跨角色互锁马拉松**——用某角色通关 → 其「过去 (Past)」出现在下一局 → 击杀过去或再通关；Paradox 需先通关后于任意角色局内寻得 cosmic rift 并击败 Lich 或击杀其过去；Gunslinger 则需「以 Paradox 开局并通关」。
**哲学**：**内容即进度、进度即内容**；单个「职业」的解锁深度靠**跨局链条**堆出来。
**对 S04 的启示**：本作的 `chainId/chainStep/nextJob` 与 `awakenedJobs` 持久化，本质上**已经是 EtG 式的跨局链**——架构对，缺的是「链上每一环都可判定」(T1) 与「链尾的可见奖励」(无第四阶)。

| M9 | **空我 5 阶段（同职多阶）** | 冒险日记 (L2) | 职 = 单点，无职内阶 | ✅ **适合（即 O7）** | 与「明线 3 阶」天然同构：给 `chainTail` 职挂 2-3 阶「证道深度」，复用 `tierBonus` 曲线，成本最低地补深度分 |

**转职系统对冒险日记的「最大差距」单项裁决**：不是职业数（本作 45 已足），而是 **决策密度那一列的「树 vs 链」**——竞品每层给你 2-3 个互斥出口且**转完立刻改变种族/技能/外观**，本作 `nextJob` 单值 ⇒ **玩家从未在「两个隐藏职之间」做过选择**；叠加 D1（6 条种子恒假）后，实际体验退化为「看运气路过哪一难」。

## 五、可实施优化设计（只设计，不改码）

> 每条含：问题 → 目标值/公式 → 落点（owner 文件:行）→ 验收门禁 → 风险 → 优先级。跨系统数值一律链接 [S18](./S18_数值曲线与难度_深度分析与优化设计.md) 与 [02_耦合矩阵与数值口径登记表](./02_耦合矩阵与数值口径登记表.md)，本文不另立第二套口径。

### O1 · cond DSL 收口：消灭「恒假门槛」（**P0**）

- **问题**：`_KNOWN` 白名单外的语义短语被当作材料名（T1 / §1.4）；正传 13 条种子 6 条恒假；三套真源并存（cond 文本 / `requireNoTreasure` / consequence 散文）。
- **方案**（三段，按侵入度递增，建议按序落地）：
  1. **兜底改造（止血）**：`evalHiddenCond` 第 8 段由「当材料名查背包」改为**白名单材料表查表**——仅当 token ∈ `NDX.JOB_MATERIAL_TOKENS`（新增，内容 = `MATERIAL_ALIAS` 键 ∪ events 实际投放的 `material:` 值集合）时才判背包；否则返回 `{ok:false, kind:'unknown-token', tag}` 并在 `selfCheck` 期即报错。**把「判负」改成「判错」**，让静默死锁变成响亮的构建期故障。
  2. **语义收编**：`未用法宝 / 未请救兵` 升格为 `_KNOWN` 已知模式，判定源指向**既有实现**而非新造状态（`requireNoTreasure` 结算侧见 game_event_4.js:176-182，旗标范式见 game_event_3.js:615-617 的 `d6Ni/d22Refuse/fuxinwang`）；`第N难逆` 收编为 `^第(\d+)难(逆|渡|缘|战|夺|隐)$` → 读 `s.flags['d'+N+'Ni']`；顺带把 :282 的三条硬编码前缀（`第3打选渡 / 助讨龙筋 / 问九世因`）迁入正则，删除隐式真源。
  3. **单一真源**：注册表 `HIDDEN_JOBS[*].cond` 与节点级 `TRIAL_LIB[n].hidden.cond` **取其一**——建议以注册表为真源，节点仅存 `{hero, job}`，判定时用 `hiddenJobEntry(hero, job)`（:450-459）回查 cond。可一并消灭 D4（cond 零消费）与 §1.4 末列 2 例漂移。
- **目标值**：`unknown-token` 计数 = **0**；REG/NODE 同名职 cond 不一致 = **0**（现 2）；:282 式硬编码前缀 = 0。
- **落点**：`js/data_trials.js:269-423`（重点 :282、:412-421）；`js/game/game_event_2.js:407`；`js/game/game_event_3.js:615-617`；`js/game/game_event_4.js:176-182`。
- **验收门禁**：新增 `scripts/_verify_job_cond.js`（并入 `npm run check` 的 `smoke:hidden`）——① 45 条 REG cond + 13 条 NODE cond 全部可解析（每 token ∈ {_KNOWN, `lootById`, 材料投放集}）；② 同名职两源一致；③ 每条 cond 均可被某个可构造状态判 `ok:true`（以 `.tmp/_probe_s04b.js` 为蓝本）；④ `wk_chibang` 7 步全部可达。
- **风险**：改判语义会使旧存档里「因宽判而通过」的路径变严 ⇒ 必须保留 `isAwakened` 直承通道（game_event_2.js:495-497 已有），**已觉醒者永不受新门槛影响**。
- **优先级**：**P0**（不做则其余皆无意义）。

### O2 · 补齐断链：`齐天·大圣` 与 `六耳·残`（**P0**）

- **问题**：唯一种子在零消费的 `RETURN_TRIALS`（trials_return.js:244）；`六耳·残` 前置判 `isAwakened('齐天·大圣')`（:352）⇒ 连锁锁死；成就 `h_wk_great`（achievements.js:41,141）、卷十五 `nb_shuang`（:306）与旗标 `liuerUnlocked` 永不可得。
- **方案**：在**正传 难45（真假美猴王）或难46** 节点补 `hidden:{hero:'wukong', cond:'逆 + 紧箍 + 夺宝≥1', job:'齐天·大圣'}`（与注册表 `trial:45` 对齐）；**保留** `d22Refuse` 免紧箍特例（game_event_2.js:526）。若倾向「零新增内容」，退路是把 `RETURN_TRIALS` 以二周目返程接入（即 O8），但那是 P2 工程，不可作为 O2 的唯一解。
- **目标值**：两职在正传各存在 **≥1** 条可达种子；依赖闭包断言：任一职的前置觉醒职必须有正传入口（现缺 2）。
- **落点**：`js/trials_ch5.js`（难45/46 段，写法参照 :31 / :131 现有种子）；`js/data_trials.js:58`、:351-354。
- **验收门禁**：O1 的 ④ 扩为「全部 45 职的觉醒依赖图无孤点」。
- **风险**：难45 的 `held:['liuer']` 若在该难并不掉落，只是把 cond 死锁换成 held 死锁 ⇒ 落地前先跑 held 掉落核对（可扩 `_verify_hidden_jobs` R1 范式）。
- **优先级**：**P0**。

### O3 · 职业加成封顶口径并入 S18 全局表（**P0**）

- **问题**：`JOB_BONUS_CAP` 只封 4/9 键、且只封 `ti`（§1.5 / D8）；全 45 职理论叠加 `dr +1.10`、`eva +0.47`；明线 `tierBonus` 可给出 `drPlus 1.014`。
- **方案**：`JOB_BONUS_CAP` 补键，`mergeJobBonus`（:718-745）把 `yuan` 桶纳入同轮封顶，末段统一交回 S18 的面板夹取函数，**不在本系统重算**。

  | 键 | 现值 | 提案上限 | 备注 |
  |---|---|---|---|
  | `dr` | 无界 | **0.35** | 与 S18 坦度总封顶 0.55 协调，余量留给装备/等级 |
  | `eva` | 无界 | **0.35** | 实测叠加可达 0.47 |
  | `cri` | 无界 | **0.30** | 与被动 `criBonus`（顶 0.10）分池，合计交 S18 面板夹 |
  | `mdef` | 无界 | **0.35** | — |
  | `spd` | 无界 | **12** | 影响出手序，须与 S18 节奏曲线联动 |
  | `yuan.*` | **不封** | 与 `ti` 同规则 | 现 `matk123`（ts 链尾）为无封底样本 |
- **公式**：`final_k = min(CAP_k, Σ bonus_k)`，`k ∈ {ti, yuan}`；明线 `drPlus` 与暗线 `dr` **合并进同一 DR 通道后再夹**，杜绝两系统各自封顶。
- **落点**：`js/data_trials.js:492`、`mergeJobBonus :718-745`；`js/attr_calc.js:325-327`、`:344`；`js/combat_part1.js:484-489`。
- **验收门禁**：探针升级为常驻 `scripts/_verify_job_cap.js`——枚举「全 45 职 + 六系三转」极端态，断言各键 ≤ 提案值且 `DR_total ≤ S18 封顶`。
- **风险**：**削弱老存档数值**（`awakenedJobs` 持久化 ⇒ 全觉醒玩家变弱）⇒ 须以补偿曲线对冲（上调 `JOB_LEGACY_PCT` 或给链尾机制性奖励），并在 02_耦合矩阵登记补偿项。
- **优先级**：**P0**。

### O4 · 装备 `style` 标签落地，激活 2.4 权重（**P1**）

- **问题**：`STYLE_W.EQUIP = 2.4` 恒 0（D5 / §1.6），流派轴最高权重空转。
- **方案**：给装备池**分批**补 `style` 字段——先覆盖「主角本命件 + 各章末 Boss 掉落 + 套装件」（约 60-90 件，占常用池主体），未标注件走 `BASE` 底色；同时在 `styleSourcesOf`（data_jobspec.js:538+）UI 显示「装备」行贡献，让「改了就有反馈」。
- **目标值**：`EQUIP` 非零触发率 ≥ 60%（代表性存档抽样）；10 流派各自「可被装备驱动」件数 ≥ 4。
- **落点**：`js/equipment_part1.js` / `part2` / `part3`（数据）；`js/data_jobspec.js:383-389`、`:472-514`（消费）。
- **验收门禁**：扩展 `_verify_jobspec`：断言「非底色信号源 ≥2 类」，并把 `STYLE_W` 中**现网零触发**的键从注释升级为红牌失败。
- **风险**：补标签会改变既有玩家的显影流派（回归敏感）⇒ 仅新一周目生效，或用 `jobStyleHint` 明示变化。
- **优先级**：P1。

### O5 · `behGate` 行为口径真实化（**P1**）

- **问题**：`behType/behUnit`（「正面击溃 精英」）仅文案（D6，zhuanjie.js:121-129 自述）。
- **方案**：`Z.behavior/accumulate` 改为按 `behUnit` 分类计数（`精英/Boss/救援/夺宝/化缘/放生/抗命`），数据源本已存在（`s._runStats`、`battleFlags`、`setFlag` 一族）；过渡期以「真实行为数 ×0.5 + 旧抉择次数 ×0.5」混算，避免难度断崖。
- **目标值**：每类 `behType` ≥1 个真实计数器；战/夺 `behGate[4,9,15]` 与 渡/缘/隐/逆 `[4,8,13]` 的平均达成难号落在 S18 预期带内。
- **落点**：`js/zhuanjie.js:124-146`、`gateMet/evaluate`；新增旗标落 `js/game/game_event_*.js` 结算处。
- **验收门禁**：`Z.selfCheck`（:515-531）增「behType 枚举 ∈ 已实现计数器集合」；`.tmp` 跑 20 局模拟统计 `currentTier` 分布，与原口径偏差 ≤1 阶。
- **风险**：门槛实质抬高 ⇒ 必须同步复核 `actGate`(3/6/8，逆 4/7/9) 与 `daoGate`(18/28/38)，三闸叠加易过陡。
- **优先级**：P1。

### O6 · 死亡解锁开 `zhuanjie` 线（可达性，**P1**）

- **问题**：`DEATH_UNLOCKS.zhuanjie = []`（D7）；30/45 职的 trial 不在本英雄必经清单，玩家无从规划。
- **方案**：仿 heroes/sutras/events 三线开三档——`1 死`：转职面板显影本英雄全部已知链及进度（只读，`hiddenChainsOf` :778-800 已存在，接上即可）；`3 死`：`HIDDEN_SHUNMING_NEED` 对渡/缘系由 10 降 7；`6 死`：允许**跳步 1 次**（直取下一 `chainStep`，代价 = 该步 bonus 永久缺失），契合 RL2「明码标价」哲学。
- **目标值**：任一隐藏职在开局面板「可见其存在与门槛」比例 = 100%；`zhuanjie` 线三档均有非空实现。
- **落点**：`js/data_reincarnation.js:86-102`；`js/data_trials.js:262-263`、`:778-800`；`js/ui/ui_misc_2.js:690-738`。
- **验收门禁**：断言 `DEATH_UNLOCKS` 五线全部非空且各有 ≥1 真实消费点（现 4/5）。
- **风险**：跳步与 `chainStep` 强顺序冲突 ⇒ 须同时放宽 `jobTier`（:600-636）的链成员聚合判定，否则跳步者会被错判为 `solo`。
- **优先级**：P1。

### O7 · 链尾「第四阶 / 终极觉醒」（深度，**P2**）

- **问题**：`nextJob` 单值 + 明线固定 3 阶 ⇒ 深度分 2.5；竞品有 5 阶段职（L2）。
- **方案**：不给所有职加层，只给 **5 条链的 `chainTail` 职**加「证道 2-3 阶」，以 `JOB_LEGACY` 槽位与命数为货币：`tier4` 需 `chainTail + 该道命 ≥38 + legacy ≥6 槽`；数值复用 `tierBonus` 的 `k=t/3` 曲线延到 `t=4`（`k=1.333`），**必由 O3 封顶表兜住**。
- **目标值**：`currentTier` 上界 3 → 4；理论 `atkPct` 上界不越 S18 规定的单来源占比（登记于 02_耦合矩阵）。
- **落点**：`js/zhuanjie.js:225-248`；`js/data_trials.js:488-489`；`jobTier`（:600-636）。
- **验收门禁**：`_verify_hidden_jobs` R2 扩为「链尾职必有 `awakenTiers ≥2` 定义」；曲线端点与 S18 校验脚本联合。
- **风险**：与 S18 高难段曲线尚未定档相互污染 ⇒ **须等 S18 相关项定档后排期**（跨系统依赖，本文只登记不抢跑）。
- **优先级**：P2。

### O8 · `RETURN_TRIALS` 接入二周目返程（**P2**）

- **问题**：324 行、20+ 难、7 条转职种子零消费（D3）。
- **方案**：二周目以「返程」节点序列复用（文件头注释本就为此预留）；**下策**：删除并把 `齐天·大圣` 等种子迁至正传（即 O2）。二者择一，**不可并存**，否则永远是第二真源。
- **验收门禁**：断言「`RETURN_TRIALS` 消费者数 > 0」或「该符号不存在」。
- **优先级**：P2。
