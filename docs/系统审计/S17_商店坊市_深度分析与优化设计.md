## 〇、执行摘要（TL;DR）

- **系统现状**：坊市是"节点供货（`rollEquips`）+ 金币刷新（三段常量）+ 劫灰坊永久升级（五线）"的**三层经济触点**，双货币（局内 `s.gold` / 跨周 `ash.credits`）。工程上**极薄**：`game_shop.js` 全文仅 54 行、`buyShop` 12 行、无出售分支、无 `BalanceDB` 覆盖、**`scripts/` 66 个 `_verify_*` + 9 个 `_smoke_*` 门禁中零个命中 shop/gold/econ/price**。
- **一句话病根**：**"价格"与"收入"两条曲线由两套互不相干的标尺驱动，且物价那条被三重焊死。** 收入侧吃难度乘子（`rewardMult` 0.8~1.6 × `curseRewardMul` 最高 1.5，[game_combat_2.js:471-498](../../js/game/game_combat_2.js)）并按难号 1~81 线性增长；物价侧只吃一个 5 档枚举、**该档位在难号 12~16 就永久封顶**、且 `act` 轴在四个调用点全部丢失 ⇒ 坊市在前期贵到买不起、在后期便宜到无所谓。
- **五大真问题（全部实测，非旧文档）**：
  1. **act 轴漏传 4 处**（§1.2）⇒ 后期物价恒取第一章价，−26.5%~−28.4%；叠加 `shopPrice` 自身**三重失效**（`act>=10` 死分支 / `min(0.8)` 实际只到 0.45 / 注释写 +8% 实现 +5%）⇒ "V8.41 金币轴决断"这条设计**从未生效过一天**。
  2. **档位价早饱和 + 两极化**（§1.4）：`priceTier` 由 `1+floor(d/4)+_rand(0,1)` 钳在 1..5，d=16 即触顶，此后 **65 个难号物价恒 48 金**；20 局 194 个坊市直方图 **t5 占 73.7%、t2 占 19.6%，中间三档合计仅 6.7%，t1 = 0**。
  3. **定价真源分裂**（§1.6）：作者给 162 件钱套商品标了 `cost`（价域 40~13,904，中位 4,954），但 `item.cost` 全仓**零消费点**；实收一律 36~48。设计斜率 156.7× 被压平成档位斜率 1.50×；价目顶 = 实收的 **290 倍** ⇒ "坊市购"作为获取通道在数值层是**象征性的**。
  4. **138 件商品是死库**（§1.6）：`tierOk` 排除全部 T2/T3 成品（108 件）+ `chapterOk` 的 `cap` 全局最大只到 4（`regionToTier`）排除 T1·ch5-9（30 件）；而 `RECIPES.out` 对这两批**零命中**、`equipment_part3.js:910` 又明文把 `cost` 件排除在掉落池外 ⇒ 盘缠 69 + 巡游 69 件**零获取通道**，其中含 54 件红装（S03 称"红装最大来源是买"，实测买不到）。
  5. **折扣体系三处承诺、一处生效**（§1.8）：朝代 `shopDiscount`（还要"已通关"且当前朝代为商，十世仅 1 世，通关即重置）、盘缠套 `goldPct/shopDiscount`（`combat_part1.js:367-368` 只塞进面板、**零消费者**）、每日"版本庆典" `shopDiscount:0.8`（零消费、`ui_daily.js` 也不展示）⇒ 同轴唯一被接线的是巡游 `nodeGold`（`game_core_2.js:121-128`）。
- **竞品一句话结论**：STS1 商店是**构筑节奏的泄压阀**（价格随稀有度 + 随 Act +10%、删卡费 75+25n 递增、五种遗物改写商店规则），STS2 更进一步把**价格钉进种子**（`PlayerRng.Shops`）并用 A6 Inflation 把删卡抬到 100+50n；ETG 用 **Sell Creep 回收 45% base cost** 给"弃牌"标价、并把**局内币与跨局币彻底分离**（Money vs Hegemony Credit）。本作**多出了"刷新涨价封顶 + 合成抢占货架"两个竞品都没有的结构**，但在**"稀有度定价"、"构筑泄压阀"、"物价随进度膨胀"三件商店的本分上全部缺位**。
- **优化优先级**：**P0 = O1（补 act 同尺）+ O2（抽 `shopNodePrice` 单入口消折扣分叉）+ O3（接 `cost` 为定价真源，与 S18 难度曲线同尺）**；P1 = O4（经济↔难度同标尺）+ O5（新增回购/移除泄压阀，兑现 `ui_panel_2.js:1607` 的承诺）+ O6（钱套可达性：改 `cap` 或开专属货架，激活 138 件死库）+ O7（新建 `_verify_shop_economy` 门禁 + 修 `_verify_treasure_lux.js:62` 空断言）；P2 = O8（`priceTier` 分布重定标）+ O9（rng 归一）+ O10（件数/文案一致性）。

**后果不是"显示≠成交"，而是"同一店内价格口径互相矛盾"**：

1. 玩家站在商朝坊市，初架 43 金（有折扣）；点一次"刷新货架" ⇒ 新货 **58** 金（无折扣 + ×1.2），**比刚看到的贵 34.9%**；若再点"暂不炼化"退出合成页，复开货架是 **48** 金（+11.6%）。三条路径三个数，且**没有任何一处注释说明这是有意的**。
2. 显示与成交**同源**（`ui_panel_2.js:1309` 渲染 `e.price`），UI 预告价用的 `_rrUsed+1` 与成交的 `next=used+1` 在点击时点一致 ⇒ 无 off-by-one。**任务书给的"显示价≠成交价"这条线索经实测不成立**，如实更正。
3. `act` 漏传 ⇒ `actMult = 1 + min(0.8, 1×0.05) = 1.05` **恒定** ⇒ 价目永远等于第一章：`32/36/40/44/48`，而设计意图（补 act 后）act9 应为 `44/49/55/61/67`。**tier 越贵缺得越多**（tier5 −28.4%）。

### 1.3 `shopPrice` 自身的三重失效（补齐 act 也仍有两个坑）

```js
// js/events_part2.js:66-71（原文）
NDX.shopPrice = function (tier, act) {
  const base = 30 + (tier - 1) * 4;
  // 地区加成：每地区+8%，后期（地区10+）+15%，避免金币通胀      ← 注释与实现不符
  const actMult = 1 + Math.min(0.8, (act || 1) * 0.05) + ((act || 1) >= 10 ? 0.15 : 0);

};
```

### 1.4 价格档早饱和与两极化（20 种子忠实转章实测）

`priceTier` 唯一生产公式（[data_equipment.js:167](../../js/data_equipment.js)）：

```
tier = clamp(1 + floor(d/4) + _rand(0,1), 1, 5)     d = diffOfLayer(layer) ∈ 1..81
```

- **封顶极早**：无 `_rand` 上浮时 d=**16** 触顶；含上浮最早 d=**12**。此后 **65~69 个难号档位恒 5 ⇒ 实收恒 48 金**。
- **`t1` 永不可得**：`d<=5` 时 shop 直接退化为 mob（`:162-165`），而 `d<=5` 恰是 t1 唯一可能出现的区间 ⇒ 直方图 **t1 = 0**。
- **两极化**：20 局 × 全图共 **194 个坊市** ⇒ `t5 73.7% / t2 19.6% / t4 3.6% / t3 3.1%`，**中间两档合计 6.7%**。玩家对"档位"的感知坍缩为"贵档/便宜档"两种。
- **模板恒档**：`MAP_PLAN` 第 6 行 `{type:'shop', diff:6, priceTier:2}`（[data_map_plan.js:17](../../js/data_map_plan.js)）被 act2~9 **整行复用** ⇒ 终章也照样摆 36 金档；`MAP_PLAN_CH1` 全表 **10 行无一个 shop**（`:40-51`）。
- **最早出现**：20 局首个坊市所在全局层最小值 = **L7**（与 `d<=5` 退化 + 模板 L6 一致）；**0/20 局全章无市**（旧审计"0.2% 金流无出口"所指的 V8.58 前形态已不存在）。

**三张量化结论**：

1. **双标尺打架**：同一层位的普通宝窟与秘藏宝窟，一个按 layer(1~62) 运行时算、一个按 diff(1~81) 建图时算死 ⇒ L=62 处实测 **452 vs 906 = 2.00×**，而 `TREASURE_LUX_GOLD_MUL` 的设计值是 **1.6**（`:138`）。且门禁 [scripts/_verify_treasure_lux.js:41-62](../../scripts/_verify_treasure_lux.js) 的金币断言 `luxAvg > lowAvg*1.2` 里 `lowAvg` **恒为 0**（因为 `_sideNode` 给普通宝窟**根本不写 `gold` 字段**，`:148`）⇒ 该断言恒真，是一条**空门禁**。
2. **出口远小于入口**：20 种子实测单局坊市 **9.70 家**、全图 175.8 节点、shop 占比 **5.52%**。单家满购满刷（2 件 + 2 次刷新 + 新货 2 件 + 遗物残片）= **300 金**（`probe6 §4`）⇒ 九章坊市总出口 ≈ 2,955，占收入粗模（≈ 7,990，`probe7 §4`，含九章 Boss 破韧）的 **37.0%**；加上神龛 1,050 也才 **50.1%**。**试玩（act1-3，`DEMO_MAX_ACT=3`）更极端**：avg 2.55 家 ⇒ 出口 765 = **9.6%**，其余金币无处可花。
3. **收入侧与难度同尺、物价侧完全不与难度同尺**：地狱档相对简单档，收入 ×(1.6/0.8)=2.0，再叠满咒 ×1.5 ⇒ **≈×2.4**；坊市物价 ×1.0（`shopPrice` 无难度入参）⇒ **高难下坊市相对便宜约 58%**。这与 S18"难度换回报"的正向闭环恰好反相：难度越高，构筑的"购买阻力"越低，商店作为节奏闸门的强度被难度选择**单方面取消**。

## 三、竞品机制对机制（本轮 wiki 实抓）

### 3.1 Slay the Spire 1 · The Merchant

- **货架结构固定**：5 张职业卡（恒 **2 攻 / 2 技 / 1 权能**）+ 2 张无色卡（恒 1 罕见 + 1 稀有）+ 3 瓶药剂 + 3 件遗物（最右槽**恒为商店专属遗物**，是取得它们的唯一途径）+ **1 次删卡服务**；其中随机一张卡 **50% off**。
- **价格按稀有度分层——这就是商店的定价真源**：普通卡 **45-55** / 罕见 **68-83** / 稀有 **135-165**（最高档 ≈ 最低档 **3.0×**）；无色卡**再加价 20%**（81-99 / 162-198）；遗物 143-158 / 238-263 / 285-315；药剂 48-53 / 71-79 / 95-105。
- **价格随难度膨胀**：**Ascension 16 起全线 +10%**（普通 50-61、稀有 149-182）。关键是它乘在"**稀有度基准价**"上，不是乘在随机档位上。
- **删卡服务：75 起、每买一次 +25**（同一次商店限 1 次）⇒ 全游戏唯一"递增付费"，而它买的是**做减法**（构筑泄压阀）。
- **没有付费刷新**：想换货只能靠遗物 **The Courier**（买走即补货 **+ 全线 −20%**，商店遗物不补）⇒ 在 STS 里"重抽"是**遗物奖励**，不是**金币税**。
- **五件遗物直接改写商店规则**：Membership Card（−50%）、Smiling Mask（删卡恒 50 且不再递增）、Maw Bank（每层 +12 金，但**一进商店就永久失效**）、The Courier、Meal Ticket（进店回 15 HP）。⇒ 商店是**遗物价值的兑现场所**，不是仓库。

### 3.2 Slay the Spire 2 · The Merchant（EA V0.103.2）

- 结构沿用，价格重标：普通 **48-53** / 罕见 **71-79** / 稀有 **143-158**；无色加价降到 **15%**；遗物 149-201 / 191-259 / 234-316，商店遗物 170-230；货架仍"不打升级"（除非持 Toxic Egg）。
- **删卡 75 起 +25/次**；**Ascension 6「Inflation」改为 100 起 +50/次**——v0.102.0 补丁把 A6 从 Gloom（少休息点）**整个换成专挑经济下手**的 Inflation，说明作者认为"高难下商店太便宜"是顶级难度必须亲自动手的问题。
- **产金遗物被逐出商店池**：黑名单 Amethyst Aubergine / Bowler Hat / Lucky Fysh / Old Coin / The Courier；v0.100.0 补丁原话"能产金币的遗物不再出现在商人处"⇒ **禁止"用金币买回金币"的正反馈**。
- 另有 Lord's Parasol（进店自动买光一切）、Foul Potion（扔商人身上换 100 金）等"规则破坏件"，购买失败话术分"没钱 / 没槽 / 禁买"三套。
- ⚠ **对标本作最关键的一条**：本作**盘缠/巡游（纯产金套）恰恰是"坊市购"专属商品**，且作者标价 40~13,904、实收 36~48 ⇒ 等于**用 48 金买一条永久产金流**。STS2 专门打补丁消灭的结构，本作是**默认结构**（现在只因 `goldPct` 未接线而侥幸未爆）。⇒ 它是 O6-③ 的**硬前置**。

### 3.3 Enter the Gungeon · Bello 商店

- **每层几乎必有店**（Forge 由铁匠替代）；主柜台**恒 3 个随机补给** + 额外 **0-3 件**商品，三个额外位填充率 **95% / 50% / 20%**（每位再各 20% 概率被替换成补给）；副圆桌最多 4 格（Blank / 玻璃 Guon 石 / 地图，单格空格率 **48.98%**）；**恒至少 1 把钥匙在售**。
- **商店池 ≡ 全解锁池**：" unlike other merchants, Bello's shop is **not limited to a loot pool**"——任何已解锁物品/枪都可能上架（仅 Ser Junkan 例外）⇒ **商店的功能就是给图鉴一条付费定向通道**。
- **品质分布随楼层右移，但价格不随楼层变**：AG&D 规则 1 层 60/30/10/0/0 → 4 层 20/30/30/20/0；**最高阶恒 0%（店里永远买不到顶阶）**；每件商品售价 = 它自己的固定 base cost。
- **回收通道 Sell Creep**：商店副区（Annex）按权重随机 NPC，Sell Creep 权重 0.5（全解锁口径 ≈ **30.21%** 出场），**丢弃物按其 base cost 的约 45% 付金币**（Active Item 须先丢地上才能卖）；**新档唯一能遇到的副 NPC 就是它** ⇒ 游戏把"弃置"当作商店教学的第一课。
- **跨局钩子挂在局内商店里**：Glass Case 的 Gnawed Key **1,000 金**、可**跨局分期付款**，首次付清后永久降到 **115**；Prime Primer 110。
- **反经济设计**：Clown Mask / Drill / Loot Bag 未解锁前 5% 上架、标价 **9,999** ⇒ 故意"买不起"，逼玩家用偷窃/引 Lord of the Jammed 等非常规手段；偷窃被抓 Bello 本局离店。
- **货币分离**：局内 Money（商店消费）/ 跨局 Hegemony Credit（解锁）彻底两轨——本作 `s.gold` / `ash.credits` 结构同构。

### 3.4 更正任务书假设："STS 刷新费递增"不存在

实抓两代 STS 商人页：**都没有付费刷新/重抽**（唯一的"补货"是 The Courier 遗物，而且它还**降价 20%**）。真正的"递增费"是**删卡服务 75→+25/次**（STS2 A6 = 100→+50）。付费刷新递增的正解在 **Balatro**：**刷新费 $5 起、每次 +$1、进新店重置**（Reroll Surplus 使每次刷新 −$2）。⇒ 本作坊市"30 金 ×2 次封顶 + 货价 ×1.2"是**两家的杂交**（有限次递增税 + 涨价转嫁），骨架不坏；坏在**它挂在"档位价"这条假轴上**（§1.3），以及**刷新后不吃折扣**（§1.2 同店三价）。O10b 会把"刷新费"与"货价"两条曲线拆开重定标。

- **问题**：D7。`tier = clamp(1 + floor(d/4) + _rand(0,1), 1, 5)`（[data_equipment.js:167](../../js/data_equipment.js)）在 **d=16 触顶**（含 `_rand` 最晚 d=12），此后 **65 个难号物价恒 48**；194 家坊市直方图 **t5 73.7% / t2 19.6% / 中间三档合计 6.7% / t1 = 0%**。另一条成因：[data_map_plan.js:17](../../js/data_map_plan.js) 把模板行的 `priceTier` **写死为 2** 且 act2-9 整行复用 ⇒ “货郎”永远卖第二章价。
- **目标值**：除数从 `4` 改为 **`16`**（`1 + floor(d/16) + _rand(0,1)`）⇒ 五档在 d=1..81 上**均匀右移**，目标各档占比 **12%~32%**、t1 不为 0、t5 不超 40%；模板行改为 `priceTier: null`（表示“交给工厂现算”），不再跨章复用硬编常量。
- **落点**：`data_equipment.js:159-168`（公式）、`data_map_plan.js:10-53`（模板档位字段）、`game_core_2.js:908`（确保读到节点档位而不是默认值）。
- **验收门禁**：probe8 重跑 20 种子 → 五档占比均入 **[12%, 32%]**；`grep -n "priceTier" js/data_map_plan.js` 不再出现硬编 `2`；与 O7 第 5 项一致。

### O9【P2】rng 归一：转章建图播种 + 建图期随机切播种流

- **问题**：D11。开局 `withSeed(seed, ()=>generateMap(1))`（[game_event_1.js:11-17](../../js/game/game_event_1.js)），但转章 `NDX.generateMap(s.act)`（[game_region.js:214](../../js/game/game_region.js)）**在作用域外**；`data_seed.js:60-61` 注释自认“`withSeed` 仅约束地图布局”。实测（probe8 §2）：同种子下“仅 ch1 播种 vs 全章播种”的**坊市数量与档位分布 10/10 组不同**⇒ **真正会出高价坊市的地方（ch≥2）完全不可复现**，“种子分享”分享不了商店。另有三种随机源并存：裸 `Math.random`（`_rand`/`_pick` 见 `data_seed.js:10/12`；`data_equipment.js:137/153/163`；`game_loot.js:26/33/68`）、`runRandom()` 播种流（`rollEquips` 主链 `:544/581/586/594`）、`withSeed` 全局替接。
- **目标结构**：① `generateMap` 的每次调用（包括转章）都包进 `withSeed(derive(seed, act))`；② 建图期随机（含 `priceTier` 与 shop/rest 退化判定 `:153/:163`）从裸 `Math.random` 切到 `runRandom()`；**战斗过程随机保持不播种**（尊 `data_seed.js:65-66` 已定的设计边界）。
- **落点**：`game_region.js:214`、`game_event_1.js:17`、`data_seed.js:58-67`（注释同步更新）、`data_equipment.js:137/153/163/167`。
- **验收门禁**：**probe8 §2 从“10/10 组不同”变“10/10 组相同”**（直接可执行，无需新工具）；同种子两局的坊市档位序列逐位相等。
- **优先级 P2（但若要做“物价类门禁回归”，不先修它测试结果不可重现）；回归风险：中**——换随机源会改变地图分布，需重跑全量地图类门禁（`_verify_*` 中涉及 `generateMap` 的项）。
