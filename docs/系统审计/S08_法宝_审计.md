## ① 当前游戏内容（代码事实）

> 硬规则：每条数值/机制必须带 `file:line` 或 BalanceDB 键；无证据者移入 §⑥。

### 1.1 核心循环
法宝以「主动祭出 / on-hit 常驻 / 夺宝进化」三条子循环驱动，容器同为 `s.equips`（法宝件带 `treasure:true`+`treasureId`）：

1. **获取**：① 关隘 Boss 三选一「唯一」发放 `NDX.bossRewardsFor(hero, act)`（`equipment_part2.js:353`，按章返回全新克隆重置充能 `:355`）；② 三/四章逆道开放追加金色法宝 `goldenBossTreasureFor`（`:361`，逆道劫印 `ni` 者四选一红阶真器 `:368`）；③ 随机/坊市/事件走 `rollEquips`（`data_equip_core.js:503`）。发放点在 `game_combat_1.js:318/328`、`game_combat_2.js:308-312`。
2. **祭出（主动）**：`phase:'in'/'both'` 战斗中可祭，`'out'` 非战斗化缘，`'dead'` 败亡自动替劫；充能 `charges`/`chargesLeft` 用尽即废（`equipment_part2.js:413-414` 语义注释）。AI 自动祭宝限 `aiCanAuto`（`:382`）——仅 `low` 阶（非 `bf_` 前缀）且 `in/both`（`:385-387`）。
3. **on-hit（被动）**：6 件西游名器 `phase:'passive'`、`auto:true`、`charges:0`，普攻命中按 `proc` 概率触发，不耗充能、不入祭宝列表（`equipment_part2.js:427-460`）。结算入口 `NDX.applyTreasureOnHit`（`combat_part2.js:536`）。
4. **进化（夺宝线）**：持 T0 至宝 + 对应道累计达标 → `NDX.tryEvolveTreasures`（`data_treasure_evo.js:253`）在每次劫难结算后（`game_event_2.js _afterChoice`）把原宝 `splice` 替换为顺命/逆命特殊装备（`:268-273`）。
5. **反馈**：on-hit 触发时压 `rd.onHitFx` 供 `main.js` 出飘字（`combat_part2.js:570-575`，`ONHIT_FX_LABELS:508`）；进化成功 `pushLog`+`toast`「至宝圆满」（`data_treasure_evo.js:275-277`）。

### 1.5 边界与异常
- **先收集后一次性结算**：`applyTreasureOnHit` 显式「先收集、后一次性结算：避免同击/窗口内逐回合重掷造成的重复叠乘」（`combat_part2.js:551/621`）——多源减伤取最小乘数（最强）`:582`。
- **Boss 控制弱化**：`stun/silence` 对 Boss `_bossDur=min(2,n)`（`:548/590`），`silence` 只减半伤害（`×0.5`）、`stun` 归零（`:593`）；减伤类（shrink/slow/reflect）保留 `SHRINK_FLOOR0.30` 地板防 Boss 变木桩（`:628`）。
- **rng 不一致**：`applyTreasureOnHit` 的触发判定用裸 `Math.random()`（`combat_part2.js:567`），`applyTreasureStatus` 的 `rng` 缺省亦回退 `Math.random`（`data_skill_variant.js:105`）——两者均**不吃整局播种**（见 §1.7）。
- **进化幂等 / 断链保护**：`tryEvolveTreasures` 逐件命中即 `break`（一宝一只进化一条支线 `:280`），`lootById(e.id)` 取不到则 `continue`（`:272`），进化后 `splice` 原位替换避免重复入档（`:273`）。
- **退役可逆留档**：`T1_RETIRED` 11 件「定义仍在 T1 数组留档、不物理删除」（`data_treasure_evo.js:47`），`TREASURE_RETIRED` 导出供门禁核验「退役件确实不在池内」（`:236`）。
- **字段兼容双写**：`treasureStatusSources` 同时扫 `gear/treasures/held/equip` 四字段「兼容两套存档字段」（`data_skill_variant.js:87`），字符串或对象 id 均可（`:89`）。

### 1.6 跨系统接口
- **法宝 → 状态 → 技能（主链）**：`TREASURES` on-hit → `data_skill_index.js` `TREASURE_STATUS`（`:69`）→ `applyTreasureStatus` 挂 `STATUS_DEFS` 状态（`data_skill_variant.js:103`→`data_skill_index.js:50`）。→ 见 [耦合矩阵 §1.5](02_耦合矩阵与数值口径登记表.md)。
- **法宝 → 六道（S06）/经文**：`TREASURE_SYN.daoMatch` 比对玩家 `ctx.playerDao`、`sutraMatch` 比对 `ctx.sutraDaos`（`combat_part2.js:563-566`）；进化门槛读 `s.fate[dao]` 与 `DaoSystem.calcDaoStats`（`data_treasure_evo.js:265-267`）。
- **法宝槽位 → S03 owner**：`isActiveTreasure`/`treasureCaps`/`SLOT_CAP.treasure` 归装备侧 `equipment_part3.js`（`:394/424/170`），本系统仅消费。→ [耦合矩阵 §1.3](02_耦合矩阵与数值口径登记表.md) 与 S03 §1.6。
- **法宝 → 经济/善念**：紫金钵 `effect.evil` 增减善恶值（`equipment_part2.js:472/479/485/492`），`weakNext` 降下一战难度（`:485`）——经 `useItem`（`game.js`）消费。
- **法宝 → 战斗结算底座**：`applyTreasureOnHit` 回补 `res.roundsDetail`（`combat_part2.js:639` `_bumpHp`），最终并入 `computeStats` 结算流（[耦合矩阵 §二](02_耦合矩阵与数值口径登记表.md)）。

### 1.7 已知债务与死区
> ⚠ 以下均为**实测代码债务**，本审计只登记不改码。

1. **【双真源·潜在分叉】`TREASURES` 库 vs `EQUIP_POOL`**：法宝条目既定义于 `equipment_part2.js:426` 的 `NDX.TREASURES`（运行时祭出/AI/克制读此），又经 `rollEquips`/`BOSS_REWARDS`/夺宝 `POOL`（`data_treasure_evo.js:238` `EQUIP_POOL.concat`）流入装备池；BalanceDB `slot:'treasure'` 203 件与 `TREASURES` 93 条**数量级不同**（前者含进化产物/仿品/特殊装备），两处无引用联动，`treasureId` 若单侧改名即静默失联。
2. **【门禁缺口·数值漂移风险】on-hit `proc` 具体值未锁进门禁**：`TREASURE_SYN` 四系数被 `_verify_treasure_synergy` 写死断言（`combat_part2.js:526-528` 注释），但 6 件名器**各自的 `proc` 值（0.18~0.30）本身**仅靠注释「具体 proc 未被门禁锁死，故本轮只做审计不改数」（`:430`）声明自洽——无自动拦截，手改 `proc` 不会触发失败。`_verify_treasure_onhit` 探针存在（`scripts/_verify_treasure_onhit.js`）但是否逐值断言待核（§⑥）。
3. **【rng 不一致】** on-hit 触发（`combat_part2.js:567`）与法宝状态注入（`data_skill_variant.js:105`）均用裸 `Math.random()`，破坏 seed 可复现性；与 `rollEquips` 主链统一走 `runRandom()` 相悖（见 S03 §1.5）。
4. **【`phase` 语义分散】** 祭出时机 `phase` 有 `out/in/both/dead/passive` 五态，判据分散在 `aiCanAuto`（`equipment_part2.js:387` 只认 in/both）、`isActiveTreasure`（`equipment_part3.js:394`）、`useItem`（game.js）多处，无常量枚举，新增态易漏改。
5. **【T1 rationale 与实值脱钩】** `data_treasure_evo.js:15` 注明 `atk=12+章*1.6` 等生成公式，但 `T1` 数组（`:17-39`）第 3 元素实为**难号（trial）**而非数值，真正件值由 `mk`/生成段（`:~200-231`）产出；rationale 注释与数组语义不完全对齐，读者易误读 `12`/`13` 为 atk（§⑥待核生成段实际输出）。
6. **【退役留档悬挂】** 11 件 `T1_RETIRED` 仍在 `T1` 数组物理留存（`:41-61`），靠 `POOL` 生成时过滤（`:46`）；若消费方直接遍历 `T1` 而非 `POOL`/`DUO_TREASURE_POOL`，退役件会重新泄漏入池。
