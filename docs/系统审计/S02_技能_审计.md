## ① 当前游戏内容（代码事实）

### 1.1 核心循环
- **三键出手 → 变体收口**：玩家在 `combat_active.js` 触发 atk/chant/ult 任一键 → 构出基础 `act` → 调 `NDX.resolveSkillAct(act, kind, ctx)` 逐层加工 → `applyActiveIntervention` 落到回合结算。接线点 `../../js/combat_active.js:51`(atk)、`:190`(chant)、`:273`/`:295`(ult)。
- **三层收口（V9.55）**：层一元信息（图鉴）/ 层二数值真源（`STATUS_DEFS`…`ULT_STYLE_MOD`，**只在此定义**）/ 层三顺序真源（`SKILL_ORDER` + `SKILL_LAYERS` + `resolveSkillAct`）。设计动机见 `../../js/data_skill_index.js:5-15`。
- **变种来源**：无独立"选变种"UI；变种 = 隐藏职流派的表现层（`JOB_STYLE_VARIANT`），未转职⇒`plain`，转职瞬间三键形态即变。`../../js/data_skill_index.js:218-259`。

### 1.5 边界与异常
- **幂等回归防线**：`resolveSkillAct` 用 `act._skillDone[layer]` 逐层登记，同层同 act 永不执行两次——直接针对 V9.54「同一变体应用两次」缺陷（note 不重复拼接、加法字段不翻倍）。`../../js/data_skill_index.js:384,399-407`。
- **单层异常隔离**：`try { layer.run(...) } catch (e) {}`——单层异常不得拖垮整条三键链路。`../../js/data_skill_index.js:407`。
- **顺序即数值正确性**：`variant` 必须排在 `sutra` 之后（"舍攻为盾"抹 dmg，若经文 dmgMul 先加再归零会白吞整层收益），故 `SKILL_ORDER` 固定「…→sutra→variant→treasure」。`../../js/data_skill_index.js:298-302`。
- **rng 可注入**：`c1.rng`（V9.64）透传给 `jing` 层与 `applyTreasureStatus`，生产不传则回退 `Math.random`，门禁可 stub 概率分支。`../../js/data_skill_index.js:369,397`；`../../js/data_skill_variant.js:105`。
- **未知 op 静默跳过**：`applyActVariant` switch `default: break` + 外层 try/catch，"变种绝不拖垮战斗"。`../../js/data_skill_variant.js:71,74`。
- **multi 变体数值纠错**：旧数据 `dmg×0.42 + hits3` 实为净削 58% 却写"×1.15"，V9.55 按"总量 ×1.15 拆 3 击"重写口径（对齐 `combat_active.js:366` 分摊语义）。`../../js/data_skill_index.js:139-146`。
