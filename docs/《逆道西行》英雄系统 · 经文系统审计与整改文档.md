## 二、问题清单（按严重程度排序）

### P0 · 崩溃级

#### P0-1 `combat.js:559` 引用未定义变量 `deal` → ReferenceError　**【已修复 2026-09-12】**

**位置**：`enemyAttack()` 内，命痕·万劫结算分支

```js
// 修改前（崩溃）
if (F('lowHpReflectMult') && pHp > 0 && pHp <= pTi.maxHp * 0.35 && deal > 0) {
  const extra = Math.round(dealt * (fate['lowHpReflectMult'] - 1 >= 1 ? 1 : 1));
// 修改后（已落地）
if (F('lowHpReflectMult') && pHp > 0 && pHp <= pTi.maxHp * 0.35 && dealt > 0) {
  const extra = Math.round(dealt); // 低血追加一段等值反伤
```

**问题**：`deal` 在 `enemyAttack()` 作用域从未定义（正确名 `dealt`）；560 行三元 `(x-1>=1?1:1)` 两分支恒为 1，废码且未消费 `mechVal`。
**触发**：持有金色万劫劫印（`jieseals.js:78` `mech:'lowHpReflectMult'`）+ 气血 ≤35% + 被命中 → 战斗崩溃。
**修复**：`deal`→`dealt`；560 行化简为 `Math.round(dealt)`（追加一段等值，语义不变）。改动 2 行，无歧义。

### P1 · 数值 / 接线失衡（需实测或复核）

#### P1-1【经文·系统性】`effect` 顶层字段被 `computeStats` 静默丢弃

**影响面**：几乎全部经文（最严重）

**根因链路**：
- `attr_calc.js:273-299` 把每部经 `effect` 原样（主道经经 `_routeDao` ×1.5）塞入 `bonus.sutras`
- `combat.js:113-122` 合并时**只读**：
  - `eff.ti.{atk, hp, dr, eva, cri}`
  - 顶层 `eff.matk` / `eff.mdef`
- **不读**顶层 `dr / crit / eva / reflect / criDmg / maxhpPct / healPct`，也不读 `eff.yuan.hp`

**后果**：`data_sutra.js` 中大量经文将 `dr/crit/eva` 置于 `effect` 顶层（非 `ti` 内）→ **减伤、暴击、闪避几乎全不生效**，玩家无感知。

| 失效字段 | 受影响经文（节选） | 失效值 |
|---|---|---|
| 顶层 `dr`（减伤） | 金刚 0.03 / 华严 0.05 / 阿弥陀 0.03 / 无量寿 0.05 / 圆觉 0.02 / 涅槃 0.06 / 地藏 0.04 / 十善 0.03 / 金光明 0.05 / 仁王 0.06 / 梵网 0.07 / 逆天录 0.06 / 灭世咒 0.05 / 齐天残卷 0.03 | 全部静默丢弃 |
| 顶层 `crit`（暴击） | 文殊 0.06 / 心猿 0.04 / 牛魔 0.03 / 血佛 0.04 / 逆天录 0.06 / 灭世咒 0.05 | 全部静默丢弃 |
| 顶层 `eva`（闪避） | 心猿 0.04 / 牛魔 0.03 / 堕天录 0.06 / 逆天录 0.03 | 全部静默丢弃 |
| 顶层 `reflect`（反伤） | 血佛 0.08 | 静默丢弃 |
| 顶层 `criDmg`（暴伤） | 堕天录 0.15 | 静默丢弃 |

> 对比：若同一经的 `dr` 写在 `ti` 内（如 `SUTRA_COUNT_BREAKPOINTS` 数量加成），则生效。纯属 `data_sutra.js` 写法随机性，玩家无法察觉。

**建议改法 A（推荐·一处）**：`combat.js:113-122` 合并前把 `eff` 顶层数值字段并入 `eff.ti`：
```js
bonus.sutras.forEach((eff) => {
  if (!eff) return;
  const st = Object.assign({}, eff.ti || {});
  ['dr','eva','cri','reflect','criDmg','maxhpPct','healPct'].forEach((k) => { if (eff[k] != null) st[k] = (st[k]||0) + eff[k]; });
  atk += st.atk||0; maxHp += st.hp||0; dr += st.dr||0; eva += st.eva||0; cri += st.cri||0;
  matk += eff.matk||0; mdef += eff.mdef||0;
  // maxhpPct/healPct/reflect/criDmg 需 computeStats 另行扩展或确认结算通路（见 P1-2）
});
```
**改法 B（data_sutra.js）**：把每部经顶层字段移入 `ti`——需改 ~15 部，易漏，不推荐。

#### P1-2【经文·待确认】`maxhpPct / healPct / yuan.hp / reflect / criDmg` 无消费点

**现状**：这些字段既不被 `combat.js:113-122` 读取，也未见战斗结算层专门消费（`reflect` 走 `player.reflect`/`sealFlags`，非经文字段）。
**影响经文**：华严 `maxhpPct:0.04`、法华 `healPct:0.06`、无量寿 `maxhpPct:0.05+healPct:0.04`、观音 `healPct:0.08`、仁王 `maxhpPct:0.03`、梵网 `maxhpPct:0.05`、阿弥陀/观音 `yuan.hp:40`、血佛 `reflect:0.08`、堕天录 `criDmg:0.15`。
**⚠️ 待验证 V3**：确认战斗结算是否另有读取路径。若否，则属静默失效，需随 P1-1 改法 A 一并扩展 `computeStats` 支持（或明确设计意图删除该字段）。

#### P1-3【英雄】善念加成系数与善念量级疑似严重失配

| 英雄 | 字段 | 系数 | 注释宣称 | 一致性 |
|---|---|---|---|---|
| 悟空 | `mercyAtk` | 0.07 | 每点善念体攻 +7% | ✅ |
| 八戒 | `mercyAtk` | 0.06 | +6% | ✅ |
| 八戒/小白龙/沙僧 | `mercyHp` | **0.004** | 宣称 **+4%** | ❌ 差 10 倍 |
| 取经人 | `mercy` | 0.10 | 法伤 +10% | ✅ |
| 沙僧 | `mercy` | 0.06 | 法伤 +6% | ✅ |

**核心疑点**：`mercyHp`(0.004) 与 `mercyAtk/mercy`(0.07/0.10) 量级差 17~25 倍，不可能同时正确。
**善念 `good` 量级**：无上限（`game_event_3.js` 纯累加），单次 +10~+42，无封顶。
**⚠️ 需实测 V1 定方向**：若 `good` 中位数 <20 → `mercyHp` 笔误（应 0.04）；若 >50 → `mercyAtk/mercy` 应下调一个量级（0.007/0.010）。**方向互斥，先实测再动。**

#### P1-4【英雄】反伤按「削力前」伤害计算，与承伤不对称

- 玩家实际扣血：`dealt × 0.5`（combat.js:529）
- 反伤基数：`dealt × rPct`（combat.js:538，用未削力 `dealt`）
**后果**：反伤（沙僧 0.20 / 劫印逆道 / 装备 / 命痕蚀骨）相对实际承伤**系统性翻倍**。
**建议**：反伤基数改用削力后 `preDealt`，或明确为设计意图并同步机制说明。

### P2 · 定位 / 描述 / 数据漂移

#### P2-1 悟空「金睛破甲」描述与实现不符
- 描述：物理出手**无视 10% 护甲**（理解为固定值）
- 实现（combat.js:601）：每回合叠加 10%，**累积至 50% 封顶** → 实际是描述 5 倍。
建议：改描述「每次出手叠加破甲 10%，最多 50%」，或实现改固定值。

#### P2-2 英雄数值横向失衡
| 英雄 | sys | atk | hp | dr | eva | spd | 问题 |
|---|---|---|---|---|---|---|---|
| 悟空 | ti | 180 | **880** | **0.16** | 0.05 | 12 | 被小白龙全面压制，hp+dr 双垫底 |
| 小白龙 | ti | **230** | 1000 | 0.20 | **0.28** | **16** | 六项居前无短板，超模 |
| 沙僧 | yuan | 180 | 1150 | 0.26 | 0.03 | 7 | atk180 是废属性（走法伤） |

建议：下调小白龙 1~2 项；上调悟空 atk 或生存；沙僧 atk 转投 matk/mdef。

#### P2-3 注释与实现不符（次要）
- `data_config.js:86` 注释称取经人法伤由 `mercyAtk` 放大，但 passive 只有 `mercy:0.10`，无 `mercyAtk`。注释应改 `mercy`。

#### P2-4【经文】`SUTRA_SPEC` 数量声明与实际不符
- 声明（data_sutra.js:105-110）：渡 203 片 / 逆 76 片 / 合计 279 片
- 实际（动态生成 `SUTRA_FRAG_NAMES`）：渡 **201** 片 / 逆 76 片 / 合计 **277** 片（渡少 2 片）
- 运行时碎片动态生成，SPEC 仅供文档/审计；若存在 UI/断言引用 `SUTRA_SPEC.ferry.frags` 会显示 203≠实。建议对齐或注明「动态真源在 `SUTRA_FRAG_NAMES`」。

#### P2-5【经文】`routePendingSutras` 死代码 + 措辞偏差
- data_sutra.js:217-235：`rest` 永空，所有待投全本均推入 `sutras/niSutras`（fullId 必能在两表之一找到），`s.sutraBackpack = rest` 恒清空。功能正确（待投全投），但 `rest` 分支冗余。

#### P2-6【经文】重复碎片多扣（资源浪费）
- `grantSutraShard`/`tryCombineNiSutra` 集齐后每片 −1。若玩家集 2 套（每片≥2），合成一次后每片=1 仍≥1，但 `s.sutras` 已含 id 不再合成 → 多余碎片消失。无崩溃，属轻微资源浪费。
