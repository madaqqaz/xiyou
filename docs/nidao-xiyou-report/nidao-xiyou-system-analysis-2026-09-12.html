二、各系统详析

2.1 命运·六道系统 —— 架构收敛完成

  • 零属性范式已落地：六道 s.fate 只作投放池概率偏置（软饱和 w=1+1.5·f/(f+4)），不给属性、不设硬门槛；隐藏职/至宝进化用「命数 OR 劫印道数」软门槛。单一真源 dao_system.js daoPoolWeights，四池（装备/法宝/劫印/经文）同口径叠加接线。
  • 善恶解耦：六道=路径（雷达图），善恶=后果（逐选项签署）；_applyFate 兜底极性规则（渡/缘+善，逆/夺+恶，战/隐中性）。
  • 残留风险：SEAL_RED_MULT=1.55 / SEAL_GOLD_SCALE=4.65 为设计定标值，标记 [PLACEHOLDER·待10局采样]；转职 daoGate 仍读 fate[dao] 硬门槛（GDD 自标「待决」）。

2.2 劫印系统 —— 阶梯重构收口

  • 品质阶梯 白<蓝<红<金：红劫=融合≥3难 / 关隘Boss 双源保底（不掷骰）；金劫唯一来源=三红合金（土地庙），金≡3×红 精确恒等；计层 白蓝1/红2/金3；弃印定价按战力序 6/12/30/45。
  • 来源真源 rollSealTier 收敛 5 文件 6 处散落判定；主道契合度三三成组（战夺逆/渡缘隐）驱动 UI 标签。
  • 门禁_verify_seal_source(55)/pool(42)/alloy(13)/rites(53) 全绿，含反证断言与 4000 次采样。
  • 待办三红合金按钮与红劫三选一 UI 需实机目测；倍率待采样标定。

2.3 战斗系统 —— 三键真源收敛 自动战斗门禁偏严

  • 回合制状态机 INTRO→WAIT→收尾；三键技能（攻/经/绝）唯一定义 combat_active.js；经文=招式包（chantSkill 持诵位，scale∈[0.5,1.5]），仅叠于英雄本命之后、不夺身份。
  • 法宝×经文×六道协同真源 TREASURE_SYN（daoMatch 1.25 / sutraMatch 1.15 / proc 封顶 0.35）。
  • FIGHT_GATE：auto:4 / speed2:1 / speed3:6 / skip:8 —— 自动战斗第 5 难起才解锁，Boss 禁自动；教学与前期强制手动。实测观察：自动战斗开启后 tick 仍频繁出现 fight-auto-toggle 重复触发，自动战斗的回合推进节奏偏慢（每次操作点 awaitOp 强制等待），速刷体验在手机端可能偏拖。
  • 操作点（awaitOp）风险：第 1 地区 deadline:Infinity 无时限；若 UI 因横屏遮挡或模态覆盖导致「跳过/祭宝」按钮不可见，会形成本轮调试中见过的等待型软锁表象——建议给 awaitOp 加保底「放弃本次操作点」入口常显。

2.4 装备·法宝·宠物 —— 标尺已统一

  • 装备 384 词条池，regionToTier（17地区→4档）+ regionToActChapter（17地区→9章）双映射闭合，消除后期装备提前 47 难掉落的膨胀（V8.37 修复）。
  • 法宝六道权重 DAO_FABAO_W 与劫印池同口径；英雄专属装备随章节自动进阶（upgradeHeroGear，幂等）。
  • 逆兽组 27 只由对应难【逆】选项授予，3 条羁绊；驯兽师隐藏职「逆+出阵灵兽≥3」口径已对齐。

三、自动游玩实测结论（2026-09-12 修复后）

修复前：每局必卡死两处——观音关隘「领受」循环（act2 难8）→ 即使绕过也在土地庙全按钮死锁，实际不可通关。
修复后（最终验证局）：横屏 844×390 无人值守自动游玩 806 步，越过全部历史卡点（观音关隘 → 土地庙×2 → 深入 act6），最终于 act6 火云洞 / 难50 以「大限将至 · 寿数已尽」自然终局——这是游戏设计的正常失败态（寿命机制），全流程无任何软锁、0 JS 异常。回答「能顺利到第几章」：自动化粗放策略下可稳定推进至 第 6 地区（难 50/81）；人类玩家操作更优，预期更深。
