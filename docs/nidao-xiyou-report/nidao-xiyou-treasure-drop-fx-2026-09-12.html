二、飘字反馈：让「概率触发」被看见

on-hit 本质是Math.random() 掷骰，若无可视反馈，玩家无法建立「法宝 → 战果」的因果。 本轮补一条从结算到表现的回执链，沿用既有 d.jinguProc 的 roundsDetail 范式（不新增旁路）：

applyTreasureOnHit
触发时写 rd.onHitFx→ main.js _emitBattleFx
读 d.onHitFx → emit→ ui_misc_3 _fxTreasureOnHit
金色标签 callout→ style.css .fb-tre-onhit
上浮淡出（transition）

改动点

文件改动
combat.js新增 NDX.ONHIT_FX_LABELS（效果键→文案/图标，单一真源）；applyTreasureOnHit 在 proc 触发时写 rd.onHitFx.push({tid,name,kind,label,icon})
game_combat_1.js调用时给每条 onHit 注入 _tid/_name（供回执记法宝名）

标签文案示例：🤏 收妖·变小、💫 晕眩、🔥 灼烧、🔇 沉默、✨ 圣伤。 位移走 transition（项目禁 CSS @keyframes 位移），与 .fb-skill-name 同风格；颜色语义沿用项目既有（红=暴击，不引入新色义）。
