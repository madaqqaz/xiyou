二、设计：一条真源 + 软饱和曲线 + 四池接线

1. 单一真源 NDX.daoPoolWeights(s)（js/dao_system.js，六道 owner）

按 GDD §2.3 公式实现软饱和曲线：

w[dao] = 1 + FATE_W_MAX · fate / (fate + FATE_W_HALF)

  • FATE_W_MAX = 1.5（最大加成上限）、FATE_W_HALF = 4（半饱和常数）——[PLACEHOLDER · 待 10 局采样]
  • 软饱和：fate→∞ 趋近 1+1.5=2.5 而永不抵达，任何道都不会 100% 垄断（§2.3 明确要求）；半饱和点 fate=4 → w=1.75。
  • 中性回落：无 state / 无 fate / fate 全 0 / 恶缘当道（eyuan） → 返回 null，调用方回退既有「主道 ×N / 均匀」逻辑 —— 零回归。
  • 配套 NDX.daoPoolMult(s, dao) 便捷取值（中性 → 1）。

3. 劫印首槽：从「英雄固有道」改为「动态主道」

首槽 main 改读 NDX.DaoSystem.getMainDao(s)——即「锚点（难 1 抉择）→ 劫印累积 ≥3 且领先锚点 ≥2 → 英雄六道归属」三段回落。 这使转道后首槽随新主道，与装备 / 法宝同口径；synergy-in-reach「主道劫印恒在候选池首项」的保证不变（因 dynamic main 即主道）。对应 _resolveSealTier 的「善道档位保底」判定同步改读同一真源。
