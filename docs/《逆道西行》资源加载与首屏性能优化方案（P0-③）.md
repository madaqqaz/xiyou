# 《逆道西行》资源加载与首屏性能优化方案（P0-③）

> 本文为 v=370 真源核验后的整改方案，承接《系统全景分析_v369_补充完善版》P0-③ 项。
> 目标：在「零构建 / 零第三方依赖 / file:// 双击即玩」三条宪法约束下，缓解首屏与包体压力。

## 一、现状核实（代码事实，非臆测）

| 事实 | 落点 | 说明 |
|---|---|---|
| 立绘 WebP/PNG 双格式 + 自动降级 | `js/main.js:207` `t.src = t.src.replace(/\.webp$/, '.png')` | 优先 WebP，不支持回退 PNG，已落地 |
| 立绘预加载机制 | `js/ui.js:674`、`js/ui.js:5873`、`_preloadTreasures:5969` | 法宝/立绘进局预载，已落地 |

| 同步加载的巨型 JS | `data.js`/`ui.js`/`game.js`/`combat.js` 等 5 个 5000+ 行 | 同步 `<script>` 阻塞首屏解析 |
| 包体 | `img/` 95MB / 416 图；`assets/` 音频 | 全量随包分发 |

**结论**：资源懒加载/双格式/预载的核心能力已具备，瓶颈在「包体体积」与「首屏同步解析巨型 JS」，而非"完全没做懒加载"。

## 二、核心权衡：CDN 与离线形态的冲突（关键判断）

本项目主线形态是 **file:// 双击即玩 + 本地 HTTP 预览**，宪法明令「不引入后端、不引入在线服务」。

- **若对浏览器 H5 主线引入 CDN**：`file://` 离线打开时资源 404，直接破坏「双击即玩」承诺 → **违反宪法，否决**。
- **发布版（微信小游戏 / TapTap）**：平台本就要求资源走平台 CDN/分包，与离线形态无关，可在该适配层独立处理，不污染主线。

**决策**：浏览器 H5 主线**不引入 CDN**；优化重心放在「本地资源瘦身 + 加载时序」，CDN 仅作为发布适配层的既有能力，不在主线讨论。

## 三、可执行优化清单（按优先级）

### P0（直接改善首屏，可立即做）
1. **首屏立绘范围收敛**：地图/HUD/当前英雄立绘进首屏预载；战斗敌方立绘改为「进入战斗节点时」再 `_preloadTreasures`，避免开局一次性解码数百张。
2. **图标雪碧图（sprite）**：`js/icon_map.js` 含约 191 处小图标引用，合并为 1–2 张雪碧图 + CSS `background-position`，将数百次图片解码降为 1–2 次，显著缩短首屏。

### P1（体验/体积）
3. **音频按需加载**：BGM 进局加载、SFX 进战斗加载，避免 `preload:'auto'` 在首屏并发拉满音频文件；移动端流量友好。
4. **WebP 二次压缩**：当前 `img/` 95MB，目标压至 40MB 内（视觉无损）；`main.js:207` 降级链保证旧浏览器兼容。

### P2（架构层，需谨慎）
5. **大表 JSON 化按需 fetch**：装备（163）/经文（129+122）/敌人（80+）等大体积静态数据，从手写 JS 数组改为运行时 `fetch('data/xxx.json')`，仍零构建，但需解决 `file://` 下 `fetch` 受限问题（本地 HTTP 预览可用，双击即玩需内联兜底）——**此条与 file:// 兼容性冲突，落地前必须做方案验证**。
6. **发布版 CDN 分包**：仅微信/TapTap 适配层，主线不碰。

## 四、与宪法一致性

- 不引入构建步骤、不引入 npm 运行时依赖、不引入后端——本方案全部满足。
- 缓存版本号纪律：改动 `js/*.js`/`css/style.css` 后递增 `index.html` 的 `?v=NN`。
- 大表 JSON 化（P2-5）若实施，必须先验证 `file://` 双击即玩仍可用，否则按宪法「用户明确否定的概念必须删除」回退。
