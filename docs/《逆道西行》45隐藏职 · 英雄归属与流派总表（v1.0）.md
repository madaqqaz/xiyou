## 四、⚠ 三个结构性问题（实读暴露）

### 问题 1：转职的「L3 套路层」只落地了 3/10 流派

`js/data_jobspec.js` 里 10 张套路卡**设计齐全**，但 `NDX.JOBSPEC_IMPL = ['summon','combo','reflect']` —— **代码只给这 3 个流派接了「改三键」**（`applyJobStyle` 未命中即零操作）。

| 层级 | 覆盖 | 效果 |
|---|---|---|
| L1 数值 `effect.bonus` | **45/45** | 加属性 |
| L2 机制 `effect.passive` | **45/45**（7 种 passive 模板） | 反震/残血叠攻/绝对穿透/饱食盾/免伤等 |
| **L3 三键改造** | **10/45** ⚠ | 攻/经/绝 手感改变 |
| 大招变体 `ULT_STYLE_MOD` | **45/45**（10 流派） | 大招换名换效果 |

→ **35 职（78%）目前「转了跟没转一样」**：只有属性 + passive + 大招换名，三键手感逐字节不变。

### 问题 2：单英雄流派过度集中

| 英雄 | 集中问题 |
|---|---|
| **唐僧** | 8 职中 **7 个 purify** → 大招全同 |
| **小白龙** | 6 职中 **5 个 evade** → 大招全同 |
| 沙僧 | 6 职中 5 个 ward+reflect |

**根因**：`JOB_STYLE` 是按「英雄气质」派流的（唐僧慈悲→purify、白龙灵巧→evade），而**同一英雄的气质天然单一**，所以流派必然扎堆。

### 问题 3：「大招变体」承担了它承担不了的作用

现在的设计里，**流派 → 大招**是一一映射（10 流派 → 10 个大招）。所以 45 职实际只有 **10 种大招**，同流派职之间**毫无区别**（如 7 个 purify 职全是「大慈大悲」）。

## 五、附：操作点（识破 / 破韧）的体系定位

用户提问：「识破、破韧这种初稿设计，在现有体系中是不是没有存在意义了？或作为自动战斗的一种变种保留？」

实读结论：**两者在代码里是同一个系统的两种表现 —— 「操作点（Operation Point）」。**

| 触发 | kind | 生成位置 | 玩家动作 |
|---|---|---|---|
| 怪物蓄力重击 | `telegraph` | `combat_part1.js:1023` | **识破**（反制 + 气势+2，全局限 2 次） |
| 妖敌将狂暴 | `enrage` | :1024 | 临阵祭宝逆转 |
| 玩家残血 | `lowhp` | :1025 | 续命珠 |
| 每 4~5 回合常规 | `routine` | :1026/:1033 | 常规择机 |
| 多阶段 Boss 阶段衔接 | `stageBreakPoint` | `combat_part1.js:1263`（`calcMultiStage` 独有） | **破韧**（限时 2.5s 祭克制法宝，领厚赏 / 超时走挂机兜底） |

**四个关键事实**：
1. **游戏默认手动**（V8.32「取消自动攻击：所有战斗默认手动」）；自动战斗是 `FIGHT_GATE.auto = 4`（第 4 区解锁）的**减负功能**。
2. **意图预告已常驻**：`mIntent` / `mNextIntent`（`pattern` 怪可预知下一动）→ 「识破」的**信息价值已被意图系统接管**，剩下的是**反制动作价值**。
3. **自动战斗下两者仍强制拦截**：`main.js` 的 `PHASE_WAIT` 中，`stageBreakPoint` 分支与 `operationPoint` 分支**都排在 `if (p.autoFight)` 之前**；且 Boss 战还会**强制回退手动**（V8.45）。
4. **教学战已主动豁免**：`_isTutorialFight` 不生成操作点（`combat_part1.js:1020`）—— 说明设计者已意识到「操作点会与三键教学抢注意力」。

**判断**：识破/破韧**不与三键重复**（三键＝主动出招 / 操作点＝被动应答，构成「进攻 + 拆招」双层），**不能删**——尤其破韧是**法宝克制配装的唯一硬验证点**（`monster.breakWith`，如黄风怪↔定风珠）。真正要治的是「**自动战斗下仍被打断**」这个体验矛盾。
