## 一、病灶（用户原话）

> 「逆收的随从太多了，因此还需要设计一个隐藏配合多随从的玩法，**或者随从可以进行合成这种**。」

实读确认，随从系统有两个硬缺陷：

| # | 缺陷 | 证据 |
|---|---|---|
| **G3a** | **驯兽师死锁**（循环依赖） | `驯兽师·百兽归心` 门槛「**出阵灵兽≥3**」，但宠物初始只有 **2 格**（`PET_SLOT_BASE=2`）⇒ 必须先解锁到 4 格才能觉醒，而 4 格要靠成长线/成就 —— **先有鸡还是先有蛋** |
| **G3b** | **随从无出口** | `FOLLOWERS` 12 名妖王，随行位只有 **4**（`SLOT_CAP.companion`，与徒弟共用）⇒ 收多了**只能堆着**，收服行为**没有目标** |

> 关键约束：随从在**一局内不可重复收服**（谈判系统 `s.negotiated` 保证同一妖王只收一次）
> ⇒ 原草案「2 个**同名**凡 → 1 灵」在本作**不可能成立**（不存在同名两份），已按语义修正（见 §二）。

## 二、三阶炼化（G3b 解法）

### 2.1 三阶

| 阶 | 来源 | 助战属性倍率 | 说明 |
|---|---|---|---|
| **凡** | 谈判收服时的本相 | **×1.0** | 现有 `FOLLOWERS` 数值 |
| **灵** | **2 名凡**炼化 | **×1.8** | 主体保留、饲料消散 |
| **真** | **2 名灵**炼化 | **×2.5** | 同上 |

**收敛出口**：`4 凡 → 2 灵 → 1 真`（4 → 1）。玩家「收一堆凡 → 炼一个真」，**收服行为第一次有了目标**。

### 2.2 为什么是「同阶 2 合 1」而不是草案的「2 同名 / 3 异名」

- **同名不可行**（见 §一关键约束）；改为「**同阶即可**」，语义更清晰、天然可玩。
- 草案的「3 异名凡」与「2 同名凡」在收益上重复，且**增加学习成本**（玩家要记两套规则）。
- 保留 `need` 字段（当前恒 2）便于将来加「3 合 1 更省」类变体，**不预留空机制**。

### 2.3 确定性（不掷骰）

本版**必成**。理由：
1. 随从是**稀缺资源**（一局最多 12 名、实战常用 4 名），概率失败只会让玩家**不敢用**；
2. 用户长期偏好「玩家可预期」（见 `game-design-perceived-randomness-audit` 方法论）；
3. 路线图技能选型原话是「合成是概率机制，**先审体感再定公式**」—— 确定性正是最稳的起点。

> 可选变体（**未实装**，留待体感验证后决定）：概率版 + 「3 合 1 稳成」双路径。

### 2.4 数据结构与铁律

| 项 | 落点 |
|---|---|
| 真源 | 🆕 `js/data_follower_fuse.js` |
| 阶数存储 | `s.followerTiers = { [id]: 'fan'\|'ling'\|'zhen' }`（**缺省视为 `fan`**） |
| 唯一读口 | `NDX.followerTierOf(s, id)` / `followerTierInfo` / `followerMultOf` |
| 唯一写口 | `NDX.fuseFollowers(s, mainId, feedIds)`（**原子**：失败不改 s） |
| 枚举 | `NDX.followerFuseOptions(s)`（供 UI）/ `followerTierSummary` / `followerFuseBrief` |
| 倍率生效 | `NDX.followerBonus(ids, s)` 第二参（**不传 s ⇒ 全部 ×1.0，旧行为逐字节不变**） |

## 三、驯兽师死锁修复（G3a 解法）

### 3.1 门槛改写

| 项 | 旧 | 新 |
|---|---|---|
| `驯兽师·百兽归心` | `夺 + 出阵灵兽≥3` | **`夺 + 随从≥3 + 御兽套`** |
| `逆兽师·百逆归心` | `逆 + 出阵灵兽≥3` | **`逆 + 随从≥3 + 御兽套`** |

- **「累计收服」取代「出阵」** ⇒ 解开循环依赖（觉醒不再要求先有 3 格）。
- **保留「御兽套」** ⇒ 驯兽师战力由其共鸣 `perPet` 承载，**无套则觉醒即空转**，故仍作门槛。
- **`evalHiddenCond` 新增语法** `随从≥N`（计 `s.followers + s.disciples`），并把 `御兽套` 加入 `_KNOWN` 白名单；
  **旧语法 `出阵灵兽≥N` 的解析段已删除**（活动引用归零，不留死代码）。

### 3.2 第二真源已收口

`game_event_2.js` 难 64 的**逆兽师独立觉醒路径**原有一份**并行门槛实现**（同样的 `出阵灵兽≥3`）。
现改为**直接调 `NDX.evalHiddenCond('逆 + 随从≥3 + 御兽套', s, { fate: '逆' })`** ⇒ **改注册表即改行为**，杜绝两处漂移。

### 3.3 闭环

```
收服 3 名随从 ──→ 觉醒驯兽师（随行位之外，额外解锁宠物格 2→6）
                      │
                      └──→ 多宠上阵（御兽套共鸣 perPet 放大）
                              │
堆着的多余随从 ──→ 三阶炼化 ──→ 真阶随从（助战 ×2.5）
```

## 四、驯兽师 = 六道之外的平行成长线

用户原话：「**驯兽师这个职业，原来的想法是一个不同于六道的变种**，主要是参照了冒险日记……还需要设计一个隐藏配合多随从的玩法。」

**重要前提变更**：草案 v2.0 §4.2/§六 的 S4（「驯兽师是否完全不吃**本命道 ×1.25**」）—— **该机制已于 V9.51 被用户彻底取消**（六道 = 玩家的选择，英雄不带本命道）。
⇒ **S4 不再是问题**，无需拍板。

**现在的形态**：驯兽师不吃任何「本命道加成」（已无此机制），改走**自己的线**：

| 概念 | 定义 |
|---|---|
| **御兽之力** | `Σ 上阵随从的阶数倍率`（凡 1.0 / 灵 1.8 / 真 2.5） |
| **加成** | 英雄 `atk / matk / maxHp` **+2% × 御兽之力**，封顶 **+20%** |
| **极值** | 随行位 4 格 × 真阶 2.5 = **10 点** ⇒ `10 × 2% = 20%` = 封顶（自洽） |
| **零操作** | 非 summon 路线 ⇒ `summonerFollowerBonus` 返回 `null`，绝不干扰其他流派与存量存档 |

因为随行位只有 4，所以「6 只随从 × 3%」式的草案数值不可达 —— 已按真源容量重算（4 × 2.5 = 10 点）。

## 六、同批落地：P2′ 权重调参（用户 2026-09-25 拍板）

> 用户原话：「**经文只能微调，核心的数值是装备。**」

| 源 | 旧 | 新 | 理由 |
|---|---|---|---|
| `BASE` 英雄底色 | 1.0 | **1.0** | 不变（只做先验与并列裁决） |
| `EQUIP` 装备 | — | **2.4**（新增） | **核心数值源 = 最高权重**；读件级 `it.style` 标签，B 批打标签后自动生效（现网无该字段 ⇒ 恒为 0，零副作用） |
| `SEAL` 劫印 | 1.2 | **1.2** | 不变（> BASE ⇒「一枚劫印即可转向」） |
| `SUTRA` 经文 | **1.5** | **0.8** | **低于底色 1.0** ⇒ 单持一部经**不足以改路线**，只能微调 —— 用户原话的直接落地 |
| `JOB` 隐藏职倾向 | 2.0 | **2.0** | 不变（收敛机制） |

**配套的判据修正**（否则「持经却无反馈」）：`currentStyle` 由「最佳路线*自身*须有信号」改为
「**存在**非底色配装信号」—— 单持经时仍显影（显影出底色所主导的路线）。无任何配装 ⇒ 信号总量 0 ⇒ 仍返回 `null`（零操作，存量玩家逐字节不变）。
