## 1. 五英雄基础值 + 体/愿双体系（承接上轮）

关键已确认事实（详推演脚本 `_hero_ti_yuan_analysis.js`）：

- **`sys:'ti'/'yuan'` 不参与任何数值**。全仓仅 `dao_system.js`、`data_sutra.js:343`、`ui.js:732`（CSS class）读取，战斗层零消费。体/愿目前是**标签**，不是**体系**。
- **成长曲线冲掉体系标签**（`data_heroes.js:13`）：`atk +420t`、`matk +500t`（斜率反超）、`dr +0.15t`；`hp/mdef/eva` 零成长。体攻系 baseMatk 仅 10~15 被成长项淹没，叠加回合内核 `deal = dmgP + dmgM`（双段叠加），第 81 层小白龙法术占 52%、八戒 40%、悟空 31%——无英雄纯物伤。
- **两处硬断链**：`baseSpd` 死字段（`computeStats` 不读，先手纯靠装备）；三键主动技 `dblBase` 绕开 `mercyAtk/mercy`（见 §2.1）；悟现金箍补偿双轨（仅 `stats()` 管线，直调 `computeStats` 少算 35% 攻 / 20% 血）。
- **沙僧最吃亏**：baseMatk 120（取经人 200）、passive 仅 `mercyHp` 无 `mercy` → 善念对输出 0 杠杆，1922/回合垫底，EHP 却与取经人持平。
- **小白龙同为 0 杠杆**：passive 全 cri 系、`eva` 零成长，闪避流收益随层数相对衰减。

## 2. 本轮 11 项专项审计

### 2.1 英雄被动（金睛破甲·慈悲愿力·净坛护盾·疾风连击·沉沙御念）+ s.good 链路

**善念链路：自动回合内核通、手动三键技断。**

- `s.good` 累加点：`game.js:147`(初始0)、`3120/3341/3352/3373/4266/4418/4551`（alignGood / 渡隐抉择 +1）。
- 传入战斗对象：`game.js:1677` `good: s.good || 0`（calcCombat 入参）。
- 战斗读取：`combat.js:277` `const good = Number(player.good) || 0;`
- 自动回合内核消费（**生效**）：`combat.js:326` `pTi.atk*(1+...+(P.mercyAtk||0)*good)`、`combat.js:470` `pMagicBase*(1+(P.mercy||0)*good)`、`combat.js:286` `maxHp*(1+P.mercyHp*good)`。
- **断链**：三键主动技 `NDX.activeSkill` 的 `dblBase = Math.round((ti.atk||0)+(yuan.matk||0))`（`combat.js:1333`），**未过 `mercyAtk/mercy`**（对比 326/470）。→ 悟空「斗战善果 +7%/善念」、取经人「慈悲愿力 +10%/善念」在手动「攻/经/绝」按键上**完全不生效**，与用户「多数吃 s.good」预期直接矛盾。

**被动键级对齐**（combat.js 实际消费全集）：`criBonus,criMult,mercyHp,shieldPct,glutton,mReflectBoost,mReflect,guardMdef,mercyAtk,evasion,criOnDodge,criCap,shieldBomb,buddha_def,sunder,empty,mercy,restored,reverseScale`。五英雄定义键与目标 passive 名对应无误。

**一个死键**：`evasion`（`combat.js:335` 读取 `P.evasion` 加闪避）全仓未定义（HIDDEN_JOBS 0 处、HEROES 0 处）→ 恒为 0，静默无效（债务⑫）。

**善念杠杆分布**（验证用户「多数吃 s.good」）：只有 mercy 系键吃 good——悟空(mercyAtk)、唐僧(mercy)、八戒(mercyAtk+mercyHp)。小白龙(cri 系)、沙僧(guardMdef+mReflect，无 mercy) 的 passive **完全不依赖 good** → 0 杠杆，与 §1 结论一致。

### 2.3 立绘 7 形态（evolvePortraits）+ 全 CHAR_PORTRAITS 映射 —— 🔴 阻断①

**存在三重并行立绘系统，违反宪法「禁止另起并行体系」。**

| # | 系统 | 定义位置 | 被谁消费 | 状态 |
|---|---|---|---|---|
| A | `hero.evolvePortraits`（每英雄 6 形态 base/evil/tier1/tier2/final/hidden） | `data_heroes_data.js:13-72` | 仅 `data_heroes_data.js:196-198` 的 webp 转换循环 | **ORPHANED**（无渲染消费） |
| B | `NDX.CHAR_PORTRAITS`（扁平键映射，含 `wukong_tier1` 等 tier 变体）+ `NDX.getHeroPortrait(heroId,tier)`（`data_heroes_data.js:208`） | `data_heroes_data.js:90-208` | `NDX.getHeroPortrait` **未被 ui 调用**（ui 调 `game.getHeroPortrait`） | **ORPHANED**（tier 变体键死数据） |
| C | `NDX.HERO_EVOLVE_PORTRAITS` | `enemies.js:1303-1311` | `game.getHeroPortrait`（`game.js:4100-4104`）实际读取 | **唯一生效，但仅 tangseng 一项** |

**后果**：
- `NDX.HERO_EVOLVE_PORTRAITS` 仅含 `tangseng`（5 形态，无 `hidden`）。`game.getHeroPortrait` 对悟空/八戒/沙僧/小白龙取到 `undefined` → `ep` 假 → 永远返回 `heroDef.portrait`（base）。
- 即 **4/5 英雄的转职/隐藏/恶线立绘全部不显示**，七形态系统约 90% 未落地；`hidden` 形态全仓 0 渲染。
- **命名冲突**：`NDX.getHeroPortrait(heroId,tier)`（读 CHAR_PORTRAITS）与 `game.getHeroPortrait(heroId)`（读 HERO_EVOLVE_PORTRAITS）同名不同源，极易误改（债务⑬）。
- 系统 A/B 的 tier 变体是纯维护负担（债务⑭）。

## 3. 问题分级汇总

### 🔴 阻断（当轮必须收）

10. 体/愿 `sys` 标签不参与数值，体系标签失效（§1）。
