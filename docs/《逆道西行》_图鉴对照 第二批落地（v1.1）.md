## 一、A · 格挡与反击

### 1.1 定位：为什么不是 dr 与 reflect 的重复

内核已有三个"挨打时起作用"的机制。新增两个必须先说清边界，否则就是数值重复。

| 机制 | 触发 | 结果 | 收益随什么上升 | 是否出手 |
|---|---|---|---|---|
| 护体 `dr` | 恒定 | 伤害 ×(1−dr) | **受击伤害**（越肉越强） | 否 |
| 反伤 `reflect` | 恒定 | 返还 受击伤害 × 比例 | **受击伤害**（越肉越强） | 否 |
| 闪避 `eva` | 概率 | 伤害归零 | 攻击频率（打得越多闪得越多） | 否 |
| 🆕 **格挡 `blk`** | **概率** | 伤害 ×(1−`blkCut`) | 攻击频率 | 否 |
| 🆕 **反击 `counter`** | **概率** | **追加一次攻击** | **自身攻击力** | **是** |

三条关键区分：

1. **格挡 ≠ dr 的弱化版**。格挡与闪避是**两次独立判定**：闪避失败仍可能格挡成功，但也可能双失手吃满伤。这制造了"高闪避 + 高格挡 = 方差更大、上限更高"的独立路线，而不是 dr 的稀释版。
2. **格挡对多段连击一次判定、挡下全部段**；闪避则是逐段独立判（见 `combat_part1.js:645-653`）。这是"稳 vs 险"的分野。
3. **反击 ≠ 反伤**。反伤按受击伤害比例返还（肉越厚收益越高）；反击按**自身攻击力**追加，且**吃暴击、吃吸血**。于是形成三角：
   - 堆 dr + reflect ⇒ **反伤流**（你不打我，我磨死你）
   - 堆 blk + counter ⇒ **反击流**（我站着挨，我打回去，还打暴击）
   - 堆 cri + lifesteal ⇒ **暴吸流**（原本就有）

### 1.2 数值表

**格挡**

| 参数 | 值 | 说明 |
|---|---|---|
| 字段 | `blk`（0~1） | 装备/套装/隐藏职可给 |
| 封顶 | `BLK_CAP = 0.50` | 与 `eva` 封顶 0.60 同量级 |
| 格挡削减 | `blkCut = 0.50` | 格挡成功只吃 50% 伤害 |
| 装备单点 | 凡品 0.02~0.03 / 珍品 0.04 / 精品 0.06 | 与 `eva` 单点同档 |
| 套装件 | 0.08 | 套装共鸣另计 |

**反击**

| 参数 | 值 | 说明 |
|---|---|---|
| 字段 | `counter`（0~1） | 同上 |
| 封顶 | `COUNTER_CAP = 0.40` | 低于格挡封顶（反击附带出手，不能比格挡更好叠） |
| 反击系数 | `counterRatio = 0.35` | 不落数据，内核常量 |
| 伤害口径 | 物伤受击 → `pTi.atk × 0.35`；法术受击 → `pYuan.matk × 0.35` | 按来源分流，法系不吃体攻 |
| 每回合上限 | 1 次 | 防 `multi` 段数放大成斩杀 |
| 吃暴击 | 是（× `criMult`） | 暴击流的**纯增量**，不抢暴击率 |
| 吃吸血 | 是（走 `lifesteal`） | 与夺道吸血共鸣同管线 |

**战力总评纳入**：`power += blk × 1200 + counter × 900`（对齐 `eva × 800` 量级），否则玩家看不到该条线的成长。

## 二、B ·「同效果仅生效一次」——两个候选口径

图鉴原始规则：「所有装备同效果仅生效一次」。
逆道没有"可重复装备"（每件唯一），所以这条规则在逆道的**对应形态**不是字面照搬。

我实测过影响面：`dr` 是全池 372 件在用的核心字段，同时叠加来源还有**劫印·缘道、套装共鸣（玄武 drMult）、隐藏职、命痕、业镜**，全部走累加。若直接改成"取最大"，玄武套与缘道劫印的联动会被直接废掉——那是二话不说推翻既有数值设计。

所以给出两个口径，**请用户拍板**（不是弹窗，纯文字）：

### 口径甲 ·「同套内同类只取最高一件」（推荐）

- 规则：同一 `set` 内，`dr / mdef / eva / cri` 同类效果只取**最高一件**生效；跨套仍累加。
- 影响面：**只惩罚"同时穿三件减伤套"的堆叠**，不动跨套构筑、不动套装共鸣、不动劫印联动。
- 收益：让"套装定位"真正成立（现在混搭三件套的收益 ≥ 同套三件，套装形同虚设）。
- 数据侧改动：无（全部在 `computeStats` 里做集合聚合）。

### 口径乙 ·「全局同类只取最高一件」（图鉴字面）

- 规则：全装备栏同类效果只取最高一件，`dr / mdef / eva / cri` 皆然。
- 影响面：**推翻玄武套、缘道劫印联动、命痕·坚甲、套装共鸣**。必须连套装共鸣、劫印加成一起重做数值。
- 收益：与图鉴完全一致，构筑收敛快。
- 代价：存量玩家数值大幅下调，属**平衡级改版**，需重跑数值验证。

> **我的推荐是甲。** 乙的"一次"在图鉴里成立是因为冒险日记装备可重复；逆道装备唯一，字面照搬会误伤整套防御体系。

### 🔴 终审裁决（2026-09-26）：**不做 B（维持现状）**

用户复核时问「玄武套为什么会出现同件的情况」，暴露出本节两个问题，裁决据此推翻原推荐：

1. **措辞纠错**：逆道装备唯一、一件一格，不存在「同件」。玄武套的真实形态是**同 set 多件携带同一主题字段**（dr 铺在镇海甲 0.28 / 盔 0.14 / 靴 0.10，同穿合计 0.52）——主题字段按件铺开是套装设计手法，不是重复缺陷。
2. **口径甲自相矛盾**：按「同 set 内同类只取最高一件」推演——同穿玄武三件只算 0.28（+共鸣 ≈0.47），而**混搭三个减伤套各穿一件反而 0.52 全生效**（每套一件、件件都是「套内最高」）。甲会奖励混搭、惩罚同套，与「让套装定位成立」的目标正好相反。
3. **前提不成立**：实测当前数值下同套（≈0.74 含套装共鸣 `drPlus 0.14 + drMult 1.12`）**已经压过**混搭（0.52）——本节要解决的「混搭 ≥ 同套」问题并不存在。

**结论**：为一个不存在的问题引入回归风险不值得。B 关闭，装备聚合逻辑零改动；A/C/D 维持本批已落地内容。

## 四、D · 事件后续嵌套

### 4.1 现状：机制有、数据零

| 检查项 | 结果 |
|---|---|
| `s.pending.then` 消费点 | ✅ 有（`game_event_3.js:189`、`game_event_2.js:328`） |
| 数据里 `then` 的使用 | ❌ **零** —— `trials_ch*.js` 中 `then:` 出现 0 次 |
| 多层展开 | ❌ `s.pending = s.pending.then` 是**单次替换**，第 2 层起的 then 被丢弃 |

### 4.2 落地

1. 新增数据字段 **`opt.thenEvent`**（下一个事件的 key），带 `depth` 表达嵌套层数（最多 4）。
2. 结算后**循环展开** then 链（把现有单次替换改成 while），让 4 层可以真正串起来。
3. `NDX.pickEvent` 侧提供按 key 取事件的入口，供数据引用。

**零回归**：`thenEvent` 缺省 ⇒ 展开循环不进入 ⇒ 行为逐位不变。存量事件全部不填该字段。
