## §一 诊断：v1.1 的星阶是**死数据**（第 6 条死路）

### 1.1 实锤

```
grep -rn "PET_STAR_MUL|petStarMul|petStarCost|PET_STAR_UNLOCK|PET_STAR_MIX_LOSS|PET_STAR_CAP" js/
→ 命中 0 处（仅 scripts/_verify_pet.js 引用）
```

v1.1 交付的 `PET_STAR_CAP` / `PET_STAR_MUL` / `petStarMul` / `PET_STAR_COST` / `petStarCost` /
`PET_STAR_MIX_LOSS` / `PET_STAR_UNLOCK` —— **七个符号，游戏代码里零读取、零写入**。

**后果**：玩家即使把宠物合到 ★5，属性不变、被动不开、羁绊不动。v1.1 文档 §2.4 承诺的
「主要收益是机制不是倍率」**收益为 0**。门禁 P1~P3 只验了表的**自洽性**（曲线单调、消耗是斐波那契），
没验**有无消费点** ⇒ 又一处「假绿」。

### 1.2 与既有 5 条死路的区别

| 死路 | 性质 |
|---|---|
| ①`PET_LIB` 孤儿表 / ②`petSlotCap` 残留 / ③`cfxPetSynergy` 前门 / ④`petLv` 无写入点 / ⑤`bond-mantra` 挂靠 0 部 | **写了但接不上**（读端或写端缺一侧） |
| ⑥ 星阶 | **连读都没读**（两端全缺）——更彻底 |

### 1.3 连带发现：v1.1 的机制解锁表**两项无法落地**

| v1.1 原文 | 能否实现 | 原因 |
|---|---|---|
| ★2「解锁被动槽 2（第 2 个 `petPassive`）」 | ❌ | 全仓**没有 `petPassive2` 字段**（`grep -c petPassive2 js/*.js` = 0）。宠物只有一个 `petPassive`。所谓「槽 2」无槽可解 |
| ★3「羁绊触发门槛 −1」 | ❌ | 羁绊是 `{a,b}` 的**二元**结构（`petFetterEffects` 要求两 id 同时上阵），**没有「门槛」这个量**，减无可减 |
| ★5「觉醒：额外被动槽（3）」 | ❌ | 同 ★2 |

⇒ v1.1 的 §2.4 是一张**三格空头支票**。v1.2 必须换成**有落地点**的机制。

## §二 星阶机制解锁表（v1.2 定稿 · 可落地版）

### 2.1 判据

> **能落地 = 存在唯一消费点，且消费点读得到星阶。**

复用既有的、**已经跑通的语义**，不新开概念：

| 星阶 | 解锁（v1.2） | 唯一消费点 | 为什么是它 |
|---|---|---|---|
| ★1 | 数值 ×1.15 | `computeStats` 装备遍历 | 基础档 |
| ★2 | **被动档数 +1**（该宠物的 `petPassive` 计 2 档） | `aggregatePetPassive` | 「档数」是**既有概念**（`pp[key] = 同型只数`，注释原文「同型可叠加计数」）。★2 语义 = 「这只宠物顶两只同型」 |
| ★3 | **羁绊效果 +20%**（该宠物参与的羁绊） | `petFetterEffects` | 羁绊是宠物唯一的「组合」出口，星阶提升它 = 「升级链咬合组合链」，正是「多重升级**组合链**」的字面义 |
| ★4 | 数值 ×1.33 | 同 ★1 | — |
| ★5 | **觉醒：被动档数再 +1（共 +2）** | 同 ★2 | 与 ★2 同轴递增，避免 ★5 又开新概念 |

**只保留两项纯数值、三项真机制**，且全部指向**已存在**的读取端。

### 2.2 ★3 的防双吃

若羁绊双方都 ★3+，**只计一次 ×1.20**（`Math.max`，非乘积）。

> 理由：`1.20² = 1.44` 会让「两边都堆星阶」成为唯一解。判定取 max，让第二只的 ★3 收益
> 转移到它自己参与的**另一条**羁绊上 —— 鼓励**铺开**而不是**叠一头**。

### 2.3 数值乘子的适用范围（白名单，**有封顶的属性不许乘**）

```
✅ 乘：atk  hp  matk          —— 平铺数值，无封顶
❌ 不乘：dr  eva  cri  mdef  hit —— 有硬封顶（dr≤0.60 / eva≤0.6 / mdef≤0.50）
```

**理由**（skill「属性模块·临界值」模板）：

百分比属性一旦封顶，**边际收益 = 0**。若星阶也乘 `dr`，玩家把 dr 堆到 0.60 后再升星
⇒ 乘出来仍是 0.60 ⇒ **星阶的这部分收益被静默吞掉**，玩家看到「升了星没变强」。
不乘它们，是把星阶的收益 100% 放在**不封顶**的轴上，收益永远可见。

> ⚠ 这条规则必须**写进代码白名单表**并配门禁（Q3）——不能只写在文档里，
> 否则将来有人顺手加个 `e.dr * mul` 就又埋一个「撞顶浪费」。

**⚠ 例外（端到端实测发现，如实记录）**：★2/★5 的「被动档数 +1」是**机制层**给的，
会经由 `petPassive` 传播。若该宠物的被动本身就是封顶属性（`guard`/`rockwall`/`hymn` → `dr`），
这部分收益**仍然可能撞顶**。实测（`wukong` + `灵岩幼兽`）：★5 时 `dr` 由 0.21 → 0.25（+0.04，
来自 `guard` 2→3 档），而 `atk/hp` 的 +7/+55 才是纯乘子贡献。

**裁定：接受，不设特例。** 理由：
① 量极小（`guard` 每档 +0.02 `dr`，★5 全程共 +0.04），单只宠物贡献不足以触达 `dr` 0.60 封顶；
② 若为它加特例（「★2 对 `guard` 无效」），会变成玩家无法解释的隐规则 —— 比撞顶更糟。
门禁 Q11b 因此**只断言 `eva`/`cri` 零泄漏，不断言 `dr`**（`dr` 的增量是设计内行为）。

### 2.4 零副作用是**构造性的**

★0 ⇒ `petStarMul(0) = 1.00` ⇒ 装备遍历里的乘子是恒等。
存量存档无人有 `petStarOf` ⇒ 全部 ★0 ⇒ **战斗结果逐字节不变**。
这不是「测出来没回归」，是**构造上不可能回归**。

### 2.5 落地边界（与既有三轴的关系，v1.1 §2.5 不变）

```
   基础宠（q0）
      │
      ├── evolveTo ──► 分支进化（q0→q1→q3）        ← 品质跃迁轴（乘 atk/hp/matk）
      ├── 合成升星 ──► ★1..★5（v1.2 接线）         ← 机制解锁轴（档数 / 羁绊 / 数值）
      └── 等级 Lv1-10（petLvOf）                   ← 线性成长轴
                    ▲
            三轴正交、叠乘；★0/ Lv1 / 未进化 时为恒等
```

## §三 羁绊组合扩容（7 → 21 条）

### 3.1 诊断：扩了池子，没扩组合

- v1.1 把宠物从 67 只扩到 91 只（+24 只原著原型）
- 但 `PET_FETTERS` **一条没动**，仍是 7 条、覆盖 14 只宠
- ⇒ **91 只里 77 只没有任何组合出口**，v1.1 新增的 24 只**全部是羁绊孤儿**

「多重升级**组合**链」的「组合」二字，落点就在羁绊。v1.1 扩了「数量」，v1.2 补「组合」。

### 3.2 设计原则：**扩可达性，不抬天花板**

| | 既有 7 条 | 新增 14 条 |
|---|---|---|
| 数值带 | hpPct 0.25~0.30 / atkPct 0.12~0.18 / matkPct 0.20~0.30 | **hpPct 0.20~0.26 / atkPct 0.12~0.16 / matkPct 0.16~0.22** |
| 定位 | 招牌组合（高数值） | 覆盖组合（略低数值） |

**新增一律低于既有上限**。理由：组合数量变多 = 玩家更容易凑出一条，
若数值同时抬高 ⇒ 总收益翻倍 = power creep。
**扩充的是「有多少种组合」，不是「一条组合有多强」**。

### 3.3 成员难度分档（skill 装备模块 `qualityMultiplier` 类比）

| 档 | 成员构成 | hpPct | atkPct | matkPct |
|---|---|---|---|---|
| A | 双 q0（B 路顺路可得） | 0.20 | 0.12 | 0.16 |
| B | 含 q1+ 或需跨章 | 0.24 | 0.14 | 0.20 |
| C | 含 q2 传说 / A 路 `ni_*` | 0.26 | 0.16 | 0.22 |

> 机会成本口径：羁绊占 **2 个出战槽**（普通上限 4 / 召唤师 6）
> ⇒ 一条羁绊 ≈ 「少上一只宠物」的代价，故数值 ≈ 一只宠物的主属性收益，不高于两只。

## §五 门禁要求（Q 组）

| # | 断言 | 防什么 |
|---|---|---|
| **Q1** | 星阶读写闭环：`petStarUp(s,'x',1)` 后 `petStarOf(s,'x')===1`；连升封顶 ★5 | 防再次「表在、没人读」 |

| **Q5** | 羁绊 id 无重复；`a!==b` | 防复制粘贴事故 |
| **Q6** | 第二批 24 只 id 无重复定义、不与经文/随从表交叉 | 同 P4 判据 |
| **Q7** | ★2/★5 被动档数：★2 宠物在 `aggregatePetPassive` 里计 2 档 | 防机制解锁空转 |
| **Q8** | ★3 羁绊加成取 `max` 不取乘积（`1.20` 而非 `1.44`） | 防星级双吃 |
