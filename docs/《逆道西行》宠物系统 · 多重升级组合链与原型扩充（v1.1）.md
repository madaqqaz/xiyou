## §一 诊断

### 1.1 🔴 三重叠加的爆炸风险（实测数据）

宠物是**第四条成长轴**。既有两条（进化链 / 等级）已被实测放大，本次新增第三条（星阶）必须验算叠乘后果：

```
实测基准（EQUIP_POOL + CRAFT_POOL 中 slot==='pet'，共 67 只）

  基础形态（无 evolveFrom）  n=?   均 atk / hp / matk
  进化形态（有 evolveFrom）  n=?   均 atk / hp / matk
  ⇒ 进化增幅  atk ×1.13 / hp ×1.58

叠加推演（基准 = q0 基础宠 × Lv1 × ★0 = 1.00）：
  进化 q1        ×1.13(atk) / ×1.58(hp)
  × 等级 Lv10    ×2.60(atk) / ×3.64(hp)
  × 星阶 ★满     ×6.51(atk) / ×9.11(hp)   ← 冒险日记原值 ×2.5
```

**结论**：冒险日记的「灵 ×1.8 / 真 ×2.5」是为**随从**设计的——随从只有**一条**成长轴。
宠物有**三条**（进化 + 等级 + 齐击），直接套用等于给三倍成长 ⇒ 宠物取代装备 ⇒ 违背
「装备 = 基础数值」的分层定位。

> ⚠ **教训沉淀**：单条轴"看起来合理"的乘子，乘在一起会爆炸。
> 任何新增成长层，**必须先算三重叠加后的终值**，再反推单层幅度。

### 1.2 《冒险日记》机制的准确定义

| 来源 | 机制 | 本项目对应 |
|---|---|---|
| 事件装备体系 | `events.js` 中 `gear:'ev_*'` 授予，**仅事件可得、不入掉落/商店** | 宠物的 **C 路·事件进化**（已有 `evolveFrom`） |
| 三阶炼化 | 凡（收服直接得）→灵（2同名 **或** 3异名 → ×1.8 + 解锁第2被动）→真（2灵 → ×2.5 + 解锁羁绊技） | **宠物星阶（本文件 §二）** |
| 设计意图 | 「收太多没处用」⇒ 玩家主动「收一堆凡 → 炼一个真」，**收服行为有了目标** | 齐击需要多只 ⇒ 星阶天然消耗冗余宠物 |

> **关键**：冒险日记的收益主体是**机制解锁**（第2被动 / 羁绊技），数值只是附赠。
> 本项目沿用同一结构——**星阶的主要价值是解锁，不是倍率**。

### 1.3 A4 经文 · `bond-mantra` 是死声明

| 项 | 实测 |
|---|---|
| 34 部经的 `chantSkill.kind` 分布 | `veil-mantra` 8 / `ward-mantra` 7 / `zen-heal` 6 / `glut-ton` 5 / `war-buff` 4 / `break-mantra` 4 / **`bond-mantra` 0** |
| `data_jobspec.js:36` | `summon` 流派 `fit.sutra: ['bond-mantra']` |
| 后果 | `fit.sutra` 命中 `chantSkill.kind` ⇒ 该键伤害 ×1.15。召唤流派**永远匹配不到** ⇒ **×1.15 永远拿不到** |

> 🔴 这是与宠物「四条死路」同构的**第 5 条死路**：V9.51 预留的缘系通道从未接通。

**内核边界**（`combat_active.js:492 applySutraVariant` 实际支持的字段）：
`dmgMul / healPct / lifestealPct / shieldPct / trueDmgPct / dotPct+dotRounds / ignoreDef / armorBreak / crit`
⇒ **bond 的数值必须落在这几个字段内**，否则又是「定了接不上」。

## §二 多重升级组合链定稿

### 2.1 星阶倍率曲线（等比增量递减）

沿用 `game-numeric-design` 的「数组数列 · 等比」模板：首增量 `a=0.15`，衰减比 `r=0.60`。

| 星阶 | 增量 | 累计 | **倍率** | 递减量 |
|---|---|---|---|---|
| ★0 | — | — | 1.00 | — |
| ★1 | 0.150 | 0.150 | **1.15** | −0.060 |
| ★2 | 0.090 | 0.240 | **1.24** | −0.036 |
| ★3 | 0.054 | 0.294 | **1.29** | −0.022 |
| ★4 | 0.032 | 0.326 | **1.33** | −0.013 |
| ★5 | 0.019 | 0.345 | **1.35** | — |

**衰减量单调递减 ✅**（对齐既有的「F8 二阶校验」门禁要求）

**终值验证**：

| 组合 | atk 总倍率 | hp 总倍率 |
|---|---|---|
| q0 → q1 进化 → Lv10 → ★5（定稿） | **×3.51** | **×4.91** |
| 同路径用冒险日记原值 ×2.5 | ×6.51（❌ 超标） | ×9.11（❌ 超标） |
| 压降幅度 | **−25%** | **−32%** |

### 2.2 合成消耗（斐波那契 · 复用冒险日记「2同名 / 3异名」结构）

消耗量取**斐波那契数列**（skill 公式工具库），避免指数爆炸（2⁵=32 只过于肝）：

| 目标 | 同名路径 | 等效 ★0 数 |
|---|---|---|
| ★1 | 1 只 ★0 | 1 |
| ★2 | 2 只 ★1 | 2 |
| ★3 | 3 只 ★2 | 3 |
| ★4 | 5 只 ★3 | 5 |
| **★5** | **8 只 ★4** | **8** |

★5 = 8 只基础宠，落在「一局能攒出个把」的量级，同时保留「炼一个真」的目标感。

### 2.3 异名替代路径（冒险日记「3 个异名凡」同构）

**3 只不同种类**的 ★(n−1) 亦可合成 1 只 ★n，但产出属性 **×0.9**（均值折损）。
> 意图：让 A 路 27 只「多而无用」的同源宠**都有去处**——正是冒险日记「解决收太多没处用」的核心。

### 2.4 星阶的机制解锁（**主要收益**）

| 星阶 | 解锁 |
|---|---|
| ★1 | 数值 ×1.15 |
| ★2 | **解锁被动槽 2**（第 2 个 `petPassive`） |
| ★3 | **羁绊触发门槛 −1**（更容易凑齐击 / 风火连天） |
| ★4 | 数值 ×1.33 + **被动效果 +15%** |
| ★5 | 数值 ×1.35 + **觉醒：**额外被动槽（3） |

对应 `data_pet.js` 新增：`PET_STAR_CAP=5`、`PET_STAR_MUL[]`、`petStarMul(n)`、
`petStarCost(n)`、`PET_STAR_MIX_LOSS=0.9`。

### 2.5 落地边界（与既有系统的关系）

```
   基础宠（q0）
      │
      ├── evolveTo ──► 分支进化（既有 q0→q1→q3，13 条链）   ← 品质跃迁轴
      │
      └── 合成升星 ──► ★1..★5（本文件新增）                  ← 机制解锁轴
                  │
                  └── 与「等级 Lv1-10」正交，三者叠乘
```
⚠ **不得**让星阶复制 `evolveTo` 的功能（那是第二真源）。星阶只管「机制解锁 + 温和数值」。

## §四 A4 经文 · `bond-mantra` 接通

### 4.1 定案

**语义升级**：`bond-mantra` = **同伴协同系**（与宠物 / 随从联动），而非「伴生回血」。

**数值改落内核已支持字段**（避免「定了接不上」）：

```js
'bond-mantra': {
  atk:   { dmgMul: 1.14,  note: '·伴生' },   // 齐击增伤（内核 dmgMul ✅）
  chant: { healPct: 0.14, note: '·唤伴' },   // 同伴分担（内核 healPct ✅）
  ult:   { trueDmgPct: 0.22, note: '·齐击' } // 万兽朝元真伤（内核 trueDmgPct ✅）
}
```

**数值方向对照**：

| kind | atk 列 | chant 列 | ult 列 | 定位 |
|---|---|---|---|---|
| `ward-mantra` | shieldPct 0.22 | shieldPct 0.20 | shieldPct 0.40 | **防御向** |
| `bond-mantra`（定稿） | dmgMul 1.14 | healPct 0.14 | trueDmgPct 0.22 | **协同向**（输出 + 分担） |

> 🔴 **落地时抓出的第二处漏网**：`JING_KIND_MOD`（`data_sutra.js:1063`，经位身份派生表）
> **没有 `bond-mantra` 条目** ⇒ 挂上 bond 的 3 部经 `jingBookOf()` 恒返回 null，**根本入不了经位**。
> 已补注册 `{ slot:'chant', mod:{regen:0.02}, def:{ti:{dr:0.02}}, note:'唤伴·协同' }`，
> 数值刻意低于 `zen-heal`（regen 0.04 / dr 0.03）——bond 的强力在**变体层**，不在经位被动层。
> 修复后实测经位计数 `atk 21 / chant 13`（与改动前完全一致，零收益偏移）。

### 4.2 挂靠经文（3 部 · 叙事强绑定）

| 经文 | 原 kind | 新 kind | 绑定 |
|---|---|---|---|
| 《地藏本愿经》 | `ward-mantra` | **`bond-mantra`** | 地藏座下「谛听」是既有同伴宠物的原型 |
| 《观音经》 | `zen-heal` | **`bond-mantra`** | 与随从体系同源（观音救度） |
| 《阿弥陀经》 | `zen-heal` | **`bond-mantra`** | 「往生」= 齐击同行的叙事表达 |

**kind 分布变化**：

| kind | 改前 | 改后 |
|---|---|---|
| `veil-mantra` | 8 | 8 |
| `ward-mantra` | 7 | **6** |
| `zen-heal` | 6 | **4** |
| `glut-ton` | 5 | 5 |
| `war-buff` | 4 | 4 |
| `break-mantra` | 4 | 4 |
| **`bond-mantra`** | **0** | **3** ✅ |

> ⚠ **零收益损失**：`bond.chant.healPct = 0.14` 与 `zen.chant.healPct = 0.18` 同向，
> 改挂 bond 的经文**不失去治疗能力**，只是从「甘露」改为「唤伴」的表述 + 获得协同向的三键修饰。

### 4.3 打通的死声明

`summon` 流派的 `fit.sutra:['bond-mantra']` 从此**可命中** ⇒ 召唤流玩家终于能吃到
那 **×1.15** 的经文配对加成，`how: '诵经唤伴齐击'` 的描述从空头支票变成事实。
