## 一、先钉死一个事实：两批都是"零运行引用"

`img/ui` 全仓只有 **1 处**引用点 —— `js/ui/ui_panel_2.js:490`，用于战斗屏敌人头像的兜底背景图：

```js
background-image:url('${ _foePortrait || (_foeTier==='boss' ? 'img/ui/Boss.webp'
                              : _foeTier==='elite' ? 'img/ui/精英.webp'
                                                   : 'img/ui/小怪.webp') }')
```

| 引用名 | 文件 | 结论 |
|---|---|---|
| `img/ui/Boss.webp` | ✅ 存在 | **分支不可达**（见下） |
| `img/ui/精英.webp` | ❌ 不存在 | 404，且同样不可达 |
| `img/ui/小怪.webp` | ❌ 不存在 | 404，且同样不可达 |

**为什么不可达**：`_foePortrait = NDX.portraitOf(...)`（`js/game/game_combat_1.js:66`），而 `NDX.portraitOf`（`js/enemies_part2.js:616-637`）**保证返回非空路径**，有三个终结兜底且文件实测存在：

```
boss  → img/portraits/enemies/mon_boss_liusha_yaowang.webp   ✓ 存在
elite → img/portraits/enemies/mon_elite_chizong_yaoshuai.webp ✓ 存在
mob   → img/portraits/enemies/mon_combat_xunshan_xiaoyao.webp ✓ 存在
```

所以 `|| 'img/ui/...'` 永远走不到。另 `dao_du.jpg` / `dao_duo.jpg` 的"引用"是假阳性（命中的是事件 id `dao_duo_nishang`）。

> **净结论：`img/ui/` 147 个文件，运行时被渲染的数量 = 0。**

## 二、判定"更合适"的真正尺子：形态，而不是风格

我原本想用"明暗是否匹配主题"来判，但数据否决了这条：

- 在用的 `img/icons/eq_weapon.webp` 明度 **202.9**（亮底）、`fa_jingubang.webp` **186.9**（亮底）——**项目本来就在暗 UI 里用亮底图标**。
- 章节底图明度跨度 69~183，浅底并非不可用。
- 且**全线素材都无 alpha**（`map_nodes 0/13`、`kenney 0/98`、`rpg 0/87`、`seals 0/47`、`ui 0/147` 均为 RGB）——这是美术管线把透明通道整体压平的共性，"无透明"不构成 A/B 差异。

真正硬性的差异是**素材形态**：

| | 项目骨架类素材（在用） | B 批 |
|---|---|---|
| 尺寸 | **9×18 / 18×18 / 22×21 / 32×32 / 96×16 / 64×60** | **287×512 ~ 512×512** |
| 用途形态 | CSS **九宫格切件**（可拉伸、可拼） | **整图大图**（只能等比缩放） |
| 代表 | `barRed_horizontalLeft` / `arrow_basic_e` / `check_square_grey` | 底板、按钮条、圆框、标签 |

**量级差 20~50 倍。** B 批自称的岗位是"UI 框件/按钮/边框"，但项目所有骨架类岗位都由 CSS 绘制 + 34 个在用切件（`img/kenney` 12 + `img/rpg` 22）承担；CSS 全库 92 处 `url()` **全部是背景图**，零图片边框/按钮。B 批要接入，等于要求项目改用"整图贴皮"路线 —— **方向相反**。

这是一套**统一圆框 + 暗底 + 单主体 + 水墨**的成体系视觉，正好补 `[六道总览 / 道途进度 / 六道转盘]` 这类界面。

**接入前必须修正的一处口径冲突**：A 批 `dao_*` 用的是 **善 / 恶**，而现役六道是 **战 / 隐** —— 只对上 4/6。二者需**改名或重绘 2 张**（`dao_e`→战、`dao_shan`→隐），否则会引入第四套六道词汇（项目已在推进统一为 `战/渡/隐/夺/缘/逆`）。

### 可选（非缺口）

- `warn_enrage / warn_lowhp / warn_routine / warn_telegraph`（4）：现役狂暴/预警由 CSS 特效承担（`fx-enrage` / `fx-enrage-cu` + 文字「狂暴」），接入图片属**装饰性增强**，非补缺。
- `Boss.webp` / `foe_avatar_base.jpg`：兜底分支不可达 → **死件**。

## 四、结论与建议

> **A 批更合适。但不要整体替换 —— 只取六道视觉层 13 个（其中 2 个改名）。**

1. **A 批**：形态与项目一致（整图徽章，和 `map_nodes 256²` / `icons 512²` / `seals 128²` 同规格），调性与暗墨主题一致，且独占一个**现役完全缺失的六道视觉层**。其余 26 个（节点 8 + 法宝 9 + 经文 6 + 兜底 2 + 背景 3 − 重叠）岗位重复或死件，**不要接入**。
2. **B 批**：**不建议采用**。形态错配（整图 vs 9-slice 切件）、108/108 无岗位、且它要替换的岗位已被 34 个在用切件占据。建议归入 `img/_library/` 并生成索引页保留复用价值，不接 UI。
3. **两批都不构成"节点/法宝图标升级"的理由** —— 那两处现役资源更优。
