# 地图界面修复：背景铺满 + 聚焦窗口（万世剑冢式）

> 时间：2026-09-14 · 触发：用户截图反馈「背景显示不完整 + 路径太乱」
> 状态：**已修复并过门禁；待你真机目视验收**

## 一、你要的两件事，分别是什么根因

| 你的反馈 | 根因（已取证） |
|---|---|
| **背景显示不完整** | ① 本该铺满整屏的 `#mapBgLayer`（`ui_core.js` 挂在 `#trail` 内、`_applyActBg` 主动画）**在全仓 CSS 里 0 条匹配** —— `.map-bg-layer / .map-bg-cur / .map-bg-next` 从未被定义，等于尺寸 0 的死代码；② 它用 `style.backgroundImage` 贴图，而代码注释早已写明 **file:// 直开时浏览器拒绝加载 CSS background-image 的本地 webp**；③ 真正看得见的 `.region-bg` 只画 `mapH≈300px` 一条横带，带外上下露 `#trail` 深底 → 「背景缺一块」。 |
| **路径太乱** | `mapHtml` 把 **11 层 × 最多 5 列** 节点全铺出来，并把**整图所有连通边**画成 `ln-base` 虚线网 → 手机小屏上「一条路四五段 + 满屏交叉线」。 |

> 说明：「万世剑冢」是**对比参考游戏**（本仓 `docs/` 有多份竞品对比文档），不是本作模式；本次按它的**聚焦视野**思路实现。

## 二、改了什么（4 文件 + 1 新门禁）

### 1. 背景铺满 —— 让死代码活过来
- `css/style.css`：补上 `.map-bg-layer`（铺满 `#trail`、`overflow:hidden`、`border-radius:inherit`）与 `.map-bg-img`（`object-fit:cover`，`opacity 0→1` 0.8s 淡入）；删掉已死且误导的 `.region-bg-img`。
- `js/ui/ui_misc_1.js` `_applyActBg()`：贴图从 `backgroundImage` 改为 **`<img class="map-bg-img">`** —— 这是 file:// 与 http 下都能加载本地 webp 的唯一稳妥写法。
- `js/ui/ui_map.js`：`.region-bg` 两个 div 去掉内联 `height:${mapH}px` 与 `background-image`，`regionPal()` 由不透明 `hsl()` 改**半透明** `hsla()`；`css` 侧 `.map .region-bg { top:0; height:100vh }` 让它铺满整高。
  → 现在的层次：**整屏地区大图（`#mapBgLayer`）+ 一层很淡的「本区/下一区」左右分色薄罩**。

### 2. 聚焦窗口（万世剑冢式）
- `js/ui/ui_map.js` `mapHtml` 新增 `winCls(L)`：以**当前层**为锚，只点亮 `WIN_AHEAD = 2`（前方 2 层）/ `WIN_BACK = 1`（身后 1 层）；
  - 窗口边缘 → `dimwin`（节点 `opacity .26` + 去饱和、连线 `opacity .18`）
  - 更远 → `offwin`（完全隐去）
  - **节点与连线同步淡化** —— 交叉线网才是「乱」的主因。
- 锚点：`centerCurrent()`（`ui_misc_1.js`）与渲染期 `place()`（`ui_core.js`）的 `anchorRatio` 由 `0.5/0.72` 统一改为 **0.82**，把视野让给「前方几步路」。（两处必须同值，否则首帧/resize 跳位。）

**降噪实测**（act1：LAYER_COUNT=11、MAX_COL=5，锚定第 5 层）：

| 窗口 | 明亮节点 | 明亮连线 |
|---|---|---|
| 改前（全铺） | 38 / 38（100%） | 59 / 59（100%） |
| AHEAD=3 / BACK=1 | 24 / 37 | 39 / 57 |
| **AHEAD=2 / BACK=1（采用）** | **19 / 38（50%）** | **31 / 59（53%）** |

一眼可见的路径只剩 **当前 + 前方 2 步**，正对你说的「不要一条路四五段节点」。
