## §一 诊断：本轮抓出的两个硬问题

### 1.1 🔴 升星是「资源驱动」，与定调相反

v1.2 落地的升星入口是：

```js
NDX.PET_STAR_COST = [0,1,2,3,5,8];          // ★1=1 只 / ★5=8 只基础宠
NDX.petStarUp(s, petId, mode)               // mode: 'same' 同名 N 只 / 'mix' 异名 3 只
```

这是一条**通用消耗升级**路径：只要攒够材料，任何宠物在任何时候都能升星。用户定调是「独有事件 / 专属 Boss」，两者**结构性冲突**：

| | 资源驱动（v1.2 现状） | 内容驱动（本轮定稿） |
|---|---|---|
| 入口 | 面板按钮（只要材料够） | **事件 / Boss 战绩** |
| 节奏 | 玩家自主，可刷 | **策划控制，绑内容** |
| 失败模式 | 「挂机刷材料」——冒险日记被吐槽的通病 | 内容即上限，不会无限刷 |
| 与「宠物不是单纯数值」的关系 | 冲突（升星 = 纯数值买路） | 一致（升星 = 剧情里程碑） |

> ⚠ 附带问题：即使删掉消耗表，**`petStarUp` 本身就是通用入口**——只要它是公开可调的，任何 UI 都能调它。
> 因此定稿要求：`petStarUp` **必须显式声明来源通道**（`via`），非白名单通道直接拒绝。

### 1.2 🔴 池子 115 只 vs 内容出口 3 个

实测（`node` vm 加载全量 js 后统计）：

| 项 | 实测值 |
|---|---|
| 宠物池（`EQUIP_POOL+CRAFT_POOL` 中 `slot:'pet'`） | **115 只** |
| **能授予宠物的事件** | **3 个**（`gui` / `longwang` / `tianzhu_moon`） |
| 能提升宠物品质/星阶的事件 | 2 个（`puti_dianhua` / `guanyin_dianhua`） |
| 随从 `NDX.FOLLOWERS` | **13 条**（上场 4） |
| 随从获取节点 `NEGOTIABLE` | **13 个** ⇒ **1:1** |
| 事件总数 `NDX.EVENTS` | 162 |

⇒ **112 / 115 只宠物没有专属获取出口**；随从是 **13 节点 / 13 随从（1:1，每只都有出处）**，宠物是 **3 出口 / 115 只（1:38）**。这就是「数量太多」的客观依据。

**第二后果：稀释掉落池。** 宠物带 `set:'御兽', setTier:1`，满足 `rollEquips` 的 `isBase()` 判据 ⇒ 全部进入**套装基座优先池**。实测 `setTier` 分布：

| setTier | 数 | 是否进掉落池 |
|---|---|---|
| **1** | **67** | ✅ 进（`tierOk = setTier < 2`） |
| 2 | 44 | ❌ 不进（A 路 `ni_*` 成品，事件专属） |
| 3 / 4 | 4 | ❌ 不进 |

⇒ 我 v1.1/v1.2 新增的 48 只（全部 `setTier:1`）**直接把宠物基座从 67 抬到 115**，宠物在基座池中的占比近乎翻倍。

### 1.3 🔴 第 7 条死路：3 条进化链断链（`evolveFrom` 的父级漏填 `evolveTo`）

实测（前向可达性遍历）：

| 宠物 | ch | 品质 | 声明 | 问题 |
|---|---|---|---|---|
| `tongbishiyuan` 通臂石猿 | 7 | q2 | `evolveFrom:'xiaoshihou'` | `xiaoshihou.evolveTo` 只有 `tongbiyuanhou`，**未含本 id** |
| `taigu_shanling` 太古山灵 | 8 | **q3** | `evolveFrom:'lingyan_ju'` | `lingyan_ju.evolveTo` **为空** |
| `taiyin_xinghu` 太阴星狐 | 9 | **q3** | `evolveFrom:'yueying'` | `yueying.evolveTo` **为空** |

⇒ **这两只 q3 传说宠玩家永远进化不到**（前向遍历不可达）。反向断言缺失是漏网原因：v1.2 门禁只验 `evolveTo` 指向的目标存在（**前向**），没验 `evolveFrom` 的父级登记了回填（**反向**）。

> 🩸 **教训（第 4 次同型）**：「A 指向 B」和「B 被 A 指向」是**两个断言**。只验一个方向 = 放行单边链。

### 1.4 顺带：链上宠物只到 ch6（收敛前）

收敛前可达 31 只，章节分布 `{1:6, 2:10, 3:4, 4:4, 5:5, 6:2}` —— **ch7/8/9 无宠**。修 §1.3 的 3 条断链后分布补全为 `{...7:1, 8:1, 9:1}` ⇒ **一石二鸟**。

## §二 升星内容化（定稿）

### 2.1 唯一入口表

```js
NDX.PET_STAR_CHANNELS = ['event', 'boss'];   // 白名单：独有事件 / 专属 Boss
```

| 通道 | 载体 | 实现 | 语义 |
|---|---|---|---|
| **`event`** | 宠物**独有事件** | 事件 `effect.petStarUp` = `1` 或 `{petId, star}` | 「专属奇遇」——某只宠在某段剧情里开窍 |
| **`boss`** | **百兽星君**（专属升级 Boss） | 击败 `baishou_xingjun` → `effect.petStarUp` | 「百兽朝宗」——打服万兽之主，全队灵宠进阶 |

**通用入口被封**：`petStarUp(s, petId, via)` 的第三参 `via` **必填**且 ∈ 白名单；`via` 缺失或非法 ⇒ 返回 `{ok:false, reason:'event-or-boss-only'}`，**不写入存档**。

> 这条的写法本身就是要被**门禁验的**——`_verify_pet.js` 用「无 `via` 调用必须失败」的反向断言把「通用入口」钉死。
> 同理，`PET_STAR_COST` / `petStarCost` / `PET_STAR_MIX_LOSS` 三符号 **删除**（门禁验其不存在）。

### 2.2 百兽星君（新 Boss · 专属升级器）

沿用 v1.0 §随从的「点化」思路，但**不是一个面板**，而是一场可遇的 Boss：

| 项 | 定稿 |
|---|---|
| id | `baishou_xingjun` |
| 名 | **百兽星君** |
| 定位 | 万兽之宗，非敌非友——「你带的这些小家伙，根骨如何，我一试便知」 |
| 出现 | 地区 5~9 的**事件节点**（`region:[5,9]`），非必遇 |
| 效果 | `effect.petStarUp: 1`（全队已上阵灵宠各 +1 星，上限 ★5） |
| 与事件的分工 | 事件 = **单宠定向**升星（叙事绑定）；Boss = **全队齐升**（rare、一次） |

### 2.3 星阶数值不变（v1.2 已定稿，本轮不动）

`PET_STAR_MUL = [1.00, 1.15, 1.24, 1.29, 1.33, 1.35]`；★2/★5 被动档数 +1/+2；★3 羁绊 +20%（取 max）。
**本轮只换入口，不动数值**——避免「一次改两件事」。
