## 1. 动画总规范（融总纲，先记死这几条）

| 项目 | 规范 |
|------|------|
| 分辨率 | **1024×1024**（手机横屏，清晰度与体积平衡） |
| 背景 | 纯透明 PNG（引擎叠加用） |
| **朝向** | **全部面朝右**（我方在左、敌在右）；朝左用代码水平翻转，**零美术成本** |
| 画风 | **水墨暗黑国风**（焦墨厚涂写意），低饱和黑白灰主调 + 角色专属点缀色（鎏金/朱砂/暗紫） |
| 输出 | 透明 PNG 序列帧 + GIF 预览（给策划/自己核对用） |

### 1.1 标准动作集（每形态 25 帧 — 这是生图时的切帧依据）

| 动作 | 帧数 | 每帧时长 | 循环方式 | 说明 |
|------|------|----------|----------|------|
| 待机 | 4 | 300ms | 循环 | 呼吸微动，战袍/毛发轻飘 |
| 攻击 | 6 | 150ms | 播完回待机 | 蓄力→挥砍→命中→收势 |
| 施法 | 6 | 200ms | 播完回待机 | 按 Boss 施法类型设计 |
| 受击 | 3 | 150ms | 播完回待机 | 后仰→颤抖→恢复（代码加闪白） |
| 死亡 | 6 | 400ms | 停最后一帧 | 虚弱→跪倒→倒地→静止 |
| **合计** | **25** | — | — | 每形态固定 25 帧 |

> **给美术的硬约束**：生图时必须按上面帧数分别出图（如待机出 4 张、攻击出 6 张），不要一张图里塞多帧。脚底统一对齐画布下方 1/5（锚点）。

### 1.2 形态分类与美术消耗（决定你要做多少活）

| 形态 | 帧数 | 代表 |
|------|------|------|
| 单形态（纯妖） | 25 | 金角银角、青牛精、大鹏、黄眉、九灵元圣 |
| 双形态（人+妖） | 50 | 黄袍怪、牛魔王、铁扇、白鼠精、玉兔精 |
| 三阶段（人→妖→终极） | 50 + 粒子层 | 黄风怪、红孩儿、牛魔王 |
| 白骨精特殊 | 75 + 粒子 | 少女25+老妪25+老翁25+白骨夫人施法 |

### 1.3 三段变身优化（省 70% 美术）

```
一阶段（人/基础妖）→ 完整25帧
二阶段（妖/强化）  → 完整25帧（形象变化大，必重做）
三阶段（终极）     → 二阶段动作帧 + 粒子层(5~8帧循环) + 代码泛光/变色/体型+15%
```
粒子层 = 独立透明 PNG 序列，可跨 Boss 复用（黑气/火焰/沙尘）。

### 1.4 施法 7 分类 / 异常状态（代码层，不额外出图）

- 施法：风/火/水/雷/毒/法宝/法术，各 6 帧固定流程（见手册第 5.5 节）。
- 异常状态（中毒/燃烧/冰冻/麻痹/眩晕）全部用代码 `colorMatrix` 偏色 + 角标实现；受击闪白用白色蒙版闪烁。

## 2. 精灵表打包规格（散图 → 引擎能吃）

美术产出的是**一堆单张 PNG**，引擎要的是**一张大图（图集/精灵表）+ 一份帧坐标 JSON**。

### 2.1 单形态 25 帧排布（推荐 5×5 网格）

```
横向顺序：待机(4) 攻击(6) 施法(6) 受击(3) 死亡(6)  = 25 帧
排成 5 列 × 5 行，每格 1024×1024 → 整张图集 5120×5120（单形态）
```
- **锚点**：每帧角色脚底对齐该格下方 1/5；打包时记录 `pivot`（脚底在格内的相对坐标）。
- **间距/外扩（padding/extrude）**：每格四周留 **2px 透明外扩**，防相邻帧渗色（纹理过滤用）。
- **Trim**：保留透明边距即可，不要裁掉角色。
- **朝向**：全部朝右；朝左在引擎用 `scaleX = -1` 翻转。

### 2.2 图集拆分策略（控包体）

| 对象 | 建议 |
|------|------|
| 单形态 Boss | 1 张图集（5120²）或拆成 待机/战斗 两张 |
| 双形态 | 人、妖各 1 张图集 |
| 三阶段 | 二阶段图集 + 独立粒子层图集（小尺寸，如 512² 循环 8 帧） |
| 普通小怪 | 多怪拼进同一张共享图集（按章节） |

### 2.3 帧数据 JSON 格式（TexturePacker / Aseprite 通用结构）

```json
{
  "meta": {
    "image": "huifengguai_atlas.png",
    "size": { "w": 5120, "h": 5120 },
    "fps": { "idle": 3.33, "attack": 6.67, "cast": 5.0, "hit": 6.67, "death": 2.5 },
    "pivot": { "x": 0.5, "y": 0.8 }
  },
  "frames": {
    "idle_0":  { "frame": {"x":0,    "y":0,    "w":1024,"h":1024}, "duration":300 },
    "idle_1":  { "frame": {"x":1024, "y":0,    "w":1024,"h":1024}, "duration":300 },
    "idle_2":  { "frame": {"x":2048, "y":0,    "w":1024,"h":1024}, "duration":300 },
    "idle_3":  { "frame": {"x":3072, "y":0,    "w":1024,"h":1024}, "duration":300 },
    "attack_0":{"frame": {"x":4096, "y":0,    "w":1024,"h":1024}, "duration":150 },
    "attack_1":{"frame": {"x":0,    "y":1024, "w":1024,"h":1024}, "duration":150 },
    "death_5": { "frame": {"x":...,  "y":...,  "w":1024,"h":1024}, "duration":400 }
  }
}
```
> `duration` 单位 ms，直接对应总纲的每帧时长；`pivot.y=0.8` 即脚底在格高 80% 处（下方 1/5）。

## 3. 引擎播放实现（Canvas 示例）

### 3.1 序列帧播放器（恒定速度循环 / 单次播完回待机）

```js
// SpritePlayer.js —— 适配上面 JSON 的极简播放器
class SpritePlayer {
  constructor(img, frames, meta) {
    this.img = img; this.frames = frames; this.meta = meta;
    this.state = 'idle'; this.idx = 0; this.acc = 0; this.faceLeft = false;
    this.once = false; // 是否单次（攻击/受击/死亡）
  }
  setState(s) {
    if (this.state === s) return;
    this.state = s; this.idx = 0; this.acc = 0;
    this.once = (s === 'attack' || s === 'hit' || s === 'death' || s === 'cast');
  }
  update(dt) { // dt: ms
    const key = this.state + '_' + this.idx;
    const f = this.frames[key]; if (!f) return;
    this.acc += dt;
    while (this.acc >= f.duration) {
      this.acc -= f.duration; this.idx++;
      const next = this.state + '_' + this.idx;
      if (!this.frames[next]) {            // 当前动作播完
        if (this.once) {
          if (this.state === 'death') { this.idx--; return; } // 死亡停最后一帧
          this.setState('idle');           // 其余播完回待机
        } else { this.idx = 0; }           // 循环
      }
    }
  }
  draw(ctx, x, y) {
    const f = this.frames[this.state + '_' + this.idx];
    const p = this.meta.pivot;
    ctx.save();
    ctx.translate(x, y);
    if (this.faceLeft) ctx.scale(-1, 1);    // 朝左：水平翻转，零美术成本（美术资源统一面向右）
    ctx.drawImage(this.img, f.frame.x, f.frame.y, f.frame.w, f.frame.h,
      -f.frame.w * p.x, -f.frame.h * p.y, f.frame.w, f.frame.h);
    ctx.restore();
  }
}
```

### 3.2 战斗手感增强（用动画原则，不动图）

| 效果 | 实现 | 作用 |
|------|------|------|
| **受击闪白** | 受击帧叠加白色蒙版闪烁 1~2 帧 | 打击反馈 |
| **Hit-stop** | 命中瞬间冻结全部动画 60~100ms | 增强打击感（一次性，非循环） |
| **idle→attack 过渡** | 攻击起手前 1~2 帧保持待机姿势再切 | 不瞬切，更顺 |
| **三阶段泛光/变色** | 代码整体 tint + 体型 `scale(1.15)` | 终极形态，零美术 |
| **粒子层叠加** | 独立粒子图集按 `globalCompositeOperation` 叠到角色上 | 黄沙/火焰/鬼火 |

### 3.4 性能（H5 移动端关键）

- **只动 `transform` / `opacity`**；精灵用 GPU 合成，必要时 `will-change: transform`。
- 播放用 `requestAnimationFrame`，**不要每帧改 DOM/重排**。
- 大图集注意显存：1024²×25 单形态 ≈ 100MB 未压缩显存，**必须纹理压缩**（见 4 节）。
- 减少 draw call：同屏角色尽量共用一张图集。

### 3.5 可访问性

- 提供"减弱动态"开关；开启时：循环动画降级为更低帧率或静止首帧，打击特效减弱（`prefers-reduced-motion` 对应逻辑）。

## 4. 三端导出与性能预算

| 平台 | 包体限制 | 纹理策略 | 注意 |
|------|----------|----------|------|
| 浏览器 H5 | 无硬限制，但首屏越小越好 | PNG / WebP | 图集按需加载，首屏只载第一章 |
| 微信小游戏 | 主包 4MB、整包 ≤ 20MB（可分包） | **ETC2/ASTC 压缩** | 1024² PNG 必须转压缩纹理，否则爆显存/包体 |
| TapTap（买断） | 商店包体建议 ≤ 200MB | ASTC | 走平台审核 + 内容规范（无血腥暴力） |

**落地建议**：
1. 美术吐 PNG 序列帧（透明）→ 自动脚本拼图集 + 出 JSON（用 TexturePacker / 自写脚本）。
2. 微信/移动端用 `etc2comp` / `astcenc` 把图集转压缩纹理，PNG 仅留做预览。
3. 三端共用同一份 JSON 帧数据 + 各自纹理格式，逻辑零改动。
