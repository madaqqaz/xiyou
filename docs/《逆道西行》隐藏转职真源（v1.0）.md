## 〇、真源声明

| 项 | 结论 |
| --- | --- |
| 唯一真源 | `js/data_trials.js` 的 `NDX.HIDDEN_JOBS` —— 共 **45 条**（V9.23 收口后） |
| 条件判定 | **实机以正文 `hidden.cond` 为准**（`game_event_2.js:390` 调 `NDX.evalHiddenCond(h.cond, s, opt)`） |
| ⚠ 注册表 `cond` | **零消费**——仅作文档字段，与正文不一致时不改变实机难度（见 §六） |
| 数值/被动 | 只认注册表的 `effect.bonus` / `effect.passive`（`attr_calc.js:315`、`combat_part1.js:335` 按 `job` 反查） |
| 双重门槛 | ①`hiddenTrialsMet` 必经劫难　②`held` 持宝　—— **仅注册表有条目才生效** |
| 觉醒记账 | `NDX.recordAwakened(job)` → localStorage `ndx_awakened_jobs`，跨周目继承 |

### 关键机制：注册表缺条目 = 后门

`game_event_2.js:477-527` 的分叉决定了「孤儿职」的真实性质：

```js
const hiddenEntry = /* 全表按 job 反查 */;
if (hiddenEntry) { /* 门槛1 劫难前置 + 门槛2 持宝 */ }
else { s.flags.jobConfirm = jobConfirm; NDX.recordAwakened(jobConfirm); }  // ← 零门槛直得
```

因此 V9.23 之前，正文有 `hidden` 种子但注册表无条目的 **7 条孤儿职** 是**空壳后门**：
玩家能拿到职名与成就，但**无数值、无被动、无门槛校验**。本轮已全部补注册。

## 一、字段规范

| 字段 | 必填 | 说明 |
| --- | :-: | --- |
| `trial` | ✔ | 触发难号（全局 1-81）。位置感知：`hiddenTrialsMet` 只校验 ≤ 当前难的必经劫难 |
| `job` | ✔ | 职名，**全局唯一**（反查主键）。重复会导致先命中者生效 |
| `cond` | ✔ | 文档性条件串。实机以正文 `hidden.cond` 为准，两者须人工保持一致 |
| `held` | — | 持宝门槛（装备/法宝 id）。本难自身 `treasure` 视为已持有 |
| `hero` | — | 仅在 `all` 桶内使用，指定该职的实际归属英雄；缺省视为全英雄 |
| `effect.bonus` | ✔ | `{ti:{...}, yuan:{...}}` 基础数值加成，叠加不替换 |
| `effect.passive` | — | `empty/sunder/glutton/restored/mercy/mReflect/reverseScale/chaos` 等被动钩子 |
| `chainId` | — | 事件链标识。同链按 `chainStep` 升序 |
| `chainStep` | — | 链内序号，从 1 起 |
| `nextJob` | — | 下一节职名；链尾写 `chainTail: true` |
| `hint` / `note` | — | 暗线线索 / 备注，进冒险日记与转职受阻提示 |
