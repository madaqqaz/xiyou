| 完善流派与职业对应（P1-6） | ❌ 已完成。`JOB_STYLE` 45 条对 `HIDDEN_JOBS` 45 职 **100% 覆盖**，无缺口无幽灵映射，10 流派全 `impl:true` | **划掉** |
| 「变化感不强」 | ✅ 诊断对，但**抓错病灶** | 见下 |

### 🔴 真病灶：多职并发只生效 1 个

`s.flags.jobConfirm` 是**单值**，两条合并路径都是 `find(...)+break`：

```js
// attr_calc.js:319-331（数值）／combat_part1.js:470-474（被动）／data_jobspec.js:143 同构
const hit = (...).find((x) => x.job === jobKey);
if (hit && hit.effect && hit.effect.bonus) { ...; break; }   // ← 只取最后一个
```

实测悟空持棒者链（7 步）全中：

| 项 | 理论累计 | 实际生效 | 丢弃 |
|---|---|---|---|
| atk | +180 | +50 | **72%** |
| hp | +280 | +200 | 29% |

⇒ **玩家转了 7 次职，只有最后一次算数。** 这比「数值给小了」严重得多。

## 三、条目 1 · 多职并发合并规则

### 3.1 数据契约

新增单一真源（全部放 `js/data_trials.js`，与 `HIDDEN_JOBS` 同文件）：

```js
NDX.activeJobs(s)     // → string[]  已确认隐藏职（按确认顺序，去重，过滤不存在的条目）
NDX.currentJob(s)     // → string|null  末位 = 「当前形态」（兼容旧 jobConfirm 语义）
NDX.mergeJobBonus(names, mult)  // → { ti:{}, yuan:{}, good:num }
NDX.mergeJobPassive(names)      // → passive 对象（已套硬顶）
```

### 3.2 数值合并

```
ti / yuan  → 逐键累加（不做取最大）
good       → 累加
再 ×(1 + JOB_LEGACY_PCT × legacyCount())     // 条目 3 的跨周目继承
```

**封顶（防止多链全中爆炸）**：

| 字段 | 封顶规则 |
|---|---|
| `ti.atk` | ≤ 英雄基础 atk × 3.0 |
| `ti.hp` / `ti.maxHp` | ≤ 英雄基础 hp × 4.0 |
| `ti.matk` | ≤ 英雄基础 matk × 3.0 |

### 3.3 被动合并 —— 同名取最大、异名累加、逐键硬顶

> 不能简单全叠。悟空链 passive 全是绝对穿透系（`empty` 0.12/0.14/0.16/0.20），
> 11 个 `empty` 职全叠 = **143% 绝对穿透率**，游戏当场崩盘。

| passive 键 | 硬顶 | 单职区间 | 硬顶理由 |
|---|---|---|---|
| `empty` | **0.30** | 0.08 ~ 0.20 | 绝对穿透，最高单职已 0.20 |
| `sunder` | **0.18** | 0.05 ~ 0.08 | 破防 |
| `glutton` | **0.20** | 0.12 ~ 0.20 | 开局护盾 + 受击回血 |
| `mercy` | **0.08** | 0.04 ~ 0.06 | 善值转气血 |
| `mReflect` | **0.40** | 0.25 | 反震比例 |
| `mReflectBoost` | **0.20** | 0.08 ~ 0.10 | 反震增幅 |
| `buddha_def` | **0.15** | 0.06 | 受击反震 |
| `chaos` | **0.15** | 0.10 | — |
| `criBonus` | **0.10** | 0.05 | — |
| `restored` | 布尔，取 `or` | `true` | 每场首次受击免伤 |
| `reverseScale` | 布尔，取 `or` | `true` | 残血叠攻 |

> 已逐个 grep 确认：**11 个 passive 键在 `combat_part1.js` / `combat_active.js` 均有消费点**，
> 本次新增的合并器不会造出「建表无消费点」的死字段。

## 五、条目 3 · 跨周目觉醒继承（通用通道）

### 现状
`awakenedJobs` 全仓仅 3 处读取：
- `game_event_2.js:484` —— 「早已觉醒 → 跳过弹窗」（**门槛豁免**）
- `equipment_part3.js:96` / `:510` —— **两条硬编码特例**（逆兽师 · 额外宠物格 + 御兽增幅 ×1.5）

⇒ 45 个隐藏职攒满几周目，**战力零回报**。

### 设计：觉醒印记（Legacy Seal）

| 参数 | 值 | 说明 |
|---|---|---|
| `JOB_LEGACY_CAP` | **9** | 继承槽位上限（45 职 / 5 英雄） |
| `JOB_LEGACY_PCT` | **0.03** | 每槽给隐藏职数值 +3% |
| 满槽收益 | **×1.27** | 与一条链尾职（atk+50 / hp+200）量级相当 |

**作用面**：只放大**隐藏职 bonus**，不放大英雄基础与装备 ⇒ 溢出可控。
**计槽口径**：`min(NDX.awakenedJobs().length + favor 特殊职数, 9)`。

### 去硬编码
`equipment_part3.js` 的两条特例改为注册表驱动（与 `HIDDEN_JOBS` 同文件）：

```js
NDX.JOB_PET_SLOT        = { '逆兽师·百逆归心': 1 };                  // 额外宠物格
NDX.JOB_TREASURE_SYNERGY = { '逆兽师·百逆归心': { perPetMult: 1.5 } }; // 御兽套 perPet 增幅
```

## 六、条目 4 · 补 `burn` 流派（2 → 3）

| 职 | 原流派 | 新流派 | 理由 |
|---|---|---|---|
| 罗刹·铁扇 | `purify` | **`burn`** | 芭蕉扇控火，原著与红孩儿三昧真火对位；`purify`（净化/治疗）与铁扇的攻击面不符 |

影响面：`purify` 8→7（仍是最大的流派）、`burn` 2→3（成环）。
三键变种自动跟随：`burn → atk:sunder / chant:aoe`（已存在，无需新接线）。

### 顺手修掉的两处 latent bug（审计未发现）

1. **`六耳·残` / `真·逆道` 的 effect 从来没生效过** —— 这两个全英雄级隐藏职只置 `liuerUnlocked / allHiddenUnlocked` 旗标，**从不写 `jobConfirm`** ⇒ `effect`（六耳 atk+20 cri+0.05 / 真逆道 hp+300 atk+30 dr+0.08）一直空转。现已改走 `confirmHiddenJob`。
2. **`逆兽师` 本职效果上周目残留才触发** —— 原判断是 `isAwakened(...)`（跨周目持久），本局确认却不生效。现已收紧为 `activeJobs`（本局），语义正确。

### 平衡影响（须复核）

本轮改动**放大了隐藏职收益**，这是有意为之（旧口径丢 72% 内容本来就是缺陷），但也意味着：

- 单链全中的玩家 atk 理论 +180（旧 +50），**约为 3.6 倍**；
- 因此 `JOB_BONUS_CAP`（atk ≤ 英雄基础 ×3、hp ≤ ×4）与 `JOB_PASSIVE_CAP`（`empty` ≤ 0.30 等）是**硬护栏**，
  改动这两个表之前必须先跑全量门禁 + 平衡快照。
