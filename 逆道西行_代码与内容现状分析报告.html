1. 工程架构与模块地图

项目为零依赖、零构建的原生 ES6 + DOM 应用，遵循 AGENTS.md 宪法：所有共享语义进入唯一 owner 数据文件，game.js 处理逻辑，ui.js 只渲染，平台差异由 platform/ 适配层隔离。整体分层清晰、单源合规良好。

1.1 index.html 加载顺序与缓存纪律

index.html 第 211 行注释明确约定顺序：data → events → equipment → … → game → ui → main。实际 <script src> 严格按此序加载，每个文件均带 ?v=NN 缓存版本号（HTML 自身不缓存，静态资源可缓存）。CSS 经 css/style.css?v=528 + css/mobile-landscape.css?v=2 加载；PWA 由 sw.js 注册（含 ./sw.js 与 /sw.js?v=1 两处注册点）。

1.4 入口链与 NDX 命名空间

  • data.js:5-8 建立全局 window.NDX = {}；各文件以 var NDX = window.NDX 挂载（非 class，纯对象枢纽）。
  • main.js:156 监听 DOMContentLoaded → NDX.Platform.buyout.verifyAndBoot（买断门禁，:164）→ 成功调 startGame()（:190）。
  • startGame() 播开场动画/加载屏 → NDX.game = new NDX.Game()（:218，仅实例化一次）。
  • game.js:6 class Game 纯逻辑状态机；ui.js:24 NDX.ui 纯渲染，读 NDX.game.state。

1.5 平台适配层（三端）

platform/ 下 4 文件：browser.js / taptap.js / wechat.js / index.js。各经 window.__NDX_PLATFORM_FACTORIES[name] 注册，index.js:11-32 按宿主 hint（window.tt→taptap、wx→wechat、否则 browser）装配。统一接口 NDX.Platform：storage / buyout / achievements / share / purchase。差异：browser 走 localStorage + 默认 mock 已购；taptap 接 SDK 并 failback；wechat 走 wx.*StorageSync、免费无买断（恒 purchased:true）。

4. 测试与门禁基线

  • scripts/ 共 68 个 .js；门禁类：_audit_ 7 + _smoke_ 5 + _verify_ 26 + _run_all_gates.js 1 = 39 个门禁脚本。
  • _run_all_gates.js：fs.readdirSync 自动发现匹配 /^(_smoke_|test_|_verify_).*\.js$/ 的脚本，再 concat 硬编码白名单（regression.js / platform_test.js / validate_audio.js / bus_decoupling_test.js / _audit_trial_dao.js / _check_dao_fieldloss.js / _audit_trials81.js），existsSync 过滤后 spawnSync 逐个跑，按“N 失败 / exit≠0”判 bad，输出 脚本数 / 通过 / worst(0=全绿)。
门禁盲区：正则仅覆盖 _smoke_/_verify_/test_ + 白名单只补 2 个 audit，故 5 个 _audit_*.js（balance / herotrial_align / jobs_chapter / save_capacity / seal）未被自动发现。实际发现量≈33，与 AGENTS 声称“32 全绿”口径略有出入。
虚假基线已证实：scripts/regression.js 与 scripts/_smoke_monster_behavior.js 经 ls 确认从未创建（AGENTS.md 已标注作废）。旧版“regression.js(157项)”属虚假基线，_run_all_gates.js 为唯一真源。
